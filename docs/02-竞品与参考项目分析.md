# 御书 · 竞品与参考项目分析

> **摘要**：横向拆解开源、商业、中文三组共 30 家写作与世界构建工具后可以确认：竞品在单点能力（设定注入、结构化条目、地图时间线、中文码字体验）上已被充分验证，但**没有任何一家同时做到「世界分层构建 + 设定影响传播 + 一致性校验 + 全流派派系包 + AI 合规证据链 + 本地数据主权」**——御书的差异化是组合空白，不是功能空白。

## 0. 摘要与结论速览

本文不做功能罗列，而是回答一个决策问题：**御书的六项差异化，是「别人已做好的功能」还是「无人同时做到的组合」？** 逐条核验结论如下：

| 御书差异化 | 最接近的竞品 | 空白判定 |
|---|---|---|
| 世界分层构建 + 设定影响传播 | Fantasia Archive / World Anvil / Campfire 做到了分层条目，但没有「上游变更→下游受影响清单→逐项确认」的传播机制 | **无竞品** |
| 跨层一致性校验 | show-me-the-story / Closure 有事实抽取与有限校验；其余全部停留在「提供结构化设定供作者自查」 | **无竞品（空自区）** |
| 全流派派系包（schema + 规则 + 节拍 + 平台映射） | Plottr / Campfire / Scrivener 只有「结构模板」，无流派语义与校验规则 | **无竞品** |
| AI 合规证据链（AI 使用记录 + 编辑轨迹 + 平台申报） | 无。Sudowrite / NovelCrafter 把 AI 做得越强，越回避「人类创作证明」 | **无竞品** |
| 本地数据主权（Markdown 真源 + 可重建索引） | novelWriter / manuskript / Closure 具备本地纯文本；商业侧无一家提供 | **部分具备，但未与世界引擎合流** |
| 中文网文工作流适配 | 橙瓜 / 妙笔 / 小黑屋是「全家桶」标杆，但无世界引擎与一致性能力 | **功能具备，架构未具备** |

三条总判断：

1. **能力已被验证、组合未被实现**。设定卡、注入预算、地图-条目双向链接、时光机、自动分章等每一条都有人做过，没有一家把它们放进同一个「世界优先」的内核。
2. **越强的 AI，越缺合规**。商业 AI 工具押注「代笔越自动越好」，而 97% 的作者反对 AI 代写（S6 预研）；御书把「AI 副驾 + 证据链」当作合规卖点，竞品集体缺席。
3. **越强的云，越弱的主权**。World Anvil / Campfire / LegendKeeper 云端绑定，墨者写作已于 2022 年后停运——「云服务停运 = 书稿风险」是可直接引用的反面教材。

## 1. 分析方法与维度说明

**素材来源**：以 `research/K-软件工程与产品/K01-竞品与参考项目.md` 为研究底座（30 家竞品、12 维归纳、34 条已核实来源），本文在其上做独立分析，不复制原文。

**分析方法**：对每家竞品按 12 个维度逐项判定，并强制给出「可借鉴」与「明确不应照搬」两组结论——只写功能不做判断的条目一律视为不合格（对应 K01 校验规则 `comp-borrow-empty`）。所有竞品结论都必须能追溯到 §8 的来源编号，禁止无出处的判断（`comp-schema-complete`）。

**12 个比较维度**：

1. **世界观构建方式**——实体化（类型化条目 + 模板 + 双向链接）vs 文档化（Binder 树 / 文件夹 / 白板，弱结构化）。
2. **是否支持类型化设定卡**——是否有人物/地点/势力等有 schema 的设定实体，而非普通文档。
3. **关系、时间线、地图**——三件套是否齐备，以及是否互相绑定。
4. **流派或模板组合**——是「结构模板」还是「流派语义包」（schema 扩展 + 校验规则 + 爽点节拍 + 平台映射）。
5. **AI 记忆与上下文注入**——触发方式（关键词/别名/常驻）、Token 预算、插入优先级、级联激活。
6. **一致性检查能力**——是否主动检测战力崩塌、时间线冲突、称呼漂移。
7. **本地优先与数据迁移**——数据格式是否开放、能否脱离工具读取、是否强制账号。
8. **版本历史与防丢稿**——自动保存、快照、章节版本、崩溃恢复。
9. **中文网文工作流适配**——自动分章、一键排版、敏感词、取名、更文统计、有效字数口径。
10. **插件或扩展能力**——插件生态、扩展点数量、封闭程度。
11. **许可证、定价与锁定风险**——判据不是价格，而是「数据能否无损带出」。
12. **可借鉴点与明确不应照搬的部分**——本报告的落点。

**判定口径**：`强 / 中 / 弱 / 无` 为四档定性；地图、时间线、关系用三段式记法（关系/时间线/地图）。所有定价与许可证以官方页面为准，仅记录写作时的口径。

## 2. 开源阵营（12 家）

### 2.1 novelWriter（GPLv3，Python/Qt6）

- **定位**：面向长篇小说的纯文本写作工具，天然 Git 友好。
- **关键能力**：类 Markdown 正文 + `@tag` 实体引用语法，把人物、地点、标签写成可检索的结构化记号。
- **12 维速评**：世界观 `文档化/弱` ｜ 设定卡 `弱（@tag 而非 schema）` ｜ 关系·时间线·地图 `弱/弱/无` ｜ 流派模板 `无` ｜ AI 注入 `无` ｜ 一致性 `无` ｜ 本地优先 `强（纯文本）` ｜ 版本防丢 `强（Git 友好）` ｜ 中文网文 `弱` ｜ 插件 `弱` ｜ 许可/定价 `GPLv3 / 免费`
- **可借鉴**：**纯文本 + 实体标记**是御书 Markdown 真源 + 实体内联标记（`@引用`）的直系参照；证明「结构化标记」不必依赖私有数据库。
- **不照搬**：不做「纯文本记号即设定」的弱结构化路线；御书需要类型化设定卡与 schema 扩展，@tag 只是引用层。

### 2.2 manuskript（GPL）

- **定位**：多视图开源写作工具（前提/人物/情节/大纲/索引卡/世界观/物品/故事线）。
- **关键能力**：同一项目的多视图切换，开放纯文本项目格式，适当的强结构化。
- **12 维速评**：世界观 `半结构化` ｜ 设定卡 `中` ｜ 关系·时间线·地图 `弱/弱/无` ｜ 流派模板 `中（结构模板）` ｜ AI 注入 `无` ｜ 一致性 `无` ｜ 本地优先 `强` ｜ 版本防丢 `中` ｜ 中文网文 `弱` ｜ 插件 `弱` ｜ 许可/定价 `GPL / 免费`
- **可借鉴**：**多视图同一实体**的思路（Binder 文档 = 索引卡 = 大纲条目），以及「开放纯文本项目格式」的克制。
- **不照搬**：视图数量堆叠而不做分层依赖；御书视图必须由世界层级派生，不是并列面板的堆砌。

### 2.3 bibisco（开源 + 商业版）

- **定位**：以「人物访谈式问卷」著称的小说写作工具。
- **关键能力**：用访谈问题生成人物档案；提供人物出场分布统计；场景级写作。
- **12 维速评**：世界观 `文档化` ｜ 设定卡 `中（人物为主）` ｜ 关系·时间线·地图 `弱/无/无` ｜ 流派模板 `弱` ｜ AI 注入 `无` ｜ 一致性 `弱（出场分布）` ｜ 本地优先 `中` ｜ 版本防丢 `中` ｜ 中文网文 `弱` ｜ 插件 `弱` ｜ 许可/定价 `开源+GPL / 有商业版`
- **可借鉴**：**问卷脚手架驱动设定生成**——直接对标御书起源工作台的「向导式建档」，且验证了「提问比表单更适合新手」。
- **不照搬**：把世界观压缩成人物访谈；御书的问卷必须覆盖起源→法则→地理→文明全层级，人物只是其中一层。

### 2.4 Obsidian（闭源免费 + 商业许可）

- **定位**：本地 Markdown 知识库，插件生态的标杆。
- **关键能力**：属性（frontmatter）+ 双向链接 + Bases 结构化表格视图 + Obsidian Sync 版本历史；数千插件。
- **12 维速评**：世界观 `文档化（可自建）` ｜ 设定卡 `中（属性+YAML）` ｜ 关系·时间线·地图 `中（图谱/插件）/无/插件` ｜ 流派模板 `无（插件可凑）` ｜ AI 注入 `插件` ｜ 一致性 `插件（非内核）` ｜ 本地优先 `强` ｜ 版本防丢 `强（Sync 版本历史，另有本地快照）` ｜ 中文网文 `弱` ｜ 插件 `强` ｜ 许可/定价 `免费（个人）/ 商业许可 $50/人·年；Sync $4 起、Publish $8 起`（来源 35、36）
- **可借鉴**：**「属性即列」+ 双向链接 + 未创建条目占位（空链接）**的组织范式，是御书设定卡元数据与「待补设定」清单的直接参照；插件生态证明「内核最小 + 扩展繁荣」可行。
- **不照搬**：**插件生态的复杂度**——配置成本高、质量参差、普通作者上手门槛大。御书内核必须提供开箱可用的世界引擎与一致性，不能把核心能力外包给插件。

### 2.5 Logseq（AGPL）

- **定位**：大纲式笔记工具，数据库版改用 SQLite + isomorphic-git。
- **关键能力**：块级引用与大纲结构；「笔记即数据库」；本地 Git 版本化。
- **12 维速评**：世界观 `文档化` ｜ 设定卡 `弱（块/属性）` ｜ 关系·时间线·地图 `中/无/无` ｜ 流派模板 `无` ｜ AI 注入 `弱` ｜ 一致性 `无` ｜ 本地优先 `强` ｜ 版本防丢 `强` ｜ 中文网文 `弱` ｜ 插件 `强` ｜ 许可/定价 `AGPL / 免费`
- **可借鉴**：**SQLite 索引 + isomorphic-git 并存**的工程组合，与御书「Markdown 真源 + SQLite 可重建索引 + Git 版本化」的技术路线高度同构，可作为可行性背书。
- **不照搬**：大纲式（outliner）单一形态不适合正文创作；御书正文是章节化的连续文本，块结构只在设定与大纲层使用。

### 2.6 SillyTavern（AGPL）

- **定位**：多后端 LLM 前端（角色扮演/续写），World Info 机制的集大成者。
- **关键能力**：World Info 支持激活关键词/次要关键词、常驻、扫描深度、Token 预算、插入顺序与插入位置、递归激活、互斥组、sticky/cooldown/delay 时序效果；多后端抽象（模型无关）。
- **12 维速评**：世界观 `条目化（弱分层）` ｜ 设定卡 `中（Lorebook 条目）` ｜ 关系·时间线·地图 `无` ｜ 流派模板 `无` ｜ AI 注入 `强` ｜ 一致性 `无` ｜ 本地优先 `强` ｜ 版本防丢 `中` ｜ 中文网文 `无` ｜ 插件 `强` ｜ 许可/定价 `AGPL / 免费`
- **可借鉴**：**「常驻 + 关键词/正则触发 + Token 预算 + 插入优先级 + 级联激活」**这套注入参数是御书记忆系统的直接对标（docs/01 §4.3、J05）；其「多后端抽象」也是 Provider 能力矩阵的参照。
- **不照搬**：条目无作者、无出处、无置信度、无状态（来源 37），设定「谁写的就是真的」——御书必须给设定卡记来源、设可见性、可审计，不能做无治理的注入堆。

### 2.7 Long-Novel-GPT（开源，中文）

- **定位**：中文长篇生成框架：大纲→章节→正文三层扩写 + RAG 上下文 + 拆书导入。
- **关键能力**：层级化生成流水线、成本显示、把已有小说拆解为可续写的结构。
- **12 维速评**：世界观 `无` ｜ 设定卡 `弱` ｜ 关系·时间线·地图 `无` ｜ 流派模板 `弱` ｜ AI 注入 `中（RAG）` ｜ 一致性 `弱` ｜ 本地优先 `中` ｜ 版本防丢 `弱` ｜ 中文网文 `中` ｜ 插件 `弱` ｜ 许可/定价 `开源 / 免费`
- **可借鉴**：**三层扩写（大纲→章节→正文）**与「拆书导入」，分别对标御书三级大纲与 I09 存量稿迁移；证明中文长篇的分层生成可行。
- **不照搬**：以「生成」为中心而非以「世界」为中心；御书是创作工具，AI 是副驾，不把小说当成一次性的生成产物。

### 2.8 GPT-Author（开源）

- **定位**：候选情节→大纲→逐章→EPUB 的最小全流程实验。
- **关键能力**：极简可复现的端到端管线，验证「AI 出书」的工程可行性。
- **12 维速评**：世界观 `无` ｜ 设定卡 `无` ｜ 关系·时间线·地图 `无` ｜ 流派模板 `无` ｜ AI 注入 `弱` ｜ 一致性 `无` ｜ 本地优先 `中` ｜ 版本防丢 `弱` ｜ 中文网文 `无` ｜ 插件 `无` ｜ 许可/定价 `宽松许可 / 免费`
- **可借鉴**：**「候选→大纲→逐章→EPUB」的管线骨架**，对应御书 AI 多候选 + 大纲 + 导出三段式。
- **不照搬**：把「AI 自动写完一本书」当产品目标；这正是御书明确定位为副驾、并把 AI 默认关闭的原因。

### 2.9 show-me-the-story（开源，中文）

- **定位**：自托管中文长篇创作工具，最接近御书 AI 侧目标的开源实现。
- **关键能力**：设定条目全量注入、事实抽取带出处、伏笔追踪、一致性校验。
- **12 维速评**：世界观 `条目化` ｜ 设定卡 `中` ｜ 关系·时间线·地图 `弱/弱/无` ｜ 流派模板 `弱` ｜ AI 注入 `强（全量注入）` ｜ 一致性 `中（事实/伏笔）` ｜ 本地优先 `强（自托管）` ｜ 版本防丢 `中` ｜ 中文网文 `中` ｜ 插件 `弱` ｜ 许可/定价 `开源 / 免费`
- **可借鉴**：**「事实抽取 + 带出处 + 伏笔追踪 + 校验」**的组合，是御书记忆分层（事实级记忆带出处）与伏笔台账（F08）的现成对标；证明中文一致性校验可落地。
- **不照搬**：设定**全量注入**不具备 Token 预算与分层（御书要做「核心常驻 + 别名触发 + 分层摘要」）；且其校验只覆盖有限事实类型，未达跨层（战力/时间线/称呼）。

### 2.10 Closure / 可露希尔（开源）

- **定位**：开源、本地优先的 AI 小说创作 IDE，是御书最接近的直接竞品。
- **关键能力**：人物卡 + 世界观资产卡 + 本地项目 + AI 辅助创作。
- **12 维速评**：世界观 `条目化（弱分层）` ｜ 设定卡 `中（人物卡/资产卡）` ｜ 关系·时间线·地图 `弱/弱/无` ｜ 流派模板 `无` ｜ AI 注入 `中` ｜ 一致性 `中（有限）` ｜ 本地优先 `强` ｜ 版本防丢 `中` ｜ 中文网文 `中` ｜ 插件 `弱` ｜ 许可/定价 `开源 / 免费`
- **可借鉴**：**「本地优先 + 人物卡 + 世界观资产卡」**的产品形态直接验证了御书的核心假设；其多视图 IDE 布局可作 UI 参照。
- **不照搬**：世界观资产卡**平铺不分层**，没有起源→法则→文明的自上而下依赖链，也没有影响传播；御书必须在「分层 + 传播 + 派系包」上做出代差。

### 2.11 Fantasia Archive（GPL-3.0）

- **定位**：100% 免费离线的世界构建工具，侧重「信息之间的关系」而非写作本身。
- **关键能力**：数十套模板 + 双向关系 + 项目级搜索；完全离线。
- **12 维速评**：世界观 `实体化（分层模板）` ｜ 设定卡 `强` ｜ 关系·时间线·地图 `强/中/无` ｜ 流派模板 `中（模板组合）` ｜ AI 注入 `无` ｜ 一致性 `弱` ｜ 本地优先 `强` ｜ 版本防丢 `中` ｜ 中文网文 `弱` ｜ 插件 `弱` ｜ 许可/定价 `GPL-3.0 / 免费`
- **可借鉴**：**离线免费 + 大量类型化模板 + 双向关系**，证明「重度世界构建可以完全本地」。其模板组织方式可作御书设定卡 schema 库的参照。
- **不照搬**：与世界构建分离的「写作工具」定位——御书要写作与设定同源，世界即创作现场，不能做成两个应用。

### 2.12 Azgaar's Fantasy Map Generator（开源，宽松许可）

- **定位**：程序化幻想地图生成器，分层数据模型的工程范本。
- **关键能力**：Voronoi 程序化生成；`world / generators / editors / renderers` 四层架构；输出 PNG/SVG/JSON 全量世界状态；200+ 参数。
- **12 维速评**：世界观 `强（地理层）` ｜ 设定卡 `中` ｜ 关系·时间线·地图 `弱/弱/强` ｜ 流派模板 `无` ｜ AI 注入 `无` ｜ 一致性 `弱` ｜ 本地优先 `强（纯前端）` ｜ 版本防丢 `中（JSON 导出）` ｜ 中文网文 `无` ｜ 插件 `弱` ｜ 许可/定价 `开源 / 免费`
- **可借鉴**：**四层分离管线（生成→编辑→渲染）**是御书世界引擎「生成→手工微调→再生成不回退手工结果」的直接工程参照；**JSON 全量世界状态导出**佐证「世界可序列化迁移」。
- **不照搬**：地图是独立产物而非世界的一部分；御书地图是地点的投影（图钉↔条目双向绑定），不是终点。

### 2.13 开源阵营小结

- 强项集中在：**本地优先、开放格式、纯文本/Git、插件生态、AI 注入机制**。

## 6. 市场空白与御书差异化结论

### 6.1 六项差异化的逐条空白验证

1. **世界分层构建**
   - 最接近者：World Anvil（25+ 模板）、Campfire（18 模块）、Fantasia Archive（分层模板）。
   - 空白点：三家的分层是**模板集合**，不是**依赖链**；没有「起源→法则→地理→生态→历史→文明→人物→故事」的推演顺序，也无法用一套模型统一表达都市与玄幻（docs/01 §2.3）。
   - 判定：**无竞品做「可推演的分层世界模型」，御书独占。**

2. **设定影响传播**
   - 最接近者：无。World Anvil/Campfire 修改一个模块不影响另一个；Azgaar 有生成管线但不传播设定语义。
   - 空白点：修改上游设定后自动列出下游受影响实体并逐项确认，在 30 家中**没有任何一家提供**。
   - 判定：**完全空白，是御书世界引擎的第一号差异化。**

3. **一致性校验**
   - 最接近者：show-me-the-story（事实/伏笔校验）、Closure（有限校验）、bibisco（人物出场分布）。
   - 空白点：**跨层**校验（等级战力 / 时间线冲突 / 人物-历史矛盾 / 称呼漂移）无一家覆盖；其余工具都只把结构化设定当作「供作者自查的资料」。
   - 判定：**能力空白区，对应 D03/J07/G06 已有的规则 DSL 与校验规则集。**

4. **全流派派系包**
   - 最接近者：Plottr（40+ 结构模板）、Campfire（10+ 模板）、Scrivener（项目模板）。
   - 空白点：全部只是「结构模板/骨架」，**不含 schema 扩展、校验规则、爽点节拍、术语表、雷点清单、平台映射**；没有任何一家的流派配置可插拔、可导出、可社区分享。
   - 判定：**无竞品，对应 G06 派系包 YAML 与 schema 扩展点。**

5. **AI 合规证据链**
   - 最接近者：无。Sudowrite/NovelCrafter/NovelAI 都在强化 AI 生成能力，却不提供「人类创作证明」。
   - 空白点：编辑轨迹留存 + AI 使用记录 + 一键生成平台申报材料，**30 家中零覆盖**；而中文平台已开始关注 AI 使用政策（I07）。
   - 判定：**空白且随监管趋紧而升值，御书独占。**

6. **本地数据主权**
   - 最接近者：novelWriter / manuskript / Closure / Fantasia Archive / 小黑屋 / 妙笔（本地纯文本或本地库）。
   - 空白点：开源侧有本地纯文本但**没有世界引擎与一致性**；商业侧有世界引擎却**云端锁定**（World Anvil/Campfire/LegendKeeper）；中文侧有本地但**数据格式封闭**。**「本地 Markdown 真源 + 可重建 SQLite 索引 + 分层世界引擎」的组合无一家具备。**
   - 判定：**部分具备，组合空白**。

**总判定**：六项差异化中，②③④⑤为「完全空白」，①⑥为「组合空白」。这正面回答了 docs/01 §1 的论断——没有任何单一竞品同时覆盖六项，御书做的是**组合式差异化**，风险不在「功能没人要」，而在「组合的工程复杂度」。

### 6.2 各家「明确不应照搬」清单（设计评审检查项）

| 竞品 | 明确不应照搬 | 理由 |
|---|---|---|
| Obsidian | 插件生态复杂度、核心能力外包给插件 | 普通作者配置门槛高；御书内核必须自带世界引擎与一致性 |
| World Anvil | 云端强绑定 + 重量级模板（表单恐惧） | 数据主权风险；改为少量必填 + 渐进披露 |
| Campfire | 模块并列而非分层依赖 | 模块间必须能上游→下游传播 |
| LegendKeeper | 用「可导出承诺」对冲云端锁定 | 御书把承诺变成事实：本地真源、离线可用 |
| Scrivener | 中文网文不适配 + 高学习曲线 | 自动分章/一键排版/敏感词/统计须默认内置 |
| Plottr | 只做结构模板不做流派语义 | 结构 ≠ 派系包（缺 schema/规则/节拍/平台映射） |
| Sudowrite / NovelCrafter / NovelAI | AI 默认开启、以代笔为核心、无人类创作证据 | 与作者合规诉求冲突；御书 AI 默认可关 + 证据链 |
| SillyTavern | 设定无出处/无可见性/无版本的注入堆 | 御书设定卡必须记来源、设可见性、可审计 |

| SillyTavern / Ulysses / Obsidian | 订阅型增值与云端版本历史依赖 | 御书版本历史落本地文本，可 Git 化 |
| 橙瓜 / 妙笔 / 小黑屋 | 云优先与封闭生态、无开放格式 | 学工作流，不学锁定；数据须可无损带出 |
| 阅文 / 番茄作家助手 | 平台生态内闭环 | 御书只做格式适配与自查，不替平台发布 |
| 墨者写作 | 依赖云服务的商业模式 | 停运即书稿风险，反证本地优先 |
| Vellum | 只管排版、与创作过程断裂 | 御书导出是世界与正文的自动汇编 |

## 7. 对 03 / 04 的输入结论

### 7.1 对 docs/03-开发规划方案 的架构启示

1. **世界引擎必须是内核一等公民**（对齐 §6.1 第 1、2 项）：需提供 World 根实体 + 分层依赖图 + 变更影响传播算法 + 用户逐项确认机制，参照 Azgaar 的「生成/编辑/渲染」三层分离，保证「生成→手工微调→再生成不回退手工结果」。
2. **一致性引擎要与世界引擎同级**（对齐 §6.1 第 3 项）：规则分类至少覆盖战力/时间线/历史矛盾/称呼漂移四类，直接吸收 D03 战力防崩塌 DSL、F04 POV lint、F08 伏笔生命周期、F12 结局回收义务。
3. **派系包规范以 G06 YAML 草案为准**（对齐 §6.1 第 4 项）：必须含世界预设 + schema 扩展 + 校验规则 + 写作节拍 + 爽点模式 + 术语 + 雷点 + 大纲模板 + 平台映射 + 演化版本，不得另起格式。
4. **记忆系统吸收三套注入机制**（对齐 §6.1 第 5 项）：NovelAI/SillyTavern 的关键词/常驻/预算/插入顺序 + NovelCrafter 的别名提及与 Progressions + show-me-the-story 的事实带出处；在此之上做「核心常驻 + 别名触发 + 分层摘要 + 上下文预览器」。
5. **数据层必须证明「可重建」**（对齐 §6.1 第 6 项）：Markdown/YAML 为真源，SQLite 仅索引，随时可从文件重建；参照 Logseq 的 SQLite + isomorphic-git 组合验证可行性。
6. **AI 证据链需要一个专门模块**：记录 AI 调用、采纳/拒绝、编辑轨迹，并支持一键导出平台申报材料；是 03 中容易漏掉但差异化最强的模块。
7. **中文工作流作为默认层而非插件**：自动分章、一键排版（GB/T 15834 / W3C clreq）、敏感词分平台自查、取名助手、有效字数口径，参照橙瓜/妙笔。

### 7.2 对 docs/04-开发计划 的优先级启示

- **M1 世界基座 MVP 优先做**：World 分层模型 + 影响传播 + 最少 5 张设定卡 + 三级大纲 + 派系包（先做「男频+玄幻+系统流」一包打样）+ AI 第一章生成 + TXT 导出与敏感词自查。这与交接文档 §6.3 的 M1 验收场景一致。
- **M2 补本地数据层**：Markdown 真源 + SQLite 可重建索引 + 自动保存四层防线 + 中文排版与分章。
- **M3 上 AI Provider 与记忆分层**：Provider 能力矩阵 + 注入预算 + 上下文预览。
- **M4 做一致性引擎 + 伏笔 + 时间线 + 关系图谱**：这是差异化兑现的关键里程碑，且已被验证为「无竞品」。
- **M5 做地图 + 派系包工坊 + 导入导出 + 平台适配**，**M6 做插件生态 + 云备份（可选）+ v1.0**。
- **风险提示**：组合式差异化的主要风险是范围蔓延；派系包与一致性引擎应尽早用「一个流派 + 一套规则」跑通闭环，再横向扩展流派数量。
