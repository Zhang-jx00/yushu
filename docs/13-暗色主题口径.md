# 暗色主题口径（docs/13）

> **本轮只记口径，不动色板**（R116）。默认色板的**每一个取值都逐字未变**——
> 判据里有一张基线表钉着，改一个色值就红。
> 真正的暗色色板是**下一轮**的事；这一轮先把"换主题时该动哪里、哪些绝不能动"写清楚。

## 0. 为什么先记口径

暗色主题最常见的失败不是"颜色不好看"，而是**改着改着，把纸墨色系的语义改没了**：
纸（底）反成了纯黑、墨（字）反成了纯白 ⇒ 界面看着"暗"，但那种**纸上的墨**的感觉没了，
而御书是作者每天坐八小时的写作工具，**底色不能变成一块发光的屏幕**。

所以规矩是：**先定"哪些东西必须保留"，再定"颜色怎么换"**。

## 1. 令牌分两层（这就是"暗色时该动哪里"的答案）

| 层 | 名字 | 职责 | 换主题时 |
|---|---|---|---|
| **primitive（调色板）** | `--c-paper` / `--c-ink` / `--c-accent` / … | 只说"这是什么颜色" | **只改这一层** |
| **semantic（用途）** | `--bg` / `--panel` / `--ink` / `--muted` / `--accent` / … | 只说"用在哪" | **一个字都不动** |

`semantic` 全部写成 `var(--c-*)` 引用 ⇒ 换主题时改 21 个 primitive，
那一整套用途（`--bg` / `--panel` / `--ink` / `--muted` / `--accent` / `--bad` / …）自动跟着变。

**已有的先例**：Windows 高对比模式（`prefers-contrast: more`）现在覆盖的也是 primitive 一层
（改版前它覆盖的是 semantic 一层）—— 同一个道理：覆盖点集中在一处，才不会漏掉某个用途。

## 2. 换暗底时**不能直接反相**的三样东西

1. **纸（`--bg` / `--panel` / `--panel-2`）**：不是纯黑。是**深一档的纸**——
   纸墨体系的底色关系（纸比面板浅、面板比凹陷深）必须保留，否则层次全丢。
2. **墨（`--ink`）**：不是纯白。纯白在深底上会"发亮"，长时间阅读刺眼；
   应该是**偏暖的浅色**（纸上的淡墨）。
3. **朱（`--accent` / `--accent-soft`）**：强调色在深底上要**降饱和、提亮**，
   但不能变成高饱和的荧光色——御书的朱是**落款印**的颜色，不是警示灯。

## 3. 对比度底线

- 正文（`--ink` on `--bg`）与次要文字（`--muted` on `--bg`）：**都要 ≥ 4.5:1**
  （正文级对比度，WCAG AA）；大标题与图标可 ≥ 3:1。
- `--muted` 是低对比色，**不许承载只有它可读的关键信息**（契约 §6 已有这条，继续有效）。
- 描边（`--border`）在深底上要**比纸更亮**（不是更深）——深底上"更深的描边"等于看不见。

## 4. 与「高对比模式」的区别（别把两件事混了）

| | 触发条件 | 目的 | 对色板 |
|---|---|---|---|
| **高对比** | 系统开了「高对比度」（`prefers-contrast: more`） | 让**视力不佳的作者**看清界面 | 覆盖 **primitive**，只加深对比 |
| **暗色主题** | 作者自己选（未来的 `data-theme`） | 夜里写作 | 覆盖 **primitive**，换一整套暗色值 |

两者都是"覆盖 primitive 一层"，但**目的不同、不能互相替代**：
高对比不换色相（仍是纸墨，只把对比拉满）；暗色换的是纸的明度，不是把纸换成黑。

## 5. 什么时候才动色板（下一轮）

- 先有**暗底下的对比度实测**（不是凭感觉）；
- 再改 primitive 的值，**semantic 一行都不动**；
- 改完要有一张**逐页截图对照**（与默认档同一屏），
  以及一条"默认档取值逐字未变"的基线锁（现在就已经有了）。

## 6. 本轮明确没做的

- 暗色色板的**具体取值**（下一轮）；
- 作者可切换的开关（`data-theme` 属性与 UI）——开关没有口径就没意义；
- **默认色板一个像素都没动**（本轮的全部产出就是这两层结构 + 这份口径）。
