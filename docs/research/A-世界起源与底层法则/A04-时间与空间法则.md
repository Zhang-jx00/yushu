# A04-时间与空间法则

> 类别：[A-世界起源与底层法则] ｜ 世界构建金字塔层级：[L0 起源层]
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

本领域研究虚构世界中时间与空间的"制度层"与"规则层"：历法体系（年月周的划分、闰法、纪元、节日锚点）、时间的不均匀性（不同世界/位面之间的时间流速差）、空间的结构（位面间的相对位置与通行方式——只做单世界的规则侧，多世界整体架构归 A07）以及叙事所需的时间坐标系（故事内事件应能换算为统一时间轴）。它回答"世界如何计时、事件如何定位"：没有可换算的时间轴，编年史与多线叙事必然失序；没有明确的时间流速规则，跨位面/跨世界剧情就会出现"回来时女儿已白发"式的失控。与 A03 的区分：A03 管"自然有多厚"，本领域管"时间与位置如何度量"；与 A08 的区分：本领域是设定事实，A08 是把时间信息按节奏透露给读者。

## 2. 核心知识框架

1. **历法设计的参数空间**：Fantasy Calendar 与 donjon 等工具把历法拆解为——月长与月数、周长与周名、闰日/闰周规则、多月亮的月相周期、季节定义、纪元切换点。RJD20 的教程强调"先理解地球历法为何如此（天/月/年的天文来源），再决定你的世界哪些参数要改"。
2. **历法即世界观数据**：Reactor 的《Counting the Days》梳理了五类 SFF 计时方案（从 Le Guin 的历法 Appendix 到 Glen Cook 的模糊纪年），指出历法不只是装饰——播种季、节日、契约期限都是情节驱动器；LegendKeeper 把自定义历法与 Chronicle/Gantt 时间线视图做成三联，证明"历法数据 + 时间线渲染"是可产品化的组合。
3. **多月亮与复杂周期**：RPG.net 社区给出用电子表追踪三个月亮相位的方法（参照火星卫星、泰坦周期）；Fantasy Calendar 支持多月亮条件事件——月相可以作为故事内的"魔法潮汐"或预言触发器。
4. **时间流速差的文化母题**：妖精国度时间与人间不同步是凯尔特民俗的核心母题——Spooky Scotland 记录的 Thomas the Rhymer 在地下七年"人间感觉或三年或三夜"；TV Tropes "Land of Faerie" 条目系统收录了该 trope 的方向性（那边一刻=这边一年，或相反）与代价（归来即老、换子 changeling）。D&D 的 Feywild 也继承了"时间不可靠"设定。
5. **时间流速需要显式规则**：社区实践共识是：流速差本身可以模糊（梦一样），但凡角色往返穿越，作者必须私下决定换算比与稳定性（每次是否相同），否则无法维持续作一致性——这适合做成"作者必答、读者不可见"的字段。
6. **纪元与历史分期**：Wrede 问卷要求作者写明历史分期与其间的技术/政治变迁，防止"千年停滞的中世纪"；纪元切换点通常锚定重大事件（创世/灾变/王朝更替），是历法与历史两套数据的连接键。

## 3. 可转化为产品规则的关键实践

1. 历法参数化 → 实体 `Calendar`：month_lengths[]/week_cycle/leap_rules/moons[]/epochs[]，全部可配置并可导出换算函数。
2. 日期为结构化字段 → 所有事件实体的 `date` 用 `{calendar_id, epoch, year, month, day}` 结构而非自由文本。
3. 时间流速登记表 → 实体 `TimeFlowRule`：`world_a`/`world_b`/`ratio`/`stability`（恒定/波动）/`author_notes`（读者不可见）。
4. 月相作为可查询资源 → 由 `moons[]` 参数自动生成任意日期的月相，供仪式/预言场景调用。
5. 节日绑定历法 → `Festival` 实体必须引用某 Calendar 的具体日期或周期规则，禁止"悬空节日"。
6. 纪元切换校验 → `epoch` 边界必须挂至少一个 `EpochEvent`，纪元名不得凭空出现。
7. 流速差往返校验 → 场景含跨域往返时，自动用 TimeFlowRule 换算两侧年龄/季节并提示矛盾。

## 5. 对御书设计的启示

**数据结构建议**
- `Calendar`（如上）+ `Epoch`（`name`/`start_event_id`/`end_event_id`）+ `TimelineEvent`（`calendar_date` 结构化、`precision`（年/月/日/时刻）、`perspective_calendar`（不同文明可用不同历法记同一事件，需 `equivalence` 映射））。
- `TimeFlowRule` 含 `ratio`（如 1:7）与 `stability`；跨世界/位面场景实体的 `entered_at`/`exited_at` 双时间戳分别记录两侧时间。

**功能建议**
- 历法编辑器：可视化配置月长/闰法/多月亮，实时渲染年视图与月相。
- 双时间轴视图：故事时间轴与世界历史轴并排，写作时悬浮显示"今天是某历某纪某年某月某日，月相 X"。
- 时间换算器：输入 A 世界经过时长，自动输出 B 世界经过时长与季节变化。

**校验规则建议**
- 日期合法性：事件的月/日必须存在于所引用 Calendar（含闰日规则）。
- 时序矛盾检测：同一 `perspective_calendar` 下，后发生事件的日期早于先发生事件 → 阻断警告。
- 流速未登记警告：场景中出现跨域往返但无对应 `TimeFlowRule` → 提示"请先决定时间换算"。

**AI 提示词建议**
- 生成涉及月相/节日的场景时注入："今日为 {calendar_date}，月相={phase}，节日={festival?}，描写中的天象必须一致。"
- 生成跨域往返情节时注入换算规则并要求 AI 在输出中显式写明两侧流逝时间。

## 6. 领域内子主题备忘（可选）

- 时间旅行规则（单时间线自洽/分支/不可改）的参数化——与 A07 分支世界衔接。
- 不同文明历法间的换算与"历法外交"（条约日期以何方历法为准）。
- 空间规则侧：传送门拓扑（谁能过/代价/稳定度）的最小字段集。
- 寿命参数（各族寿命差）与时间感差异对叙事节奏的影响。
