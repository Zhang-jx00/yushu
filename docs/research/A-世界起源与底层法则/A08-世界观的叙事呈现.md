# A08-世界观的叙事呈现

> 类别：[A-世界起源与底层法则] ｜ 世界构建金字塔层级：[L0 起源层 + 叙事层交叉]
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

世界观的叙事呈现研究"设定以什么节奏、什么载体、什么顺序抵达读者"：信息投喂的总量控制（冰山原则——展示十分之一）、信息差工具（悬念 vs 惊奇、桌下炸弹）、展示手法（行动/对话/物件中的世界，而非说明书式 infodump）、视角过滤（只写 POV 角色会注意的东西）以及网文场景的章级投喂节奏（每章钩子与回报）。它是起源层设定（A01-A05）与读者体验之间的转换器：同样一套设定，投喂节奏的好坏决定"宏大深邃"还是"设定轰炸"。与 A06 的区分：A06 管"事实不矛盾"，本领域管"事实何时露面"。边界内还包括：伏笔的埋设与回收节奏、信息可见性矩阵、新手章（第一章）的世界信息配额。

## 2. 核心知识框架

1. **冰山原则**：GRRM 的"九分之十在水下"与托尔金式内功表明——作者掌握的设定量远大于文本呈现量，呈现的是"可感知的露出部分"；Sanderson 第一定律从另一侧约束投喂：读者对某个魔法/规则的理解程度决定它能否承担解决冲突的功能，因此"揭示"必须先于"用它解扣"。
2. **信息差理论**：希区柯克"桌下炸弹"（Nevala-Lee 记录）区分 surprise（观众不知道炸弹）与 suspense（观众知道而角色不知道）；Bordwell 的学术梳理（借莱辛《拉奥孔》的"可见的恐怖 vs 想象的恐怖"之辨）说明信息差的结构史。应用到世界观：有些设定应该先给读者"上帝视角的预警"制造悬念，有些应该藏到最后一刻制造惊奇——需要逐条决策。
3. **契诃夫之枪与伏笔节奏**：维基条目确立"叙述过即须兑现"的期望管理；Writing Stack Exchange 的实践讨论（如何藏枪、red herring 与枪的边界）把节奏问题精确到"埋设章与回收章的间隔控制"。
4. **反 infodump 手法集**：Savannah Gilbo 的五法——只保留"真正为故事干活"的设定、把信息织入叙事而非整块倾倒、通过角色行为戏剧化规则（在边界犹豫而非讲述禁令）、POV 过滤、以冲突呈现规则；BTL/写作社区的补充共识：纯说明不超过一两句就要回到场景；"As you know, Bob"式对白是高危反模式。
5. **叙事学的投喂坐标**：Genette 结构叙事学（时序/时距/频率/语式/语态）提供理论坐标——"语式"（信息调节）正是世界观投喂的形式化描述；网文方法论（webnovel-handbook 的"每章承诺-进度-回报-钩子"）则把投喂节奏压到章级：每章至少给出一点世界信息作为回报，章尾钩子常是新信息预告。
6. **配额思维**：综合社区经验，第一章的世界信息配额应最少（读者尚未建立锚点），随剧情推进逐步放大；"设定为故事干活"是每一条信息准入的判据。

## 3. 可转化为产品规则的关键实践

1. 信息可见性矩阵 → 每条设定维护 `reveal_state`（未揭示/预告/已揭示/已回收）与 `reveal_chapter`，形成全库投喂台账。
2. 揭示先于使用 → 校验：某能力/规则被用于解决冲突的章节必须晚于其 `reveal_state=已揭示` 的章节（Sanderson 第一定律的 lint）。
3. 伏笔双时间戳 → `planted_chapter`/`payoff_chapter`，间隔与未回收提醒（可设类型：枪/red herring）。
4. 信息密度计 → 统计每章"新设定条目首次揭示数"，超过阈值（如 3 条/章）警告"设定轰炸"。
5. POV 过滤检查 → 场景卡的 POV 字段与所引用设定的 `knowable_by`（谁能知道）比对，越权揭示提示。
6. 钩子登记 → 章卡必填 `hook` 字段并允许挂"新信息预告"引用，网文模式强制。
7. 悬念/惊奇开关 → 情节节点可选 `info_strategy`（suspense：读者先知；surprise：读者后知），驱动大纲与文本一致性检查。

## 5. 对御书设计的启示

**数据结构建议**
- 设定条目增加叙事层字段：`reveal_state`、`reveal_chapter`、`knowable_by[]`（哪些角色/势力知道）、`info_strategy`（suspense/surprise/背景）。
- `Chapter` 卡增加：`new_reveals[]`（本章首次揭示的设定引用）、`hook`（文本+引用）、`info_density`（自动统计）。
- `Foreshadowing` 实体：`type`（gun/red_herring）、`planted_chapter`、`payoff_chapter`、`status`。

**功能建议**
- 投喂时间线视图：横轴为章节、纵轴为设定条目，格子标记揭示事件——一眼看出哪些设定从未露面（"水下入水"分布）。
- 写作模式水线：正文编辑器只自动展示 `reveal_state<=当前章` 的设定详情，未揭示项仅显示标题（防 AI/作者误泄）。
- 章末体检：完成后自动生成"本章新揭示清单 + 钩子确认 + 超期伏笔"三段式检查。

**校验规则建议**
- 解扣先于揭示 → 阻断级警告（本章用未揭示规则解决冲突）。
- 单章新揭示数 >3 → 警告"信息密度过高"。
- `knowable_by` 不含当前 POV 角色 → 警告"越权揭示"。

**AI 提示词建议**
- 续写注入："本章可揭示的设定（按投喂计划）：{allowed_reveals}；以下设定已存在但禁止直接解释：{hidden}。请用行为/对话/物件展示，禁止整段说明。"
- 章节生成后自查提示词："列出本章中每条世界观信息的呈现方式（叙述/对白/动作），标记任何超过两句的纯说明段。"
