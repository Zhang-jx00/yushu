# A06-世界观一致性方法论

> 类别：[A-世界起源与底层法则] ｜ 世界构建金字塔层级：[L0 起源层 + 叙事层交叉]
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

世界观一致性方法论研究"设定与设定之间、设定与已发布文本之间如何长期保持不矛盾"的管理学：硬设定与软设定的区分、正典（canon）的版本管理、连续性（continuity）追踪、一致性检查的时机与工具、以及设定未写明时的裁决规则。它横跨起源层与叙事层：设定库（L0）是真相源，已发布的章节正文（叙事层）一旦定稿也成为不可回改的事实，两者冲突时需要明确的优先级规则。与 A05 的区分：A05 关注设定层内部的推导逻辑，本领域关注"事实台账"层面的防错机制（角色眼睛颜色、时间线、地点名、已述规则）与跨章节、跨卷、跨作品的长期一致性。与 A09 的区分：A09 研究如何编撰世界圣经这个"文档"，本领域研究其中的治理规则。

## 2. 核心知识框架

1. **冰山原则与设定分层**：GRRM 在 Rolling Stone 访谈中自述"托尔金 inside out、我 outside in"，并引"冰山九分之十在水下"——作者知道的远多于展示的。方法论推论：设定条目应区分"已展示给读者"与"仅作者可见"两种状态；水下部分可以随时修正，水上部分（已发布）不可。这是"硬/软"之外更可操作的一层划分。
2. **硬设定 vs 软设定**：结合 Sanderson 律法视角——已向读者明示、承担解冲突功能的规则（如能力代价）是硬设定，一经发布即成铁律；氛围性、未解释的设定（软设定）允许后续细化但不得反向矛盾。工具层面的对应物是"字段锁定"：正文提及即锁定。
3. **故事圣经作为事实台账**：Scryla 区分 story bible（保持叙事一致的事实参考）与 worldbuilding bible（世界如何运作的参考）；BlurbBio 提出八节结构与"五分钟防错习惯"（每写完一章立即回填台账）；PlotForge 强调系列圣经的四习惯与"Google Docs 为何会失败"（无结构、无校验、无回溯）。
4. **连续性追踪的实务**：r/writing 的长篇作者共识是 5 万字以后靠记忆必然崩溃，需要外部系统；Scrivener 论坛案例同时警示反向风险——"先造圣经再硬套故事"会变成兔子洞，圣经应服务于正在写的故事（Writing Excuses 5.34 同样强调 worldbuilding 必须匹配 story）。
5. **契诃夫之枪作为一致性公理**：维基条目与写作社区把"台上的枪必须响"扩展为事实管理规则——一旦某设定在文本中"上膛"（被叙述），台账必须记录，后续要么兑现要么有意反转（red herring 需显式标记）。
6. **正典分层**：成熟系列（如 D&D 各版本、Comics）的经验是正典可以分层（核心正典/扩展/废案），工具需支持"版本化正典"而非单一真相平面——Notion 系列圣经模板与 D&D 社区的版本演化都证明了这一点。

## 3. 可转化为产品规则的关键实践

1. 双状态字段 → 每个设定条目含 `visibility`（作者可见/已向读者揭示）与 `locked`（已被发布正文锁定）。
2. 正文引用即锁定 → 从章节文本中提取到的设定提及自动置 `locked=true`，再修改需走"正典变更"流程。
3. 逐章回填提醒 → 每章标记完成后生成"本章新事实清单"待确认，确认后写入圣经（BlurbBio 五分钟习惯）。
4. 矛盾检测器 → 对新章节文本与圣经做实体级比对（人名/地名/日期/规则引用），输出冲突 diff。
5. 契诃夫台账 → 伏笔实体含 `planted_chapter`/`paidoff_chapter`，超期未回收提醒；red herring 显式标记防误报。
6. 正典版本层 → 圣经支持 `canon_version`（核心/扩展/废案/平行世界），可按卷切换有效正典集。
7. 圣经服务故事的护栏 → 每条设定的 `story_refs[]` 为空超过 N 章时提示"未服务任何故事的设定，考虑冻结"。

## 5. 对御书设计的启示

**数据结构建议**
- 全实体通用元数据：`visibility`（waterline 水线字段）、`locked`、`locked_by_chapter[]`、`canon_version`、`story_refs[]`。
- `CanonChange` 事务实体：`target`/`old_value`/`new_value`/`reason`/`approved`——锁定字段的修改必须生成事务记录（正典变更留痕）。
- `ContinuityFact`：从正文中抽取的原子事实（"第三章：主角左眼为灰"），外链设定条目，构成正文↔圣经的双向索引。

**功能建议**
- 水线视图：设定库按"已揭示/未揭示"过滤，写作模式默认只展示已揭示+本章计划揭示项（与 A08 衔接）。
- 逐章回填面板：章节完成后弹出事实清单确认流，一键生成 ContinuityFact。
- 一致性体检：发布前跑全量检测（实体引用/日期/规则/称呼）并输出报告。

**校验规则建议**
- 锁定字段修改 → 必须走 CanonChange 审批，且提示历史章节受影响数。
- 正文出现圣经中不存在的专有名词 → 警告"未登记实体"（或建议新增）。
- 伏笔超期（planted 后 K 章未 payoff 且未标 red herring）→ 提醒。

**AI 提示词建议**
- 续写时注入："以下是本章可用的已揭示设定（locked）与作者私下设定（unlocked，禁止在文本中直接解释）：{facts}。"
- 检测任务提示词："对照圣经逐句检查本章，输出 {事实, 圣经条目, 冲突描述, 置信度} 列表，宁报勿漏。"
