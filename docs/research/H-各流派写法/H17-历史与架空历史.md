# H17-历史与架空历史（历史正剧 / 穿越历史 / 架空王朝）

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

历史维流派覆盖三类写法：历史正剧（在真实朝代框架内叙事）、穿越历史（现代人重回历史改写走向，金手指手法归 H14）、架空历史（自建王朝但沿用历史运作逻辑）。docs/05 §2 已有"历史"世界维条目（史实约束、改革种田、权谋；雷点=史实硬伤、古人言行现代化），本文档深入该流派专属知识：史实与虚构的边界管理、朝代制度考据、架空世界的"淘洗历史"方法。核心共识（社区研究帖）：**穿越是重新进入历史，架空则是淘洗历史——洗尽装扮历史的金粉，留下支撑历史的骨头**——即架空小说中具体史实只是装饰，真正需要考据的是制度、经济与社会规则的运作逻辑。"七分骨架考据，三分血肉虚构"是本流派的边界公式。与 H16 的区分：历史文常带种田基建元素，但本文档侧重历史真实性层（考据/称谓/官制），经营手法归 H16。

## 2. 核心知识框架

1. **历史文光谱**：穿越救亡流（改写历史走向，爽点在改变）、历史正剧流（嵌入真实事件，爽点在代入与谋略）、架空流（自建王朝，爽点在"历史逻辑的真实感"）。网络文学叙事研究（中国作家网/搜狐转载）：网文中的历史是"公众在真实史料与媒介虚构之间对传统的自发把握"，但纯情绪导向的古风写作被认为不够扎实——历史感的来源是制度与生活细节而非意象堆砌。
2. **马伯庸方法体系**（当代考据型写作范式）：①"历史可能性"写作——尊重历史大事实，在缝隙中用想象填补（人民网）；②"夹心饼干式"结构——虚构故事夹在真实历史事件之间；③微观视角——从办事小人物的角度切入大事件（长安的荔枝：具体是谁办、预算几何、协调几个部门）；④"以人性观照历史，从细节揣摩人性"，历史闪光藏于底层与小处（岳麓书会讲座）。这套方法把"考据"从学术负担转化为剧情引擎。
3. **考据的知识分层**：制度层（官制/科举/军制——阅文作家专区设"中国各朝代官制"系列科普，秦汉官制沿革等）、称谓层（避讳、自称、官称误用是高频硬伤）、生活层（服饰、饮食、货币购买力）、事件层（大事年表与因果链）。制度史专著（刘浦江辽朝国号考释、杨若薇契丹政治军事制度研究等）是高阶参考，说明辽金等冷门朝代有北面/南面官等易错点。
4. **架空的构建法**：架空≠随便编——用真实朝代做"骨架模板"（选一个组织度高的原型朝代移植其制度逻辑），再替换地理/国名/事件；红袖百科样本《大唐一刀999级》展示混合式：基于渭水之盟、门阀势力等真实框架，允许主角借系统改变走向（与 H15 系统卡联动）。架空的可信度=制度自洽+经济闭环+语言习惯统一。
5. **权谋与"规则显影"**：社区评论总结《奸臣之女》的手法——不直白阐释权谋概念，而是把规则物化为"可感、可触、可被人物反复碰撞"的具象存在（一件逾制的官服、一次不合礼的称呼）；好历史文的笔锋要冷静，"记录的事情要深刻，背后的得失逻辑要合理"。
6. **平台生态**：历史是起点传统大分类（历史-架空历史/秦汉三国/两晋隋唐等子分类），免费平台把它切分为"历史脑洞""穿越古代"等爽点向标签——同一流派在两类平台的写法差异（考据密度与节奏）需要在派系包做平台映射。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 朝代档案卡：原型朝代（真实或模板）/纪年/大事年表/当前历史偏移度 → 世界向导必备，穿越改写事件后偏移度自动累加。
2. 制度基线卡：官制结构/科举或选官方式/军制/税赋 → 权谋与升迁情节的合法性来源。
3. 架空模板选择器：从真实朝代模板（组织度/开放度/军事压力三轴）派生架空王朝 → "淘洗历史"的产品化。

**设定卡 schema 扩展（历史年表/史实-虚构边界标记）**
4. 历史年表卡（事件/纪年/史实性标注：真实/推演/虚构/已改写）→ docs/05"史实-虚构边界标记"的落地，所有事件四态标注。
5. 官制知识卡（官职/品级/职权/隶属/称谓规范）→ 称谓与升迁校验的依据。
6. 虚构边界卡（本章虚构内容/涉及的真实史实/冲突说明）→ 作者自声明+AI 续写继承。
7. 人物身份卡（历史人物：生卒/史实事迹/本作改动）→ 与年表卡联动，改写留痕。

**校验规则**
8. 时代一致性：出现晚于故事年代的官职/器物/作物/称谓 → error"时代硬伤"（如明写军机处、宋写内阁级别的规则库）。
9. 史实冲突：改动"史实性=真实"的事件但未同步年表偏移 → warn"历史分叉未登记"。
10. 称谓规范：称呼与身份/时代不匹配 → warn（依托官制知识卡）。
11. 架空自洽：架空王朝的税赋/军事规模与人口经济数据矛盾 → warn。

**写法指南与节拍**
12. 开局考据节拍：三章内建立时代锚点（纪年/在位者/都城/一餐饭的价格）——用生活细节替代设定倾泻。
13. 权谋节拍：规则显影（具体物件/礼制事件）→ 人物碰撞规则 → 代价与得失结算；避免人物开口讲制度课。
14. 改变历史节拍：小改动验证 → 蝴蝶效应登记 → 大事件偏移 → 新格局稳定；每卷结算一次偏移账。

**读者期待与雷点**
15. 期待=历史代入感/改变走向的爽感/权谋智斗/制度细节的"考据快感"/小人物撬动大时代；雷点=史实硬伤、古人言行现代化（口语/观念穿越）、金手指无代价碾压、主角以现代价值观傲视古人无反思、考据堆砌压过剧情 → taboos 清单。
16. 平台分化提示：付费端读者奖励考据密度，免费端读者奖励事件密度——同一年表卡支持两种提示词模板。

**AI 提示词倾向**
17. 续写状态块注入：当前纪年/在位者/已改写事件及偏移度/主角身份与称谓规范——防 AI 时代漂移。
18. AI 输出中涉及制度、称谓、器物的名词须回查官制知识卡与时代一致性规则，未登记名词标记为"待考据"而不是静默输出。

## 5. 对御书设计的启示

**数据结构建议：历史派系包核心卡 schema**

```yaml
# schemas/历史年表卡.yaml —— 史实-虚构边界的管理单元
extends: core/setting-card
fields:
  events:                        # 事件数组，四态标注
    - name: {type: string}
      year: {type: string}       # 本作纪年
      status: {type: enum, values: [real, inferred, fictional, altered]}
      divergence: {type: number} # 改写后偏移度（real 事件被改时累加）
  dynasty_profile: {type: ref}   # 朝代档案卡引用（真实或架空模板）
  official_system: {type: ref}   # 官制知识卡引用
```

配套：官制知识卡（office/rank/duty/superior/form_of_address）、虚构边界卡（per-chapter）、人物身份卡（历史人物改动留痕）。

**功能建议**
- 历史分叉视图：真实时间线（虚线）与本作时间线（实线）并列，复用 H14 蝴蝶效应视图，偏移度共享。
- 时代一致性检查器：内置各朝代"器物/官职/作物/称谓"出现年代索引（起步：官制系列科普数据化），可增量扩充。
- 架空模板生成器：按组织度/开放度/军事压力三轴从真实朝代派生架空王朝骨架。

**校验规则建议**
- `era-anachronism`：越代名词 → error（规则库按朝代索引）。
- `divergence-unsynced`：改写真实事件未登记偏移 → warn。
- `address-mismatch`：称谓与官制卡不符 → warn。
- `regime-economy`：架空王朝兵制/税赋与人口数据矛盾 → warn。

**AI 提示词建议**
- 状态块："纪年{year}，在位{ruler}，已改写{events}，偏移度{d}，主角称谓规范{rules}"。
- 名词回查指令：制度/称谓/器物名词未命中知识卡时输出"待考据"标记；提示词按平台分档（考据密集型/事件密集型）。
