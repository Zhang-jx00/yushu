# H19-娱乐圈与直播文（演艺圈 / 选秀综艺 / 网红直播 / 舆论博弈）

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

娱乐圈文是以演艺行业生态（影视/音乐/选秀/综艺/经纪/粉丝经济）为舞台的题材，爽点是"作品成名路径"与"舆论博弈打脸"；直播文是它的近亲变体：主角行为被直播/围观，弹幕与观众反应构成第二叙事层。docs/05 §2 已有"娱乐圈"世界维条目（作品成名路径、舆论博弈；雷点=行业逻辑失真）、§3 已有"直播流"手法条目（观众反应模板化雷点），本文档合并两者：娱乐圈文的知识底座是行业流程（剧组/番位/营销/平台），直播文的知识底座是围观机制（弹幕/切片/人气值/舆论发酵）。两条线共用"舆论场"这一核心装置——娱乐圈文的绯闻热搜与直播文的弹幕狂欢是同一机制的两档强度。频道分布以女频（晋江娱乐圈标签生态）与纯爱为主，男频多为"文娱+系统"复合。边界：游戏主播文的直播机制归 H18，本文档管娱乐圈直播与围观反应写法。

## 2. 核心知识框架

1. **流派底座：行业流程的真实性**。晋江官方写作指导（《网文写作指导总结》）给出好书六判据——文字通顺/题材新意/情节吸引/金手指亮点/人物鲜明/主线清晰；对娱乐圈文而言"金手指亮点"通常落在行业资源或系统加持上，而"行业逻辑失真"是最致命雷点：剧组流程、番位规则、平台购播、粉丝控评等细节决定可信度。近年趋势（中国作家网对《蓄意逐风》一类作品的评价）是"网感"强、爆梗频出——用真饭圈语汇写假娱乐圈。
2. **成名路径的节拍学**：娱乐圈文的主线骨架是"作品-声望"双螺旋：接作品（试镜/资源争夺）→ 作品播出（角色出圈名场面）→ 声望跃迁（奖/热搜/代言）→ 更大平台的作品。爽点单元=名场面出圈：一段表演、一首歌、一次救场被"观众视角"放大。复仇线（《你好，陆先生[娱乐圈]》：带目的入圈、拉人下马、身败名裂）与甜宠线（《和影帝前夫上恋综后》：恋综+破镜重圆）是两大情绪外壳。
3. **综艺/恋综子类**：综艺是近年最高频的场景装置——"上综艺暴露真实关系/真实性格"把多人物强制放进同一镜头场，天然适合群像与关系推进；恋综将感情线与围观弹幕直接绑定（全网嗑 CP/全网扒马），是马甲文+娱乐圈的天然杂交场景。
4. **直播文围观机制**：双视角结构=主角视角推进剧情+弹幕/观众视角提供即时反应（Scribd 收录的综英美容器样本展示弹幕与正文交织的典型排版：【弹幕骤然炸开】【平流层里怎么会有强对流天气！】）。弹幕承担三重功能：情绪放大器（震惊/打脸的共鸣腔）、信息差投影（观众不知道的真相形成期待感）、喜剧解压（吐槽役群体人格）。现实直播运营知识（切片引流/福利留人/话术节奏）是写直播文的第一手素材库。
5. **舆论博弈模板**：热搜事件的标准回合——黑料爆出 → 舆论发酵（甩锅/洗白/反黑）→ 证据反转 → 打脸结算（掉粉/掉代言/社死）；粉丝群体（唯粉/CP 粉/黑粉/路人）构成舆论棋局的棋子。马甲文机制（多重身份逐层揭开）在娱乐圈文中落地为"扒马"——扒皮马甲即舆论打脸的名场面。
6. **疲劳管理**：GitHub 网文写作手册的通用经验（重复打脸/机制重复致读者疲劳、连续三章压力递进）对娱乐圈文尤其重要——热搜-反转回合若模板化重复，需用新舆情载体（短视频/直播事故/颁奖典礼）与新对手类型破局；知乎作者经验谈强调"想写某类型文，先找近期成绩好的同类文精读、逐章记录情绪波动点、拆解节奏"。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 娱乐圈生态档案：经纪公司/平台/媒体/粉丝圈层的势力关系图 + 行业流程表（试镜-签约-进组-播出-宣发）→ 世界向导必备。
2. 舆论场档案：热搜机制/营销号/粉圈派系（唯粉/CP 粉/黑粉/路人）→ 舆论回合的棋子库。
3. 直播间档案（直播文）：平台规则/人气数值体系/切片与热搜联动 → 围观机制的坐标系。

**设定卡 schema 扩展（作品资源卡/直播间卡/舆论事件模板）**
4. 作品资源卡（作品名/类型/角色/档期/播出效果/口碑数据）→ 成名路径的登记单元，声望曲线的数据源。
5. 直播间卡（直播间名/人气值/粉丝构成/弹幕风格预设/切片记录）→ docs/05 直播流"直播间卡+弹幕反应库"的落地。
6. 舆论事件卡（事件/发酵阶段/各方立场/证据链/反转点/结算后果）→ 热搜回合的状态机。
7. 马甲-扒马清单（马甲身份/知情范围/暴露计划章）→ 复用 H-马甲文清单并与舆论事件卡联动。

**校验规则**
8. 行业流程校验：情节违背已登记行业流程（未签约即官宣主演/未播出即拿奖）→ error"行业失真"。
9. 声望连续性：声望/粉丝数/作品成绩跳变无事件支撑 → warn"数据穿帮"。
10. 弹幕信息差校验：观众/弹幕说出其不应知晓的信息（未直播内容/未公开身份）→ error"信息差穿帮"。
11. 舆论回合完整性：事件无反转证据链即强行打脸 → warn"打脸无源"。

**写法指南与节拍**
12. 成名路径节拍：入圈契机 → 首个作品（小角色名场面）→ 声望首跃 → 资源升级冲突（抢角/换角）→ 更大舞台；每卷一次"舞台升级"（网剧→电视剧→电影→奖）。
13. 舆论回合节拍：黑料引爆（章末钩子）→ 发酵与站队 → 反转证据 → 打脸结算；单回合 ≤5 章，连续回合必须更换舆情载体。
14. 直播围观节拍：主角行动 → 弹幕即时反应（≤3 条/千字）→ 人气值跳变 → 切片/热搜外溢；弹幕频率不得挤占正文推进。

**读者期待与雷点**
15. 期待=作品出圈名场面/舆论反转打脸/扒马名场面/群像嗑 CP/行业揭秘感；雷点=行业逻辑失真、观众反应模板化（清一色"卧槽"）、主角无来由资源碾压、反派反派化降智、感情线挤压事业线 → taboos 清单。
16. 频道侧重预设：女频/纯爱偏感情线+群像嗑糖，男频偏事业爽+系统金手指；感情线形态按 docs/05 §5 做独立开关。

**AI 提示词倾向**
17. 续写状态块注入：当前声望数据/在播作品/进行中的舆论事件阶段/直播间人气——AI 产出的热搜与弹幕须引用舆论事件卡与弹幕风格预设。
18. 弹幕生成按"知情范围"过滤：每条弹幕标注其信息来源（直播画面/切片/爆料），禁止越界剧透；名场面描写强制"作品内文本+观众反应"双栏输出。

## 5. 对御书设计的启示

**数据结构建议：娱乐圈/直播派系包核心卡 schema**

```yaml
# schemas/作品资源卡.yaml —— 成名路径的登记单元
extends: core/setting-card
fields:
  title: {type: string}
  type: {type: enum, values: [drama, film, song, variety, livestream]}
  role: {type: string}           # 主角在其中承担的角色/位次
  metrics:                       # 口碑数据（声望曲线数据源）
    popularity: {type: number}
    reputation: {type: number}
  milestones: {type: array}      # 出圈名场面（关联舆论事件卡）
```

配套：直播间卡（popularity/fans_mix/danmaku_style/clips）、舆论事件卡（stage/stances/evidence/reversal/fallout）、马甲-扒马清单。

**功能建议**
- 声望曲线面板：作品资源卡数据随章节推进绘制声望/粉丝双曲线，跳变自动溯源到事件卡。
- 舆论状态机视图：事件卡按"引爆→发酵→反转→结算"四阶段流转，超期未结算提示收束。
- 弹幕反应库：按情绪（震惊/嗑糖/护主/嘲讽）与知情范围双维标签，生成时按标签抽取组合。

**校验规则建议**
- `industry-flow`：违背行业流程 → error。
- `fame-jump`：声望数据无事件支撑跳变 → warn。
- `info-leak`：弹幕/观众越界知晓未公开信息 → error。
- `hype-no-source`：打脸无证据链 → warn。

**AI 提示词建议**
- 状态块："声望{p}/{r}，在播{works}，舆情阶段{stage}，人气{viewers}"；弹幕输出须带知情范围标注。
- 双栏名场面模板：作品内文本（表演/歌词/直播画面）+观众反应（弹幕/热搜词条）成对生成；按频道切换感情线/事业线权重。
