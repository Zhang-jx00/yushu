# H13-悬疑推理

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究以谜题（案件/阴谋/身世）为核心驱动的类型写法：本格解谜（whodunit）、温馨推理（cozy）、黑色/硬汉（noir/hardboiled）、警察程序（procedural）与中文语境的社会派，以及不设案件但以悬念结构推进的悬疑惊悚。核心工程约束是**公平性原则**——读者必须拥有与侦探同等的解谜信息，这使本流派成为唯一"校验规则可以形式化到近乎 lint"的流派。边界：心理恐怖向的悬疑归 H11；网文常见的"悬疑+灵异/系统"混搭只取其悬念机制；docs/05 §8.1 已有推理子类映射表，本文档补足线索工程与公平性校验侧。

## 2. 核心知识框架

1. **黄金时代公平性规范**：诺克斯十诫（Ronald Knox，1928/1929）与范·达因二十条（S.S. Van Dine，1928）共享一个激进内核——"读者必须有公平的解谜机会"：关键线索须呈现给读者、凶手必须前期登场、不得依赖超自然或科学无法解释的手段、秘密通道数量受限、侦探不得向读者隐瞒自己的推理。第五戒"不得有中国人登场"在中文网络存在大量误读与辟谣（NGA 专帖），引用时需注意语境。
2. **线索工程**：本格的正解=线索全公开+误导（红鲱鱼）的组合——平铺直叙展示线索，靠谜团设计让读者误入歧途（什么值得买书单归纳）；契诃夫之枪（Chekhov's gun）要求重要伏笔必须回收；红鲱鱼与契诃夫之枪的边界（Writing Stack Exchange）：误导线索自身也须合法、与真相有真实关联，不能是作者的作弊。
3. **悬念机制**：希区柯克"桌下炸弹"——观众知道炸弹在桌上而角色不知=悬念；双方都不知=爆炸只是惊奇（Alec Nevala-Lee 与 Bordwell 的学术梳理：悬念/惊奇的信息差概念史）。S2 关键发现"悬念=信息可见性矩阵"的直接理论源。
4. **子类谱系**（Darling Axe《Mystery Subgenre Guide》）：whodunit 重谜题公平、cozy 重小镇日常与弱暴力、noir/hardboiled 重宿命与道德暧昧（视角常在罪犯一侧）、procedural 重取证审讯卷宗的程序写实；社会派（中文语境）以案件折射社会结构，公平性约束放宽但逻辑自洽要求不减。
5. **谜团结构**：谜面（密室/消失/不可能犯罪）→ 调查与误导 → 解谜反转 → 解答篇；叙述性诡计是公平性的例外形态——利用叙事视角欺骗读者，但须在揭晓后"重读成立"（海猫/乱步诡计表语境的社区讨论）。
6. **中文网文语境**：悬疑与灵异、系统、规则怪谈混搭是主流形态；智斗与逻辑自洽本身即爽点；创作工具书（博客来引入的推理创作教程）总结"公平/不公平写法"与"理想伏笔埋设"为两大核心议题。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 案件时间线全局视图：凶手视角的真实事件序列与叙述视角事件序列分层存储 → 世界预设即"事实层"，正文是"叙述层"。
2. 侦探能力边界预设：本格包默认禁用超自然破案手段（对应诺克斯第 2 戒）→ 派系包能力清单。

**设定卡 schema 扩展（悬疑推理特有卡）**
3. 线索卡（clue：内容/发现章节/呈现方式[明示|暗示|隐瞒]/指向/是否红鲱鱼）→ 公平性校验的最小单元。
4. 人物嫌疑卡（suspect：动机/不在场证明/秘密/揭露顺序）→ 与关系棋局卡（H09）同构但字段偏"嫌疑权重"。
5. 诡计卡（trick：原理/所需条件/前置铺垫/公平性自检清单）→ 密室、不在场证明等核心诡计的档案化。

**校验规则**
6. 线索公平性：解答揭晓时所用关键线索必须在早前章节有"已呈现给读者"的记录（线索卡状态非隐瞒）→ error，本流派旗舰规则。
7. 红鲱鱼合法性：误导线索必须与真相有真实关联且自身可解释，纯天降误导 → error。
8. 时间线一致性：不在场证明、案发时刻、移动路径无矛盾 → error；伏笔未回收（契诃夫之枪）→ warn。

**写法指南与节拍**
9. 谜题三幕节拍：案发（谜面亮出）→ 调查与误导（每 3-5 章一个新证据或新疑点）→ 解答反转（解答篇逐条回收线索）。
10. 悬念注入模板：关键场景按"桌下炸弹"检查——读者是否比角色多知道一点？全书至少保留一条持续悬念线。

**读者期待与雷点**
11. 期待=公平竞猜/合逻辑反转/智斗快感/真相的情感重量；雷点=靠巧合或未公开线索破案、凶手为无名工具人、最后时刻引入新角色、超自然万能钥匙、红鲱鱼与真相无关 → taboos 清单。

**AI 提示词倾向**
12. 生成推理场景时注入线索矩阵（角色已知/读者已知/仅作者已知三层），要求 AI 的侦探推理只使用"角色已知"层信息。
13. 解答篇生成强制引用线索卡 ID 逐条对应；负面禁令：不得在解答篇引入正文未出现过的事实。

## 5. 对御书设计的启示

**数据结构建议：悬疑推理派系包核心卡 schema**

```yaml
# schemas/线索卡.yaml —— 公平性校验的最小单元（悬疑推理特有）
extends: core/setting-card
fields:
  content: {type: string}        # 线索内容
  revealed_at: {type: chapter}   # 呈现章节
  mode: {enum: [明示, 暗示, 隐瞒]}   # 呈现方式
  points_to: {type: ref}         # 指向的人物/诡计卡
  is_red_herring: {type: boolean}
  linked_truth: {type: ref}      # 红鲱鱼也必须关联真实解释
```

**功能建议**
- 线索矩阵视图：行=线索，列=角色/读者/作者的知情状态，直接可视化"桌下炸弹"。
- 解答篇对照器：解答揭晓时自动列出所引用线索及其呈现章节，供作者自查公平性。

**校验规则建议**
- `fair-play`：关键线索未向读者呈现即用于解答 → error（本流派旗舰规则）。
- `herring-legitimacy`：红鲱鱼无真实关联解释 → error。
- `timeline-consistency`：不在场证明与案发时间线矛盾检测（error）。
- `chekhov-recall`：明示级线索全文未回收 → warn。

**AI 提示词建议**
- 侦探视角生成注入"角色已知集合"，禁止越界推理；叙述者视角生成注入"读者已知集合"，用于控制悬念信息差。
- 解答篇模板逐条引用线索卡 ID，未引用则要求 AI 重写或提示作者补线索。
