# H09-古代言情（宫斗宅斗 / 种田经商 / 穿越奇情）

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究古代背景下女频言情的三大子类写法：宫斗宅斗（后宅/后宫的人际博弈与权力斗争）、种田经商（家宅叙事中的经营致富与烟火日常）、穿越奇情（现代人穿古代的爱情线，穿越机制本身归 H14）。边界：宫斗宅斗作为手法维条目在 docs/05 §3 有摘要条目，本文档补足写法侧；朝堂权谋向的男性向历史文归 H-历史相关文档；推理破案手法归 H13。古代言情区别于现言（H08）的根本点：礼制与宗法是硬约束，空间（后宅/后宫）本身就是权力地图，这带来独特的设定卡与校验需求。

## 2. 核心知识框架

1. **宅斗文定义**（百度百科）：官宦/商贾世家后宅中的嫡庶之争、妻妾权力较量及情感纠葛；豆瓣书评社区观察其常见形态为"古代背景下女主重生复仇，斗兄长斗姐妹斗长辈"，是种田文向权力叙事的延伸。
2. **人物关系棋局**：核心关系网=嫡庶、妻妾、婆媳、姑嫂、主仆（陪嫁/心腹/内奸）、外家与夫家；争斗本质是利益与资源之争（嫁妆、恩宠、地位、家产）。学术视角（中国作家网女频空间叙事研究）指出空间是主旨表达的隐形载体——正院偏院、位分高低即权力地图。
3. **算计写法**：算计要有因果链（布局→试探→反制→收网），最好隔几章再揭晓伏笔；反派要聪明，女主赢在"更细一步"而非对手降智；算计范围由小到大层层升级（后宅→家族→朝堂）。
4. **种田经商**：种田=以务农为生的劳作，基建=基本建设与扩大再生产（起点写作课堂《异世界基建种田文常见爽点和剧情设计》）；中国作家网周敏的解读——种田文在家长里短的世情叙事中突出"勤劳致富"主线，主人公要有明确的改变命运目标与行动。爽点=丰收/扩建/交易获利/技术改进/旁人震惊；最大危险=平实视角导致流水账，需穿插冲突（邻里纠纷、天灾、市场波动、权力打压）。
5. **礼制与名物约束**：宅斗宫斗的一切博弈都在礼制规则内进行（嫡庶尊卑、孝道守制、婚嫁六礼、宫规位分、丧仪祭祀）——礼制既是限制也是武器（借礼压人）。
6. **感情线节奏**：女频爆款开局快——重生/穿书后三章内给出第一次小反击；感情线与权谋线交织是高分宅斗的共同特征（番茄女频 TOP10 拆解）。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 时代背景模板（架空朝代/类明清/类唐宋）+配套礼制等级库 → 世界向导第 1 步选择，决定可用礼制事件与称谓体系。
2. 空间即权力：府邸/后宫平面图作为权力地图建档（院落位次、宫室方位、通行权限）→ 空间卡与人物位分联动。

**设定卡 schema 扩展（古代言情特有卡）**
3. 人物关系棋局卡（关系边：利益诉求/立场/忠诚度/把柄/近期动向）→ 宫斗宅斗的骨架，比通用人物卡多"利益维"。
4. 礼制事件卡（婚丧嫁娶/节庆/宫宴/祭祀——博弈的固定舞台与回合制节点）。
5. 产业经营卡（田产/铺面/嫁妆/作坊：产出、扩张条件、账本流水）→ 种田经商线资源循环节拍的物料库。

**校验规则**
6. 反派智商校验：女主获胜方式若依赖对手明显失误而非己方布局 → warn"反派降智"。
7. 算计闭环校验：布局→收网必须能回溯到已埋伏笔（联动 F 伏笔台账 plant/payoff 链接）。
8. 礼制越界校验：角色行为超出时代礼制（如守孝期议亲）且无剧情理由 → warn"礼制穿帮"。

**写法指南与节拍**
9. 开局三章反击模板：重生/穿书锚点 → 首次吃亏 → 第一次小反击 → 长线对手亮相。
10. 种田资源循环节拍：每卷一个产业里程碑（安家→第一桶金→扩张→危机→跃升），日常线每 3-5 章穿插一次冲突事件。

**读者期待与雷点**
11. 期待=打脸虐渣/经营致富/身份提升/深情双洁；雷点=反派降智、礼制常识穿帮、流水账日常、现代知识无工业基础却量产、重生先知滥用（联动 H14）→ taboos 清单。

**AI 提示词倾向**
12. 生成博弈场景时强制注入"关系棋局状态+礼制约束+在场人物利益诉求"，防止 AI 写出无立场打脸戏。
13. 种田章节要求输出资源变化表（本章产出/消耗/新增），生成对话时带称谓体系（庶出/姨娘/老夫人）保持语境。

## 5. 对御书设计的启示

**数据结构建议：古代言情派系包核心卡 schema**

```yaml
# schemas/关系棋局卡.yaml —— 宫斗宅斗的骨架（古代言情特有）
extends: core/setting-card
fields:
  edges:
    - from: {type: ref}          # 人物 A
      to: {type: ref}            # 人物 B
      interest: {type: string}   # 利益诉求（嫁妆/恩宠/家产/继嗣）
      stance: {enum: [敌, 中立, 暗助, 盟, 亲]}
      leverage: {type: array}    # 互相掌握的把柄
      faction: {type: string}    # 所属阵营（嫡房/妾室/外家/宫中）
  space_link: {type: ref}        # 关联的空间卡（院落/宫室）——空间即权力
```

**功能建议**
- 棋局视图：人物关系网按阵营着色，标记"把柄"与"利益"边；生成博弈章节前自动拉取在场人物棋局状态。
- 礼制日历：礼制事件卡排成时间轴，作为剧情回合节点，支撑"借礼压人"类情节。

**校验规则建议**
- `villain-iq`：反击/收网段落检测胜负归因，若依赖对手失误 → warn。
- `scheme-closure`：收网章节必须引用≥1 个已 plant 的伏笔 ID。
- `etiquette-violation`：礼制事件与角色行为冲突检测（联动 E 系人文知识库）。

**AI 提示词建议**
- 博弈生成模板："在场人物及利益诉求{edges}，当前礼制场合{event}，本章目标{试探|反制|收网}"。
- 种田章节模板要求结尾附资源变化表，用于产业经营卡自动记账。
