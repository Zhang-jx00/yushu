# H12-规则怪谈与无限流

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

合并调研两个"规则驱动"的流派：规则怪谈（2021 年 A 岛《动物园规则怪谈》起源，以规则条文为核心恐怖/解谜装置）与无限流（《无限恐怖》"主神空间"开山，副本闯关+队伍经营+跨副本成长）。二者在当代网文中高频复合（副本内嵌规则怪谈、主神空间发规则任务），且共享"受限条件+封闭环境下的智力角逐"的博弈叙事内核（2025 年网络文学评论视角），故合并一份。世界维挂靠民俗志怪/诸天无限；docs/05 §3 已有手法维摘要条目（规则卡真伪标注、副本世界卡），本文档补足写法与校验侧。边界：副本若为恐怖氛围载体，氛围技法参考 H10/H11。

## 2. 核心知识框架

1. **规则类怪谈的定义与特征**（萌娘百科词条，已验证）：以带有恐怖诡异元素的规则为核心，用守则/说明书/注意事项格式分条撰写；较强逻辑性、有明确答案指向。常见手法=描述违背常理的现象、把安全事物说成危险、建议读者做违背常理的事、不明示原因、多条规则相互矛盾、行文不连贯或受涂抹。
2. **起源谱系**（萌百+维基）：欧美前身是 Reddit"保姆怪谈"（过于精确的规则制造不安）；中文互联网爆火于 2021-11 A 岛《动物园规则怪谈》——九段规则由多个张贴主体（游客守则/员工守则/海洋馆告示/纸条）向不同对象告知互相矛盾的守则，作者称存在唯一解；衍生 Espedro 市怪谈（融入录音、文档记录）；与 SCP 基金会、模拟恐怖同源相邻。docs/05 §6 记录了"2024 蓝皮书批评浅层模仿"的生命周期节点。
3. **规则设计方法**（知乎问答）：用固定句式编规则、编写时"一定要有逻辑，不能光从上往下推断"；工程化归纳=先定底层真相再反推规则→规则间埋矛盾暗示异常→真规则保命假规则致命→所有规则指向同一答案形成闭环。
4. **博弈型叙事**：2025 年网络文学年度评论把规则怪谈归入"受限条件与封闭环境下的智力角逐、规则利用与代价权衡"的博弈叙事变体，并警示元素堆砌、情节高度类似的浅模仿问题。
5. **无限流嵌套结构**（百度文库世界观构建方法论）：核心魅力是"嵌套式"结构——主神空间作为中枢平台（结算/交易/强化）连接无数风格迥异的副本世界，既保证叙事开放性又维持整体性；CSDN 分析称其为模块化世界观架构，适合跨媒介改编。
6. **循环叙事的新鲜感管理**：文学研究指出"升级打怪"是以"语义反复"为特征的循环叙事（主角+助手战胜面目不同的敌人）——无限流既靠此"爽"，也靠变换副本类型（恐怖/科幻/民俗/智斗）对抗重复疲劳；近年热门无限流愈发强调规则解谜与逻辑（智斗向）。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 主神空间中枢预设：结算/交易/强化/复活规则一次性建档 → 无限流包的世界向导第 1 步。
2. 副本世界模板：每个副本一份独立世界预设+规则集（可引用 H10/H11 的恐怖预设）→ 世界卡模板的"每副本一实例"用法。

**设定卡 schema 扩展（规则怪谈/无限流特有卡）**
3. 规则卡（rule：条文/来源张贴者/真伪[真|假|条件真]/违反后果/指向的真相片段）→ docs/05 §3"规则卡（真伪标注）"的落地，真伪字段对读者隐藏。
4. 副本世界卡（类型/规则集/威胁等级/通关条件/奖励/时限/队伍配置）。
5. 诡异档案卡（联动 H10）：副本内异常实体的档案化记录，供跨副本情报复用。

**校验规则**
6. 规则自洽校验：所有"真规则"不得互相矛盾；若呈现矛盾必须能被"张贴者来源不同"解释 → error。
7. 唯一解校验：规则推理链必须存在通向底层真相的完整闭环（规则→矛盾→辨伪→真相），断链 → error。
8. 副本难度曲线：相邻副本威胁等级跳跃过大或长期持平 → warn"难度失控/重复疲劳"。

**写法指南与节拍**
9. 规则怪谈节拍：入场领规则 → 执行中遭遇异常 → 发现规则矛盾 → 辨伪（真规则保命）→ 触及真相 → 逃离/收束；辨伪场景必须引用具体规则条文。
10. 无限流单元剧节拍：副本=三幕小结构；跨副本主线（系统真相/幕后黑手）每 2-3 副本推进一步，防止"语义反复"疲劳。

**读者期待与雷点**
11. 期待=解谜智斗/规则压迫感/每副本新鲜感/队伍群像；雷点=规则无解、矛盾无解释、难度失控、副本同质化、浅层模仿元素堆砌、奖励通胀 → taboos 清单。

**AI 提示词倾向**
12. 生成规则集时强制输出真伪+指向真相的元数据（对读者隐藏），并要求"矛盾可解释"备注。
13. 辨伪/解谜场景生成时注入规则卡编号与已验证状态，要求 AI 的推理引用具体条文；副本生成强制引用世界卡模板保持模块化。

## 5. 对御书设计的启示

**数据结构建议：规则怪谈/无限流派系包核心卡 schema**

```yaml
# schemas/规则卡.yaml —— 真伪元数据对读者隐藏（规则怪谈特有）
extends: core/setting-card
fields:
  text: {type: string}           # 条文原文（呈现给读者的部分）
  source: {type: ref}            # 张贴者（员工守则/纸条/广播……来源不同解释矛盾）
  verdict: {enum: [真, 假, 条件真, 未知]}   # 作者层真伪，渲染时过滤
  consequence: {type: string}    # 违反后果
  truth_link: {type: ref}        # 指向的底层真相片段（唯一解闭环用）
```

**功能建议**
- 副本管理器：副本世界卡按顺序排列，每张卡内嵌规则卡列表与威胁等级，自动生成难度曲线图。
- 双层渲染：正文视图只显示规则条文，作者视图显示真伪/真相链接——同一数据两种投影。

**校验规则建议**
- `rule-consistency`：真规则间矛盾检测；矛盾必须有 source 差异解释（error）。
- `solution-closure`：从规则矛盾到底层真相的推理链完整性检查（error）。
- `difficulty-curve`：副本威胁等级曲线平滑性检查（warn）。

**AI 提示词建议**
- 规则生成模板："底层真相{truth}，请产出 5-9 条规则，其中≥1 假规则、≥1 组可解释矛盾"，输出自动拆分为规则卡。
- 解谜场景模板强制引用规则编号，禁止 AI 使用"规则没写但主角灵机一动"的 unfair 解法。
