# H03-武侠国术

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究"武侠"世界维的写法，含两支：传统武侠（金庸、古龙定型的江湖武林谱系，门派恩怨+侠义精神+招式武学）与国术流（《龙蛇演义》开山，以真实传统武术技法与民国武林为底、武道层级化的近现代变体）。与 H02 的边界：武侠之力是"人的技艺"，有生理代价与极限；仙侠之力是"超凡体系"。对应 docs/05 世界维"武侠"条目（派系包要素：武学秘籍卡、门派恩怨图谱）的写法侧细化，并为"武侠同人"新手路径提供平台映射参考。

## 2. 核心知识框架

1. **江湖嵌套历史的传统**：武侠一大特色是把身怀绝技的主人公置于动荡的历史时段，与真实历史人物互动、甚至暗中左右历史（香港教育城"也文也武"归纳）；这决定了武侠世界预设需要"江湖层+历史层"双轨。
2. **门派与恩怨图谱**：门派=武功传承+经济来源+人际关系的三位一体；恩怨（夺书、灭门、夺爱、夺位）是情节第一驱动；金庸式隐喻设计（如《侠客行》谈侠客岛色变）示范了武功与寓意的绑定。
3. **武功设计学**：招式命名-内功心法-兵刃暗器的三层体系；武功应与角色成长、主题寓意绑定；读者心理层面要避免主角十全十美，用"角色冲突调动情绪"（金庸茶馆写作讨论：黄蓉不教杨过武功即是经典张力案例）。
4. **国术流体系**：以《龙蛇演义》（梦入神机，2008 起点武侠连载）开山；境界划分直接借用真实拳理——明劲、暗劲、化劲出自孙禄堂/郭云深对形意拳练法的划分，向后延伸抱丹、见神不坏等虚构层级；时代底色多为清末民国（国术对抗枪炮的时代挽歌感），当代代表作品谱系见"十大国术流"盘点（龙蛇演义居首、武道宗师第四）。
5. **演化链与新手路径**：1954 梁羽生→金庸古龙→新世纪复仇主题演变（乔靖夫《武道》）→国术流→武侠+玄幻融合（武道升级体系化）；对写作实力信心不足者，社区建议从武侠同人入手（借成熟世界观练手）。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 江湖=半正式社会：需同时建"朝廷-江湖"双权力结构与两者接口（诏令/招安/镖局税）→ 世界预设模板"双权力结构"字段。
2. 门派地理网（山门/分舵/镖局路线/武林大会会址）→ 地图按"门派势力范围"分层（联动 B01）。
3. 国术流项目强制设定时代坐标（清末/民国/当代）与火器-武功战力接口规则 → 世界向导国术流预设。

**设定卡 schema 扩展（武侠特有卡）**
4. 武学秘籍卡（品阶/来历传承链/修炼条件/副作用代价）→ docs/05"武学秘籍卡"落地。
5. 门派恩怨卡（恩怨事件列表：何事/何代/双方/未解状态）→ "门派恩怨图谱"的数据化。
6. 招式卡（名称/字面意象/实战效果/克制关系）→ AI 战斗描写素材库。
7. 国术境界卡（明劲/暗劲/化劲/抱丹…每层生理特征与极限）→ 国术流派系包专用。

**校验规则**
8. 武力代价校验：重伤后无恢复期继续高强度战斗 → error（区别于玄幻的核心 lint）。
9. 恩怨一致性：恩怨卡中"未解之仇"双方若同场而无反应 → warn。
10. 秘籍传承链校验：秘籍出现在无来源解释的角色手上 → warn。
11. 国术战力-火器对照：火器时代徒手搏枪械需底牌说明 → warn。

**写法指南与节拍**
12. 快意恩仇循环：受辱/结怨→寻师学艺或奇遇→复仇/对决→新恩怨 → 节拍表模板。
13. 比武大会结构（报名-轮次-黑马-决计-夺魁风波）→ 大纲模板。
14. 武侠同人路径：选原著→设定库引用→OOC 检查（复用同人文机制，docs/05 §3）→ 新手引导流。

**读者期待与雷点**
15. 期待=快意恩仇、侠义精神、"武功合理"的实感；雷点=武力无代价、侠义崩坏（主角滥杀仍称侠）、招式描写堆砌名词、国术练级速度失真（一月化劲需代价解释）→ taboos 清单。

**AI 提示词倾向**
16. 战斗描写提示词要求短句、动作分解、以意带招、禁止一次性罗列招式名 → 武侠文风模板。
17. 生成前注入"在场者恩怨关系+已习武功清单"→ 防止 AI 遗忘师承与仇怨。

## 5. 对御书设计的启示

**数据结构建议：门派恩怨图谱（本流派核心差异化结构）**

```yaml
# schemas/门派恩怨卡.yaml
extends: core/setting-card
fields:
  grudges:
    type: array
    items:
      required: [event, parties, generation, status]
      properties:
        event: {type: string}        # 何事（夺书/灭门/夺爱/夺位）
        parties: {type: array}       # 双方（门派或人物 ref）
        generation: {type: integer}  # 第几代结怨
        status: {enum: [未解, 已雪, 待报]}  # status=未解 的双方同场需触发校验
```

**校验规则建议**
- `cost-of-force`：战斗事件后主角 HP/伤势状态必须写入，重伤未愈再战 → error（武侠区分于玄幻的第一规则）。
- `grudge-consistency`：`status=未解` 的双方出现在同一场景 → warn 提示处理或标注回避理由。
- `lineage-check`：武功使用者的"已习武功清单"必须能沿传承链回溯到秘籍卡。

**写法指南与节拍建议**
- 节拍表：恩怨事件驱动，无系统面板；卷级高潮=复仇对决或武林大会。
- AI 文风包：武侠=短句动作流；国术流=拳理术语（听劲、整劲、寸劲）+时代氛围。

**读者期待与雷点**
- taboos.yaml：武力无代价/侠义崩坏/招式堆砌/练级失真；国术流追加"拳理失实"条目。

**AI 提示词建议**
- 续写模板注入：在场人物恩怨表 + 武功清单 + 伤势状态；国术流追加当前境界（明劲/暗劲/化劲）与"拳理注释"开关（考据向读者需要）。
