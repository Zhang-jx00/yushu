# H15-系统流（系统面板 / 签到 / 气运 / 数值金手指）

> 类别：H-各流派写法 ｜ 世界构建金字塔层级：叙事层 · 流派写法
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

系统流是手法维中覆盖面最广的"元流派"：主角绑定一个游戏化的"系统"实体，获得面板（属性/技能/背包）、任务-奖励循环、兑换商城、签到等机制性金手指。docs/05 §3 已有摘要条目（系统流/签到流），本文档合并调研系统、签到、气运三个近亲手法：系统流是任务驱动型金手指，签到流是其"低压力懒人变体"（定点领奖励、苟着变强，2019-2020 随免费阅读爆发），气运流则是前数值时代的东方变体（气运加身、夺运镇运，根植洪荒流"量劫"设定与命理文化，多与历史/儒道/洪荒题材复合）。边界：系统作为纯对白伙伴的"吐槽役"写法归人物层；无限流副本的"主神系统"归 H12；第四天灾的"游戏策划系统"归 H18。系统文被称为"精神预制菜"——工业化、可复制、爽点密集，因此是御书最需要"模板化支持+反模板化校验"并重的流派。

## 2. 核心知识框架

1. **核心闭环**：系统文的核心机制是"任务-奖励-惩罚"闭环（QQ 阅读小说百科）：系统发布任务 → 完成得奖励（能力/道具/积分）→ 失败受惩罚 → 变强 → 开启新任务。知乎写作帖展示的标准循环结构：【任务奖励：从其余七项选其中之一】【完成后开启下一主线】【前往下一世界，开局再选择一项】——任务→奖励→新主线→新地图是系统文的骨架节拍。
2. **面板设计传统**：以《完美人生系统》为代表的经典面板结构为六大固定栏目——身体面板、学习经历面板、掌握技能面板、兑换目标面板、自制目标面板、成就奖励面板；即"属性/经历/技能/目标/成就"五类信息的界面化呈现。知乎"金手指类型 204 种"整理将系统类细分为 16 种：任务系统、签到系统、加点系统、抽奖系统、商城系统、模拟系统等——每种都是面板 schema 的一个变体。
3. **演变三代**（什么值得买系统文专题）：第一代是"给任务→给奖励→变强"的机械模式；第二代开始把系统嵌入人物命运与情感逻辑（如《重生取得成果》的"成果系统"，反"数值面板+即时奖励"套路）；第三代以《悟性逆天》为代表，金手指从"外挂"变为"放大器"（悟性/气运/专注等隐性属性）。系统文的创新从未停止——面板不变，机制内核在换代。
4. **主角-系统关系**：QQ 百科总结主角应对系统的经典三步——拒绝（确立自主性）→ 试探（摸清规则边界）→ 反向利用（把系统当工具而非主人）。系统从"发奖机器"沦为背景板是最大雷点；后期主流是给系统人格（毒舌/卖萌/神秘），用系统对白承担喜剧与信息投递。
5. **签到流机制**：每日/定点签到领奖励，核心爽点是"零成本、日积月累、蹲守变强"（红袖《签到七天我于都市全无敌》：连续签到+财富持续增长机制，主打追读稳定）。写作教程指出签到的作用是"不断塑造短线期待感，再通过签到及选择为后面剧情塑造期待感"——签到是节拍器而非剧情本身。风险=奖励通胀：奖励增长曲线一旦超过剧情压力曲线，张力归零。
6. **气运流机制**：主角或势力"气运加身"，夺气运、镇气运、承载人道/国运（起点设"气运流"分类，代表作《洪荒人皇》等）；反套路方向是"气运之子"自嘲与"反派夺主角气运"（《我师兄实在太稳健了》式稳健流即为对气运流的无声反讽）。气运是可量化、可转移、可被观测的资源——本质是把"运气"数值化的面板。

## 3. 可转化为产品规则的关键实践

**世界预设要点**
1. 系统来源档案：系统是谁造的/为何绑定/终极目的 → 世界向导强制项，决定"系统真相"主线是否成立。
2. 世界规则与面板的接口：系统数值以何单位锚定（境界/星级/点数），与原世界力量体系的换算表 → 防两套体系互相打架。

**设定卡 schema 扩展（系统面板卡/签到奖励表）**
3. 系统面板卡（面板区块：属性/技能/背包/任务/商城/成就，每区块可开关）→ 《完美人生系统》六大栏目结构的产品化。
4. 任务卡（任务名/目标/时限/奖励/惩罚/主线关联）→ 任务-奖励闭环的最小单元。
5. 签到奖励表（签到点/周期/奖励池/保底与随机/累计节点大奖）→ 签到流专属表结构，奖励按稀有度分层。
6. 气运卡（当前气运值/来源/消耗事件/气运可视化的异象描写）→ 气运流资源化。

**校验规则**
7. 奖励通胀校验：面板战力曲线斜率 > 剧情威胁曲线斜率 → warn"奖励通胀，张力衰减"。
8. 任务悬空校验：已发布任务无完成判定也无放弃解释 → error"任务悬空"。
9. 系统人格漂移：系统语气/称谓/立场突变且无剧情解释 → warn（与快穿人设漂移同源）。
10. 签到时序校验：签到记录与正文时间线冲突（跳日/重复日）→ error。

**写法指南与节拍**
11. 开局面板节拍：绑定系统 → 首个面板展示 → 第一个任务（小、可即刻完成）→ 首次奖励兑现；前三章内完成整个循环的第一次演示。
12. 系统关系节拍：工具期（发奖机器）→ 磨合期（拒绝-试探）→ 反向利用期 → 真相期（系统来源揭秘）；每次关系升级应对应一个剧情高潮。
13. 签到节拍：签到奖励必须"三次里有一次用于即时剧情"，避免签到记录连续三章与正文无关。

**读者期待与雷点**
14. 期待=数值成长可视化/奖励开箱感/任务清单达成/系统吐槽喜剧/苟着变强安全感；雷点=系统沦为发奖机器、奖励通胀、面板刷屏挤占叙事、任务反复刷同类、签到与剧情脱节 → taboos 清单。
15. "精神预制菜"警示：套路可复制但读者对第三代机制（隐性属性/命运嵌入）有明确升级期待 → 派系包应提供"机制内核换代"选项而非只提供经典模板。

**AI 提示词倾向**
16. 续写状态块自动注入：当前面板关键数值、进行中任务、最近三次签到奖励、系统当前人格阶段——防 AI 写出数值漂移。
17. 面板展示由模板渲染而非 AI 自由生成：AI 只写叙事层，面板数据走 schema → 防止 AI 幻觉出未登记的技能/道具。

## 5. 对御书设计的启示

**数据结构建议：系统流派系包核心卡 schema**

```yaml
# schemas/系统面板卡.yaml —— 系统流的手法核心卡
extends: core/setting-card
fields:
  origin: {type: string}            # 系统来源与目的（系统真相主线的伏笔登记处）
  sections:                         # 面板区块开关（参照六大栏目）
    attrs: {type: boolean, default: true}
    skills: {type: boolean, default: true}
    inventory: {type: boolean, default: false}
    shop: {type: boolean, default: false}
    achievements: {type: boolean, default: false}
  metric_unit: {type: string}       # 数值锚定单位（与境界体系换算）
  persona_stage: {type: enum, values: [tool, friction, reversal, truth]}
```

配套：任务卡（name/goal/deadline/reward/penalty/mainline_link）、签到奖励表（point/cycle/pool/pity）、气运卡（value/source/costs）。

**功能建议**
- 面板渲染器：从面板卡数据渲染"面板插文"，与叙事正文分离存储，一键更新数值。
- 奖励账本：签到/任务奖励自动入账，生成战力曲线与威胁曲线叠加图（通胀可视化）。

**校验规则建议**
- `reward-inflation`：战力曲线斜率 > 威胁曲线斜率 → warn。
- `task-orphan`：任务无判定无放弃 → error。
- `sign-in-timeline`：签到记录与时间线冲突 → error。
- `system-persona-drift`：系统语气突变无解释 → warn。

**AI 提示词建议**
- 续写上下文强制注入面板状态块（数值/任务/人格阶段），AI 输出中新增技能/道具须回写登记。
- 提示词模板按机制代际分档：一代（机械任务）/二代（命运嵌入）/三代（隐性属性放大），供作者选择套路代际。
