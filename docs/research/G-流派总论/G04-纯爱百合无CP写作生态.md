# G04-纯爱·百合·无CP 写作生态

> 类别：G-流派总论 ｜ 世界构建金字塔层级：叙事层 · 流派维度
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究言情之外的三大感情线生态：纯爱（BL/男男）、百合（GL/女女）与无CP（感情线留白的事业/冒险主线）。核心问题有二：一是三大生态在各平台的频道归属与规范差异（晋江性向判定逻辑、起点无对应频道、番茄"无CP"归女频生态等）；二是"感情线形态"如何从频道属性中解耦为独立开关（docs/05 四维模型已将其列为频道维之外的独立开关）。边界：女频通论归 G03；本领域只管非言情的感情线形态生态、平台规范与无CP漂移防控。

## 2. 核心知识框架

1. **晋江性向判定逻辑（官方成文）**：以"CP"为判定依据——有 CP 按性别逻辑分入言情/纯爱/百合；无 CP 归入无CP；2024-06 上线"多元"频道，收纳不属于已有四大性向定义的作品。这是"感情线形态=独立分类轴"最明确的官方先例，御书 romance 开关的判定向导可直接复刻。
2. **平台归属差异**：晋江（纯爱/百合/无CP 均为正式频道，分原创/衍生两层）；起点（无纯爱频道，相关内容多以衍生同人间接承载，男频有"无女主"标签传统）；番茄（"无女主"归男频、"无CP"归女频的生态事实）；飞卢（同人站承载大量 BL/GL 同人）；豆瓣阅读（跨性向的情感标签体系组织作品）。
3. **纯爱（BL）生态**：双主角关系推进为主线，晋江纯爱频道为主阵地；写作焦点在关系张力、双向奔赴、破镜重圆等情感母题；各平台尺度规范差异大，投稿需分级自查——派系包必须携带平台映射与合规提示字段。
4. **百合（GL）生态**：体量小于纯爱但读者黏性稳定，与百合同好社区、衍生同人共生；存在"无CP+百合完结"的混合频道形态（晋江手机版频道页可见），说明"性向频道"与"感情线强度"并非同轴。
5. **无CP 生态**：男频无女主是成熟传统（《天人图谱》等标杆作）；女频无CP大女主是新增长赛道（争霸科举/基建种田/星际末世/无限流，用事业线替代感情线驱动）；读者核心诉求"女主要强、名义男主存在感薄弱即劝退"；最大写法风险是"暧昧拉扯变相成为感情线"。
6. **读者与社区**：性向题材社区聚合度高（豆瓣无CP爽文小组、播客专题、NGA 科普帖），标签声明（纯爱/无CP/HE/BE/1v1）是读者的第一筛选入口——简介承诺与正文一致性是硬性期待。

## 3. 可转化为产品规则的关键实践

1. 平台规范差异表 → 派系包必填的 platform_mapping 性向扩展字段 + 合规提示。
2. 感情线开关 → 项目级 romance 开关（形态/强度/锁定/结局预期），独立于频道维。
3. 无CP漂移预警 → mode=none 时检测暧昧关系事件与单对角色互动密度异常。
4. 性向判定向导 → 按"有无CP×性别逻辑"自动推荐频道归属（复刻晋江官方逻辑）。
5. 标签声明检查 → 简介必须声明性向与 HE/BE 预期，与结局章事件做一致性校验。
6. 尺度合规词库 → 按平台加载敏感内容自查参数（联动敏感词自查流水线）。

## 5. 对御书设计的启示

**数据结构建议：平台规范差异表**

| 平台 | 纯爱 | 百合 | 无CP | 备注 |
|---|---|---|---|---|
| 晋江 | 正式频道（原创/衍生） | 正式频道 | 正式频道（另有"多元"） | CP 判定逻辑官方成文 |
| 起点 | 无对应频道（衍生同人间接承载） | 无 | 男频"无女主"标签 | 映射为空并提示改投 |
| 番茄 | 有限 | 有限 | "无CP"归女频生态 | 免费+短剧向 |
| 飞卢 | 同人站承载 | 同人站承载 | 少 | 同人快餐流 |
| 七猫 | 有限 | 有限 | 细分标签 | 免费下沉 |

对应派系包扩展字段：

```yaml
channel_support:                    # platform_mapping 的性向扩展
  - platform: jjwxc
    channel: 纯爱                   # 正式频道
    compliance: [尺度分级, 敏感词自查]
  - platform: qidian
    channel: null
    note: 无纯爱频道，建议衍生同人间接承载或改投晋江
```

**感情线开关设计（项目级，独立于频道维）**

```yaml
romance:
  mode: none              # none | single | dual(BL/GL) | multi | harem | ambiguous
  locked: false           # true 时一致性引擎拦截感情线推进事件
  intensity: 0-5          # 感情线在叙事中的权重（0=完全留白）
  ending_expectation: HE  # HE | BE | open —— 简介承诺与结局一致性校验
  rules:
    - "mode=none：禁止登记 心动/告白/接吻 类关系事件；允许 羁绊/战友/师徒"
    - "mode=none：单对角色互动密度 >40% 且无事业动机 → 暧昧漂移预警"
    - "mode=dual：双主角戏份差 >30% → 主次失衡提示"
    - "ending_expectation 与结局章事件不符 → 红牌"
```

**校验规则建议**
- 性向判定向导：按"有无CP×角色性别"自动推荐频道，用户可改并留痕。
- 无CP漂移：关系图谱中"羁绊"边被 AI 建议改为"心动"时强制人工确认。

**AI 提示词建议**
- mode=none 注入："本章不得出现恋爱推进描写；人物互动限于事业/冒险动机。"
- 纯爱向注入："双主角视角均衡，关系张力按 铺垫-升温-确认 节拍推进。"
