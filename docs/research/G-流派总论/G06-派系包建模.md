# G06-派系包建模（流派差异的数据化表达）

> 类别：G-流派总论 ｜ 世界构建金字塔层级：工程层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究如何把"流派差异"表达为可插拔、可融合、可分享的数据包（Genre Pack）：包清单（manifest）结构、与四维派系模型（频道/世界/手法/基调+感情线开关，见 docs/05-流派总表）的对齐方式、设定卡 schema 扩展点、校验规则 DSL、多包融合与冲突消解算法。上游需求见 docs/01-需求总纲 §3.2（派系包 11 件套）与 §3.3（"合并 schema、规则去重、冲突提示"融合要求）。本领域回答一个工程问题：**流派差异如何在不搞大一统架构的前提下（docs/01 §3.3"核心最小化"），全部由数据注入。**

## 2. 核心知识框架

1. **先例：游戏 Mod 的数据格式**。Minecraft 数据包（文件夹约定+JSON 定义+命名空间）、RimWorld XML Defs（定义文件+继承+补丁）、Stardew Valley Content Patcher（JSON patch 指令集：EditData/Include/追加与覆写分层）。共同模式：**声明式数据 + 稳定 ID + 命名空间隔离 + 覆写/补丁分层**。
2. **格式选型**：机器维护的配置用 JSON/TOML、人写的内容用 YAML（Fighters Legacy 的 TOML/YAML 分工先例）；御书数据主权承诺（docs/01 §6：Markdown+YAML、可 Git 版本化）→ 派系包统一 YAML，JSON 仅作序列化产物。
3. **规则即数据**：JSONLogic 把规则表达为可序列化 JSON（`{"<":[1,{"var":"temp"}]}`），前后端可共享、可做可视化规则构建器；CEL 是非图灵完备的安全表达式语言（Envoy/Google 生产验证）。御书规则 DSL 取折中：**条件用 JSONLogic 子集（或 CEL 风格受限表达式），产出为结构化 YAML 动作**。
4. **包的 11 件套与四维对齐**（docs/01 §3.2）：世界预设/schema 扩展/校验规则/节拍表/爽点模式库/AI 提示词/术语表/雷点清单/大纲模板/演化链/平台映射——manifest 逐项有文件位；包声明的四维取值与 docs/05 流派总表同一词表，新词经 docs/05 §6 流程（开山作→社区发酵→平台设分类）收录。
5. **融合与冲突**：多包组合 = 四维并集 + 内容合并；消解优先级"用户覆盖 > 包显式声明 > 引擎默认"；冲突必须显式提示而非静默合并。

## 3. 可转化为产品规则的关键实践

1. 命名空间隔离 → 所有 ID 采用 `pack_id/element_id` 形式，杜绝跨包冲突。
2. 稳定 ID+语义化版本 → 包版本与引擎兼容区间（requires.yushu），升级走迁移脚本。
3. 补丁分层 → 包可携带 patch 操作（改字段/增条目），不 fork 原包即可微调（Content Patcher 模式）。
4. 规则 DSL 沙箱 → 表达式禁循环禁 IO，求值超时与递归深度上限（CEL 安全原则）。
5. 融合预演 → 项目向导先出"融合报告"（新增/覆盖/冲突三类），确认后才写入项目配置。
6. 包市场 lint → 分享前校验：schema 合法、ID 唯一、11 件套文件位齐全、映射表覆盖 ≥1 平台。

## 5. 对御书设计的启示

**数据结构建议：派系包完整 YAML 草案（manifest）**

```yaml
apiVersion: yushu.pack/v1          # 包格式版本（semver + 引擎兼容区间）
kind: GenrePack
metadata:
  id: xuanhuan-xitong              # 全局唯一，作命名空间前缀
  name: 男频玄幻·系统流
  version: 1.2.0
  license: CC-BY-4.0
  requires: {yushu: ">=0.4.0"}     # 引擎兼容区间
genre_axes:                        # 四维声明（与 docs/05 同一词表）
  {channel: [男频], world: [玄幻], technique: [系统流], tone: [爽文], romance_mode_default: none}
content:                           # 11 件套，对应 docs/01 §3.2
  world_preset: presets/world.yaml                       # 1 世界预设
  schema_extensions: [schemas/境界体系卡.yaml, schemas/系统面板卡.yaml]  # 2
  rules: [rules/power-consistency.yaml, rules/realm-progress.yaml]      # 3
  beat_sheets: [beats/upgrade-cycle.yaml]                # 4 节拍表
  satisfaction_patterns: [patterns/face-slap.yaml]       # 5 爽点模式库（G05 结构）
  prompt_templates: [prompts/continue.yaml]              # 6 AI 提示词模板
  glossary: glossary.yaml                                # 7 术语表（境界/称呼/器物）
  taboos: taboos.yaml                                    # 8 雷点禁忌清单
  outline_templates: [outlines/three-act-upgrade.yaml]   # 9 大纲模板
  evolution: {origin_work: 《斗破苍穹》, era: 2009, chain: [开山:斗破苍穹 → 仿作 → 反套路(凡人流反向)]}  # 10
  platform_mapping: mappings.yaml                        # 11 平台映射（G01 结构）
fusions:
  compatible_with: [fanren-liu]
  conflicts_with:
    - {pack: guiju-guaitan, reason: 规则解谜节奏与战力爽点节拍冲突}
```

**schema 扩展点（设定卡扩展）**

```yaml
# schemas/境界体系卡.yaml —— 继承核心通用设定卡（core/setting-card: id/name/summary/refs）
extends: core/setting-card
fields:
  realms:
    type: array
    items:
      required: [name, tier, lifespan, combat_power]
      properties:
        name: {type: string}
        tier: {type: integer, order: asc}
        lifespan: {type: integer, unit: 年}
        combat_power: {type: number, scale: power_scale}   # 引用全局战力刻度
```

**规则 DSL 示例（条件=JSONLogic 子集，产出=结构化动作）**

```yaml
# rules/power-consistency.yaml —— 战力防崩塌
rule:
  id: power-no-regress
  severity: error                  # error | warn | info
  scope: cross_chapter             # scene | chapter | cross_chapter | project
  when:
    and:
      - {">=": [{var: "b.realm.tier"}, {var: "a.realm.tier"}]}
      - {"<": [{var: "b.combat_power"}, {var: "a.combat_power"}]}
  message: "境界提升但战力下降（{a.chapter}→{b.chapter}），疑似战力崩塌"
```

**多包融合与冲突消解策略**

| 合并对象 | 策略 |
|---|---|
| genre_axes | 并集；同一维取值冲突 → 用户择一 |
| schema_extensions | 按 extends 目标合并字段；同名字段类型不同 → 冲突提示 |
| rules | 同 id 高版本胜出；语义冲突（同目标矛盾）→ 按 severity+priority 排序并弹确认 |
| beats/patterns | 时间轴叠加；相位互斥（爽文释放段 vs 黑深残压抑段）→ 冲突提示 |
| glossary/taboos/prompts | 并集去重、多模板并存；同名术语异义 → 命名空间并列由用户裁定 |

消解优先级：`user overrides > pack 显式声明 > 引擎默认`；一切冲突显式提示（docs/01 §3.3），禁止静默覆盖。

**校验规则建议**：包 lint（schema/ID 唯一/11 件套齐全/映射覆盖）；融合预演报告未确认不得写入项目。
