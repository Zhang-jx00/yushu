# E05-反派设计

> 类别：E-人文与人物 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

反派设计研究"对立面角色"的构建方法：动机的自洽性（反派是自己故事的主角）、与主角的镜像关系、威胁与压迫感的营造、以及反派作为"人物"的建档与弧线（负弧）。边界区分：E05 关注反派**作为人物**的设计；其推动的悬念机制（桌下炸弹、信息差）归入 C 类情节/悬念领域；其负弧线字段复用 E01。中文网文语境下还需覆盖"反派是否有必要可共情"的类型分层——从纯压迫型爽点反派到洗白型人气反派。

## 2. 核心知识框架

1. **镜像反派论**（The Write Practice）：最有效的反派是主角的暗面镜像——共享相似的伤/欲望，但选择不同的路；Mirror 反派让主题通过对抗而非说教呈现。
2. **Want vs Belief 框架**（iWrity）：反派有真实的 Want，但持有扭曲的 Belief（信念/世界观），恶行是"用错误手段追求合理目标"；去脸谱化清单：拒绝"为坏而坏"、给出自我辩护逻辑、保留能力与魅力。
3. **"自己故事的主角"原则**（Sudowrite/社区共识）：反派不认为自己是反派；其计划在其价值观内是最优解。
4. **共情≠同情**（Max Florschutz 等）：读者可以理解反派而不认同；共情的桥梁是可辨认的欲望（被认可/恐惧/爱），不是洗白。
5. **McKee 反作用力**：对立面的强度决定故事强度；反派应迫使主角做出愈来愈艰难的选择。
6. **负弧反派**（Weiland）：反派多数是负弧人物——Truth→Lie 或困于 Lie；其弧线字段与 E01 完全共用。
7. **网文分层**：爽文结构中"压迫→蓄力→打脸"的反派是功能件，允许脸谱化但要求"坏得有节奏"；高智斗文要求反派棋力对等。产品需支持两档。

## 3. 可转化为产品规则的关键实践

1. 反派卡字段组（表面行为/深层 Want/扭曲 Belief/自我辩护词/底线与恐惧） → E02 人物卡的"反派扩展包"。
2. 镜像性声明 → 字段 `mirror_of: char_id` + `共享点说明`，AI 生成对立场景时引用以保持主题对位。
3. 反派计划台账 → 目标→阶段→资源→每阶段"对主角的压迫事件"，与情节大纲联动，缺压迫事件则警告"反派蛰伏过久"。
4. 威胁等级与胜利条件 → 显式记录"反派怎样算赢"，供大结局倒推与伏笔回收（联动伏笔台账）。
5. 恶行分级与红线 → 记录恶行清单及其在关系网（E03）上的受害者边；平台合规校验（违法手段描述需符合发布平台规范）。
6. 打脸节奏标记 → 网文模式：每个压迫事件挂"预期反击点"，检查压迫与反击的配对回收。
7. 反派声线卡 → 权势者的语言特征（引经据典/称谓俯视/威胁委婉化）强制登记（联动 E07）。
8. 洗白/救赎开关 → 声明"可救赎"后，E01 弧线类型自动建议"负弧→平弧"混合并要求"代价"字段。

## 5. 对御书设计的启示

**数据结构建议**
- 反派扩展包字段：`{want, belief, 自我辩护词, 威胁等级: 域内|区域|世界, 胜利条件, mirror_of?, 可救赎: bool, 代价字段}`；恶行清单作为事件实体挂时间线与关系边。

**功能建议**
- 反派进度板：左侧压迫事件时间线，右侧主角蓄力/反击事件，直观呈现"打脸配对"；未配对的压迫事件进入"待回收"队列。
- 镜像对照视图：主角与镜像反派的 Lie/Truth/Want 并排展示，供作者检查主题对位。

**校验规则建议**
- 反派卡缺 `want` 或 `belief` 时标记"脸谱化风险"。
- 反派在连续 N 章无行动且无在场压力事件 → "蛰伏过久"警告。
- 洗白类反派必须填"代价"，否则禁止 HE 结局标签。

**AI 提示词建议**
- 生成反派场景时注入三件套：其 belief 视角下的"自我辩护"、当前计划阶段、对在场者的知情差；指令 AI 用反派自己的逻辑为恶行赋予正当性叙述，而非贴"邪恶"标签。
- 生成打脸场景前自动带出历史压迫事件清单，保证反击的账目感。
