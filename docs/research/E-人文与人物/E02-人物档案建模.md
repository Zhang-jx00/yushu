# E02-人物档案建模

> 类别：E-人文与人物 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

人物档案建模研究"如何把一个人物结构化为可维护的数据对象"：档案的字段分层（外貌表层—经历中层—心理内核）、必填/选填的分级、与世界观要素（出身地、阵营、时代）和情节要素（伏笔、关系、弧线）的引用关系。边界区分：E01 弧光是档案的一个字段组的展开；E03 关系网络是档案之间的边；E07 声线是档案的派生校验规则。对"御书"（从起源构建世界）而言，人物档案必须**引用而非复制**世界设定——人物的出身、职业、价值观都应锚定到世界层的要素 ID，保证世界改动时人物卡可级联提醒。

## 2. 核心知识框架

1. **Reedsy 三层档案法**：Outer Layer（外貌/言谈/举止）、Story Layer（经历/关系/创伤）、Inner Layer（恐惧/欲望/价值观/秘密），50+ 问题问卷。三层即"读者可见性分层"，直接对应档案的展示权限。
2. **雪花法人物摘要**：每个主要人物一句话（姓名+概括）→ 一段（动机/目标/冲突/顿悟/叙述线），是"由简到繁"的字段生成顺序。
3. **Weiland 心理内核字段**：Lie/Truth/Want/Need/Ghost 五字段构成心理层，与 E01 弧线共用。
4. **Dabble 问卷法**：用 5 步递进问题（谎从何来→如何表现→代价→裂缝→出路）把抽象心理转成可填写字段。
5. **AI 层级生成先例**：Dramatron 先生成人物集再生成节拍场景；MoPS 把故事前提拆成可组合模块——都证明"人物卡作为独立结构化对象、供下游生成消费"是可行管线。
6. **中文网文实践**：webnovel-handbook 把人物声线/风格写成"圣经"式结构化文档，说明中文网文工具需要档案卡之外附**声线卡与标签包**（流派/人设标签）。

## 3. 可转化为产品规则的关键实践

1. 三层可见性分层（读者可见/作者可见/AI 专用） → 档案字段级权限开关，防止剧透字段混入生成上下文。
2. 分级建档（主角全卡/重要配角中卡/龙套姓名卡） → 模板预设三档，减少群像建档成本。
3. 字段引用化（出身地/阵营/时代引用世界要素 ID） → 世界层改动时级联提醒"X 人的出身村已改名"。
4. Ghost 关联时间线 → 创伤事件必须挂在时间线节点上，可引用世界大事件。
5. 弧线类型+阶段指针 → 与 E01 共享，避免两处维护。
6. 人物标签包（流派人设词：傲娇/病娇/团宠/马甲） → 复用 S1 流派词表，支持检索与 AI 人设锚定。
7. 档案完成度评分 → 关键字段缺失（如主角缺 Want）时在写作首页提示。
8. 声线卡外挂 → 引用 E07 规则表，档案卡不重复存储。

**人物卡 schema（核心交付）**

```yaml
character:
  id: char_001
  基础: {姓名, 别名, 性别, 年龄, 生日, 身份/职业, 所属阵营ref, 出身地ref(世界要素), 时代锚ref, 标签包: [傲娇, 马甲], 分级: 主角|配角|龙套}
  外貌: {体型, 发型发色, 瞳色, 着装习惯, 标志物, 声音特征, 身体特征/伤痕}
  经历:
    时间线事件: [{事件ref, 年龄, 影响}]   # 引用世界/个人时间线
    ghost: 事件ref                        # 旧伤（E01 联动）
    教育/技能: [{}]
    前史秘密: [{内容, 揭示章节(可空), 可见性}]  # 剧透字段, 默认 AI 不可见
  心理: {性格特质: [], 恐惧, 价值观, 习惯动作, 金钱观, 道德红线}
  want: 有意识的情节目标（一句话）          # E01/E06 共用
  need: 无意识的主题需要（一句话）
  lie: 人物相信的谎
  truth: 需要领悟（或最终拥抱/抛弃）的真
  弧线类型: 正弧|平弧|负弧|混合|待定       # 引用 E01 CharacterArc
  声线卡ref: voice_001                     # 引用 E07
  关系edges: []                            # 引用 E03
```

1. [经典理论资料] Character Profile Template & Guide（Reedsy） — https://reedsy.com/blog/character-profile/ — 三层 50+ 问题人物档案模板，字段分层的直接依据。

## 5. 对御书设计的启示

**数据结构建议**
- 采用上文 schema；`出身地/时代/阵营` 一律存世界要素 ID 而非文本，实现"世界起源→人物"单向依赖（呼应御书宗旨）。
- 秘密类字段（前史秘密、真实身份）带 `可见性` 标记，生成对白/POV 时按 POV 人物的知识边界过滤（联动 E07）。

**功能建议**
- 档案向导：按雪花法顺序先填一句话→一段摘要→再展开全卡，避免一上来面对 50 个空字段。
- "从世界长出人物"入口：在世界某要素（如某行业、某阶层）页面上点"生成/添加在此出身的人物"，预填出身与时代锚字段。
- 档案完成度雷达图：基础/外貌/经历/心理/弧线五维，主配角阈值不同。

**校验规则建议**
- 主角/重要配角：want、need、lie、弧线类型不得为空。
- 同名与别名冲突检测；标签包词语必须来自受控词表（可扩展）。
- Ghost 必须指向时间线上早于故事起点的事件。

**AI 提示词建议**
- 生成任何场景前，把出场人物卡的"心理+want+声线卡+可见性过滤后的知识"打包为上下文，禁止注入标记为剧透的字段。
