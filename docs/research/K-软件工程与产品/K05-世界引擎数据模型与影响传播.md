# K05-世界引擎数据模型与影响传播

> 类别：K-软件工程与产品 ｜ 世界构建金字塔层级：工程层 · 软件工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究御书世界引擎（World Engine）的分层数据模型与「设定变更影响传播」机制：World 根实体与 Genesis→Laws→Geography→Ecology→Eras→Civilizations→Factions→Characters→Events→Storylines→Chapters 的层级（交接文档 §5.1）；Entity/Relation/Event/Timeline/Storyline/Chapter/Foreshadow 的字段建模；实体间「外键式引用 + 反向索引」构成的依赖图；修改上游设定后反向依赖遍历、受影响实体清单生成与用户逐项确认（docs/01 §4.2）；变更提案（proposal）与版本回滚；引用完整性校验（悬空引用、循环依赖）。边界：K03 研究文件格式层（Markdown+YAML+SQLite 真源），本领域研究其上的语义模型与传播算法；J07 做内容级一致性检测，本领域做结构级依赖与传播；C02 提供编年史理论，本领域只做其数据结构。

## 2. 核心知识框架

1. **分层依赖管线先例（Azgaar FMG）**。19 阶段有序生成管线，每阶段只读上游写入的输出，模块导入顺序即显式依赖链；分层四层：world data（纯状态）/generators（程序逻辑）/editors（用户交互）/renderers（可视化），修改一层不破坏其他层。
2. **全局状态 + 外键式引用**。唯一运行时对象 `PackedGraph`：cells 为平行数组（同一下标描述同一格），实体各成一个数组（states/provinces/burgs/cultures/religions），格上存实体 ID 作外键（如 `cells.state→pack.states`，0 表示中立）。
3. **变更影响分析（CIA）**。给定一处变更估算受影响实体集合，三类信息：结构性（依赖图/调用图）、语义性（文本相似度）、演化性（提交历史）。纯结构有盲点（无边但语义相关）、纯语义有盲点（无词重叠）；融合两种信号并在每条结论上给出显式传播路径。
4. **依赖图与拓扑序**。Kahn（入度 BFS，输出数 < 顶点数即存在环）或 DFS 三色（白/灰/黑，灰→灰回边即环）；拓扑序即「重算顺序」，与电子表格自然序重算同构——信息流方向上上游必先于下游。有环 ⇔ 无拓扑序（DAG 判定）。
5. **引用完整性校验**。以 JSON Schema 声明字段类型/必填/枚举，`$id`/`$ref` 支持跨文档引用；外键悬空、类型不符、枚举越界为三类结构错误。
6. **属性图建模**。nodes/edges 两表 + CTE 展开（御书暂不引入图库）；对照 Neo4j 概念（label/关系/属性）判断「何时把属性升格为节点」。
7. **传播语义**。上游变更 → 沿反向边遍历（谁引用了我）→ 多跳传播并按关系类型/深度衰减 → 生成受影响清单 → 分级（error/warn/info）→ 用户逐项确认后写入；未确认不得静默落库。

## 3. 可转化为产品规则的关键实践

1. World 根 + 分层实体 → 每层一个目录（world/genesis/laws/geography/…），每实体一个 Markdown+YAML 文件（承接 K03 真源约定）。
2. 外键式引用 → 引用一律写稳定 id（`char-linyuan`），不写显示名；显示名只在渲染层解析，改名不破坏引用。
3. 反向索引 → SQLite 建 `refs(referrer, relation, target)` 表并随保存增量更新，支持「谁引用了我」的近 O(1) 查询。
4. 影响传播 → 修改上游字段即触发反向遍历（带深度与关系类型过滤），产出 proposal 报告待确认（docs/01 §4.2）。
5. 传播分级 → 结构破坏（悬空/循环）error；语义冲突（跨层事实矛盾，交 J07）warn；仅提示 info。
6. 版本回滚 → proposal 落库前先建 Git 快照（承接 K10），一次 proposal = 一次提交，可整体回滚并 diff。
7. 完整性校验 → 保存与重建索引时跑 lint：悬空引用、循环依赖、层级倒置、必填缺失。
8. 依赖图可视化 → 报告每条结论附「传播路径」（起源→法则→文明…），可点击定位实体（承接 K07）。
9. 层级可裁剪 → 未启用层不参与校验与传播（docs/01 §4.1 渐进披露、交接文档 §9.3），如现实都市不启用 Ecology。

## 5. 对御书设计的启示

**数据结构建议：World 分层与实体 schema（草案）**

```yaml
# world/world.yaml —— World 根实体
apiVersion: yushu.world/v1
id: world-tianqi
title: 天启界
layers:                      # 层级启用开关（渐进披露）
  genesis: true
  laws: true
  geography: true
  ecology: false             # 现实都市可关闭
  eras: true
  civilizations: true
  factions: true
  characters: true
  events: true
  storylines: true
  chapters: true
genesis_ref: genesis/origin  # 分层实体以独立文件承载
```

```yaml
# settings/characters/char-linyuan.yaml —— 实体通用头
id: char-linyuan
type: character              # 类型由派系包 schema 扩展点注册（G06）
layer: characters
name: 林渊
aliases: [墨客]
refs:                        # 外键式引用（稳定 id）
  - {relation: from_region, target: loc-qingyun}
  - {relation: belongs_to, target: fac-danxia}
  - {relation: appears_in, target: ch-012}
source_chapters: [ch-003, ch-012]
visibility: written_unrevealed   # 冰山原则（docs/01 §4.2）
```

```yaml
# .yushu/proposals/prop-20260929-01.yaml —— 变更提案 + 影响传播报告
proposal_id: prop-20260929-01
base_snapshot: git:<sha>
change:
  entity: law-lingqi
  field: spiritual_density
  from: 0.6
  to: 0.3
impact:
  - {entity: geo-qingyun, relation: derived_from, depth: 1, severity: warn,  path: [law-lingqi, geo-qingyun]}
  - {entity: civ-danxia,  relation: depends_on,  depth: 2, severity: warn,  path: [law-lingqi, geo-qingyun, civ-danxia]}
  - {entity: char-linyuan, relation: power_source, depth: 3, severity: info, path: [...]}
confirmations:               # 用户逐项确认（未确认不得落库）
  - {entity: geo-qingyun, decision: accept, at: 2026-09-29T15:02:00+08:00}
  - {entity: civ-danxia,  decision: pending}
status: awaiting_confirmation   # awaiting_confirmation | applied | reverted
```

**依赖图索引（SQLite，可由文件重建；承接 K03）**

```text
entities(id PK, type, layer, file_path)
refs(referrer, relation, target)          -- 反向索引：谁引用了我
impacts(proposal_id, entity, depth, severity, path)
```

**功能建议**

- 影响传播面板：左侧改动字段，右侧受影响实体按层分组，逐条显示传播路径与分级，支持 accept/reject/pending（docs/01 §4.2）。
- 反向引用查询：实体详情页展示「被引用清单」（谁用了我的境界名/地名），一键跳转。
- 层裁剪向导：新建项目按流派包决定启用层，隐藏层不参与校验与传播（交接文档 §9.3）。
- 依赖图视图：全量只读图谱 + 局部影响子图高亮（承接 K07）。
- 变更提案历史：proposal = 一次 Git 提交（承接 K10），可整体回滚、可 diff。

**校验规则建议**

- `ref-dangling`：实体引用的 target id 不存在 → error（悬空引用）。
- `ref-cycle`：引用构成环（A 派生自 B、B 派生自 A）→ error（拓扑序前置条件被破坏）。
- `layer-order-violation`：反向引用上游层（如地理引用人物）→ warn。
- `propagation-unconfirmed`：存在 impact 但 decision=pending 即尝试写入真源 → error（禁止静默覆盖，docs/01 §4.2）。
- `entity-required-missing`：实体缺 schema 必填字段（JSON Schema required）→ error。
- `layer-disabled-ref`：引用指向已关闭层实体 → warn（层裁剪一致性）。

**AI 提示词建议**

- 「影响传播解读」：输入 proposal 报告，输出受影响的叙事后果与需回改章节清单（只建议，不自动改）。
- 「设定卡抽取」：从章节正文抽取实体与引用，产出符合本领域 schema 的 YAML 候选（承接 J06）。
- 「依赖修复助手」：针对 ref-dangling/ref-cycle 给出修复候选（改引用/合并实体/拆环）。
