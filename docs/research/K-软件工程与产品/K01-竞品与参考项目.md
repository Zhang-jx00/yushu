# K01-竞品与参考项目

> 类别：K-软件工程与产品 ｜ 世界构建金字塔层级：工程层 · 软件工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究「同类工具已经做到哪一步」，为 docs/02-竞品与参考项目分析提供原始底座。范围覆盖三组对象：① 开源写作/世界构建工具（novelWriter、manuskript、bibisco、Obsidian、Logseq、SillyTavern、Long-Novel-GPT、GPT-Author、show-me-the-story、Closure、Fantasia Archive、Azgaar's Fantasy Map Generator）；② 商业创作工具（NovelCrafter、Sudowrite、NovelAI、World Anvil、Campfire、LegendKeeper、Plottr、Scrivener、Ulysses、Vellum）；③ 中文码字与网文工具（橙瓜码字、壹写作、小黑屋、墨者写作、妙笔 WonderPen、Effie、阅文/起点作家助手、番茄作家助手）。边界：本领域只做横向比较与「可借鉴 / 明确不照搬」的结论提取；编辑器内核见 S5 与 K14，存储与检索见 S8，AI 注入机制见 J03/J05，派系包机制见 G06。核心问题：御书的「世界分层构建 + 一致性校验 + 派系包 + AI 合规证据链 + 本地数据主权」在竞品格局中处于什么位置，哪些单点能力已被验证、哪些组合尚未被任何一家同时做到。

## 2. 核心知识框架

1. **世界观构建方式：实体化 vs 文档化**。World Anvil / Campfire / LegendKeeper / Fantasia Archive 走「类型化条目 + 模板 + 双向链接」路线——World Anvil 提供 25+ 世界构建模板，并允许「先为尚未创建的条目建链接（自动进待办）」；Campfire 把世界拆成 18 个互联模块（文化/物种/语言/宗教/魔法/时间线/历法）；Fantasia Archive 是免费离线同构实现，侧重「信息之间的关系」而非写作本身。相反，Scrivener / Ulysses / 壹写作 / 妙笔把世界当「文档与文件夹」，靠 Binder 树、白板卡片、自定义元数据承载设定（弱结构化）。
2. **类型化设定卡**。bibisco 用「人物访谈式」问卷生成人物档案并统计人物出场分布；NovelCrafter 的 Codex = 条目 + Aliases & Mentions + Progressions（设定随剧情演进）；NovelAI Lorebook 是设定注入的事实标准（激活关键词/正则/Always On/Token Budget/插入顺序/级联激活）；SillyTavern World Info 把机制推到最全（扫描深度/递归/互斥组/时序效果/插入位置）。御书「类型化设定卡 + schema 扩展」与之一致，但在「世界观分层与上游变更传播」上无竞品对标。
3. **关系、时间线与地图**。LegendKeeper 把「无限嵌套地图 + 每根图钉链接 wiki 页面 + 时间线/白板」绑成一件事；Campfire 设 Relationships（关系网/家谱）、Timeline、Calendar（多月亮/自定义纪元）三模块；World Anvil 用「平行时间线 + 纪元分段」支持多国/多角色视角；Azgaar 用 Voronoi 程序化生成，输出 PNG/SVG/JSON 全量世界状态，其「world / generators / editors / renderers」四层架构是分层依赖管线的工程范本。中文侧普遍只有「人物卡高亮」（橙瓜）与「白板/卡片列表」（妙笔），几乎没有关系图与时间线。
4. **流派模板组合**。Plottr 内置 40+ 基于成熟故事结构的模板（英雄之旅/救赎节拍/12 步悬疑/三幕/故事圈），并高调强调「没有 AI」；Campfire 提供 10+ 结构模板与可复用元素模板；Scrivener 提供小说/剧本/学术等项目模板。但这些都是「结构模板」而非「流派语义包」——没有任何一家把「境界体系卡 + 战力校验规则 + 爽点节拍 + 平台映射」打包成可插拔、可分享的派系包（docs/01 §3.2）。
5. **AI 记忆与上下文注入**。NovelAI 的 Lorebook 与 SillyTavern 的 World Info 定义了「关键词触发 / 常驻注入 / Token 预算 / 插入优先级」这套一等参数；NovelCrafter 的 Codex Tracking 保证「只把相关条目送进上下文」；Long-Novel-GPT 用「大纲→章节→正文」三层扩写 + RAG 上下文 + 拆书导入；show-me-the-story 是「设定条目全量注入 + 事实抽取带出处 + 伏笔追踪 + 一致性校验」的中文完整开源实现；Closure 是「本地优先 + 人物卡 + 世界观资产卡」的最接近直接竞品；gpt-author 是「候选情节→大纲→逐章→EPUB」的最小全流程。御书「记忆分层 + 核心常驻 + 别名触发 + 上下文预览器」（docs/01 §4.3、J03/J05）是这些机制的合流与加强。
6. **一致性检查**。竞品普遍停留在「提供结构化设定供作者自查」：Scrivener 只能把早前章节与本章并排对照；bibisco 提供人物出场分布；show-me-the-story 与 Closure 做到「事实抽取 + 校验」，但覆盖范围有限。跨层一致性引擎（等级战力 / 时间线 / 人物-历史冲突 / 称呼漂移）在竞品中基本缺失，是御书最明确的能力空白区。
7. **本地优先与数据迁移**。novelWriter（纯文本 + 类 Markdown + @tag，对 Git 最友好）、manuskript（开放纯文本项目格式）、Logseq（数据库版用 SQLite + isomorphic-git）代表开源侧；中文侧小黑屋、墨者、壹写作、妙笔都强调离线本地 + 云备份。反面案例：商业工具（World Anvil / Campfire / LegendKeeper）云端绑定，LegendKeeper 只能以「永远可用导出、你拥有数据」作为反锁定承诺；而墨者写作已于 2022 年后停运，直接印证「云服务停运 = 书稿风险」。
8. **版本历史与防丢稿**。橙瓜「时光机」每章 10 个云端备份 + 本地备份；墨者每章 5 个历史版本；妙笔默认每 15 分钟全库备份 + 最近文档快照；小黑屋每回车即保存、每十分钟生成独立文档并可邮箱存稿；Ulysses 提供本地自动备份。御书「四层防线（WAL+debounce / 本地快照 / 崩溃恢复 / 防手滑）+ 可 Git 版本化」（docs/01 §4.6、S8）在粒度与可迁移性上高于全部竞品。
9. **中文网文工作流适配**。橙瓜码字是「国产功能全家桶」标杆：多端同步、拼字战队、强制锁定、随机取名、敏感词检测、大纲助手、自动分章（设定字数触发切章）、一键排版（首行缩进两字、段间空行）、稿费预测、护眼模式；妙笔提供大纲视图 + 自定义元数据 + 一键排版 + 打字机模式；阅文作家专区与番茄作家课堂把「黄金三章 / 伏笔表 / 百万长篇时间线规划 / 发稿前四步自查」工具化。御书需把这些「默认预期」内置，再用「平台规则包 + 有效字数口径」（I07/I08）做本地化增强。
10. **插件扩展**。Obsidian / Logseq / SillyTavern 都有成熟插件或扩展生态，SillyTavern 的多后端抽象是「模型无关架构」的参照；中文工具几乎全部封闭、不可扩展，只用「皮肤/主题」满足个性化。御书的五类扩展点（命令 / 视图 / 实体类型 / 规则 / AI 任务，docs/01 §4.10）可对标 Obsidian 与 SillyTavern，但增加了「规则」与「AI 任务」两个创作领域专属扩展点。
11. **许可证、定价与锁定风险**。开源侧：novelWriter GPLv3、manuskript GPL、SillyTavern AGPL、Fantasia Archive GPL-3.0、Azgaar 与 gpt-author 多为宽松许可；商业侧：Scrivener 一次性买断、Ulysses 订阅、Vellum 一次性（Vellum Press $249.99）、Plottr 一次性/订阅混合、Campfire / LegendKeeper / World Anvil 订阅制且 LegendKeeper 明确「订阅失效后仍可查看与导出」；中文侧：橙瓜免费 + VIP 增值、妙笔免费 / Pro 买断 / Pro+ 订阅、壹写作免费 + 订阅。锁定风险的判据不是价格，而是「数据能否无损带出」。
12. **可借鉴与明确不照搬**。可借鉴：novelWriter 的纯文本 + 实体标记；Azgaar 的分层生成管线；LegendKeeper / Campfire 的「地图-条目-时间线」三位一体；NovelCrafter / NovelAI 的别名提及与注入预算；橙瓜的时光机与自动分章；Vellum 的「导出即排版」。明确不照搬：云端绑定与强制账号；把设定写成不可迁移的私有数据库；仅在「结构模板」层面做流派（缺语义与校验）；把 AI 做成默认开启的代笔（97% 作者反对 AI 代写，见 S6）；把导出锁在付费墙后。

## 3. 可转化为产品规则的关键实践

1. 类型化条目 + 双向链接 + 「空链接自动进待办」（World Anvil / LegendKeeper / Campfire）→ 设定条目支持 `[[未创建条目]]` 占位，自动生成「待补设定」清单。
2. 地图图钉链接条目、条目反查地图（LegendKeeper / Campfire）→ 地点卡与地图标注双向绑定，支持图中图（大陆→城→建筑）嵌套。
3. 平行时间线 + 纪元分段（World Anvil / Campfire）→ 编年史支持多文化视角与多历法渲染，内部统一数字刻度（docs/01 §4.2）。
4. 程序化分层管线（Azgaar：world→generators→editors→renderers）→ 生成、编辑、渲染三层分离，允许「生成→手工微调→再生成」不回退手工结果。
5. 设定注入双轨（NovelAI / SillyTavern：关键词触发 + Always On）→ 记忆系统提供「常驻 / 别名触发 / 正则触发」三类激活器与 Token 预算（docs/01 §4.3、J05）。
6. Aliases & Mentions + Progressions（NovelCrafter）→ 设定卡支持别名表与「随剧情演进」的历史版本（战力/身份/关系随时间变化）。
7. Material Sheets 不计入字数（Ulysses）→ 设定卡/大纲/研究资料默认不计入「正文有效字数」，仅正文与章节计入统计（I08）。
8. 时光机 + 每章多版本（橙瓜 / 墨者）+ 15 分钟全库备份（妙笔）→ 项目级自动快照 + 章节级历史版本双轨，均落本地文本（docs/01 §4.6、S8）。
9. 自动分章（字数触发切分）+ 一键排版（首行缩进两字 / 段间空行）→ 导入存量稿自动分章（I09）+ 按 clreq / GB/T 15834 的一键排版（K14）。
10. 强制锁定小黑屋（时间 / 字数）+ 段落聚焦 / 沉浸（橙瓜 / 小黑屋）→ 专注模式：番茄钟 + 沉浸 + 可选锁屏，均可关闭（docs/01 §4.6、I08）。
11. 商业工具「永远可导出」承诺（LegendKeeper）→ 数据主权验收项：任一功能下线后，纯文本与导出管线仍可用（docs/01 §6）。
12. 竞品缺失的跨层一致性校验（战力 / 时间线 / 称呼）→ 作为御书「规则引擎 + 校验规则集」的首要差异化能力（D03 / J07）。
13. 结构模板 ≠ 流派包（Plottr / Campfire / Scrivener）→ 派系包必须含 schema 扩展 + 校验规则 + 爽点节拍 + 平台映射（G06），不能只做「大纲骨架」。
14. 中文化默认预期（橙瓜 / 妙笔 / 网文平台）→ 默认开启中文校对、敏感词自查、取名助手、平台分类映射。
15. 云依赖风险（墨者停运、World Anvil / Campfire 云端绑定）→ 官方立场：核心创作链路 100% 离线可用，云仅作可选备份（docs/01 §5 非目标）。
16. 插件扩展但内核最小（Obsidian / SillyTavern vs 封闭中文工具）→ 五类扩展点 + 派系包工坊，内核只保留最小通用概念（docs/01 §3.3）。

## 5. 对御书设计的启示

**数据结构建议：竞品矩阵字段 schema（供 docs/02 引用）**

```yaml
# research/competitors.yaml —— 每行一条竞品记录；字段即 12 维比较维度
- id: legendkeeper
  name: LegendKeeper
  group: commercial            # open_source | commercial | chinese
```

**校验规则建议（规则 id）**

- `comp-schema-complete`：矩阵条目缺 12 维中任一字段或缺 `sources` → error（禁止无出处的竞品结论）。
- `comp-source-verified`：`sources` 引用的编号在 §4 不存在或 URL 非 http(s) → error。
- `comp-license-unknown`：`license` 为 proprietary 但 `pricing.model` 为空 → warn（需补定价口径）。
- `comp-lockin-claim`：任一条目 `data_format: proprietary_cloud` 且 `export_formats` 为空 → error（必须记录数据能否带出）。
- `comp-diff-coverage`：御书差异化 6 项（世界分层 / 一致性校验 / 派系包 / AI 证据链 / 本地主权 / 中文工作流）中存在任一未被任何竞品覆盖的说明 → info（提示可标注「无竞品」）。
- `comp-borrow-empty`：任一条目 `borrow` 与 `avoid` 均为空 → warn（要求给出明确判断，不接受功能罗列）。

**功能建议**

- 竞品矩阵视图：docs/02 用同一份 `competitors.yaml` 渲染「12 维 × 30 家」透视表，支持按 group 与维度筛选，替代功能罗列式清单。
- 「差异化雷达」：把御书现有能力与每家竞品在 12 维上打分，自动生成「无人同时做到」的能力清单（对应 docs/01 §1 差异化定位）。
- 借鉴-落地台账：每条 `borrow` 必须能链接到 K01/K14/J/G 某篇调研或一条功能需求，形成「竞品 → 规则 → 需求」可追溯链。
- 「不照搬」清单看板：把 `avoid` 项固化为设计评审检查项（评审 PR 时逐条确认未踩坑）。

**AI 提示词建议**

- 「竞品补全」：输入项目名 + 官网/仓库 URL，输出符合上述 schema 的 YAML 草案，并标注需人工核实的字段（不臆造定价与许可证）。
- 「借鉴点提炼」：输入某竞品功能页正文，输出「可借鉴点 / 明确不照搬点」两组，各自附一句理由与对应御书能力编号。
