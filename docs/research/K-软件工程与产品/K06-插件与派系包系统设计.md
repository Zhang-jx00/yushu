# K06-插件与派系包系统设计

> 类别：K-软件工程与产品 ｜ 世界构建金字塔层级：工程层 · 软件工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究御书的可扩展性工程：插件 API 五类扩展点（命令/视图/实体类型/规则/AI 任务，docs/01 §4.10）；插件安全边界（沙箱、权限声明、受限 API，与 K12 分工只引用）；派系包的工程化（manifest 结构、11 件套文件位、schema 扩展点、规则 DSL，全部以 G06 为唯一输入）；多包融合与冲突消解的工程实现（覆盖优先级 user > pack > engine、融合预演报告）；包/插件的导入导出、版本化与兼容区间；社区分发与审核（引用 K15）。边界：G06 研究派系包的内容建模（YAML 草案、schema、规则 DSL、融合策略），本领域研究其工程承载（文件布局、加载器、扩展点注册、版本与分发）；K12 研究安全实现细节，本领域只声明权限模型并引用它。

## 2. 核心知识框架

1. **游戏 Mod 数据格式先例**。Minecraft 数据包：根目录 `pack.mcmeta` + `data/<namespace>/<type>/<name>.json`，命名空间隔离，同名文件按类型「完全覆盖或合并」，`pack_format` 声明兼容版本。RimWorld XML Defs：Def 可用 `ParentName` 继承，`Patches/` 目录以 PatchOperationAdd/Insert/Remove/Replace + xpath 定位补丁，`PatchOperationFindMod`/`PatchOperationTest` 做条件补丁。Stardew Content Patcher：`Format` 版本 + `Changes` 指令集（EditData/EditMap/Include）+ Tokens/条件，manifest 内 `ModId` 作 ID 前缀。共同模式：声明式数据 + 稳定 ID + 命名空间 + 覆写/补丁分层 + 格式版本区间。
2. **IDE 插件 API 先例**。VS Code：Extension Manifest（name/version/publisher/`engines.vscode`/license/`contributes`/`activationEvents`）+ Contribution Points（`contributes.commands`/`views`/`configuration`/`languages`… 静态声明式扩展点）。Obsidian Plugin：`manifest.json`（id/name/version/`minAppVersion`/`isDesktopOnly`）+ 入口 `main.js` 导出 Plugin 子类，`registerView`/`registerEditorExtension`/`addCommand`/`addSettingTab` 注册能力，`versions.json` 做版本回退映射，`registerEvent`/`registerDomEvent`/`registerInterval` 在卸载时自动清理。
3. **扩展点分类（映射五类）**。命令→commands/registerCommand；视图→views/registerView；实体类型→语言/校验 schema 注册；规则→contributes + 规则 DSL；AI 任务→工具/任务路由注册（对应 docs/01 §4.10）。
4. **权限与安全边界**。插件声明所需能力，宿主授予最小权限；表达式禁循环禁 IO、求值超时与递归深度上限（CEL 安全原则，见 G06）；安全实现细节交 K12。
5. **融合与冲突消解（承接 G06）**。优先级 `user overrides > pack 显式声明 > 引擎默认`；冲突显式提示、禁止静默合并；融合预演报告（新增/覆盖/冲突三类）确认后才写入项目配置（docs/01 §3.3）。
6. **版本化与兼容区间**。语义化版本 + requires 区间 + 兼容回退表；包间依赖图与循环依赖检测（G06 §6）。

## 3. 可转化为产品规则的关键实践

1. manifest 声明式 → 插件/包均以 manifest 描述元数据与能力，加载器只读 manifest 决定注册什么（VS Code 模式）。
2. 命名空间隔离 → 所有 ID 用 `<publisher>.<plugin>` 或 `<pack_id>/<element_id>`，杜绝跨包冲突（G06）。
3. 五类扩展点注册 → 插件通过声明式 contributes 注册命令/视图/实体类型/规则/AI 任务，宿主在激活时实例化。
4. 补丁分层 → 插件/包可携带 patch 操作（改字段/增条目/删条目）而不 fork 原包（RimWorld PatchOperation / Content Patcher 模式）。
5. 条件启用 → 借鉴 PatchOperationFindMod，插件/包声明「仅当某包存在时生效」。
6. 版本区间 → manifest 声明 requires(yushu 区间) 与包依赖；不满足即拒绝加载并给出可读原因（Obsidian minAppVersion 模式）。
7. 融合预演 → 项目向导先出融合报告（新增/覆盖/冲突），用户确认后才写入项目配置（docs/01 §3.3）。
8. 卸载清理 → 插件注册的资源由宿主统一登记与反注册，避免手动清理遗漏（Obsidian register* 模式）。
9. 分发审核 → 包/插件走社区市场规范：lint（schema/ID 唯一/11 件套齐全/映射覆盖 ≥1 平台）+ 人工审核（引用 K15）。
10. 权限最小化 → manifest 声明权限（文件/网络/AI），默认只读，越权调用拒绝并记录（细节见 K12）。

## 5. 对御书设计的启示

**数据结构建议：插件 manifest（草案）**

```yaml
# .yushu/plugins/<id>/manifest.yaml
apiVersion: yushu.plugin/v1
kind: Plugin
id: yushu.pomodoro            # publisher.name，作命名空间前缀
name: 番茄钟
version: 0.3.1                # semver
license: MIT
requires: {yushu: ">=0.4.0 <0.6.0"}
permissions: [editor:read, ui:view, storage:local]   # 最小权限声明（实现见 K12）
contributes:                  # 五类扩展点（docs/01 §4.10）
  commands:    [{id: pomodoro.start, title: 开始专注}]
  views:       [{id: pomodoro.panel, location: sidebar}]
  entityTypes: []             # 实体类型扩展（如恐怖「规则卡」）
  rules:       [rules/hook-density.yaml]
  aiTasks:     [{id: pomodoro.break-tip, provider: default}]
main: dist/index.js
```

**派系包 manifest（以 G06 §5 为唯一输入，本领域仅补工程字段）**

```yaml
apiVersion: yushu.pack/v1
kind: GenrePack
metadata:
  id: xuanhuan-xitong          # 与 G06 完全一致，不得另立格式
  version: 1.2.0
  requires: {yushu: ">=0.4.0"}
  integrity: {hash: sha256:..., files: [...]}     # 本领域新增：完整性
content: { ... 11 件套文件位，见 G06 §5 ... }      # 不在此重复定义
conflicts_with: [{pack: guiju-guaitan, reason: "..."}]   # 承接 G06
```

**多包融合报告（预演，写项目配置前）**

```yaml
# .yushu/fusion-preview.yaml
axes_merged: {world: [玄幻], technique: [系统流, 穿越流], tone: [爽文]}
added:      [schemas/系统面板卡.yaml, rules/realm-progress.yaml]
overridden: [{file: glossary.yaml, by: 用户覆盖, fields: [境界名]}]
conflicts:
  - {type: schema_field_type, target: 境界体系卡.tier, packs: [A, B], resolution: pending}
  - {type: beat_phase, target: 情绪节拍, packs: [爽文, 黑深残], resolution: pending}
precedence: user > pack > engine    # 与 G06 一致，禁止静默覆盖
approved: false                      # 未确认不得写入项目配置
```

**功能建议**

- 市场与包工坊同构：导入导出统一为目录/zip，入口 manifest 决定类型（Plugin/GenrePack）。
- 扩展点注册中心：宿主维护五类扩展点注册表，插件激活时按 contributes 注册、禁用时统一反注册。
- 融合预演向导：选多维派系 → 生成 fusion-preview（新增/覆盖/冲突）→ 逐项裁定 → 写入项目配置。
- 兼容性检查器：加载前校验 requires 区间、包依赖图（含循环依赖）、文件完整性 hash。
- 权限中心：集中展示已装插件声明的权限与来源，支持逐项收回（呼应 docs/01 §6 默认关闭）。
- 包 lint 工具：分享前校验 schema 合法、ID 唯一、11 件套齐全、平台映射覆盖 ≥1（G06）。

**校验规则建议**

- `plugin-manifest-invalid`：manifest 缺必填字段或类型错 → error。
- `plugin-id-namespace-collision`：ID 未带命名空间前缀或与既有插件重复 → error。
- `pack-requires-unsatisfied`：requires 区间不满足引擎/依赖包版本 → error（拒绝加载）。
- `pack-dep-cycle`：包间 requires 构成循环依赖 → error（G06 §6）。
- `fusion-conflict-unresolved`：存在 conflicts 且 resolution=pending 即写入项目配置 → error。
- `plugin-permission-undeclared`：插件调用未声明的权限 API → error 并阻断（细节见 K12）。
- `pack-fileset-incomplete`：11 件套文件位缺失 → warn（市场 lint 时升为 error）。

**AI 提示词建议**

- 「派系包生成器」：输入四维取值 + 示例需求，输出符合 G06 manifest 骨架的包文件候选（不自动发布）。
- 「冲突解读」：输入 fusion-preview 冲突项，输出各方案对写法/节拍的影响与建议。
- 「插件脚手架」：按五类扩展点生成 manifest + 最小示例代码骨架。
