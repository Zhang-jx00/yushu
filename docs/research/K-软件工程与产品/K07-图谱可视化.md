# K07-图谱可视化

> 类别：K-软件工程与产品 ｜ 世界构建金字塔层级：工程层 · 软件工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究"把实体与关系渲染为可交互图"的工程实现：展示层图库选型、数据层的图存储与增量更新、布局算法与稳定性、大规模下的渲染策略、编辑态与只读探索态的交互分工，以及图谱与实体卡（设定卡）的联动。边界划分：K03 管数据模型与文件格式（节点/边的规范定义），本领域只管"图怎么画、怎么动、怎么点"；E03 管人物关系网的社会学建模，本领域负责其可视化落地；世界引擎的影响传播（依赖图）归 K05，本领域为它提供通用渲染视图。docs/01 §4.9 明确了两条产品线：可编辑的关系图谱（React Flow/G6）与只读探索的世界观全量知识图谱（Sigma.js）。

## 2. 核心知识框架

1. **展示层三选型（对齐 docs/01 §4.9 结论）**。① React Flow（@xyflow/react）：面向"节点即 React 组件"的编辑式应用，数据为 `nodes[]`+`edges[]`，每条边需 `source`/`target`，节点用 `data` 承载自定义内容；内置缩放/平移/多选/连线、`<MiniMap/>`、`<Controls/>`，优势是自定义节点（把设定卡嵌进节点）与受控状态（applyNodeChanges），适合万级以内"可编辑关系图"。② AntV G6：国产图引擎，内置 20+ 布局（力导向/dagre/环形/同心圆/树），支持 Canvas/SVG/WebGL 多渲染器与分层画布混用，布局可下放 Web Worker/WASM/GPU，中文文档最全。③ Sigma.js + graphology：WebGL 渲染，官方定位"数千节点与边"；graphology 负责图数据模型与算法，sigma 负责渲染与交互，适合十万级"只读探索"。
2. **性能特征对比**。SVG/DOM（React Flow）单节点可任意定制、交互精细，但节点数是 DOM 量级，万级需虚拟化；Canvas（G6 默认）渲染快、定制受限；WebGL（Sigma/G6 GPU）十万级流畅，但"拾取"（picking）需额外通道——Sigma 渲染两张图，一张正常着色、一张以唯一颜色编码 ID，据像素颜色反查命中项。
3. **数据层：中等规模优先 SQLite**。docs/01 技术基线即"关系图谱中等规模优先 SQLite `nodes`/`edges` 表"，即属性图两表建模，多跳用 CTE，暂不引入外置图库（K03/S8）。图只是设定卡的派生视图——真源仍是实体文件，图索引可从文件重建。
4. **增量更新**。图随写作持续变化（新角色、新关系、事件新增参与者），策略是插入/删除节点与边时只对受影响子图做最小重布局；G6 提供 `graph.layout()` 手动触发与 `stopLayout()`，力导向布局是异步迭代过程。
5. **布局算法与稳定性**。力导向（d3-force/ForceAtlas2/Fruchterman）适合探索式布局，ForceAtlas2 用 Barnes-Hut 近似把斥力从 O(n²) 降到 O(n log n)；层次布局（dagre，rankdir TB/LR）适合"势力从属/血脉/传承"等有向无环结构。稳定性问题的学术口径是"保留心智地图（mental map）"：动态图布局用时间惩罚（temporal penalty）与分组惩罚（grouping penalty）抑制相邻时刻节点的大位移，避免重布局跳动、用户迷失。
6. **大规模渲染策略**。视口虚拟化（只渲染可见元素）是万级第一手段；缩放到宏观时虚拟化失效，需"语义缩放/LOD"——低于某 zoom 阈值用简化节点（纯色块/聚类）替换复杂节点；聚类折叠把社区折叠为超级节点；迷你地图改用 Canvas 绘制以省 DOM。渲染器选择原则：编辑态少量节点用 DOM/SVG，探索态海量节点用 WebGL。
7. **双模式交互**。编辑态：拖拽节点改布局并写回坐标、拖手柄连线建关系、双击进设定卡。只读态：搜索定位、悬停高亮邻域、按类型/势力过滤、点击节点开设定卡，不允许意外改数据。
8. **图谱与实体卡联动**。节点 id 即实体 id（character/location/faction/item/event）；点击节点打开设定卡抽屉；设定卡内提供"在图谱中定位"，悬停显示摘要，与 docs/01 §4.7 的实体内联标记（@引用）共用同一套实体解析。

## 3. 可转化为产品规则的关键实践

1. 图 = 实体与关系的派生视图 → 图谱从设定卡 frontmatter 的 relations 聚合生成，真源仍是文件，图谱索引只读可重建（对齐 K03）。
2. 属性图两表建模 → SQLite `nodes`/`edges`（schema 见 §5），多跳关系用递归 CTE，不引入外置图库。
3. 编辑态与探索态分库分层 → 关系图谱（人物/势力）用 React Flow 或 G6，节点数上限万级；世界观全量图谱用 Sigma.js WebGL，十万级（docs/01 §4.9）。
4. 增量更新最小化 → 新增节点/边只触发受影响子图重布局；提供"重新布局"手动按钮（G6 `graph.layout()`），力导向后台迭代、可 `stopLayout`。
5. 布局稳定性优先 → 力导向布局以已有坐标为初始值增量迭代（graphology 要求节点先有 x/y），并对既有节点施加位移约束，避免每次打开图谱全部漂移。
6. 视口虚拟化 + LOD → 编辑态超阈值启用 `onlyRenderVisibleElements`；缩放低于阈值启用简化节点；节点/边数超阈值提示降级（联动 K13 性能预算）。
7. 聚类折叠 → 按势力/阵营/地域把子图折叠为超级节点，展开时再渲染内部。
8. 布局类型按语义选 → 无向关系网用 force；从属/血脉/传承用 dagre（rankdir=TB）；编年因果链可复用同一渲染器（联动 C02）。
9. 图即导航 → 节点点击打开设定卡抽屉、悬停显示摘要、右键"在图谱中定位"，双向联动（docs/01 §4.7）。
10. 过滤与分片 → 按实体类型、叙事可见性（冰山原则）、剧情出现章次过滤，避免一次全量渲染（对齐 docs/01 §4.2 元数据）。

## 5. 对御书设计的启示

**数据结构建议：图谱索引表（SQLite，真源为设定卡文件，索引可重建）**

```sql
-- nodes：实体投影（id 与设定卡 id 一致）
CREATE TABLE nodes (
  id       TEXT PRIMARY KEY,        -- char-xxx | loc-xxx | fac-xxx | item-xxx | event-xxx
  type     TEXT NOT NULL,           -- character | location | faction | item | skill | event
  label    TEXT NOT NULL,           -- 显示名（随设定卡同步）
  group_id TEXT,                    -- 所属势力/阵营（用于聚类折叠）
  x REAL, y REAL,                   -- 力导向布局缓存坐标（写回文件 frontmatter）
  visible  INTEGER DEFAULT 1,       -- 叙事可见性（冰山原则：已写未揭示可默认隐藏）
  meta     TEXT                     -- JSON：别名、出现章次等
);
-- edges：关系投影（有向，kind/weight 决定渲染）
CREATE TABLE edges (
  id       TEXT PRIMARY KEY,
  source   TEXT NOT NULL REFERENCES nodes(id),
  target   TEXT NOT NULL REFERENCES nodes(id),
  kind     TEXT NOT NULL,           -- parent|ally|enemy|belongs_to|located_in|participates_in
  weight   REAL DEFAULT 1,          -- 关系强度 → 线宽/边距
  canon    TEXT,                    -- 正史/传说/敌方记载（多版本关系，联动 C02）
  directed INTEGER DEFAULT 1
);
CREATE INDEX idx_edges_source ON edges(source);
CREATE INDEX idx_edges_target ON edges(target);
```

```yaml
# 图谱视图配置（随项目保存，非数据真源）
graph_view: character_relations
mode: editable            # editable(React Flow/G6) | explore(Sigma.js)
layout: { type: force, initial: keep_existing, enable_worker: true }
lod: { virtualize_above: 800, simplify_node_below_zoom: 0.5 }
cluster: { by: faction, collapsible: true }
filters: { types: [character, faction], visible_only: true, chapter_range: [1, 999] }
```

**校验规则建议**

- `graph-node-orphan`：`nodes` 中无任何边且 meta 未标记"孤立角色" → info，提示可能漏建关系。
- `graph-edge-dangling`：`edges.source/target` 在 `nodes` 中不存在 → error（索引与文件不同步）。
- `graph-entity-link-broken`：节点 `id` 找不到对应设定卡文件 → error（图谱必须回指真源，对齐 K03）。
- `graph-layout-unstable`：同一视图两次重布局后既有节点平均位移超过阈值（如 120px）→ warn，提示冻结坐标。
- `graph-perf-budget`：单视图节点数 > 10000 且未启用 WebGL/LOD → warn（联动 K13）。
- `graph-relation-canon-conflict`：同一对实体的多条 `canon` 关系互相矛盾 → info，作为伪史书特性展示而非报错（联动 C02）。

**功能建议**

- 分模式入口：设定面板的"关系图谱"默认编辑态；"世界知识图谱"默认只读探索态，两态共享同一 nodes/edges。
- 节点即卡：自定义节点显示头像/名称/一句简介，双击打开设定卡抽屉；抽屉内"在图谱中定位"反向高亮。
- 布局工具条：力导向/层次/环形切换、重新布局、冻结已调好的节点、一键聚类折叠。
- 邻域聚焦：选中节点后淡出非邻域，提供"展开 1/2/3 跳"。
- 过滤面板：类型、势力、叙事可见性、章次范围；与记忆系统（J03/J05）共用实体索引。

**AI 提示词建议**

- 「关系抽检」：读取两实体的设定卡与共现章节，判定 `kind/weight` 是否失真，输出修正建议（人工确认后写回）。
- 「缺失关系提示」：基于"同门/同族/同事件参与者"规则，提示可能遗漏但未登记的关系。
