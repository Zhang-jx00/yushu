## 1. 领域定义

研究御书的版本层与数据保护工程：以 Git（isomorphic-git 纯 JS 实现）作为版本层，Markdown 真源天然可版本化（docs/01 §6）；快照机制（自动快照节奏、内容寻址存储、存储占用控制）；diff（文本 diff + 设定卡字段级结构化 diff）；崩溃恢复与自动保存的配合（引用 K04）；章节版本历史与「防手滑」（docs/01 §4.6 防丢稿四层防线）；AI 编辑轨迹留存（人类创作证据链的工程实现，引用 J13）；大仓库性能（百万字项目的 git 操作优化）。边界：K04 研究本地优先架构与自动保存/WAL，本领域研究其上层的版本/快照/diff/恢复；K03 定义文件格式，本领域只做其版本化；J13 定义证据链字段与合规，本领域提供其存储与检索实现。

## 2. 核心知识框架

1. **Git 是内容寻址文件系统**。`objects` 目录以内容 SHA-1 为键存 blob（文件内容）/tree（目录）/commit；`refs`/`HEAD`/`index` 为指针与暂存区；packfile + delta 压缩去重，本质是「object ID 是主键、object content 是值」的键值表。
2. **isomorphic-git**。纯 JS Git，可在 node/browser/Worker/ServiceWorker 运行，直接读写 `.git` 目录，与原生 git 100% 互操作；提供 `statusMatrix`（单次调用返回全仓 HEAD/WORKDIR/STAGE 三态矩阵）、`merge`（`dryRun` 预演、`abortOnConflict`）以及 commit/log/checkout/stash 等；fs 抽象层可接 OPFS/Node fs。
3. **快照先例（Obsidian 文件恢复）**。周期自动保存**文件全内容快照**（非仅差异），默认最小间隔 5 分钟、保留 7 天，存于仓库之外（全局设置，按绝对路径），可查看差异、复制或整体恢复，仅支持 `.md`/`.canvas`；空间随编辑频率累积，需按需调整保留期。
4. **撤销/重做与编辑分组**。ProseMirror history：`undo`/`redo` 命令 + `depth`（默认 100）+ `newGroupDelay`（默认 500ms 相邻变更成组）+ `closeHistory()`（强制分组）+ `addToHistory=false`（协同/UI 变更不入历史）。
5. **diff 算法**。Myers O(ND)（N=两串长度之和，D=最短编辑脚本大小），编辑图最短路模型，差异越小越快；Git 派生 `minimal`/`patience`/`histogram`（重构场景可读性更好）。
6. **WAL 崩溃恢复**。SQLite WAL 把改动追加到 `-wal` 文件、commit 后才应用主库；崩溃后由下一个进程做 recovery（校验 frame 的 salt/checksum 重建 WAL 索引）；WAL 不支持网络文件系统。
7. **大仓库性能**。Scalar/`git maintenance`（commit-graph 加速可达性计算、prefetch、incremental-repack、pack-refs），partial clone（`--filter=blob:none`）、sparse-checkout、FSMonitor、`feature.manyFiles`；浅克隆 `--depth` 减小历史。

## 3. 可转化为产品规则的关键实践

1. Git 作为版本层 → 项目根 `.git`，Markdown 真源分文件提交（一次提案/一次批量改动 = 一次提交），保留完整谱系（docs/01 §6 可 Git 版本化）。
2. 快照独立于 Git → 轻量本地快照（内容寻址 blob，仅存变更文件）承担高频保护与粗粒度回退；Git 提交承担语义化历史，二者分工。
3. 内容寻址存储 → 快照按内容 hash 去重，相同内容只存一份，控制占用。 
4. 快照节奏与保留 → 默认最小间隔 5 分钟、保留 7 天（可配），并设容量上限与自动清理（Obsidian 模式）。
5. 文本 diff → 章节正文用 Myers 文本 diff（前后对比、候选采纳高亮）。
6. 结构化 diff → 设定卡 YAML 用字段级 diff（路径 + 旧值/新值），直接对接影响传播（K05 proposal）。
7. 崩溃恢复分工 → 自动保存（WAL+debounce，承接 K04）保「当前会话不丢字」；快照保「误删/误改可回退」；Git 保「长期历史」。
8. 防手滑 → 破坏性操作（删除卷/清空章节/批量替换）先建快照 + 二次确认 + 可撤销窗口（docs/01 §4.6）。
9. 编辑轨迹 → 每次 AI 采纳/人工大批改记录 diff 与来源，写入证据链供申报（J13）。
10. 大仓库优化 → 启用 commit-graph/fsmonitor/增量重打包，正文按卷分目录避免单文件过大，百万字项目提交耗时可控（承接 K13）。
11. 多设备 → `.git` 与快照可经可选云备份（WebDAV/S3/Syncthing）携带，但索引库禁放网盘（K04）。

## 5. 对御书设计的启示

**数据结构建议：快照元数据（草案，内容存对象库）**

```yaml
# .yushu/snapshots/<ts>.yaml
snapshot_id: snap-20260929-1500
taken_at: 2026-09-29T15:00:12+08:00
trigger: autosave          # autosave | manual | pre_destructive | pre_apply_proposal
scope: [chapters/vol1, settings/characters/char-linyuan]
objects:                   # 内容寻址：仅存变更文件
  - {path: chapters/vol1/ch-012.md, blob: sha256:ab12..., size: 3120}
  - {path: settings/characters/char-linyuan.yaml, blob: sha256:cd34..., size: 812}
retention_days: 7
device_id: <local-id>      # 快照设备本地，不随同步
```

**编辑轨迹（证据链，J13 落地）**

```yaml
# .yushu/audit/edit-trail/ch-012.yaml
chapter: ch-012
events:
  - {ts: 2026-09-29T14:20:05+08:00, actor: ai, task: draft_prose, session: sess-2026...,
     before_blob: sha256:..., after_blob: sha256:..., accepted_chars: 340, human_edits_after: 412}
  - {ts: 2026-09-29T14:41:10+08:00, actor: human, op: rewrite, range: [1200, 1480]}
git_ref: {commit: <sha>, branch: main}
```

**结构化 diff（设定卡字段级，服务 K05 影响传播）**

```yaml
entity: char-linyuan
fields:
  - {path: realm.tier, from: 3, to: 4, change: modify}
  - {path: "refs[1].target", from: fac-danxia, to: fac-qingyun, change: modify}
  - {path: aliases, from: [], to: [墨客], change: add}
```

**Git 配置建议（大仓库优化）**

```text
feature.manyFiles = true
core.fsmonitor = true
core.untrackedCache = true
# 由应用在空闲时触发 commit-graph / incremental-repack，而非依赖系统定时器
```

**功能建议**

- 版本时间线：按 Git 提交 + 快照两层展示（提交=语义节点，快照=高频保护点），可对比、可回滚。
- 设定卡字段级 diff 视图：字段路径 + 旧/新值对照，一键生成 K05 proposal。
- 崩溃恢复启动流：检测到未正常退出 → 先读 WAL/自动保存残稿 → 提示「恢复未保存内容」（承接 K04）。
- 防手滑守卫：删除卷/清空章节/批量替换前自动建 pre_destructive 快照 + 二次确认 + 撤销窗口。
- 证据链查看器：把「版本历史 / 编辑轨迹 / AI 使用台账」按时间轴串成一条可读证据线（J13）。
- 存储占用面板：快照/对象库/Git 各自占用与清理入口，超阈值提示调整保留期。
- 百万字性能：正文按卷分目录分片、启用 commit-graph+fsmonitor、后台增量重打包。

**校验规则建议**

- `snapshot-retention-exceeded`：快照占用超阈值 → warn 并建议清理或缩短保留期。
- `git-index-in-sync-dir`：`.git` 或 SQLite 索引位于同步/网盘目录 → error（K04：索引禁放网盘）。
- `trail-ai-event-missing`：AI 采纳写入正文却无对应 edit-trail 事件 → error（证据链完整性，J13）。
- `prop-apply-without-snapshot`：应用变更提案前未建 pre_apply_proposal 快照 → error（可回滚底线）。
- `destructive-without-backup`：破坏性操作未触发 pre_destructive 快照 → error（docs/01 §4.6）。
- `snapshot-orphan-blob`：快照引用的 blob 在对象库中不存在 → error（内容寻址完整性）。

**AI 提示词建议**

- 「版本差异解读」：输入两次快照/提交的 diff，输出「改了什么、可能影响哪些设定与章节」（联动 K05）。
- 「提交信息生成」：依据本次改动生成符合规范的 commit message（叙事化描述改了什么）。
- 「恢复建议」：输入崩溃残留与最近快照，建议最可能想恢复的版本与合并点（只建议，不自动覆盖）。
