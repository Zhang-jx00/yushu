# D07-升级节点与爆点设计

> 类别：D-力量与文明水平 ｜ 世界构建金字塔层级：L4 文明层 + 叙事层交叉
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

升级节点与爆点设计研究"变强在剧情时间轴上的摆放艺术"：升级节点（突破/觉醒/得宝）放在哪里、蓄力期多长、爆点（爽点集中释放）如何设计、升级与冲突/断章/卷结构的对齐方式，以及"挣得的突破"（earned breakthrough）的铺垫-延迟-释放三段结构。边界：D01-D04 管"力量与载体是什么"，本领域管"力量增长在叙事中的编排"；它是升级流追读率的直接杠杆——网文实证显示爽点与期待感的编排比密度更能拉动追读。

## 2. 核心知识框架

1. **爽文通用算法**：压抑蓄力 → 暗示期待 → 集中释放 → 新循环。S1 种子库实证（知乎网文节奏分析）显示"删 1/3 爽点并延后，追读率 35%→67%"——期待感>爽点密度，延后释放比堆量有效。
2. **挣得的突破（earned breakthrough）**：progression fantasy 社区的核心共识——快速成长可以接受，但突破必须"在页面上挣得"：铺垫（setup）、训练/代价、障碍、回报四段齐全。TeaNovel 对比指出《凡人修仙传》韩立式缜密积累 vs 无因 power-up 是作品分水岭。
3. **升级节奏的两难与解法**：Royal Road 的 Progression Pacing 讨论共识是"小境界之间不要有无因的轻松升级"，用挫折期、资源瓶颈、意外中断把长升级拆成多章钩子；"Making progression more satisfying"则强调升级后要有"用新力量的舞台"，否则爽感打折。
4. **升级的代价与风险**：Entangled Text 准则——每次 power-up 绑定可见成本；Silas Bellhaven 强调"power-up 的满足感取决于周边 stakes"，风险越大、回报越响。突破失败/走火入魔/夺舍风险是天然的断章点。
5. **威胁递增与升级对齐**：TV Tropes 的 Rule of Escalating Threat 要求对手升级曲线与主角升级曲线咬合——每个大境界对应一个量级的对手与一卷的张力；爽点三分类（打脸/升级/收获）与"每章一个情绪波动点"是中文网文的操作层经验。

## 3. 可转化为产品规则的关键实践

1. 升级节点登记"铺垫四件套"：setup 伏笔引用 / 代价字段 / 障碍事件 / 回报舞台 → 四缺一预警"未挣得的突破"。
2. 升级速率承诺曲线与实际节点排布叠加视图 → 偏离预警（联动 D03 的 tone 字段）。
3. 爆点排布检查：每卷至少 1 个大爆点、每 3-5 章一个小爆点，断章落在情绪高点 → 卷级/章级两级节奏校验。
4. "新力量首用舞台"必填：突破后 N 章内须有展示新能力的高光场景 → 防突破即遗忘。
5. 对手曲线对齐：主角每升一大境，登记对应量级的对手/冲突升级事件 → 防对手脱轨（联动 D02 Sorting Algorithm of Evil）。
6. 压抑-释放配对统计：统计连续压抑章数，超过阈值提示"读者疲劳风险"。

## 5. 对御书设计的启示

### 数据结构建议
```
UpgradeNode {
  node_id, chapter_ref, type: "breakthrough|skill|item|realm",
  setup_refs: [],           // 铺垫伏笔（挂伏笔管理，≥1 条）
  cost, obstacle_event,     // 代价与障碍事件（挂事件日志 D03）
  payoff_stage_ref,         // 首用舞台章节承诺
  release_intensity,        // 释放烈度：小爆点/中/大爆点
  counterpart_threat_ref    // 对位威胁升级（挂对手实体）
}
PacingPlan {                 // 卷级排布
  volume_ref,
  climax_nodes: [],          // 大爆点（≥1/卷）
  minor_nodes_every: "3-5章",// 小爆点频率
  cliffhanger_policy: "情绪高点切",
  suppression_cap: 8         // 连续压抑章上限
}
```
### 功能建议
- "爽点排布甘特图"：按章渲染压抑段/释放点/断章位，与 PacingPlan 目标曲线叠加。
- 升级节点向导：四件套逐项填写，自动从伏笔库（F 域）拉取可引用铺垫。
- 与 D03 战力日志联动：突破节点自动生成战力变更事件，保证两边账本一致。

### 校验规则建议
- 升级节点 `setup_refs` 为空 → error："未挣得的突破：无铺垫引用"。
- 突破后 N 章内无 `payoff_stage_ref` 对应场景 → warning："新力量未展示"。
- 连续压抑章数 > `suppression_cap` → warning："读者疲劳风险，建议插入小爆点"。
- 大境界升级无 `counterpart_threat_ref` 升级事件 → warning："对手曲线脱轨"。

### AI 提示词建议
- 生成升级章节提示词模板："先写压抑与代价（2-3 拍），断章于情绪最高点；突破后 3 章内安排新能力高光；禁止无铺垫直接升级。"
