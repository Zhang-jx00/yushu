# D02-战力体系与天花板

> 类别：D-力量与文明水平 ｜ 世界构建金字塔层级：L4 文明层 + 叙事层交叉
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

战力体系与天花板研究"力量如何比较、比较的边界在哪里"：不同境界/路线/装备持有者之间的强弱换算规则、越级战斗的合法条件、以及整个世界的力量上限（天花板）声明。边界：D01 管"梯子的每一级长什么样"，本领域管"两级之间谁打得过谁"；D03 管"怎么防止比较规则随连载失守"，本领域负责把比较规则一次性声明清楚。天花板声明是升级流最容易缺位的文件——没有上限声明，"世界最强"就没有含金量。

## 2. 核心知识框架

1. **读者侧的 power scaling 文化**。粉丝社区已形成成熟的"战力体系"讨论文化：以"战绩（feats）"为证据、跨作品比较角色强弱。写作者必须意识到：任何前后不一致的战力表现都会被读者拿战绩对照并指出——战力一致性已从"隐性要求"变成"显性审判"。
2. **越级战斗需要"合法杠杆"**。社区共识是：等级排名系统能保持张力，但前提是张力分散在战斗过程中，而不是依赖最后一刻的 power-up 翻盘。越级战斗必须由体系内因素支撑：特殊功法克制、装备代差、地形、以命换命的代价——否则读者判定为"主角光环"。
3. **Sorting Algorithm of Evil（威胁递增算法）**：TV Tropes 总结的经典叙事规律——反派按威胁度严格递增登场。它隐含要求战力体系必须支持"严格排序"，且老反派在新反派出现后不能贬值（否则触发 Villain Decay：反派随时间失去威慑力）。
4. **天花板的两种写法**：（a）显式天花板——如《Cradle》早期就确立世界最高层力量，高层冲突以"影响主角世界"的方式呈现而非直接下场；（b）洋葱天花板——声明当前界上限，破界揭示更高层，每层各自自洽。社区对 Cradle 式"天花板早声明+高层事件间接化"评价极高。
5. **战力等级决定故事类型**。社区讨论指出：力量的绝对水平决定能讲的故事类型（凡人视角/精英视角/神明视角），但讲故事的手法不变。写作者应先声明天花板，再据此选故事视角，而非反过来。

## 3. 可转化为产品规则的关键实践

1. 建立全局"天花板声明"文件：世界最高力量是什么、由谁持有、读者何时知道 → 模板化"天花板声明卡"（见第 5 节）。
2. 战力比较不走数值而走"规则三元组"：压制关系/换算关系/例外条件 → 生成战力比较规则表。
3. 每场跨境界战斗必须登记"越级杠杆"类型 → 战斗情节校验：无杠杆的越级胜利标黄为"主角光环嫌疑"。
4. 反派退场后声明其战力档案冻结 → 防 Villain Decay：老反派再登场时与档案冲突即报错。
5. 高层战力"间接呈现"白名单：高层冲突影响低层世界的方式（天象、余波、遗物、传闻）→ 提示词库。
6. 装备/丹药带来的战力增益必须登记时效与代价 → 防止"临时增益"被默认为常态战力（联动 D03/D04）。

## 4. 信息来源

1. [经典理论资料] Brandon Sanderson — Laws of Magic FAQ — https://faq.brandonsanderson.com — 第二定律"限制大于能力"：战力比较规则的根基是每个力量都有明确不能做的事。
2. [百科词条] TV Tropes — Sorting Algorithm of Evil — https://tvtropes.org/pmwiki/pmwiki.php/Main/SortingAlgorithmOfEvil — "反派按威胁度严格递增登场"的经典叙事算法及其古老根源。
3. [百科词条] TV Tropes — Rule of Escalating Threat — https://tvtropes.org/pmwiki/pmwiki.php/Main/RuleOfEscalatingThreat — "总有更大的鱼"：威胁持续升级的姐妹原则及其风险。
4. [百科词条] Tropedia — Villain Decay — https://tropedia.fandom.com/wiki/Villain_Decay — 反派贬值现象定义：存活到后期的反派威慑力衰减，战力档案需要冻结机制的直接依据。
5. [社区讨论] Mythic Scribes 论坛 — Power levels and types of stories — https://mythicscribes.com — 战力水平决定可讲的故事类型，但叙事手法不变；选视角前先定天花板。
6. [社区讨论] Mythic Scribes 论坛 — An idea for a system where rpg mechanics/skills are part — https://mythicscribes.com — 《Cradle》案例：早立天花板、高层事件影响主角而非高层亲自下场。
7. [社区讨论] FanFiction.net Writers Anonymous — Writing: power scaling — https://www.fanfiction.net — 排名系统应让张力分布在整个战斗过程，而非依赖最后一刻的 power-up。
8. [评测] The Flaws of Power Scaling in Fiction — https://www.scribd.com — 跨作品战力比较缺乏逻辑一致性的批判分析：战绩解读依赖各宇宙规则，须避免混用。
9. [技术文章] Versarien — The Definitive Guide to Power Scaling and Character Feats — https://versarien.com — 战绩（feats）文化与粉丝战力审判的兴起：不一致战力的社会性代价。

## 5. 对御书设计的启示

### 数据结构建议：战力比较规则 + 天花板声明
```
CeilingStatement {          // 天花板声明（全书唯一，可分层多个）
  scope,                    // 适用范围：当前界/大陆/位面
  apex_desc,                // 最高力量描述（存在形态、能否行动）
  apex_holders,             // 持有者清单（角色引用）
  reveal_chapter,           // 读者何时知晓（reveal state，联动冰山原则）
  indirect_effects: []      // 高层力量影响低层世界的白名单方式
}
PowerComparisonRule {
  rule_id,
  relation: "压制|换算|例外",      // 三类比较关系
  a_ref, b_ref,                   // 境界/路线/装备 引用（挂 D01/D04 卡）
  condition,                      // 例外条件：克制、地形、代价
  evidence_ref                    // 正文中支撑该比较的章节战绩锚点
}
```
### 功能建议
- "战力天平"视图：任选两个实体（角色/境界/装备），自动列出适用的比较规则与例外条件，并回链战绩原文。
- 天花板声明向导：三步完成（定上限 → 定持有者 → 定揭示节奏），产出 reveal state 元数据供伏笔管理。

### 校验规则建议
- 出现"超越当前天花板"的战斗描写且无洋葱层声明 → error："越界战力，未声明更高层"。
- 跨境界胜利未登记越级杠杆 → warning："越级胜利缺少体系内依据"。
- 已冻结战力档案的角色表现超出档案范围且无新战绩锚点 → error："战力档案冲突"。

### AI 提示词建议
- 生成战斗情节前强制拼入上下文："本场战斗双方的境界、比较规则、越级杠杆、代价；禁止无依据的越级翻盘。"
