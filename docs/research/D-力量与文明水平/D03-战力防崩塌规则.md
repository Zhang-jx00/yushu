# D03-战力防崩塌规则

> 类别：D-力量与文明水平 ｜ 世界构建金字塔层级：L4 文明层 + 叙事层交叉
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

战力防崩塌规则研究"连载过程中战力体系如何不失守"：power creep（力量通胀）的成因与对策、数值/表现一致性校验、开局战力定调、以及跨百万字长线的一致性维护手段。边界：D02 负责"比较规则长什么样"，本领域负责"规则如何在整个连载生命周期内被持续执行"——它是御书"战力不崩塌"卖点的核心落地领域，产出物必须能直接变成一致性引擎的可执行规则。

## 2. 核心知识框架

1. **Power creep 的三种来源**：（a）主角侧通胀——每次危机靠新能力解决，旧能力贬值；（b）世界观侧通胀——为维持升级感不断发明更高境界/更强反派（Rule of Escalating Threat 的失控版）；（c）奇观通胀（spectacle creep）——战斗规模无限升级。社区共识：设定好要讲的弧线并坚持，用人物与写法而非更大场面保持吸引力。
2. **起点定调错误是根源之一**：Janice Hardy 指出开局把 stakes/power 定得太高，后续无路可升是结构性错误；正确做法是"起点低于天花板、留出升级空间"。反向样本同样存在：部分作品开局即满级（如 Royal Road 上明确宣称"no power-creep into infinity"的作品），靠"已到顶后如何自处"讲故事——这要求开局就冻结战力曲线。
3. **每个 power-up 必须有可见代价**：Entangled Text 的准则——快速成长可以接受，"未经挣得的突破"会杀死满足感；每次力量跃迁都应绑定成本/风险/取舍，并在档案中留痕。
4. **复用优先于新增（Sanderson 第三定律的连载化）**：Royal Road 社区的一致性经验是"限制角色与物品的数量，用新方式使用旧能力，而不是发明新能力"。已有能力的创造性组合比新增体系更抗崩。
5. **不可逆事件与档案冻结**：突破、重伤、夺舍、装备损毁都是战力档案的永久变更事件，必须有"事件日志"；老反派威慑力衰减（Villain Decay）本质是档案未随剧情冻结导致的表现漂移。

## 3. 可转化为产品规则的关键实践

1. 全书开局填写"战力定调卡"：主角起点、当前界天花板、预计终点、升级速率承诺 → 模板字段（见第 5 节 DSL 的 `tone` 段）。
2. 每次战力变更事件（突破/习得/装备/重伤）写入不可变事件日志 → 引擎按日志重建任意章节时点的角色战力档案。
3. 校验"power-up 三件套"：新能力必须同时具备 来源依据 + 代价字段 + 后续使用记录 → 三缺一即报警。
4. 新增体系/境界的"必要性门槛"：已有能力组合无法解决的冲突类型清单 → 未列清单前禁止新增（第三定律 lint）。
5. 临时增益自动过期：增益类战力带时效字段，逾期未处理则战力档案回落 → 防"临时变常态"。
6. 战斗表现回查：描写战斗前自动拼装双方当章有效战力档案 → AI 提示词强制注入，防凭印象写崩。

## 5. 对御书设计的启示

### 校验规则建议：一致性引擎规则 DSL（可直接落为规则文件）
```yaml
# power-consistency.rules.yaml
tone:                          # R1 战力定调（全书必填）
  require: [start_power, ceiling_ref, end_goal, rate_promise]
  on_missing: error
events:                        # R2 战力变更事件日志
  types: [breakthrough, skill_gain, item_equip, injury, buff, debuff]
  immutable: true              # 不可篡改，只能追加修正事件
  buff_ttl: true               # R5 临时增益必须带 expiry，逾期自动回落
powerup_gate:                  # R3 新能力三件套
  require: [evidence_ref, cost, reuse_record]
  on_missing: warning
no_new_system:                 # R4 第三定律门槛
  require: unresolved_conflict_list   # 新体系前须列已有能力解决不了的冲突
combat_check:                  # R6 战斗前档案拼装
  inject: [effective_power_a, effective_power_b, comparison_rules, leverage]
  out_of_archive: error        # 表现超出档案且无事件日志 -> error
villain_freeze:                # R7 退场反派档案冻结
  on_reappear_mismatch: error
```
### 功能建议
- "战力时间轴"：按事件日志渲染角色全书战力曲线，与升级速率承诺曲线叠加比对，偏离过大高亮。
- 一致性报告页：按上述 R1-R7 出周报（当前违规数、风险章节清单、一键跳转原文）。

### AI 提示词建议
- 写战斗/突破章节的提示词末尾固定追加："严格遵守以下战力档案与规则输出（附 DSL 校验结果），禁止无代价的新能力。"

## 6. 领域内子主题备忘（可选）

- 长篇"换赛道"策略：当前赛道封顶后切换竞争维度（修仙→官场→经营）而不抬高战力。
- 多主角/群像的战力档案同步问题。
- 番外/同人中的战力追溯校验。
- 读者侧"战力审判"舆情监测：评论区战力质疑聚类作为崩塌预警信号。
