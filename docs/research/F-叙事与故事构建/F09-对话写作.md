# F09-对话写作

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

对话写作研究小说中对白的生成与修改规则：对白的功能（推进情节/揭示人物/传递信息/制造张力）、潜台词（人物很少说出真正想说的话）、声线区分（不同角色的词汇、句式节奏、口癖差异）、对白的欲望驱动（每句话背后都是角色想达成的结果）、以及技术层面的话 tagging（said 系/动作 beat/内心插入的选择）与信息卸载（避免"如意说教"）。与 E07（声线一致性）的分工：E07 建"这个人怎么说话"的静态档案，本领域管"这场对话怎么写"的动态生成与校验——对话卡在两者之间起桥接作用。与 F03（场景与节拍）的分工：F03 管场景骨架，本领域管骨架上对白行的质量。

## 2. 核心知识框架

1. **对白的欲望驱动**（P.S. Hoffman）：一切好的对白都源于角色"想要什么"——求改变、求帮助、求掩饰；没有欲望的寒暄应删除或改造成携带欲望的假寒暄。冲突性对话=两个欲望相撞。
2. **潜台词原则**（Go Into The Story）：大多数时候"角色说 A 实际指 B"比直抒胸臆更有效力；直说的台词留给情绪顶点（说破的瞬间因此而有分量）。压力越大，人越绕弯。
3. **声线区分手段**（Weiland 14 工具 / Ride the Pen / Career Authors）：句长与结构节奏（只说短主句 vs 满口从句）、词汇域（行话/文白/地域词）、口癖 tic（专属短语或习惯语）、受教育与社会阶层痕迹、对同一话题的不同关心点。测谎法：遮住名字能否认出说话者。
4. **MRU 与对白位置**（Swain/Weiland）：对白属于"反应链"（感受→本能行动→理性行动+言语），说话之前应有刺激（动机）在场；对白与动作 beat 交替形成节奏。
5. **Tagging 技术规范**（Michael Young / LitReactor）：said/asked 是隐形标签（读者视而不见），花哨 said bookisms（冷笑/嗔道连发）与副词标签（"生气地说"）是弱点信号；动作 beat 优先于 tag——beat 同时完成身份标注、动作描写与情绪外化三件事，但"点头微笑抱臂"式空转 beat 是新型垃圾。
6. **信息卸载禁忌**：角色不该向彼此解释双方都知道的事（"as you know"综合征）；大段设定须拆碎、借冲突传出，或移交叙述层。
7. **中文网文对话传统**：对话承担"打脸台词、金句爽点、装逼名场面"等爽感功能，语速快、短句多、回合制攻防；webnovel-handbook 的"人物声线风格圣经"把声线档案列为工程资产。

## 3. 可转化为产品规则的关键实践

1. 对话卡 → 每场重要对话登记目的/各方欲望/潜台词/信息差（schema 见 §5），生成与修改都从卡出发。
2. 声线联动 → 生成对白前强制读取 E07 声线卡的 lexicon/syntax/tic 字段，注入提示词作硬约束。
3. 匿名测试校验 → 抽样遮名片段，AI 复核声线区分度，低于阈值提示"一个声音在演全场"。
4. beat/tag 配比 → 统计 tagging 构成：连续 3 行同型 tag、said bookism 密度、空转 beat（点头/微笑/挑眉）频次告警。
5. 信息卸载检查 → 检测对白中"双方已知信息"的解释性语句，建议改为冲突性传递或移入叙述。
6. 潜台词标注 → 对话卡 subtext 字段区分"明线话题/暗线真意"，关键对话要求两者分离。
7. 欲望校验 → 对话卡 wants 字段缺失时警告"这场对话没有输赢"；对话结束须记录欲望达成状态（胜/负/搁置）。
8. 金句位标记 → 网文模式：标注"打脸台词/名场面"位置，与爽点节拍器（F06）联动。

## 5. 对御书设计的启示

**数据结构建议：对话卡（与声线卡联动）**

```json
{
  "dialogue_id": "dlg-sc310-01",
  "scene_ref": "sc-310",
  "purpose": "打脸",                       // 信息传递|关系推进|冲突|误导|喜剧|打脸
  "participants": [
    {"char": "mei", "want": "拿到兵符却不暴露身份", "opens_with": "试探"},
    {"char": "hou", "want": "羞辱来客",            "opens_with": "挑衅"}
  ],
  "subtext": {"surface": "论茶道", "underneath": "互探底细"},
  "info_delta": {"s-01": "mei 知 hou 不知"},  // 引用 F07 可见性矩阵
  "outcome": "mei 胜",                      // 各方欲望达成状态
  "highlight": {"type": "金句", "chapter": 31},
  "voice_binding": {                        // ← 联动 E07 声线卡（只读引用）
    "mei": {"syntax": "短主句", "lexicon": "文白相间", "tic": "话尾轻叹", "forbidden": "市井俚语"},
    "hou": {"syntax": "长从句", "lexicon": "世家雅言", "tic": "自称'本侯'"}
  }
}
```

**联动规则建议**
- 生成前注入：participants 各自声线卡字段 + info_delta 泄底禁令 + purpose。
- 生成后校验：逐行比对声线约束（词汇域命中、tic 出现、句长分布），越线词标记；info_delta 中的"不知方"说破秘密 → 阻断。
- 修改建议：tag 层自动改写（副词标签→beat、花哨 bookism→said），beat 生成要求"服务于情绪外化"而非空转动作。

**校验规则建议**
- 声线匿名率：抽 3 段遮名让 AI 复核归属，全错的对话标黄。
- 节奏配比：单场景内对白行/叙述行比例异常（>80% 报幕剧、<20% 聊天记录体）提示。
- 欲望完整性：重要对话缺 wants/outcome 字段 → "闲聊场"警告。

**AI 提示词建议**
- "写一场 me/hou 的对话：mei 想要 X 但绝不明说（潜台词），hou 的每句话都在给他递刀；said 为主，tag 处用动作 beat；hou 不得提及 s-01。"
- 声线风格圣经整卡随注：为每个开口角色携带其 lexicon/syntax/tic 摘要，要求 AI 在对白中体现而非在叙述中解释。
