# F05-时间线与叙事顺序

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

时间线与叙事顺序研究"故事时间"（事件的客观先后）与"叙事时间"（文本呈现顺序）的映射：闪回（analepsis）、预叙（prolepsis）、多线并行、时距控制（场景/概要/省略/停顿）与频率（单叙/复叙/概叙），以及与之配套的伏笔-回收（plant/payoff）工程。热奈特的时序范畴是本领域的理论地基。边界区分：F01 管节拍在"进度轴"上的位置，本领域管节拍在"故事时间轴"上的位置；悬念的信息管理口径与 F06（冲突）、F04（可见性矩阵）交叉，本领域负责时间维度本身。

## 2. 核心知识框架

1. **热奈特三范畴**：时序（order：故事时间 vs 叙事时间，倒叙 analepsis/预叙 prolepsis/非时序 anachrony）；时距（duration：scene 场景等长/summary 概要/pause 停顿/ellipsis 省略）；频率（frequency：singulative 单叙/repetitive 复叙/iterative 概叙）。五范畴中的语式/语态归 F04。
2. **非线性叙事实操**：in medias res 开局+闪回补背景可制造悬念，但 Writing Excuses 提醒"别过量"；Book Architecture 五规则：闪回要有目的、勿离开阅读当下太久、写成完整场景而非摘要、每条时间线内部保持时间正向推进、闪前（flashforward）通常无效。
3. **阅读当下（reading present）**：读者在任何时刻都需要唯一的"叙事现在点"，一切闪回从此锚点出发并返回——多线/闪回作品的核心锚点工程。
4. **悬念 vs 惊奇（桌下炸弹）**：希区柯克——观众知道桌下有炸弹而角色不知=悬念；毫无预兆地爆炸=惊奇。Bordwell 从概念史论证信息差是悬念的本体；与契诃夫之枪、红鲱鱼构成"信息可见性"工具箱。
5. **契诃夫之枪与伏笔台账**：墙上出现过的枪必须击发；Writing Stack Exchange 讨论了藏枪（降显著度）与红鲱鱼不违反"枪必须响"的边界条件。
6. **网文实践**：断章钩子与伏笔分层——短伏笔 3-5 章回收、中伏笔一卷回收、长伏笔跨卷回收（CSDN 连载工程知识库）；伏笔逾期未回收是弃书高发原因。

## 3. 可转化为产品规则的关键实践

1. 双轴时间戳 → 每章/每场同时记录 story_time（故事内时间）与 narrative_now（阅读当下锚点），缺一警告。
2. 顺序模式标记 → 章节 order_mode 枚举：linear/analepsis/prolepsis/parallel/interleaved（schema 见 §5）。
3. 闪回三锚点 → 闪回必须声明 trigger（触发物）、anchor_from、anchor_to，缺锚点提示"读者会迷路"。
4. 伏笔台账 → plant/payoff 双向链接对象，记录埋设章/回收章/知道者名单/伏笔层级（短中长）。
5. 回收逾期提醒 → 超过层级窗口未回收的伏笔滚动提醒；完结前强制清点未回收项。
6. 多线时间一致性 → parallel 线各自维护时间戳，交叉点校验两线对齐（有意错位需标注理由）。
7. 时距标注 → 概要/省略影响"故事时间推进 vs 字数"曲线，检测"三天写十万字"式时距失衡。
8. 悬念类型标注 → 每个信息差标注类型（悬念=读者知/角色不知；惊奇=角色知/读者不知；反讽=皆知），联动 F04 lint。

## 5. 对御书设计的启示

**数据结构建议：叙事顺序标记 × 热奈特时序映射**

```json
{
  "chapter_ref": "c-042",
  "order_mode": "analepsis",       // linear | analepsis(闪回) | prolepsis(预叙) | parallel(并行线) | interleaved(交织)
  "story_time": {"start": "第三年·冬", "end": "第三年·冬"},
  "narrative_now": "c-041 之后的阅读当下",
  "device": {
    "kind": "闪回",
    "trigger": "旧剑穗（实物/感官触发）",
    "anchor_from": "c-041 末段",
    "anchor_to": "c-043 开头",
    "coverage": "完整场景"          // 完整场景 | 碎片记忆
  },
  "duration": "scene",             // scene | summary | pause | ellipsis
  "frequency": "singulative",      // singulative | repetitive | iterative
  "line_id": "主线A",              // order_mode=parallel 时必需
  "foreshadow_links": [{"type": "plant", "ref": "gun-003"}]
}
```

- 伏笔台账对象：`{id, plant_chapter, payoff_chapter, horizon: 短|中|长, known_by: [char-id], info_gap: 悬念|惊奇|反讽|无}`，plant/payoff 双向引用。
- 术语映射表：analepsis=闪回/倒叙、prolepsis=预叙/闪前、ellipsis=章间跳过、summary=过场段、interleaved=多线切换——AI 生成与校验共用同一词表。

**校验规则建议**
- 闪回完整性：analepsis 必须有 anchor_from/anchor_to，且故事时间早于阅读当下，否则警告。
- 闪回密度：连续 2 章以上 analepsis → 提示"阅读当下悬置过久"；prolepsis 默认警告（闪前通常无效，需作者确认）。
- 伏笔逾期：plant 后超过 horizon 对应章数未 payoff → 滚动提醒；完结前未清零 → 阻断级清单。
- 多线对齐：两条 line 在同一章交叉时 story_time 不连续 → 警告（有意错位需标注理由）。
- 时距失衡：连续 5 章 story_time 推进不足 1 天且无 pause 声明 → 提示节奏过缓（网文向）。

**功能建议**
- 双轨时间线图：上轨=故事时间（事件按故事先后排列），下轨=叙事顺序（章序），连线显示每次闪回/预叙的跨度。
- 伏笔台账看板：按 horizon 分列，高亮"快逾期"与"完结未回收"。

**AI 提示词建议**
- 生成闪回章时注入 device 全字段：触发物、进入/退出锚点句建议，并要求正文首句与末句呼应锚点。
- 注入"信息差卡"：本场景读者应知/角色应知清单，防止 AI 让角色说出其不知道的信息（联动 F04 L4）。
