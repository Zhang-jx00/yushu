# F02-网文连载结构

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

网文连载结构研究百万字级、日更数千字、边写边发的作品如何做宏观切分：全书→卷→篇章（arc）→章四级骨架，每级的功能、长度与高潮分布，以及"黄金三章"这类开篇工程学。它与 F01 传统结构理论的区别在两点：一是篇幅与不确定性——网文在只写完 10% 时就要让读者追更/付费，结构必须模块化可扩展；二是平台反馈——追读率、收藏等数据反向驱动结构调整。边界：断章钩子与爽点的微观技巧落在 F03（场景）与 F06（冲突升级），本领域负责"卷-章"级骨架与大纲方法（总纲→卷纲→章纲）。

## 2. 核心知识框架

1. **四级层级**：总纲（全书主线与结局承诺）→卷纲（一卷一条相对独立主线，卷末设大高潮）→篇章/情节块（3-5 章一个小三幕，完成一次"压抑-释放"）→章（2000-4000 字，自带钩子）。Royal Road 作者实操相同：先定起止，再分卷，卷内排小 arc。
2. **大纲法（总纲→卷纲→章纲）**：起点作者圈共识——大纲=世界观简介+人设+金手指+主线剧情；主线细到"每章写什么"即细纲。拆卷大纲的意义是防崩盘：跳过大纲直写的作者多数在 30 万字前后卡文或崩线。
3. **黄金三章**：平台编辑视角=首因效应。前三章决定推荐位与作品生死，需要迅速冲突、代入锚点、金手指亮相、第一个爽点闭环；知乎避坑指南总结的雷区（大段设定、群像开场、被动挨打）与编辑口径一致。
4. **每章承诺-进度-回报-钩子**：webnovel-handbook 提炼的连载原则——每章都要有明确承诺、推进感、回报感、结尾钩子，对应付费章节"本章值不值"的读者判断。
5. **升级流卷结构惯例**：一卷=一张新地图/新境界，卷内"地图升级→打脸→卷末 Boss"，卷与卷之间用总主线串联；多线群像卷与无限流副本卷是两个主要变体（码良写手五模板归纳）。
6. **AI 辅助大纲控制**：DOC（ACL 2023）证明"分层细纲+受控生成"显著提升长篇连贯性；Re3/RecurrentGPT 提供计划-生成-修订管线，与"总纲→卷纲→章纲"天然同构。

## 3. 可转化为产品规则的关键实践

1. 卷-章树状大纲 → `volume/arc/chapter` 三级嵌套数据结构（见 §5），卷内篇章自由分组。
2. 黄金三章检查器 → 前三章逐条跑 §5 检查规则，输出整改建议（warning 级）。
3. 卷模板包 → 内置"升级流卷/副本流卷/多线群像卷/日常缓冲卷"四套卷骨架，开卷向导四选一。
4. 章节四件套字段 → 每章卡必填承诺/进度/回报/钩子，漏填在发布前提示。
5. 断章点标记 → 章末钩子强度枚举（软收尾/悬念/炸裂），发布计划按强度排"强钩章"位置。
6. 字数配额 → 卷目标字数→章均字数→自动计算篇章分组，联动日更计划。
7. 单卷主线一句话 → 每卷强制填写"本卷一句话主线"，写不清=结构问题预警。
8. AI 分层生成 → 总纲→卷纲→章纲逐层生成+人工确认，参考 DOC 的 outline control。

## 5. 对御书设计的启示

**数据结构建议：卷-章结构**

```json
{
  "volume": {
    "id": "v1", "index": 1,
    "logline": "本卷一句话主线（必填）",
    "state_shift": "主角卷初状态 → 卷末状态",
    "main_conflict": "本卷核心冲突（引用 F06 冲突阶梯 rung）",
    "climax": "卷末大高潮描述",
    "exit_hook": "通往下一卷的引子",
    "chapter_range": [1, 60], "word_target": 200000
  },
  "arc": {
    "id": "a1", "volume_ref": "v1", "chapters": [3, 5],
    "type": "压抑蓄力 | 打脸释放 | 副本探险 | 日常缓冲",
    "promise": "篇章开始时的期待",
    "payoff": "篇章末的兑现"
  },
  "chapter": {
    "id": "c1", "arc_ref": "a1", "pov": "char-id",
    "promise": "本章承诺", "progress": "推进了什么",
    "payoff": "给读者的回报", "hook_close": "断章钩（软/悬念/炸裂）",
    "word_target": 3000
  }
}
```

**黄金三章检查规则（前三章逐条跑，warning 级）**
- 第 1 章：前 300 字内出现冲突或悬念；主角登场且给出代入锚点（身份/处境/目标）；具名角色 ≤3；新设定名词 ≤3。
- 第 2 章：金手指/核心悬念完成亮相；给出一条长线期待（对读者的承诺）。
- 第 3 章：完成第一个"压抑→释放"爽点闭环；章末出现"悬念"级以上钩子。
- 前三章禁区：大段设定说明、闪回、POV 切换、群像开场、主角纯被动挨打超过 1 章（联动 F04/F05 的 lint）。
- 结构层：第 1 卷主线须在第 3 章前挂出，前 10 章内出现第一个篇章级 payoff。

**功能建议**
- 卷健康度面板：每卷显示已写字数/目标、篇章数、末章钩子强度、卷主线一句话是否存在。
- 发布日历：按日更节奏把"强钩章"对齐到周末/付费节点。

**AI 提示词建议**
- 章纲生成注入四件套字段模板，生成后让 AI 自检"承诺-进度-回报-钩子"是否齐备再输出。
- 卷纲生成强制输入 state_shift 与 climax 占位，防止 AI 生成无主线的流水账。
