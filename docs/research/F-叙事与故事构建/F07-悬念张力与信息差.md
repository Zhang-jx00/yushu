# F07-悬念张力与信息差

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

悬念张力与信息差研究"读者为什么继续往下翻页"：悬念（suspense）、神秘（mystery）、惊奇（surprise）三种张力的区别与组合，张力来自叙述者与读者之间的信息差分配，以及章末钩子、时限压力（tick-tock）、多线悬念等具体制造手法。与 F06（冲突设计与升级）的分工：冲突是"阻力是什么"，悬念是"读者对阻力知道多少、何时知道"——同一冲突因信息分配不同可写成悬疑或爽文。与 F08（伏笔）的分工：伏笔是对未来的承诺，悬念是当下读者意识与角色意识的落差；二者共享台账但机制不同。本领域核心产出是"信息可见性矩阵"：谁（含读者）在何时知道什么。

## 2. 核心知识框架

1. **希区柯克桌下炸弹（surprise vs suspense）**：两人平静交谈时炸弹突然爆炸=15 秒惊奇；观众先看到无政府主义者放炸弹、看到时钟指向一点，同一对话变得无比紧张——给观众信息、让角色蒙在鼓里，观众从旁观者变成参与者。
2. **三种张力的信息差方向**：mystery=观众比角色知道得少（"发生了什么？"）；suspense=观众比角色知道得多（"它会不会发生/何时发生？"）；surprise=无铺垫的单次冲击（有力但转瞬即逝）。Bordwell 考据指出这组区分可上溯莱辛《拉奥孔》对"已知未来的恐惧"的论述，希区柯克将其工程化。
3. **McKee 的 gap 理论**：张力产生于"人物期望"与"对抗力量反应"之间的裂隙，逐场景扩大 gap 即渐进悬念；悬念的本质不是藏着秘密，而是不断制造"比预期更糟"的落差。
4. **张力工具箱**：时限（deadline）与倒计时、dread（预感的不祥）与 tension（当下压力）分层、每章至少一个未决问题（open loop）、章末钩子（cliffhanger/反转/新信息三型）、多悬念线交错（一条线等待时切另一条）。
5. **网文悬念实践**：CSDN 知识库把悬念钩子与断章并列为连载生命线；"每章承诺-进度-回报-钩子"四件套（webnovel-handbook）= 微观悬念节奏；期待感>爽点密度（S1 实证：延后爽点追读率 35%→67%）——悬念的实质是"延迟满足的管理"。
6. **悬念的反面**：廉价悬念（角色行为不合理只为保密）、泄底（POV 角色内心戏提前透露，见 F04）、疲劳悬念（无回报的假钩子堆砌导致读者信任破产）。

## 3. 可转化为产品规则的关键实践

1. 信息可见性矩阵 → 每个秘密/谜团登记一条 visibility 记录（schema 见 §5），成为全书信息差唯一事实源。
2. 张力类型标注 → 悬念线卡须声明类型：mystery/suspense/dramatic_irony，混合型须给出切换点。
3. 时限引擎 → suspense 线必须绑定 deadline（章节号或事件），到期自动催办"炸弹还没响"。
4. 章末钩子检查 → 每章结尾登记钩子类型（断章/反转/新信息/情绪高点），连续 3 章无钩子警告（联动 F02 断章）。
5. 未决问题清单 → 每章自动抽取"本章向读者提出的 open loop"，与伏笔台账（F08）交叉去重。
6. 泄底防护 → 场景生成时注入当前 POV 角色的"不可知清单"，AI 生成的内心戏/对白不得包含角色尚不知的信息。
7. 假钩子配额 → 标记为误导的钩子（red herring 钩）全书占比上限提示，防止读者信任透支。
8. 多线等待切换 → 悬念线处于"等待期"超过 N 章时，建议切入或给一次强化。

## 5. 对御书设计的启示

**数据结构建议：信息可见性矩阵**

```json
{
  "matrix_id": "info-gap-01",
  "secrets": [
    {
      "secret_id": "s-01",
      "name": "林殊即梅长苏",
      "truth": "一句话陈述真相本体",
      "tension_type": "dramatic_irony",      // mystery | suspense | dramatic_irony
      "visibility": [
        {"knower": "char:fei-liu", "knows": true,  "since_chapter": 1},
        {"knower": "char:jing-wang","knows": false,"learns_at": 48},
        {"knower": "char:xuan-ji",  "knows": false,"learns_at": 102},
        {"knower": "reader",        "knows": true, "since_chapter": 3, "mode": "半明示"}
      ],
      "deadline": {"chapter": 105, "event": "身份揭穿之夜"},
      "reveal_plan": [{"chapter": 48, "type": "部分揭示", "audience": "char:jing-wang"},
                      {"chapter": 105, "type": "完全揭示", "audience": "all"}]
    }
  ],
  "checks": [
    "读者可见性(knows)与视角模式(F04)共同决定叙述策略：reader<role→叙述藏；reader>role→叙述叠焦虑",
    "任何场景生成前，注入该场景在场角色与POV的 knows 快照作硬约束",
    "deadline 到期未安排揭示 → 高优催办"
  ]
}
```

**校验规则建议**
- 泄底检查：场景内角色 knows=false 的秘密，禁止出现在其内心独白与对白；读者 mode="半明示"的秘密允许"读者懂、角色不懂"的双关。
- 悬念线健康度：每条 suspense 线必须有 deadline 与 ≥2 次强化记录；超过 10 章无强化的悬念线标记"冷却"。
- 钩子分布：逐章统计章末钩子，连续 3 章无钩子或全书 40% 章节为同型钩子时提示。

**功能建议**
- 信息差总览图：纵轴=秘密，横轴=章节，角色与读者各一行，用色块标 knows 翻转点——一眼看出"读者领先/落后于谁"。
- 悬念仪表盘：每条悬念线的类型/时限/距上次强化章数/当前状态（待爆/冷却/已解决）。

**AI 提示词建议**
- 场景生成前置注入："你以角色 X 的视角写作；X 尚不知道：s-01、s-03；读者已知道 s-01，可在叙述中制造反讽但不许 X 说破。"
- 卷纲生成指令："本卷须完成悬念线 s-02 的一次部分揭示并抬高主悬念赌注，不得提前泄底 s-01。"
