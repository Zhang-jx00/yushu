# F12-结局收束

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

结局收束研究故事如何结束：结局类型学（封闭/开放/模糊/反转/循环/尾声扩展）、情感基调（圆满/怅然/悲怆）、结局高潮（climax）与解结（denouement）的分工、以及"收束=兑现全部承诺"的账本逻辑——主线冲突、人物弧光、感情线、伏笔、悬念五类义务在结局前逐一清算。与 F01（故事结构理论）的分工：F01 定义第三幕位置，本领域定义第三幕内部的质量标准与校验。与 F06（冲突升级）的接口：高潮=最高级 rung 的最终对抗，结局=对抗后世界的定格。中文网文特有约束：连载"烂尾"是口碑杀手，卷级收束与全书收束需要分开管理；完结章的"承诺清算清单"是防烂尾的工程手段。

## 2. 核心知识框架

1. **结局类型学**（Scribophile 7 型 / TCK 6 型 / The Write Practice 5 型的并集）：封闭结局（resolved）、开放结局（unresolved/open）、模糊结局（ambiguous）、意外/反转结局（unexpected/twist）、循环/首尾呼应结局（circular/tied）、扩展结局（expanded，即尾声/epilogue）、以及 The Write Practice 的"改变的世界/改变的自我"二分——后者提示结局必须回答"主角变了没有、世界变了没有"。
2. **情感基调三型**（Kingdom Pen 等）：happy / bittersweet / tragic；基调与类型正交（封闭结局可以是悲剧），工具中应作两个独立字段。
3. **高潮与解结的分工**（McKee / 三幕结构）：高潮=主角在最深 gap 处的最终选择，完成主价值翻转；解结=高潮后的余波，处理次级线索的落点与情绪着陆。中文语境常见病灶：高潮后戛然而止（无解结）或解结拖成流水账（赘尾）。
4. **承诺-兑现的总清算**：契诃夫之枪的宏观版——结局前盘点全部"挂上墙的枪"；未回收伏笔=读者感知的烂尾信号；同时高潮必须由已埋设的要素构成（payoff 须有 plant 支撑，联动 F08 双向校验）。
5. **"挣得的结局"（earned ending）**：结局的说服力来自主角付出的代价与之前的 try/fail 积累；干净的免费胜利（deus ex machina/天降奇兵）使结局失去合法性——校验点：高潮的胜负须能追溯到前文 ≥2 次铺垫。
6. **网文完结工程**：卷级收束（每卷留阶段性满足+新钩）与全书收束（总清算）分层；webnovel-handbook 的"每章承诺"累积到最后必须总兑现——完结章的功能是"给所有在册承诺一个落点"，番外/尾声用于安置读者情感余韵。

## 3. 可转化为产品规则的关键实践

1. 结局类型枚举 → 全书卡登记 ending_type 与 tone 双字段（schema 见 §5），倒推校验前文基调一致性。
2. 回收清单校验 → 进入结局卷自动扫描：伏笔台账全 paid/abandoned（有理由）、悬念矩阵全 revealed/sealed（联动 F07/F08）。
3. 冲突终局核对 → F06 冲突阶梯每条 rung 须有终局记录（胜/负/和解/悬置），主线 rung 最高级必须在 climax 解决。
4. 弧光收束检查 → E01 弧线的 Lie→Truth 转变须有对应场景证据；"改变的自我/改变的世界"两问强制作答。
5. 感情线落点 → E10 感情线形态（HE/BE/开放式/无CP）与结局基调交叉校验。
6. 解结篇幅建议 → 高潮章后的解结区间 1~3 章，超出提示"赘尾"，为 0 提示"急刹"。
7. 反转结局合法性 → twist 结局强制通过"回看合理"审计：反转所需线索在正文中 ≥2 处（联动 F08 藏枪记录）。
8. 完结工程包 → 完结卷模板：总清算章+余韵章+番外规划（可选），输出"承诺清算报告"供作者签字确认。

## 5. 对御书设计的启示

**数据结构建议：结局类型枚举与回收清单校验**

```json
{
  "ending_card": {
    "ending_type": "封闭",       // 封闭|开放|模糊|反转|循环|扩展(尾声)|多重主线分型
    "tone": "bittersweet",       // happy|bittersweet|tragic（与类型正交）
    "resolution": {"self": "主角自我已改变：从逃避到担当", "world": "世界已改变：封印重立"},
    "climax_scene": "sc-988",
    "denouement_range": [989, 991]
  },
  "settlement_checklist": {                       // 进结局卷自动生成
    "foreshadows": {"rule": "state ∈ {paid, abandoned(含理由)}", "open_count": 0,   "links": "ledger:foreshadow-ledger"},
    "secrets":     {"rule": "全部 revealed 或 deliberately_sealed(登记理由)", "links": "matrix:info-gap-01"},
    "conflicts":   {"rule": "每条冲突阶梯 rung 均有终局；主线最高 rung 在 climax 解决", "links": "conf:ladder-*"},
    "arcs":        {"rule": "每条主要弧光有 Lie→Truth 终点场景证据", "links": "char:*"},
    "romance":     {"rule": "感情线形态与 ending tone 一致", "links": "cp:*"},
    "hooks":       {"rule": "未解决的开放钩子须转入 deliberate_open（续作/番外）清单"}
  },
  "twist_audit": {"required": false, "clue_min": 2}   // twist 结局时开启
}
```

**校验规则建议**
- 清算红线：完结章生成前，settlement_checklist 任一项 open_count>0 → 阻断并输出未回收明细。
- earned ending：高潮场景的胜负依据须引用 ≥2 处前文场景/伏笔（payoff 无 plant 阻断，联动 F08）。
- 基调一致性：结局 tone 与全书已登记卷基调均值偏差过大 → 提示"结局画风突变"。
- 解结区间：denouement 为空或 >3 章 → "急刹/赘尾"双阈值提示。

**功能建议**
- 完结仪表盘：五类义务（伏笔/悬念/冲突/弧光/感情线）各一条进度条+未清偿清单，完结前常驻。
- 承诺清算报告：一键导出全部已回收/已弃用（含理由）/待回收条目，作为完结章写作输入与作者签收单。
- 番外挂载：deliberate_open 钩子转入番外候选池，与连载计划（I 类）联动。

**AI 提示词建议**
- 高潮章生成："本场景是主冲突最高 rung 的最终解决；主角的选择必须付出代价，胜负依据引用已登记的伏笔 fs-xxx、fs-yyy；完成主价值翻转。"
- 解结章生成："处理次级线索落点：逐一安置清单中的配角/支线（列表随注）；基调 bittersweet；不再引入新冲突与新悬念。"
- 完结章生成："本章功能是承诺总兑现：对 settlement_checklist 中每一条 open 项给出落点或显式留白说明。"
