# F04-视角与人称

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

视角与人称（POV）研究"谁在替读者看故事"：人称选择（第一/第二/第三有限/全知）、聚焦距离（热奈特语式/聚焦理论）、视角归属（一场戏只能透过谁的感知）与多视角切换的管理。它是全书最容易被"无意违反"的规则——head-hopping（头跳）会不可见地破坏代入感。边界区分：E07 声线一致性管"角色怎么说话"，本领域管"镜头架在谁头上"；多线叙事的时间维度归 F05。御书需要把 POV 从"写作习惯"升级为可配置、可校验的工程约束，而非只给一篇提醒文档。

## 2. 核心知识框架

1. **人称谱系**：第一人称（代入最强、信息天然受限）；第三有限（当代主流默认，单场单角色）；全知（可入任何人内心，需自觉控制否则变成坏意义的头跳）；第二人称（"你"，沉浸但小众）；混合人称（合法，但需显式管理）。
2. **热奈特聚焦理论**：零聚焦（全知）、内聚焦（绑定某角色）、外聚焦（只写外部可见行为）；Signo 词条是聚焦类型的标准参照。POV 选择本质是"内聚焦绑定谁、绑定多久"。
3. **Head-hopping 禁则**：一场戏内未经信号就切到另一角色内心，是新手最常见硬伤（Anne R. Allen："一场一人称"规则；Darling Axe 从读者体验论证：读者刚建立的真实感被跳头击碎）。
4. **切换的合法方式**（Jami Gold 七法）：场景/章节边界切换、分隔符+POV 名、换章不换场、双线交替等——切换必须"有信号、有节奏、有预算"。
5. **"能否知道/看到/感觉到"测试**：r/writing 社区共识检查法——写下这句话的角色，物理与心理上是否可能知道此事？
6. **网文语境**：男频常用单主角第三有限+轻全知旁白，女频多视角更常见（中国作家网：男女频差异在叙事视角与爽点设计）；升级流"伪全知"（主角视角+系统面板）是可参数化的视角变体。

## 3. 可转化为产品规则的关键实践

1. POV 模式全局声明 → 作品级字段 `pov_mode`（first/second/third_limited/third_omniscient/mixed），mixed 必须附说明。
2. 场景级 POV 绑定 → 场景卡/章卡必填 pov 字段，与 F03 场景卡联动。
3. head-hopping lint → 启发式检测内心直写（规则见 §5）。
4. 感知合法性检查 → 场景内出现 POV 不在场/不可见事件的具象描写时提示。
5. 信息可见性矩阵 → 每个秘密/伏笔记录"谁知道"，与 F05 伏笔台账共享 known_by 字段。
6. 切换预算 → 多 POV 作品设置"最小切换间隔"，违反提示。
7. 网文预设 → "伪全知+系统面板"模板：面板文本不受 POV 限制，作为显式豁免登记。
8. 人称转换助手 → 第一↔第三人称全局改写预览（AI 辅助，先试改一章再批量）。

## 5. 对御书设计的启示

**数据结构建议**

```json
{
  "pov_config": {
    "mode": "third_limited",         // first | second | third_limited | third_omniscient | mixed
    "distance": "贴近",              // 贴近 | 中性 | 疏离（对应内聚焦深浅）
    "default_pov": "char-id",
    "allowed_povs": ["char-id"],
    "switch_policy": {"granularity": "scene", "min_gap_chapters": 1, "signal_required": true},
    "exemptions": [{"scope": "chapter", "id": "c-000", "reason": "楔子用全知"}]
  }
}
```

**POV 一致性 lint 规则**
- L1 场景唯一视角：一个场景内出现 ≥2 个角色的内心直写标记（想/暗道/心里/觉得/意识到+独白）→ 警告 head-hopping，列出候选归属者。
- L2 感知合法性：场景内描写了 POV 不在场事件的具体动作/表情/对话 → 提示"POV 无法感知"。
- L3 切换信号：POV 变更处无分隔符或章节边界 → 警告；switch_policy.signal_required=true 时升级为阻断提示。
- L4 可见性矩阵联动：角色内心引用其未知的秘密（F05 台账 known_by 不含该角色）→ 错误级提示。
- L5 人称一致：第三有限作品出现无引语的第一人称长段内心独白 → 提示确认是否越权。
- 全部规则支持严格/宽松两档；"伪全知+系统面板"预设自动豁免面板文本。

**功能建议**
- POV 泳道图：横轴章节、纵轴角色，色块显示每章/每场 POV 归属，切换过密一眼可见。
- 多线轮换表：多 POV 作品的 A-B-A-C 轮换节奏检查与读者代入预警。

**AI 提示词建议**
- 场景生成注入 POV 卡：视角角色、聚焦距离、"该角色此刻不知道的信息"负面清单，防上帝视角泄漏。
- 改写指令模板："把此段改为贴近内聚焦，删除 POV 无法感知的细节"。
