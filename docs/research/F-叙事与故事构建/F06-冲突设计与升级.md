# F06-冲突设计与升级

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

冲突设计与升级研究故事阻力的来源与强度曲线：冲突的分类（外部人际/环境/社会，内部心理/道德）、单一冲突的升级阶梯（赌注逐级加码且不可逆）、主角每次尝试的失败方式（try/fail 与 Yes-but/No-and），以及反派作为冲突人格化载体的设计。与 F01 的分工：F01 定"转折在哪里"，本领域定"转折为什么疼"。与 D07（升级节点与爆点）的分工：D07 是力量体系层的数值升级，本领域是戏剧层的冲突升级——升级流网文中两者必须互相咬合（境界提升=冲突对手层级提升）。

## 2. 核心知识框架

1. **冲突类型学**：人vs人、人vs自我、人vs社会、人vs自然、人vs命运/科技；成熟作品通常"外部冲突驱动情节、内部冲突驱动人物"，两线在高潮汇合。
2. **McKee 渐进原则**：真冲突必须逐场加码（complications），每次行动激发更强的反对力量；压力下的选择揭示并改变人物本性——"角色能力与对抗强度同步上升"是避免后期崩盘的戏剧版约束。
3. **Try/Fail 循环与结局四型**：Yes / Yes-but / No / No-and（Karen Woodward）；Sanderson 与 Writing Excuses：中段不应出现干净的胜利，以 yes-but/no-and 让"新问题从旧方案中长出来"。
4. **赌注（stakes）工程**：Writing Excuses 12.41——提高赌注的高级手段不是换更大的威胁，而是与已有元素（人际关系/时限/价值观）挂钩；每级赌注应包含前一级（叠加而非替换）。
5. **镜像反派**：反派是主角暗面的放大（The Write Practice 镜像效应）；iWrity 的 want vs belief 框架让反派动机自洽——冲突因此是"两种合理信念相撞"而非好人打坏人。
6. **网文爽感循环**：压抑蓄力→暗示期待→集中释放→新循环；期待感比爽点密度更重要；反派打脸是冲突释放的最常见形态（爽感构成分析/知乎实证）。
7. **契诃夫之枪与冲突兑现**：引入的对抗性道具与承诺必须在高潮兑现，防止"聚起的冲突不了了之"。

## 3. 可转化为产品规则的关键实践

1. 冲突注册表 → 全书冲突以对象登记（类型/价值轴/双方/赌注），与场景卡 conflict 字段联动。
2. 升级阶梯模板 → rung 数组（schema 见 §5），每级 scope/stake/irreversible_event 必填。
3. 赌注叠加检查 → 相邻两级 stake 必须构成包含关系，替换式升级提示。
4. 结局四型约束 → 场景卡 disaster.outcome 枚举与 F03 对齐；中段出现 clean yes 提示。
5. 镜像反派卡 → 反派的 want/belief 与主角暗面对照字段（联动 E05）。
6. 爽点节拍联动 → "压抑→释放"循环与 F02 篇章绑定，每个篇章必含一次释放。
7. 不可逆换挡点 → 每级升档须登记一个不可逆事件，缺档提示"升级靠嘴说"。
8. 高潮兑现检查 → 标记为"高潮决胜负"的冲突，其伏笔 plant 必须在 finale 前 payoff（联动 F05 台账）。

## 5. 对御书设计的启示

**数据结构建议：冲突升级阶梯模板**

```json
{
  "ladder_id": "main-conflict-01",
  "conflict": {
    "type": "外部-人际",            // 外部-人际 | 外部-环境 | 外部-社会 | 内部-心理 | 内部-道德
    "statement": "两句话以内描述对立的本质",
    "value_axis": "安全↔毁灭",      // 价值两极，与 F03 场景卡翻转轴对齐
    "mirror_ref": "villain-01"      // 反派=主角暗面（联动 E05）
  },
  "rungs": [
    {"level": 1, "name": "摩擦", "scope": "个人日常",  "stake": "面子/小利",                        "bound_arc": "a1",  "irreversible_event": null},
    {"level": 2, "name": "冲突", "scope": "核心目标",  "stake": "含 level1 + 核心欲望",              "bound_arc": "a3",  "irreversible_event": "挚友之死"},
    {"level": 3, "name": "危机", "scope": "关系/阵营", "stake": "含前级 + 挚爱之人/身份",            "bound_arc": "a7",  "irreversible_event": "身份曝光"},
    {"level": 4, "name": "决战", "scope": "世界观层面","stake": "不可替代物：生命/信念/世界",        "bound_arc": "a12", "irreversible_event": "体系崩塌"}
  ],
  "attempt_rules": [
    "level 1-3 的尝试结局限 yes_but / no_and（联动 F03 场景卡 outcome）",
    "每次升档必须先登记一个不可逆事件",
    "stake 必须叠加而非替换",
    "反派强度随 rung 同步上调"
  ]
}
```

**校验规则建议**
- 阶梯完整性：主角线必须存在 ≥4 级 rung，每级绑定篇章（F02 arc）与不可逆事件，缺项警告。
- 赌注叠加：rung[n].stake 须显式包含 rung[n-1] 的核心要素（AI 复核），替换式升级提示。
- 结局分布：统计全书场景卡 outcome，中段 clean yes 占比 >20% 提示"冲突太容易"。
- 反派同步：反派卡强度评分未随 rung 上调 → 提示"对手停在原地"。

**功能建议**
- 冲突地图：主冲突阶梯纵向展示，横向标注每级的章节区间与对应反派，越级/跳档一目了然。
- 爽点节拍器：压抑-释放循环仪表（距上次释放的章数），联动 F02 断章与篇章 payoff。

**AI 提示词建议**
- 场景生成注入"冲突卡"：当前 rung、stake、反派 belief，要求对抗反应强度匹配 rung，不得提前泄底。
- 卷纲生成指令："本卷结局必须使冲突升档且留下不可逆事件"，防止 AI 写完一卷冲突原地踏步。
