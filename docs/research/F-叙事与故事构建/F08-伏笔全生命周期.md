# F08-伏笔全生命周期（埋设/回收/台账）

> 类别：F-叙事与故事构建 ｜ 世界构建金字塔层级：叙事层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

伏笔全生命周期研究"对读者的承诺"从建立到兑现的完整管理：伏笔的埋设（plant，以道具/对白/意象/事件等形式进入叙事）、藏枪技巧（让伏笔在场但不显眼）、强化（reinforce，多次提及维持记忆）、预期回收（payoff，兑现承诺换取"原来如此"的满足）、红鲱鱼（red herring，合法的误导性伏笔）与烂尾（未回收承诺）。与 F07（悬念）的分工：伏笔是面向未来的契约，悬念是当下的信息差；契诃夫之枪同时是两者的交点——墙上的枪是悬念的燃料，第三幕必须响。本领域核心产出是"伏笔台账"：御书伏笔看板的数据基础，支持埋设-回收双向链接与密度监控。

## 2. 核心知识框架

1. **契诃夫之枪原则**："第一幕出现的枪，第三幕必须响"——舞台上不该有对剧情无用的东西；反向约束同样成立：第三幕响的枪必须第一幕挂上（payoff 须有 plant 支撑），否则"凭空起势"。Wikipedia 词条同时记录了该原则的争议面：它被批评会滑向机械的功能主义，实际写作中需与意外性平衡。
2. **藏枪技巧（Writing Stack Exchange 实践汇总）**：把道具放进"背景过场"（角色路过时顺笔一提）、用注意力转移（在提及枪的同时发生更抓人的事）、让伏笔承担多重功能（那把枪同时是角色的心事，读者记住的是情绪而非道具）、控制首次提及的篇幅配额（一两句带过）。
3. **红鲱鱼的合法边界**：误导必须满足"回看合理"——读者被误导后重读时，所有线索都能自洽地指向真相或指向误导者的动机；红鲱鱼不是骗子伏笔，而是"叙事者按信息差说真话"。不满足回看合理的误导=欺骗读者。
4. **plant→payoff 的四种载体**（Amy Stewart Bell 等汇总）：对白（随口一句的预言）、道具（反复出现的物件）、意象/环境（天气、光影的象征）、事件/传闻（背景新闻在后期变成主线）。每种载体对应不同的"显眼度"与强化间隔。
5. **伏笔分层（中文网文实践，CSDN 体系）**：大伏笔（跨卷主线，须多次强化）、中伏笔（卷内回收）、微伏笔（章内呼应与回环）；连载文特有约束——网文断更/追读环境下，超过一定章数未强化的伏笔会被读者遗忘，"回收时无人记得"与"回收时人人想起"都要靠台账调度。
6. **AI 写作的伏笔记忆问题**：Re3 等 LLM 长文方法把"未来元素计划"写入 plan 并逐步递归，说明伏笔管理本质是外置记忆——这正是御书台账要替 AI 与作者承担的职能。

## 3. 可转化为产品规则的关键实践

1. 伏笔台账 → 每条伏笔登记：内容、承诺语义、埋设章节、载体、显眼度、预期回收、状态（schema 见 §5），全书唯一事实源。
2. 状态机管理 → planted → reinforced* → due → paid；due → abandoned 必须填写理由，禁止静默弃坑。
3. 藏枪模式枚举 → 显写/半遮/藏枪三档，藏枪伏笔生成时自动套用"背景化+注意力转移"写法。
4. 密度仪表 → 每卷统计"未回收数/埋设数/即将到期数"，超阈值提示"承诺过载"。
5. 强化提醒 → planted 超过 N 章（按显眼度分档：显写 15 章/半遮 10 章/藏枪 6 章）未强化 → 提示"读者要忘了"。
6. 回收校验 → 标记 payoff 的场景，必须存在前向 plant 链接，否则警告"第三幕响的枪没挂上墙"。
7. 红鲱鱼显式标记 → 误导性伏笔必须登记 red_herring 字段与回看合理性说明，回收时走"误导揭穿"流程而非正常 payoff。
8. 双向链接 → 伏笔↔场景卡（F03）、伏笔↔秘密（F07 矩阵）、伏笔↔冲突阶梯（F06 高潮兑现）互链，形成"承诺网络"。

## 5. 对御书设计的启示

**数据结构建议：伏笔台账 schema（御书伏笔看板）**

```json
{
  "ledger_id": "foreshadow-ledger",
  "items": [
    {
      "id": "fs-001",
      "name": "残缺的玉佩",
      "content": "主角贴身玉佩缺角，纹样与皇室印章暗合",
      "promise": "读者预期：身世真相将揭",          // 一句话承诺语义
      "plant_chapters": [12, 57, 130],              // 首次埋设+历次强化
      "carrier": "道具",                            // 道具|对白|意象|事件|传闻
      "visibility": "藏枪",                         // 显写|半遮|藏枪
      "expected_payoff_chapter": 480,
      "payoff_type": "正面回收",                    // 正面回收|反转回收|红鲱鱼
      "is_red_herring": false,
      "linked": {"secrets": ["s-02"], "arcs": ["a6"], "scenes": ["sc-112", "sc-310"]},
      "state": "reinforced",                        // planted|reinforced|due|paid|abandoned
      "abandon_reason": null,
      "recheck_after": 6                            // 藏枪档：6 章未强化即提醒
    }
  ],
  "state_machine": "planted →(再次提及) reinforced* →(进入回收窗口) due →(兑现场景) paid；due → abandoned 需 abandon_reason",
  "density_rules": {
    "per_volume_open_max": 12,                      // 每卷在册未回收上限
    "due_window": 30,                               // 距预期回收 30 章内置 due
    "reinforce_gap": {"显写": 15, "半遮": 10, "藏枪": 6}
  }
}
```

**校验规则建议**
- 兑现完整性：任何场景标记 payoff 后，其引用的伏笔 state 须为 due/reinforced 且存在前向 plant 链接，缺链警告"无中生有的回收"。
- 红鲱鱼审计：is_red_herring=true 的伏笔回收时，强制填写"回看合理性说明"（误导者动机/信息差出处）。
- 终局扫描：进入结局卷时输出"未回收清单"，state=paid 之外全部列出，abandoned 需有理由（联动 F12 回收清单校验）。

**功能建议**
- 伏笔看板：泳道按状态（埋设/待强化/待回收/已回收/已弃用）分列，卡片显示埋设-强化-回收三个章节锚点与跳转链接。
- 密度仪表：每卷"在册数/新增/回收"三线图 + 到期倒计时列表，防止承诺过载与伏笔遗忘。
- 时间轴联动：在 F05 时间线上叠加伏笔锚点，检查"埋设与回收跨时间线矛盾"。

**AI 提示词建议**
- 埋设生成指令："在当前场景植入伏笔『玉佩缺角』，要求：藏枪模式——不超过两句、嵌入背景动作、同段落安排更抢眼的情绪事件。"
- 回收生成指令："兑现伏笔 fs-001，回收前须先复现 plant_chapters 中的至少一处细节，制造'原来如此'。"
- 章节续写注入："当前在册伏笔（角色/读者各应记得哪些）随上下文注入，避免 AI 生成的对白无意间提前泄底或重复解释。"
