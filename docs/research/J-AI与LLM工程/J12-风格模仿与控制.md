# J12-风格模仿与控制

> 类别：J-AI与LLM工程 ｜ 世界构建金字塔层级：工程层 · AI 工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究"把作者文风表达为可复用、可切换、可检测的数据与提示结构"：风格卡（文风档案）的结构化定义、few-shot 示例选择（用作者旧稿选段作风格锚）、风格一致性检测（AI 段落与作者文风的偏离度）、模仿在世作家风格的法律与伦理边界、按流派/基调切换文风（派系包字段），以及"润色 ≠ 改风格"的保声润色约束设计。边界划分：E07 管角色声线一致性（人物说话腔调），本领域管"作者叙述文风"；G06 管派系包字段结构（文风预设是其中一项），H 类管各流派具体写法；J13 管 AI 合规与法律伦理细节；F04 管 POV 理论。核心问题：如何让 AI 生成/润色"读起来像作者本人写的"，并能量化偏离、守住"只学技法不冒名"的边界。

## 2. 核心知识框架

1. **风格的构成维度**。经典写作理论把 style 拆为词汇选择、句式结构、节奏、语气、意象家族与视角；voice 更深，指世界观、幽默感与情感透镜。BubbleCow 建议定义 3~5 个"声音锚点"并写成"声音宣言"（语气/句形/意象/缩写政策），作为修订时的北方星。
2. **风格的可计算化与示例锚定**。STYLEMC 发现 instruction-tuned LLM 复现"作者专属风格"并不稳定，需借助文体计量（stylometric）特征；Register Analysis 用 Biber 语域多维分析把示例转成"受约束的风格描述"，比开放式形容词更能保住语义、增强迁移强度；example-based 风格迁移让模型直接从样例推断风格，免去用户显式描述。
3. **few-shot 示例选择**。从作者旧稿挑选代表段作为"风格锚"（voice anchor / voice bank 概念），样例数量与多样性影响效果；"Catch Me If You Can" 评测发现 LLM 近似结构化文本（新闻/邮件）较易，模仿内隐个人风格（博客/论坛）较难，需多指标评估。
4. **一致性检测指标**。作者归属（AA）、作者验证（AV）、风格匹配、AI 检测四类可作为偏离度代理指标，据此触发"AI 味过重"或"风格漂移"告警。
5. **法律与伦理边界**。美国版权局明确：只有人类作者表达可获版权，纯提示词不受保护，人类对 AI 输出的修改或编排可受保护；模仿在世作家风格并在产物上冒名，可能触及不正当竞争与形象权，须在 UI 层设约束（细节交 J13）。
6. **预设与切换**。NovelAI 用 Preamble / Author's Note 的短标签列表调风格（如 `[ Style: chat, detailed, sensory ]`），位置越靠上下文底部影响越强；官方 Module 与 Preset 提供按流派/基调的风格预设——可对应派系包"文风预设"字段（G06、H 类）。
7. **保声润色**。编辑理论主张把"结构编辑 / 文风编辑 / 校对"分层，避免"过度修正"抹平个性；润色任务必须以风格卡为约束、保留作者句法与标志性表达。

## 3. 可转化为产品规则的关键实践

1. 风格卡结构化 → 把语感/句式/节奏/词汇偏好/视角习惯/意象家族写成 YAML，作为生成与润色的常驻注入层（J03）。
2. few-shot 风格锚 → 从作者旧稿抽取代表性选段作为 `style_anchors`，按"贴近当前场景"挑选（而非固定段落）。
3. 风格一致性检测 → 对 AI 段落跑偏离度评分，超阈值时提示"与作者文风偏离"，并给出对齐建议。
4. 保声润色 → 润色任务显式声明"只改错、不改声"，输出 diff 供逐处采纳，禁止整段重写默认应用。
5. 文风切换 → 派系包提供 `style_presets`（流派/基调 → 标签组），项目可开关并叠加作者风格卡。
6. 法律伦理约束 → 风格锚仅允许来自作者本人作品或公共领域；禁止以在世作家名义产出，UI 加"仅学技法不冒名"声明（联 J13）。
7. 风格漂移看板 → 统计各章偏离度趋势，识别"越写越不像作者"的章节。
8. 声音锚点守护 → 修订时对照"声音宣言"，提示可能被削弱的标志性表达。
9. 风格卡抽取 → 用结构化输出从旧稿自动抽风格卡草案，人工确认后入库。
10. 提示词模板 → 派系包内置风格指向的续写/润色提示词模板（G06 第 6 件）。

## 5. 对御书设计的启示

**数据结构建议：风格卡 schema（作者文风档案）**

```yaml
# styles/author-style.yaml —— 作者叙述文风档案（常驻注入层，J03）
id: style-author-linyuan
scope: project            # project | character（角色声线见 E07）
voice_pillars: [简洁, 冷峻, 意象克制]      # 3~5 个"声音宣言"锚点
register:                 # 语域多维（对齐 Biber MDA 思路）
  tenor: 冷静叙述
  mode: 书面 + 少量口语对话
  formality: 中
syntax:
  sentence_length: {avg: 18, max_run: 45, prefer: 短句为主}
  fragment_policy: 允许，用于强调（每页 ≤2）
  perspective: {pov: third_limited, distance: 贴近主角}
lexicon:
  prefer: [具体名词, 动词驱动, 生活化比喻]
  avoid: [堆砌形容词, 生僻词, 网络烂梗]
  imagery_families: [雨, 灯火, 旧木]
rhythm: {beat: 短长交替, dialogue_ratio: 0.3}
anchors:                  # few-shot 风格锚（来自作者本人旧稿/公共领域）
  - {doc: drafts/old-ch03.md, from: 1200, to: 1800, note: 高潮段节奏}
  - {doc: drafts/old-ch11.md, from: 300, to: 720, note: 冷静叙述范例}
presets:                  # 按流派/基调的文风切换（派系包字段，G06/H）
  - {axis: {tone: 爽文}, adjust: {rhythm.beat: 更快, sentence_length.avg: 14}}
  - {axis: {tone: 治愈}, adjust: {lexicon.imagery_families+: [暖光]}}
guard:
  avoid_mimicking_living_authors: true   # 仅学技法不冒名（J13）
  anchor_license: own_work | public_domain
```

**功能建议**

- 风格卡编辑器：结构化字段 + 实时预览"用本卡生成的一段样例文本"。
- 风格锚管理：从旧稿选中段落一键加为锚，标注适用场景；生成时按场景动态挑选。
- 风格漂移看板：逐章偏离度折线 + 阈值线，点击跳转问题段落。
- 保声润色模式：默认输出"仅错误修正"的 diff，逐条采纳/拒绝；整段重写需显式开启。
- 文风切换器：按派系包 `presets` 一键套用流派/基调文风，并与作者卡叠加显示。
- 合规提示条：当锚来自他人作品或在世作家风格时，弹出边界告知（联 J13）。

**校验规则建议**

- `style-card-missing`：项目开启 AI 生成却无风格卡 → warn（生成将退回默认"通顺 AI 腔"）。
- `style-anchor-count-low`：`anchors` < 2 段 → info，提示补充风格锚。
- `style-drift-high`：某章 AI 段落偏离度 > 阈值 → warn，给出对齐建议。
- `style-imitate-living-author`：风格锚指向在世作家作品或提示词要求冒名 → error（伦理/法律红线，联 J13）。
- `polish-voice-erasure`：润色输出删除了风格卡中的标志性表达（如受保护的短句/意象）→ warn。
- `style-preset-unmapped`：所选基调无对应 `presets` 映射 → info（联 G06/H）。
- `style-pov-conflict`：风格卡 POV 与章节设定 POV 冲突 → error（联 F04）。
- `style-anchor-stale`：风格锚指向的旧稿件已删除或迁移 → warn。

**AI 提示词建议**

- 「风格卡抽取」：输入作者旧稿选段，用结构化输出（json_schema）生成风格卡草案字段，人工确认后入库。
- 「保声续写」：注入风格卡（语域 + 句式 + 词汇偏好 + 视角）+ 2~3 段风格锚，要求"贴合锚段语感，不引入风格卡 avoid 列表词汇"。
- 「保声润色」：输入原文 + 风格卡，要求"只做错别字/标点/重复/歧义修正，保留作者句法与标志性表达"，输出 diff 与理由。
- 「风格偏离诊断」：输入 AI 段落与风格锚，输出偏离维度（句式/词汇/节奏/视角）与对齐改写建议。
- 「文风切换」：按派系包 `presets` 调整提示词（如"更快的句读、更短的句子"），并在输出后复检是否触发 `style-pov-conflict`。
