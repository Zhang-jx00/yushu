# J10-本地模型与离线写作

> 类别：J-AI与LLM工程 ｜ 世界构建金字塔层级：工程层 · AI 工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究在完全本地（不联网、数据不出机器）条件下运行 LLM 并支撑写作辅助的工程方案：本地推理后端（Ollama / llama.cpp / LM Studio / vLLM）如何以 OpenAI 兼容端点接入、本地模型的能力边界与任务适配、硬件门槛与 GGUF 量化选档、在线/离线混合策略、以及无网络时的降级体验。边界划分：J01 研究多模型接入协议与 Provider 能力矩阵，本领域只关注"本地"这一子集及其与云端的混合；J06 研究上下文工程，本领域只负责"推理在谁的机器上跑"；docs/01 §6 数据主权属需求承诺，本领域给出工程实现与可验证路径。核心工程问题：如何把本地模型像云端 Provider 一样统一接入，同时把"数据不出机器"从口号变成默认且可审计的路径。

## 2. 核心知识框架

1. **四种本地后端的定位差异**。Ollama 面向个人，一条命令即可跑模型，本地服务默认 `http://localhost:11434`，同时暴露原生 `/api/chat` 与 OpenAI 兼容的 `/v1`，且本地端口无需鉴权；llama.cpp（llama-server）是纯 C/C++ 推理，覆盖 CPU、Apple Silicon、AMD/Intel GPU，GGUF 生态的事实标准、依赖最少；LM Studio 是带 GUI 的一体化应用，本地服务 `http://localhost:1234/v1`，额外提供 `/v1/responses`、`/v1/embeddings` 与 REST 管理端点，并支持结构化输出；vLLM 面向 GPU 自托管与高吞吐，用 `vllm serve` 起 OpenAI 兼容服务，偏服务端（Linux + NVIDIA GPU）。前者适合单机写作，后者适合团队/工作室。
2. **"兼容 ≠ 一致"**。四家都宣称 OpenAI 兼容，但支持字段各异：Ollama 兼容层明确不支持 `tool_choice`/`logit_bias`/`n` 等参数；vLLM 忽略 `user` 且支持非标准 `top_k`（须走 `extra_body`）；LM Studio 的 `/v1/chat/completions` 不支持状态化对话与 MCP，需改用 `/api/v1/chat` 或 `/v1/responses`。因此本地 Provider 必须显式声明 capabilities 并自动降级（对齐 J01）。
3. **本地模型的能力差异**。中文能力、上下文长度、结构化输出支持度三个维度差异大：小参数本地模型的中文语感与长文连贯性明显弱于云端旗舰；上下文窗口常受显存限制被压低（如 7B 默认 8k，需手动调到 32k）；结构化输出（JSON Schema 强制）在本地依赖 grammar/GBNF 或后端实现，稳定性低于云端。结论：本地适合"约束强、输出短、可校验"的任务。
4. **硬件门槛与 GGUF 量化**。7B 模型 F16 约 14GB，Q4_K_M 约 4.3GB（Llama-3-8B 仅 +0.18 ppl，社区默认档），Q5_K_M 约 5.0GB（+0.06 ppl），Q8_0 近无损（+0.003 ppl）但占用翻倍，Q2_K 压缩最狠但质量显著下降（+3.5 ppl 级）。选档原则：显存/内存放得下就优先 Q5_K_M，紧张则 Q4_K_M；低于 4bit 建议用重要性矩阵（imatrix）降低质量损失。统一评测（arXiv 2601.14277）显示不同任务对量化敏感度不同，需按用途而非一律选最高压缩。
5. **在线/离线混合策略**。云端旗舰负责正文生成、润色、复杂推理；本地模型承担摘要、实体抽取、校对、敏感词初筛、向量嵌入（RAG 检索）等高频、低风险、可离线的任务——既省 token 又保隐私。任务路由（J01）应把"是否允许上云"作为一级维度，而非同质比较质量。
6. **无网络降级体验**。docs/01 §7 验收基线要求"全程不联网也能完成除 AI 调用外的所有步骤"；若有本地模型，则 AI 的离线子集（摘要/抽取/校对）仍可用，其余功能给出明确的"需联网"提示，而非静默失败或误导用户。

## 3. 可转化为产品规则的关键实践

1. 本地后端 = 一个 Provider 描述文件（base_url + runtime + capabilities + offline 标记）→ 与云端同构接入，写作任务只换目标不改代码路径。
2. 本地服务发现与探活 → 应用启动时探测 11434/1234/8080 等常见端口，展示"检测到 Ollama 正在运行"，一键设为任务目标。
3. 模型能力登记（中文档位/上下文/结构化输出）→ 每个本地模型一份 capabilities，路由时先过滤不达标任务（对齐 J01 的能力矩阵）。
4. GGUF 量化档位与硬件需求映射 → 模型选择器按本机显存/内存推荐量化档，安装前预估占用与吞吐。
5. 任务分级路由 → 任务元数据标 `privacy: local_only | cloud_ok`，local_only 任务永不出机器。
6. "数据不出机器"可验证 → 提供"网络活动"面板：每次 AI 调用的目标主机、是否发生外发、字节数。
7. 离线降级矩阵 → 定义每个 AI 功能在离线时的可用/不可用与替代路径，UI 上显式呈现。
8. 嵌入本地化 → RAG 向量嵌入默认走本地嵌入模型，避免正文分片被上传云端。

## 5. 对御书设计的启示

**数据结构建议：本地 Provider 与模型登记（YAML 草案）**

```yaml
# providers/local-ollama.yaml
id: local-ollama
kind: openai_compatible
base_url: http://localhost:11434/v1
auth: none                     # 本地服务无需鉴权
runtime: ollama                # ollama | llama.cpp | lm-studio | vllm
offline: true
capabilities:
  stream: true
  tools: false                 # Ollama 兼容层不支持 tool_choice
  structured_output: partial   # 依赖 grammar，稳定性低于云端
  usage: partial
models:
  - {name: qwen3:8b,  cn_quality: medium, context: 32768, quant: Q4_K_M, vram_gb: 6}
  - {name: qwen3:32b, cn_quality: high,   context: 32768, quant: Q4_K_M, vram_gb: 20}
```

**任务路由（YAML 草案）**

```yaml
# tasks/routing.yaml
tasks:
  - {id: summarize_chapter, privacy: local_only, prefer: [local-ollama], fallback: []}
  - {id: draft_prose,       privacy: cloud_ok,   prefer: [cloud-flagship], fallback: [local-ollama]}
  - {id: detect_typo,       privacy: local_only, prefer: [local-ollama, pycorrector]}   # 联动 J14
```

**离线降级矩阵（示例）**

```text
AI 功能             离线可用性   替代路径
章摘要 / 实体抽取    可用（本地） local-ollama 小模型
错别字 / 标点校对    可用         本地规则 + pycorrector（J14）
正文续写 / 润色      不可用       提示"需联网"，正文写作不受阻
```

**校验规则建议**

- `local-endpoint-unreachable`：任务目标为本地 Provider 但探活失败 → warn，提示启动命令与端口。
- `local-model-capability-mismatch`：把需要 structured_output/tools 的任务路由到不支持该能力的本地模型 → error（对齐 J01）。
- `local-quant-too-low`：所选量化档低于推荐下限（如 < Q4_K_M）且任务为生成类 → info，提示质量风险。
- `privacy-local-only-violation`：`privacy: local_only` 的任务被路由到云 Provider → error（对应 docs/01 §6）。
- `ai-offline-degraded`：离线模式下 AI 功能未按降级矩阵给出提示而静默失败 → warn。

**功能建议**

- 本地运行环境检测：一键扫描端口与显存，输出"本机可跑哪些模型/量化档"的可读报告。
- 混合路由看板：每次 AI 调用显示目标（本地/云端）、耗时、是否外发数据。
- 模型下载器：内置常见中文 GGUF 模型清单与量化档说明，一键拉取并校验哈希。
- 离线模式开关：显式切换后全部 AI 任务仅走本地，云端入口置灰，避免误连。

**AI 提示词建议**

- 「本地摘要」：面向小模型的短输出模板（限定 ≤150 字、只输出 JSON、禁止展开与联想）。
- 「离线结构化抽取」：给定设定卡 JSON Schema，要求本地模型仅输出该 Schema，解析失败时提示用户改走云端。
- 「本地校对」：只做"指出错误 + 给候选"，不做整段改写，降低小模型幻觉风险（对齐 J14）。
