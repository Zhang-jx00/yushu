# J14-中文校对与文本质量检测

> 类别：J-AI与LLM工程 ｜ 世界构建金字塔层级：工程层 · AI 工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究中文文本的自动校对与质量检测工程：错别字/别字检测、繁简转换、中文标点与排版规范、称呼漂移检测、重复表达检测，以及成语误用、的地得误用、长句比例等文本质量指标；并定义检测结果的分级呈现与"一键修复"的边界。边界划分：E07 研究声线一致性的理论，本领域负责"称呼漂移"的工程检测实现；J06 研究上下文与检索，本领域只负责"文本层面的错误与质量"；docs/01 §4.5 要求的中文校对（错别字/标点/重复/称呼漂移）与 OpenCC 繁简转换在此落地。核心工程原则：检测可自动、修复需确认——AI 只提供候选项与证据，最终改动由作者决定。

## 2. 核心知识框架

1. **中文拼写纠错（CSC）**。任务分检测（定位错字）与纠正（给出正确字）两个子任务，SIGHAN-7（2013）起成为标准评测基线，指标为检测 F 值与纠正准确率。开源实现以 pycorrector 为代表（Kenlm 统计 + MacBERT/Qwen3 深度学习，Apache-2.0），近期模型（ChineseErrorCorrector3-4B）进一步把 CSC 与语法纠错（CGC）统一在单一框架。中文错字以"同音 / 形近"为主，需音近与形近两路特征同时建模。
2. **繁简转换的陷阱**。OpenCC 明确"严格区分一简对多繁与一简对多异"，并支持大陆/台湾/香港的地区习惯用词（"里面 / 裡面""鼠标 / 滑鼠"）。核心陷阱是"一简对多繁"（如"发/髮""后/後"）与地区用词差异，转换后必须人工复核，不能全自动回写正文。
3. **中文标点与排版规范**。GB/T 15834-2011《标点符号用法》规定现代汉语标点用法（点号/标号分类、省略号统一为六连点、连接号三形式等），并含附录 A（标点不能怎样用）与附录 B（易混用法区分）；W3C clreq《中文排版需求》给出中文行内排版与禁则需求。工具应依据规范而非"感觉"排版。
4. **称呼漂移检测**。与 E07 声线卡联动：A 对 B 的称呼变化须有剧情阶段支撑，全书称呼映射表可自动回检，越阶段或前后不一致即告警。
5. **重复表达与文本质量指标**。高频短语/句式重复（"心中一凛""嘴角勾起一抹弧度"）是 AI 生成与注水的典型特征；其余可量化指标包含成语误用、的地得误用（定语用"的"、状语用"地"、补语用"得"）、长句比例（超长句提示）。
6. **分级呈现与修复边界**。错别字/标点可较好自动判定，但"的地得""成语误用"存在语境弹性（如"真的/真地""多的是"已形成固定写法），必须分级为确定性错误、修改建议、存疑提示，且修复默认需用户确认。

## 3. 可转化为产品规则的关键实践

1. 错别字检测流水线 → 规则层（词典/搭配）先行、模型层（pycorrector/MacBERT/Qwen3）补位，输出位置 + 候选 + 置信度。
2. 繁简转换 → OpenCC 配置（s2t/t2s/tw/hk 变体），转换结果进入"必检"队列，一简对多繁条目高亮待确认。
3. 标点与排版 → 按 GB/T 15834 + clreq 实现"一键排版"：中英间空格、全半角统一、省略号规范、连续标点合并。
4. 称呼漂移检测 → 复用 E07 称呼表 + 全书章节扫描，输出"A 称 B 由 X 变为 Y 但无过渡事件"的清单。
5. 重复表达检测 → n-gram 短语频次统计 + 句式模板匹配，超阈值短语高亮并给替换候选。
6. 质量指标面板 → 逐章显示错别字密度、的地得/成语告警数、长句比例、重复短语 Top N，形成文本健康度评分。
7. 分级呈现 → 三级：确定性错误（error）/ 修改建议（warn）/ 存疑提示（info），每级对应不同 UI 色与默认处理方式。
8. 一键修复边界 → 默认"逐条确认"；批量修复仅限确定性级别且需二次确认，全部改动写入版本历史可回滚。

## 5. 对御书设计的启示

**数据结构建议：校对规则配置（YAML 草案）**

```yaml
# rules/proofread/zh-cn.yaml
profile: zh-cn
modules:
  spelling:    {engine: pycorrector, model: macbert, fallback: qwen3-local, min_conf: 0.6}
  conversion:  {engine: opencc, preset: s2t, region: tw, flag_ambiguity: true}
  punctuation: {standard: GB/T 15834-2011, policy: clreq, autofix: false}
  address:     {source: voice_cards, cross_ref: E07}          # 联动声线卡
  repetition:  {ngram: 5, min_count: 3, ignore_dialogue: true}
quality_metrics: [typo_density, de_misuse, idiom_misuse, long_sentence_ratio, repetition_topn]
severity_map: {deterministic: error, suggested: warn, uncertain: info}
```

**检测结果条目（YAML 草案）**

```yaml
- id: pf-000123
  rule: proofread-typo
  severity: warn
  span: {chapter: ch-012, start: 340, end: 342, text: "沧海一栗"}
  suggestion: "沧海一粟"
  evidence: "同音形近词，词典搭配校验命中"
  autofix: false                 # 需用户确认
  source: {engine: pycorrector, conf: 0.87}
```

**校验规则建议**

- `proofread-typo`：命中错别字/别字词表或模型高置信候选 → warn，给出候选但不自动改。
- `proofread-conversion-ambiguous`：繁简转换命中"一简对多繁/多异"条目 → info，标注多候选待选。
- `proofread-punctuation-gb`：标点用法违反 GB/T 15834（如省略号写作"。。。"、书名号范围错误）→ warn。
- `proofread-address-drift`：A 对 B 的称呼与 E07 称呼表不符或越阶段 → warn（联动 E07/E03）。
- `proofread-repetition-high`：n-gram 短语或句式在窗口内超阈值 → info，列 Top N 与替换候选。
- `proofread-demiscue`：定语/状语/补语位置疑似的地得误用 → info（"真的/多的是"等固定写法进白名单豁免）。
- `proofread-long-sentence`：单句超长（如 > 80 字且无标点切分）→ info。
- `proofread-autofix-unconfirmed`：批量修复未获用户确认即写入正文 → error（安全底线）。

**功能建议**

- 校对面板：按章节聚合检测结果，支持按等级过滤、跳转定位、逐条采纳/忽略，忽略项进入项目白名单。
- 一键排版（可预览）：排版只改格式不改字义，涉及字词一律走"确认"流程（对应 docs/01 §4.5）。
- 称呼漂移看板：绘制全书各角色称呼随时间轴的变化，异常点高亮（与 E03 关系图联动）。
- 文本健康度报告：导出前给出逐章质量评分与问题清单，作为投稿前自查的一部分（与 I07 自查流水线衔接）。
- 结果可解释：每条结果附"为什么"（命中的词典/规则或模型置信度），避免黑箱。

**AI 提示词建议**

- 「校对结果复核」：把规则/模型候选交给 AI，要求逐条给出"确定/存疑"判断与理由，只做分级不做改写。
- 「重复表达改写」：输入被标记的重复短语与上下文，输出 2~3 个不改变语义的替换候选。
- 「称呼一致性建议」：输入 E07 称呼表与剧情阶段，输出"A 对 B 的称呼是否应升级/回退"的建议与过渡事件提示。

## 6. 领域内子主题备忘（可选）

- 中文语法纠错（CGC）与 NaCGEC 基准的引入与落地。
- 对话/口语化文本的标点与节奏规范（对话独立成段）。
- 文言/半文言写作的校对策略（不适用现代标点默认规则的场合）。
