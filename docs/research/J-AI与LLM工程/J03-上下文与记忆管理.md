# J03-上下文与记忆管理

> 类别：J-AI与LLM工程 ｜ 世界构建金字塔层级：工程层 · AI 工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究"模型每次生成时到底看到什么"的工程问题：把一部百万字长篇小说压缩成一次调用可承载的 Token 集合，并在生成后把新事实回写进记忆。边界划分：J02 研究提示词怎么写（措辞与模板），本领域研究提示词里"放什么、放多少、什么顺序"；J04 研究如何从全库检索候选片段，本领域负责把检索结果与其他记忆层按预算组装成最终上下文；J05 研究世界设定卡如何被选中注入。核心工程问题：记忆分层如何建模、注入如何被触发与排序、Token 预算如何量化与预警、作者如何审查实际发出的上下文（上下文预览器），以及多项目记忆如何隔离。

## 2. 核心知识框架

1. **分层记忆（Memory Hierarchy）**。需求基线（docs/01 §4.3）规定五层：世界核心设定卡（常驻）→ 卷摘要 → 章摘要 → 事实级记忆（带出处）→ RAG 全文检索。学术侧对应生成性代理（Generative Agents）的"记忆流 + 反思"：记忆以自然语言记录，检索时按**相关性 × 新近度 × 重要性**打分；"反思（reflection）"把多条低级记忆合成高级结论——这正是卷/章摘要的理论原型。
2. **常驻注入与触发注入双轨**。NovelAI Lorebook / SillyTavern World Info 确立的规格：常驻项（Always On / Force Activation / Constant）无条件进上下文；触发项仅在**激活关键词（Keys）命中**时注入，并支持正则、大小写敏感、扫描深度（向后扫描多少字符/消息对才判定命中）、递归（级联）激活与互斥组。
3. **别名与提及追踪（Aliases & Mentions）**。NovelCrafter Codex 的"提及追踪"：条目维护别名/昵称列表（Mia / Mimi / Miss Richards），正文命中即建立链接并可统计出现次数、生成"出场热力图"；默认大小写不敏感，可用大小写敏感或排除词表抑制误命中（"Will"人名 vs 助动词）。
4. **Token 预算与插入优先级**。Lorebook 把 Token Budget / Context % 列为一等参数：预算耗尽后即便命中也不再注入；Insertion Order 决定谁先被处理、谁可能被挤掉。模型侧约束来自"上下文腐化（context rot）"与"迷失中间（Lost in the Middle）"——信息置于首尾召回最好、中段显著衰减，因此预算分配必须区分"紧邻生成点的高优先级内容"与"背景性内容"。
5. **时序效果与状态机**。SillyTavern 把激活建成状态机：sticky（命中后保持 N 条消息）、cooldown（N 条内不再触发）、delay（第 N 条后才可触发），使"某设定在剧情进入某阶段后才出现"可被机械表达。
6. **上下文组装与预览**。Anthropic 的 context engineering 提出 write / select / compress / isolate 四类操作与"informative yet tight"原则；NovelAI 的 View Last Context 则是排查"AI 忘设定"的必备调试器——作者必须能看见真实发出的上下文。
7. **摘要闭环与人工修正**。RecurrentGPT 证明"语言化记忆可每步更新"，NovelCrafter Progressions 允许设定随时间线演进；摘要必须可被作者编辑并回库，否则错误摘要会持续污染后续上下文。

## 3. 可转化为产品规则的关键实践

1. 记忆五层落地为可寻址实体 → 增加 `layer` / `source` / `updated_at` 字段，问题可定位到具体层（见 §5 schema）。
2. 设定卡常驻 vs 触发双轨 → 每条记忆 `injection.mode`（always | trigger | manual）与 `keys[]`（别名/尊称/外号），命中即注入。
3. 别名与提及追踪 → 实体卡维护 `aliases[]`，正文扫描命中即高亮并计数，为触发注入提供命中信号（与 J05 选卡共用）。
4. Token 预算与插入优先级可调 → 项目级预算（context% 或绝对值）+ 每条 `priority` / `insertion_order`；预算耗尽时按优先级截断并记录丢弃清单。
5. 上下文预览器 → 一键显示本次调用的完整消息序列：分块来源、Token 占用、命中的触发键、被截断项，可复现、可对比。
6. 摘要生成与修正回库 → 章节/卷摘要自动写入 `summary` 字段，作者编辑后 `summary_rev` 加一，禁止 AI 覆盖人工修订版。
7. 上下文组装算法 → 固定顺序：系统卡 → 世界核心 → 卷摘要 → 章摘要（近 N 章）→ 触发设定卡 → 事实级记忆 → RAG → 最近原文窗口；同层按 priority 排序、去重（ID 去重 + 相似度去重）、末尾再截断。
8. 多项目记忆隔离 → 每项目独立命名空间（`project_id/`），检索与缓存默认不跨项目；跨项目复用需显式"引用他书设定"。
9. 摘要陈旧检测 → 正文被改写而摘要未更新时提示重算（引用 I01 章摘要字段）。

## 5. 对御书设计的启示

**数据结构建议：记忆分层 schema（实体卡 frontmatter + 记忆库）**

```yaml
# memory/cards/char-linyuan.md
id: char-linyuan
layer: world_core           # world_core | volume_summary | chapter_summary | fact | rag
project_id: novel-a         # 多项目隔离命名空间
title: 林渊
aliases: [小渊, 林师兄, 渊儿, 林公子]    # 别名/尊称/外号 → 触发键
keys: [林渊, 小渊, 林师兄, 渊儿]
injection:
  mode: trigger             # always | trigger | manual
  priority: 80              # 0-100，预算耗尽时高者先留
  insertion_order: 500      # 越大越靠前处理
  position: near_end        # near_end | near_start | after_system
  budget_tokens: 400        # 本卡允许占用的上限
  recursive: true           # 允许被其他记忆激活
  sticky: 3                 # 命中后保持 3 条消息
  cooldown: 5               # 5 条内不再触发
  reveal_gate: ch-030       # 早于该章不注入（与 A08 叙事可见性联动）
source: {chapter: ch-012, quote: "林渊踏进藏经阁"}
updated_at: 2026-09-29T10:00:00+08:00
summary_rev: 2              # 人工修正次数，>0 时 AI 不得覆盖
```

**上下文组装清单（列表顺序即插入优先级）**

```yaml
context_assembly:
  budget_total: 32000       # 可调；或按 provider 上限的 context%
  slots:
    - {slot: system_prompt,   mode: always,  cap: 1200}
    - {slot: world_core,      mode: always,  cap: 3000}
    - {slot: volume_summary,  mode: always,  cap: 800}
    - {slot: chapter_summary, mode: always,  recent_n: 3, cap: 1500}
    - {slot: triggered_cards, mode: trigger, cap: 6000}
    - {slot: facts,           mode: trigger, recent_n: 20, cap: 2000}
    - {slot: rag_chunks,      mode: query,   top_k: 6, cap: 4000}
    - {slot: recent_prose,    mode: always,  last_n_chars: 6000}
  dedup: [by_id, by_similarity_0.95]
  truncate: {strategy: priority_then_recent, keep_quote: true}
  log: {persist: true, path: ".yushu/context-log/"}
```

**校验规则建议**

- `memory-budget-overflow`：组装后总量 > 预算 → warn 并输出被截断清单（可配置为 error 阻断发送）。
- `memory-trigger-conflict`：同一触发键（如"会长"）被多张卡声明且互斥 → warn，要求加限定词或设互斥组。
- `memory-alias-conflict`：别名在项目内重复或与他卡主名冲突 → error（误触发根因）。
- `memory-source-missing`：记忆条目 `source.chapter` 指向不存在章节 → error（引用 I01 章号）。
- `memory-summary-stale`：正文被改写而 `updated_at` 早于章节修改时间 → info 提示重算摘要。
- `memory-spoiler-leak`：`reveal_gate` 晚于当前章的卡被注入 → error（与 A08 / J05 共用）。
- `context-order-violation`：组装结果违反 slots 顺序（如 RAG 置于系统卡之前）→ warn。
- `memory-cross-project-leak`：上下文中出现非当前 `project_id` 的记忆 → error（隔离红线）。

**功能建议**

- 上下文预览器：面板分列"槽位 / 来源 / Token 数 / 命中键 / 是否被截断"，支持导出可复现快照。
- 记忆面板：五层树形视图 + 命中统计（哪张卡最近被注入多少次）+ 手动 pin/unpin。
- 别名管理器：一处维护别名并实时扫描全书，输出"提及热力图"（NovelCrafter 模式）。
- 预算仪表盘：实时显示各槽位占用条形图，超预算标红并给出"压缩建议"（哪层可摘要化）。
- 项目隔离开关：多书作者可显式勾选"允许引用他书设定"，默认隔离。

**AI 提示词建议**

- 「章摘要」：输入本章正文，输出 ≤150 字摘要 + 3~5 条事实级记忆（每条带引文），结构化输出后回写（引用 J06）。
- 「摘要修正」：作者编辑摘要后提示模型"仅保留人工修订版语义，不得引入新事实"。
- 「上下文自查」：输入实际上下文快照，问"本次上下文中是否存在与当前章冲突或不该出现的设定"。
