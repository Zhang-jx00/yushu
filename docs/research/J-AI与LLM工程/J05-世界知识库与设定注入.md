# J05-世界知识库与设定注入

> 类别：J-AI与LLM工程 ｜ 世界构建金字塔层级：工程层 · AI 工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究"世界设定以什么结构存、在生成时以什么规则被选出来注入"的工程问题。上游是 A 类（起源/法则）与 B~E 类（地理/文明/人物）产出的结构化设定卡，下游是 J03 的上下文预算与 J02 的提示词模板。边界划分：J04 处理非结构化正文的检索，本领域处理结构化知识（实体/关系/事件/时间线）的选择与注入；A08 研究"设定何时对读者可见"的叙事学规则，本领域把它工程化为 `reveal_state` 注入闸门；G06 定义派系包如何扩展设定卡 schema，本领域负责注入侧消费这些扩展。核心工程问题：世界知识库如何组织进 AI 上下文、按当前场景动态选卡的算法、与依赖图/一致性引擎的联动，以及叙事可见性约束的强制执行。

## 2. 核心知识框架

1. **世界知识库的分层记忆**。借用认知架构（CoALA 派生）与 docs/01 §4.3 的六类核心实体（角色/地点/势力/物品/功法技能/事件）：语义记忆 = 设定卡与实体属性；情节记忆 = 事件与章摘要；程序记忆 = 世界约束与规则（战力/称谓/禁忌）；工作记忆 = 当前场景组装出的上下文；索引 = 关系图与时间线。运行时由"工作记忆装配器"按需提取，而非全量倾倒。
2. **注入选择算法**。锚点来自当前写作上下文：当前场景卡/大纲节点（写什么）、POV 角色与出场人物（谁在场）、地点与时间锚（在哪/何时）。工程实现是"实体图作事实源 + 按锚点召回"：先由大纲/场景 beats 解析出出场实体集合，再从设定库取对应卡（可用双路：实体 ID 精确匹配 + 向量相似召回）。SCORE 即用 TF-IDF 与 cosine 混合检索情节与物件状态，WebNovel Writer 以实体图约束生成。生成时把选中的卡交给 J03 的预算法则做截断。
3. **与依赖图联动**。docs/01 §4.2 要求"上游设定变更向下游传播"：某上游设定（如境界体系）被修改后，受影响的下游卡（能力卡/战斗场景）应被标记并在下一次生成时**优先注入**，同时提示作者复核。这把一致性引擎的静态校验与生成时的运行时保护连成一体。
4. **叙事可见性约束（冰山原则）**。A08 的 `reveal_state`（未揭示/预告/已揭示/已回收）与 `reveal_chapter` 直接约束注入：`reveal_state < 已揭示` 的设定可以进上下文供 AI 参考，但禁止在正文说破；为此注入模板须区分"可写"与"仅供理解、禁止直说"两组。NovelCrafter 的 "Never include"（剧透/私密条目完全不发给 AI）是更硬的闸门；docs/01 §4.2 亦要求设定条目带"来源章节链接"。
5. **世界约束注入模板**。把战力/称谓/禁忌规则写成结构化文本段（如 `<combat_rules>` `<address_rules>` `<taboos>`）随上下文注入，并给出"必须遵守 / 违反示例"，把 D03（战力防崩塌）、E07（声线一致）、C09（称谓体系）的规则变成生成期约束而非事后检查。
6. **一致性失败的模式证据**。ConStory-Bench 发现 LLM 长篇一致性错误在**事实与时间维度最多、多发于叙事中段**；这要求注入策略特别照顾中段生成（Lost in the Middle，见 J03/J04），并优先注入时间线锚点与既有事实。
7. **与派系包 schema 扩展对接**。G06 的 `schema_extensions`（境界体系卡、系统面板卡、诡异档案卡）新增字段必须带"注入语义"（是否常驻、触发键、token 上限、可见性默认值），否则注入器无法消费；注入器应对未知字段降级处理（忽略但告警），对关键字段缺失报警。

## 3. 可转化为产品规则的关键实践

1. 世界知识库分层 → 注入清单按 semantic / episodic / procedural / working / index 分层组装（见 §5 manifest）。
2. 按锚点动态选卡 → 由大纲节点 + POV + 出场实体解析 `present_entities`，再按优先级/可见性过滤。
3. 依赖传播优先注入 → 上游变更标记 `affected_cards[]` 置顶注入，并附"请复核"提示。
4. 可见性闸门 → `reveal_state` / `reveal_gate` 决定卡是"可写"还是"仅参考"，生成期强制分组。
5. 结构化约束段注入 → 战力/称谓/禁忌以固定标签块注入，并附正误示例。
6. 派系包扩展声明注入语义 → 扩展字段携带 `inject: {mode, keys, cap, reveal_default}`（G06 契约）。
7. 中段保护 → 生成超过 N 字或进入中段时重注入时间线锚与关键事实（缓解 Lost in the Middle）。
8. 一键导出世界圣经 → 注入清单与作者可读的世界圣经共用同一数据源（引用 A09）。

## 5. 对御书设计的启示

**数据结构建议：世界知识库注入清单（world-context manifest）**

```yaml
# .yushu/world-context.yaml —— 生成时装配世界知识的声明式清单
apiVersion: yushu.world-context/v1
project_id: novel-a
anchors:                       # 选卡锚点（由场景卡/大纲节点解析）
  scene: ch-012#scene-03
  outline_node: outline/vol1/ch-012
  pov: char-linyuan
  present_entities: [char-linyuan, char-suqingyan, loc-cangjingge]
  timeline: {anchor_event: ev-004, year: 3}
selection:
  strategy: anchor_then_rank    # anchor_then_rank | all | retrieval
  include_relations_depth: 1    # 连带注入一阶关系实体
  dependency_boost: true        # 受影响卡置顶（docs/01 §4.2）
groups:                        # 注入分组 → 决定可见性与措辞
  - {group: hard_constraints, cards: [rule-combat, rule-address, rule-taboo], mode: always, cap: 1500}
  - {group: world_core,       cards: [origin-creation, law-power-system],     mode: always, cap: 2500}
  - {group: present_entities, cards_from: present_entities,                   mode: auto,   cap: 3000}
  - {group: rising_reveals,   reveal_state: foreshadowed,                     mode: ref_only, cap: 800}
  - {group: hidden,           reveal_state: hidden,                           mode: never,  note: 禁止说破（A08）}
visibility_gate:
  rule: "reveal_gate <= current_chapter else ref_only|never"
  ref_only_prompt: "以下设定仅用于保持一致性，禁止在正文中直接写出或解释：{hidden_cards}"
pack_extension_contract:       # 消费 G06 的 schema_extensions
  required_inject_fields: [mode, keys, cap, reveal_default]
  unknown_fields: ignore_with_warning
```

**世界约束注入模板（随上下文发送的结构化文本）**

```text
<world_constraints>
<combat_rules>        # 引自 D03 战力防崩塌
- 境界：炼气→筑基→金丹→元婴；同一战斗内不得出现境界倒退。
- 越级取胜必须给出代价（法宝/秘术/环境）；禁止无解释越两级获胜。
</combat_rules>
<address_rules>       # 引自 C09 称谓体系
- 苏清砚对林渊：公开场合称"林师兄"，私下称"渊儿"；禁止直呼全名。
</address_rules>
<taboos>
- 不得把既有设定中已灭亡的"南离国"写成现存国家（时间线冲突）。
</taboos>
</world_constraints>
```

**校验规则建议**

- `inject-spoiler-leak`：`hidden` 组设定在生成正文中被直接解释 → error（A08 红线）。
- `inject-anchor-missing`：场景卡未解析出任何锚点却走 `anchor_then_rank` → warn，回退 `world_core`。
- `inject-card-not-found`：清单引用的卡 ID 不存在 → error。
- `inject-budget-exceeded`：某组实际占用超 `cap` → warn 并交由 J03 截断（联动 `memory-budget-overflow`）。
- `dependency-propagation-missing`：上游设定已改但受影响卡未在 `dependency_boost` 中出现 → warn。
- `constraint-conflict`：注入的约束段互相矛盾（如两条不同的称谓规则）→ error，要求作者择一。
- `pack-inject-contract-violation`：派系包扩展字段缺少必需 `inject` 声明 → warn（G06 对接）。
- `timeline-anchor-missing`：当前场景引用时间刻度但注入清单无 `timeline` → info（F05/C02 联动）。

**功能建议**

- 注入清单预览：生成前显示"本次将注入哪些卡、分到哪组、占多少 Token"，可手动增删 pin（与 J03 上下文预览器同屏）。
- 可见性水线：编辑器只展示 `reveal_state <= 当前章` 的设定详情，未揭示项仅显示标题（防误泄，对齐 A08）。
- 依赖传播提示条：改动上游设定后，受影响卡列表带"已置顶注入 / 请复核"标记。
- 约束段编辑器：战力/称谓/禁忌规则的所见即所得编辑，导出即 `<world_constraints>` 文本。
- 世界圣经导出：注入清单与 A09 世界圣经共用数据源，一键导出人读版。

**AI 提示词建议**

- 「设定选卡」：输入场景卡 + POV + 出场实体，输出候选设定卡 ID 列表与理由（结构化输出，引用 J06）。
- 「约束注入」：以 `<world_constraints>` 块为硬约束起草正文，明确"违反则重写"。
- 「可见性自查」：生成后检查"是否说破了 `ref_only` / `hidden` 组设定"，输出越权揭示清单（与 A08 提示词同构）。
