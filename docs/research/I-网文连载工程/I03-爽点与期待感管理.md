# I03-爽点与期待感管理

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究连载小说"爽点供给"与"期待感管理"的工程化落地：把每章的情绪兑现事件（爽点）结构化为可登记的台账（类型/强度/受益方/铺垫来源），把对读者许下而未兑现的承诺（复仇/升级/揭密/CP）管理为一份会到期、会超期、会违约的清单，并把两者合成一条可回填平台数据（追读率/章节读完率）的期待感曲线（压抑→期待→释放→新循环）。边界划分：G05 是"爽点方法论"的理论层（爽感三要素、通用循环算法、参数基线、量表）；本领域是它的工程层，负责台账、看板、校验规则与数据闭环；F07 管"当下信息差（悬念）"，F08 管"面向未来的伏笔契约"，本领域管"面向读者的商业承诺"——三者共享同一份"已许诺未兑现"模型却各管一种载体，不重复彼此内容。I01 管章末钩子的挂点，本领域管全书期待曲线的调度。

## 2. 核心知识框架

1. **爽点台账**。每章登记情绪兑现事件：类型（打脸/升级/收获/装逼/揭密/糖点）、强度（复用 G05 的 -5~+5 量表）、受益方（主角/女主/配角/读者情绪）、兑现手段，以及它兑现的是哪条读者承诺。台账使"爽点密度/分布"从感觉变为可统计的字段。
2. **读者承诺清单**。对读者许下而尚未兑现的承诺按类型建账：复仇承诺、升级承诺、揭密承诺、CP 承诺、打脸承诺；每条含"许下章节、预期兑现、状态"。与 F08 伏笔台账同构但载体不同：伏笔靠道具/对白/意象埋设，读者承诺多来自简介、"空头支票"、核心梗与角色台词；清单是防"烂尾/挂羊头卖狗肉"的账本。
3. **期待感曲线**。四相位循环"压抑蓄力→暗示期待→集中释放→新循环"（理论见 G05）；工程上表现为章级台账：登记每章相位与强度，自动连成曲线，并计算"释放间隔上限/连续压抑上限/波动点下限"等指标。爽点只是曲线上的释放点，期待感是整条曲线。
4. **"期待感 > 爽点密度"**。业内共识：先把读者勾住（期待）比多塞爽点更重要。实践口径包括"每章真诚兑现一点、但只满足一小部分，让读者知道后面更爽"（番茄官方"没有满足的情绪落差"）、"持续许诺、慢慢兑现"的空头支票理论（阅文社区）、以及"承诺→延迟"的 promise-then-delay（英文连载写作）。G05/F02 已记录"删 1/3 爽点并延后、追读率 35%→67%"类实证，本领域把它工程化为"承诺超期预警 + 爽点延后改写"。
5. **爽点过密反噬**。番茄金番作者指出：前期爽点爆发过多过密会导致读者阅读疲劳，"爽点重叠"会直接换来弃书；须"节奏要稳"，分期播种（挖坑填坑）而非一口气撒完。故台账需要"同型连续检测"与"释放间隔下限"。
6. **数据闭环**。平台把期待感折算为可运营指标：番茄后台提供章节读完率、追更人数、催更人数（帮助中心定义），福利规则以"7 日有效追更人数"为门槛，实测口径中追更率 40% 以上作品可获得约 5 倍流量倾斜。台账与曲线因此必须能叠加真实追读数据，形成"承诺/爽点→追读率"的反馈。
7. **联动关系**。章末钩子是曲线的"下一条期待线起点"（I01）；未回收伏笔是承诺清单的强关联对象（F08）；悬念线的 deadline 与承诺到期共用同一催办引擎（F07）。

## 3. 可转化为产品规则的关键实践

1. 爽点台账 → 逐章登记 type/intensity/beneficiary/device/promise_id（schema 见 §5），构成全书爽点事实源。
2. 承诺清单 → 复仇/升级/揭密/CP/打脸五类承诺建账，登记许下章、到期章、状态与来源，禁止静默弃诺。
3. 期待感曲线 → 章级相位台账自动连线，参数可按基调覆写（G05），并与章节读完率/追更率叠加显示。
4. 爽点缺失检测 → 规则 `satisfaction-missing`：已写章无任何爽点记录 → info "每章至少一个情绪波动点"。
5. 同型疲劳检测 → 规则 `satisfaction-overlap`：连续 ≥3 章同一 type → warn "爽点重叠/审美疲劳"，建议换型或穿插感情线。
6. 无铺垫爽点检测 → 规则 `satisfaction-unsetup`：强度 ≥3 的爽点无 `setup_chapters` → warn "炸糖"，须补铺垫。
7. 承诺超期预警 → 规则 `promise-orphan`：`status=open` 且已过 `due_ch` → warn "承诺超期未兑现（空头支票）"。
8. 承诺过载 → 规则 `promise-overload`：在册 open 承诺 > 阈值 → info "承诺过载"，与 F08 密度仪表联动。
9. 文案-正文一致性 → 规则 `promise-break`：来源为"简介/开篇"的承诺长期不推进 → warn "挂羊头卖狗肉"（阅文官方口径）。
10. 爽点延后改写 → 提供半自动操作：把某章过密爽点中的一部分拆分延后至后续章，并同步更新承诺 due_ch 与曲线相位。
11. 章末钩子对接 → 每次"新循环"相位须落在章末并指向下一条期待线（联 I01 `hook.type`）。
12. 数据回填 → 台账与真实追读率/章节读完率按月对照，识别"高爽点低追读"（爽点错位）与"低爽点高追读"（期待感强）。

## 5. 对御书设计的启示

**数据结构建议：爽点与承诺台账 schema（YAML 草案）**

```yaml
# ledger/satisfaction.yaml（爽点 · 承诺 · 期待感唯一事实源）
satisfaction_ledger:                 # 爽点台账（逐章登记）
  - id: sat-015
    chapter: 15
    type: face_slap                  # face_slap|upgrade|harvest|show|reveal|sweet
    intensity: 5                     # -5~+5（复用 G05 量表）
    beneficiary: 主角                # 主角|女主|配角|读者情绪
    device: 退婚者上门被打脸
    promise_id: promise-003          # 兑现了哪条承诺（可空）
    setup_chapters: [12, 13]         # 铺垫章（缺失=炸糖）
    paid: true
promise_ledger:                      # 读者承诺清单（许下未兑现）
  - id: promise-003
    type: revenge                    # revenge|upgrade|reveal|cp|power
    statement: 打脸退婚者并夺回母亲遗物
    made_ch: 12                      # 许下章节
    due_ch: 18                       # 预期兑现
    status: paid                     # open|paying|paid|deferred|dropped
    source: 简介                     # 简介|开篇|章末钩子|角色台词
    drop_reason: null                # dropped 必填理由
expectation_curve:                   # 期待感曲线（章级相位）
  phases:
    - {chapter_range: [12, 14], phase: suppress,  intensity: -3}
    - {chapter_range: [15, 15], phase: release,   intensity: +5}
    - {chapter_range: [16, 17], phase: new_cycle, intensity: +1}
  metrics:                           # 基线来自 G05，可按基调覆写
    release_interval_max: 5
    suppress_streak_max: 3
    wave_per_chapter_min: 1
    promise_open_max: 6
  readthrough:                       # 平台数据回填（口径见番茄帮助中心）
    - {chapter: 20, chapter_readthrough: 0.62, follow_ratio: 0.46}
```

**校验规则建议（含规则 id）**

- `satisfaction-missing`：已写章在台账无记录 → info "本章缺情绪波动点"。
- `satisfaction-overlap`：连续 ≥3 章同一 type → warn "爽点重叠/审美疲劳"，建议换型或穿插感情线。
- `satisfaction-unsetup`：intensity ≥3 且无 `setup_chapters` → warn "无铺垫爽点（炸糖）"。
- `satisfaction-density`：连续 5 章无 intensity ≥3 的爽点 → warn "爽点欠账"。
- `promise-orphan`：`status=open` 且已过 `due_ch` → warn "承诺超期未兑现（空头支票）"。
- `promise-overload`：在册 open 承诺数 > `promise_open_max` → info "承诺过载"（联 F08）。
- `promise-break`：`source=简介/开篇` 的承诺长期不推进 → warn "挂羊头卖狗肉"。
- `promise-line`：`satisfaction_ledger.promise_id` 指向不存在的承诺 → error。
- `expect-curve-gap`：连续 suppress 章数 > `suppress_streak_max` → warn "压抑洼地"（复用 G05 憋屈欠账）。

**功能建议**

- 爽点仪表盘：承诺清单（许下/在途/超期）+ 期待感曲线 + 违规清单三栏联动，逐章爽点以热力条铺在曲线上。
- 承诺看板：泳道按类型（复仇/升级/揭密/CP/打脸）分列，卡片显示许下→到期章节锚点与跳转，超期卡片变红。
- 数据对照视图：期待感曲线叠加真实追读率/章节读完率，自动标出"高爽点低追读"的错位章，反哺细纲（I02）。
- 爽点延后工作台：选中一章，勾选要延后的爽点 → 生成改写建议并连带更新 `due_ch` 与曲线相位。
- 联动层：与 I01 的章末钩子（新循环起点）、F08 伏笔台账（未回收=强承诺）、F07 悬念 deadline 共用同一催办引擎。

**AI 提示词建议**

- 「爽点标注」：输入一段正文，输出爽点事件候选（type/intensity/beneficiary/device + 对应的铺垫章），供用户确认后写账。
- 「承诺抽取」：从简介/开篇/章末钩子中抽取对读者的承诺，判定类型与建议 `due_ch`，生成 promise_ledger 条目。
- 「爽点延后改写」：当前章节过密时，要求"保留 1 个释放点，其余延后至第 N 章"，并说明每条被延后爽点对应的期待线如何维持（呼应 G05 相位注入）。
- 「承诺盘点」：卷末/完结前输出未兑现承诺清单与建议落点，与 F12 承诺清算报告合并。
