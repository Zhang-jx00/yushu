# I06-完本规划与烂尾防范

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究超长篇连载如何被"有计划地写完"，以及如何系统性防范烂尾、太监与断更。边界划分：F12（结局收束）研究叙事层的结局类型学与结算逻辑，本领域把它的"承诺清算"落成连载工程层面的**回收清单**；F08（伏笔全生命周期）管伏笔台账，本领域负责在完本前做全量终局扫描；I02 管卷纲/章纲的生成，本领域管"卷数与字数预算、从结局倒推"；I08 管码字与数据统计，本领域消费其更新衰减与订阅下滑信号。核心工程问题：完本规划如何建模（目标字数/卷数/倒推里程碑/完本仪式），烂尾风险如何被结构化量化（体检报告评分），以及"进入结局卷"这一时点如何触发硬性回收校验。

## 2. 核心知识框架

1. **结局回收义务＝承诺总清算**。F12 的账本逻辑要求结局前把全部"挂上墙的枪"逐一清算；工程化的回收清单分四类：① 主线承诺（核心冲突/主线目标的落点）；② 伏笔（全部 paid 或显式 abandoned 并填理由）；③ 人物弧光（主要角色 Lie→Truth 的终点场景证据，联动 E01）；④ 势力结局（每个登记势力在终局中"胜/负/和解/消亡"的归宿）。
2. **烂尾的典型信号**。① 伏笔未回收——"各种伏笔和 flag 直往后拖，像滚雪球一样越滚越大，最后滚到山脚啪一下碎了"；② 支线失控——势力关系越写越复杂、作者逐渐失去对情节的控制；③ 大纲中后期缺失——只有前半段卷纲，写到一半失去方向感；④ 更新衰减——从日更到周更、月更直至停更；⑤ 订阅下滑后强行完结——数据不达标即"腰斩"切文。
3. **烂尾的成因**。桫桫指出首要成因是**连载机制**：写一章发一章、随写随发，"创作的随意性大大增加，让小说的整体结构出现了很大的不确定性"。王昕玥对《龙族》的分析归因于**类型失焦**：主线成长叙事被言情/悬疑支线稀释，主类型锚点丢失后走向"叙事失控与世界观危机"。湖北网文综述归因于**为流量跟风、动笔前未精心构思**，以及旧作未完结就"双开"导致精力分散、弃旧文于不顾。
4. **完本规划方法**。三级大纲普遍要求把**结局方向**写进总纲（含核心矛盾、成长弧、大结局形态），再按卷纲/章蓝图逐层收敛——"先写几章再做大纲是烂尾的主要原因"；有框架者完稿率显著更高，超 60% 新手因思路混乱半途而废。完本规划的另一半是**卷数与字数预算**，以及**从结局倒推**卷级里程碑。
5. **完本仪式**。完结不是停笔，而是一套收尾动作：完结章（总兑现）＋余韵/解结章＋番外（安置读者情感与 deliberate_open 钩子）＋完本感言（作者致谢与创作复盘）。起点《桃李春风一杯酒》的完本感言样本展示了"开书六卷规划→中途砍大纲收束→番外与感言"的完整仪式。
6. **太监/断更的行业现象与读者伤害**。"太监帖"指有精彩开头却中途停更的连载；它直接伤害付费读者的情感与信任，也被批评为作者责任心缺失。断更代价呈传导链：没有更新→推荐跟不上→读者流失→没有收入；平台侧亦已把"编辑判定烂尾完结"与福利挂钩（七猫完结月不发全勤）。

## 3. 可转化为产品规则的关键实践

1. 从结局倒推的完本规划卡 → 项目级 `completion-plan`，登记 `ending_summary` 与卷级倒推里程碑，卷纲生成时强制引用（联动 I02）。
2. 卷数/字数预算 → 设定目标字数与卷数，实际进度与预算偏差可视化（与 I08 统计共用日历）。
3. 回收清单四类义务 → 进结局卷自动扫描伏笔/弧光/势力/主线承诺，输出未回收明细并阻断完结（呼应 F12 settlement_checklist）。
4. 烂尾信号监测 → `risk_report` 结构化评分（伏笔逾期/大纲缺口/支线失控/更新衰减/承诺过载/订阅下滑六项加权）。
5. 大纲中后期缺失检测 → 卷纲覆盖率校验 `lw-outline-gap`，已发布章节覆盖的卷若缺卷纲即告警。
6. 更新衰减与订阅下滑 → 消费 I08/I01 的更新与数据记录，触发"强行完结风险"提示而非默认允许完结。
7. 完本仪式 → 完结卷模板含番外规划与完本感言模板，完本时输出"承诺清算报告"供作者签收。
8. 未完本档案 → 项目可标记"暂停/停更"，登记原因与最后状态，供复盘与再启动（对应防丢稿与数据主权）。

## 5. 对御书设计的启示

**数据结构建议：完本规划卡 + 回收清单 + 烂尾风险体检报告（YAML 草案）**

```yaml
# books/<project>/completion-plan.yaml
completion_plan:
  target_words: 2400000            # 目标总字数预算
  target_volumes: 6                # 计划卷数
  ending_type: 封闭                # 与 F12 ending_card.ending_type 对齐
  ending_summary: "主角封印重立，携旧友归乡"
  reverse_milestones:              # 从结局倒推
    - {volume: vol6, milestone: "终局决战", at_words: 2200000}
    - {volume: vol5, milestone: "势力清算", at_words: 1800000}
  budget_policy: soft              # soft 可扩卷 | hard 硬收敛
  finale_ritual: {epilogue: true, author_note: true}
recovery_checklist:                # 回收清单（工程化 F12 settlement_checklist）
  main_promises: []                # 主线承诺：state ∈ {兑现, 显式留白}
  foreshadows: {rule: "全部 paid 或 abandoned(含理由)", links: "foreshadow-ledger"}
  character_arcs: {rule: "每条主要弧光有 Lie→Truth 终点场景", links: "char:*"}
  faction_endings: {rule: "每个登记势力有终局记录", links: "faction:*"}
risk_report:                       # 烂尾风险体检报告
  generated_at: 2026-09-29
  score: 72                        # 0-100，越高越危险
  band: warn                       # safe | warn | danger
  signals:
    - {id: foreshadow_overdue, weight: 25, hit: true,  detail: "17 条伏笔超预期回收章 30 章"}
    - {id: outline_gap,        weight: 20, hit: true,  detail: "第五卷之后无卷纲"}
    - {id: update_decay,       weight: 15, hit: false, detail: "近 30 日更新稳定"}
    - {id: subplot_bloat,      weight: 15, hit: true,  detail: "在册支线 9 条 > 阈值 6"}
    - {id: promise_overload,   weight: 15, hit: false, detail: "本卷在册伏笔 11 ≤ 12"}
    - {id: revenue_dip,        weight: 10, hit: true,  detail: "订阅连续 3 月下滑 >30%"}
```

**校验规则建议**

- `lw-recovery-unclosed`：进入结局卷时，`recovery_checklist` 任一项 `open_count>0` → error 并列出明细（硬性，联动 F12）。
- `lw-foreshadow-overdue`：逾期未回收伏笔数 ÷ 在册数 > 阈值 → warn（联动 F08 台账）。
- `lw-outline-gap`：已发布章节覆盖的卷缺卷纲 → warn；未登记结局方向的总纲 → info。
- `lw-subplot-bloat`：在册支线数 > 阈值（默认 6）→ warn，提示收拢支线。
- `lw-faction-endless`：登记势力缺终局字段且已进入结局卷 → warn。
- `lw-ending-drift`：正文走向与 `ending_summary` 语义偏离 → info（AI 比对，不阻断）。
- `lw-finale-ritual`：完本时 `finale_ritual` 项未处理 → info 提示。

**功能建议**

- 完结仪表盘：四类回收义务各一条进度条 + 烂尾风险体检报告评分卡，常驻结局卷。
- 烂尾风险体检：一键扫描生成 `risk_report`，命中项给出成因说明与补救建议（可导出）。
- 承诺清算报告：一键导出已回收/已弃用（含理由）/待回收清单，作为完结章写作输入与作者签收单（与 F12 共用）。
- 完本仪式助手：番外候选池（承接 deliberate_open 钩子）+ 完本感言模板。

**AI 提示词建议**

- 「完本路线图」：输入总纲与 `ending_summary`，倒推卷级里程碑与字数预算，标注"支线收拢点"。
- 「回收清单补全」：扫描伏笔台账、人物卡、势力卡，产出四类回收清单建议及各自落点章节。
- 「烂尾风险诊断」：输入 `risk_report` 的命中项，输出成因分析与分阶段补救方案（不代写正文）。
