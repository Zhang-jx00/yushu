# I05-读者数据反馈驱动

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究连载作品如何用读者侧数据（追读/追更、完读率、掉章点、收藏、票、评论、在读等）反向驱动创作决策，以及这种数据驱动的边界。边界划分：F02 已指出"平台反馈反向驱动结构调整"，但只做理论层；本领域负责工程落地——指标定义与口径对照、本地采集、仪表盘与掉章点定位，以及"数据不能越过什么线"的约束。与 I01 的分工：I01 管更新节奏与存稿；I08 管码字侧统计与体检报告框架（对应 docs/01 §4.6）；本领域管读者侧数据与"数据—创作"回路的合规边界。核心命题：在不抓取平台后台、不牺牲已承诺伏笔（F08）与爽点结构（I03/G05）的前提下，让数据真正可读、可用。

## 2. 核心知识框架

1. **读者数据指标清单**。免费平台（番茄）：阅读人数/每日阅读人数、追更人数、催更人数、加入书架数、X 万字读完率（10/30/50/80/100 万字档）、章节读完率、章节跟读率、流量来源构成（书城/分类/书架/继续阅读/搜索）。付费平台（起点）：收藏、推荐票、月票、首订、均订、追订（24 小时追读）、追读榜/留存榜（50 万字后可上榜）。海外平台：话别 PV、书签数、评价数，以及"话别 PV 递减曲线"。
2. **口径差异是复用前提**。同名指标各平台定义不同：番茄"完读率"按字数段（读至 X 万字比例）；起点"追读"限定"近三个月有充值/订阅的用户在最新章发布后 24 小时内阅读"（有真追/假追之分）；塔读另有"读者试读率"与"七十二小时追更率"。御书必须记录"指标名 + 平台 + 口径 + 统计窗口"四元组，否则跨平台对比无意义。
3. **掉章点（末点流失）与留存曲线**。留存曲线随章数自然递减，异常在"不自然的大幅下跌"：经验法则为某章阅读/完读较前一章下降 ≥30% 视为掉章点；中盘后缓慢下降＝展开太慢/节奏不佳，前 3~5 章急跌＝开篇"抓手"不足，单章异常低＝标题或内容同质。
4. **追读率为何是免费平台核心指标**。免费平台以广告时长变现，算法用追读率判断作品能否持续留人并据此分配流量：追读率≈"100 个从第一章读起的人中有多少读到最新章"。行业经验阈值：番茄追读率 50% 左右为"生死线"；追更率稳定 40% 以上可获显著流量倾斜；10 万字完读率原创约 15%、同人约 20% 为及格。追读是"期待感是否成立"的直接读数，与 G05 期待感模型同构。
5. **数据驱动大纲调整的边界**。数据有滞后性（起点 24 小时追读受"养书"影响，读者在情绪高峰后阶段性停追，易被采样误判为潜力不足），也有样本偏差（免费/付费读者画像不同、听书用户混入、冷启动期读者不计入番茄旧口径完读率）。因此数据只宜用于"调速度、调钩子、调更新节奏"，不能用来"砍已承诺的伏笔/爽点结构"——那会破坏 F08 台账与 I03 情绪曲线的信用。
6. **合规与数据主权**。平台后台数据需登录且有明确使用条款，抓取后台或第三方"数据网站"存在合规风险。御书取向：由作者在本地录入/导入自己的观测值（手工、CSV、离线截图 OCR），数据文件归用户所有，不做后台爬取、不上传（docs/01 §6 数据主权承诺）。

## 3. 可转化为产品规则的关键实践

1. 指标字典 → 内置"指标名 + 平台 + 口径 + 窗口"四元组字典（见 §5 metric schema），每平台一套口径，导入时必选，避免混用。
2. 本地数据录入 → 手工表格、CSV 导入、离线截图 OCR 三条路径，写入项目内 `data/reader-metrics/*.csv`（纯文本、可 Git）。
3. 留存曲线生成 → 按章绘制阅读/完读曲线，自动标注"自然递减带"与"异常下跌章"。
4. 掉章点定位 → 相邻章降幅 ≥30%（阈值可调）自动标记为 candidate 掉章点，并关联该章正文与章末钩子（I01）。
5. 追读/完读阈值看板 → 按平台口径显示追读率、完读率、追更率与阈值参考线，低于阈值预警。
6. 掉章点归因 → 对掉章点章节跑节奏体检（I04）与钩子检查（I01），把"数据现象"落到"文本原因"候选清单。
7. 数据—创作回路视图 → 把情绪曲线（G05/I03）与追读曲线叠在同一时间轴，观察"释放章"与"追读峰"的对齐关系。
8. 边界护栏 → 当"大纲调整建议"与 F08 未回收伏笔、I03/G05 已承诺爽点冲突时，护栏提示"不可用数据破坏已承诺结构"，只允许调节奏与更新。
9. 数据滞后提示 → 24 小时/72 小时窗口数据标注"高波动"，提示单点数据不可作为唯一依据。
10. 体检报告联动 I08 → 读者数据作为"外部信号"并入项目体检报告，与码字/节奏等"内部信号"并列展示，但不自动执行决策。

## 5. 对御书设计的启示

**数据结构建议：读者数据指标（metric schema 草案）**

```yaml
# data/reader-metrics/metrics.yaml（项目内，本地纯文本）
metrics:
  - id: fanqie-zhuidu
    name: 追读率
    platform: fanqie            # fanqie | qidian | tadu | other
    definition: 从第一章读起并读至最新章的人数占比
    window: 7d                  # 统计窗口（各平台口径不同）
    unit: ratio
    threshold: {warn: 0.40, good: 0.50}
  - id: qidian-24h-zhuiding
    name: 24小时追订
    platform: qidian
    definition: 近三个月有充值/订阅的用户在最新章发布后24h内阅读人数
    window: 24h
    unit: count
    threshold: {note: 受"养书"影响，高波动}
  - id: fanqie-wanzi-duwan
    name: 万字读完率
    platform: fanqie
    definition: 读者从第1章持续读至X万字的比例（X∈{10,30,50,80,100}）
    window: cumulative
    unit: ratio
observations:                    # 作者本地观测记录（手工/CSV/离线OCR 导入）
  - {date: 2026-10-05, platform: fanqie, metric_id: fanqie-zhuidu, value: 0.47, chapter: ch-060}
  - {date: 2026-10-05, platform: qidian, metric_id: qidian-24h-zhuiding, value: 1240, chapter: ch-012}
```

**数据结构建议：掉章点报告（drop_off_report）**

```yaml
drop_off_report:
  scope: {type: project, ref: vol2}
  curve: [{chapter: ch-041, reads: 5210}, {chapter: ch-042, reads: 3120}]  # 归一化阅读/完读
  drop_offs:
    - {chapter: ch-042, drop_pct: 0.40, level: warn,
       suspects: [pacing-no-advance, chapter-hook-missing],   # 关联 I04/I01 规则
       note: 前话钩子弱 + 本章空转场景}
  thresholds: {drop_pct_warn: 0.30}
  lag_warning: true               # 标注数据滞后（24h/72h 窗口）
```

**功能建议**

- 数据仪表盘：追读/完读/掉章点/收藏票评四区看板，按平台口径切换，阈值线可编辑。
- 掉章点定位器：留存曲线 → 异常下跌章 → 一键跳转正文并跑 I04 节奏体检 + I01 钩子检查，输出"文本原因候选"。
- 指标口径字典管理：平台口径可扩展/可覆写，导入时强制选择并生成"口径对照表"。
- 本地录入中心：手工表格 / CSV 导入 / 离线截图 OCR（OCR 可选、必须离线），不请求任何平台后台接口。
- 双曲线叠加视图：情绪曲线（I03/G05）与追读曲线同轴，标记"释放章对齐/错位"。
- 边界护栏面板：列出所有因数据触发的改动提案，凡触碰已承诺结构者高亮拦截并说明原因。

**校验规则建议**

- `metrics-window-missing`：观测记录未填平台口径或统计窗口 → error（防跨平台混用）。
- `metrics-cross-platform-compare`：把不同 platform/definition 的同名指标直接比较 → warn。
- `drop-off-unexplained`：掉章点章未登记任何归因（suspects 为空）→ info。
- `data-cannot-break-promise`：任何"依数据调整大纲"的提案若触碰 F08 未回收伏笔或 I03/G05 已承诺爽点 → error 护栏，仅允许调节奏/更新。
- `metrics-single-point-reliance`：仅凭单点（<3 次观测或 24h/72h 窗口）给出结论 → info"样本不足"。
- `metrics-stale`：观测数据超过 N 天未更新 → info。

**AI 提示词建议**

- 「掉章点归因」：输入掉章点前后各一章正文 + 已有指标，输出可能原因候选（空转场景/钩子缺失/信息倾倒/同质化），每条给证据引用，不做结构改动建议。
- 「数据解读」：输入一组本地观测数据 + 口径，区分"数据信号"与"噪音（滞后/样本偏差）"，输出小步可执行调整（调钩子/调更新节奏）。
- 「大纲调整边界检查」：输入拟调整的大纲变更 + F08 台账 + G05 承诺清单，输出"是否破坏已承诺伏笔/爽点"的判定与替代方案。
