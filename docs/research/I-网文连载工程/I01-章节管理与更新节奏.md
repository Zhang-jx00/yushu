# I01-章节管理与更新节奏

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究连载小说最小发布单元「章节」的工程化管理，以及围绕章节展开的更新节奏体系：单章字数惯例与平台口径、章末钩子（断章）的结构化设计、更新频率与时间表、存稿机制、章节发布状态流转。边界划分：F02 研究连载叙事理论，本领域只做工程落地；I02 管"写什么"（大纲层级），本领域管"怎么切分、何时发布"；I03 管全书情绪曲线，本领域只负责章末钩子的挂点与检测。核心工程问题：章节实体如何建模（含更新状态机与元数据），更新节奏如何被工具量化、管理和预警。

## 2. 核心知识框架

1. **单章字数惯例**。网文单章以 2000~4000 字为主流；平台付费章节有硬性下限（潇湘书院 VIP 章节不低于 3000 字、上限 2 万字；免费章节不低于 1000 字）。唐家三少以 3000 字/章 × 每日两章（早晚各一）为稳定节奏，认为"一天更新 6000 字是比较舒服的节奏"。番茄官方课程明确：**章节结构优先，字数不在优先考虑范围**，不为了卡 2000 字破坏章节完整性。
2. **章末钩子（断章）**。心理学依据：蔡格尼克效应——人对"未完成"事项记忆更深，章末制造认知缺口可驱动翻页。可操作的断章法：① 停在期待感上（主角谷底但暗示自有办法）；② 打脸将断未断（反派撂狠话、主角蓄势最强一句后切断）；③ 动作/对话最高点硬切（"他伸手推开门……"）。番茄课程的操作口径：一章的故事只写 80%，剩下 20% 放下一章开头，"永远不要把剧情结果放在章节末尾"；B 站教程总结为"把话说完但不要说透"。
3. **钩子的分类体系**。五类钩子：引流钩（书名）/卖点钩（简介）/开场钩（开篇）/主线钩（贯穿全文的大钩子）/章节钩（章末断章卡点）——只有主线钩没有章节钩，读者会失去追更动力。六类章末钩写法：动作截断式、反转揭秘式、未知危机突袭式、身份谜团式、两难抉择式、代价伏笔式。
4. **更新节奏体系**。日更 4000~6000 字是主流商业节奏（番茄全勤档位即按 4000/6000 字分档）；起点新书建议一日 2~3 次更新、两次更新间隔 6 小时以上；常见时间表为午间 12 点与晚间 8 点双更。存稿是节奏的稳定器：唐家三少"一直有存稿，也就一直没断过"；起点作者的真实更新时间表显示用周末多写、存稿匀到满课的周一维持日更。加更规则（均订每增 2000 加更一章、单次大额打赏加更）构成节奏的弹性上界。
5. **更新义务与断更代价**。圈内以"不断更"为核心职业信用（唐家三少将"不断更"列为最看重的成就）；断更的直接代价是推荐位流失：没有更新→推荐跟不上→没有读者→没有收入。请假条、定时发布、存稿预警是作者侧的应对工具。
6. **章节作为发布产物**。章节含卷-章两级结构、序号、章节名、字数口径（按平台的"有效字数"规则）、免费/付费分界（前 N 章免费）与上架节点；发布形式含即时发布与定时发布，修改已发布章节需处理"已订阅读者"的兼容问题。

## 3. 可转化为产品规则的关键实践

1. 章节实体 = Markdown 正文 + YAML frontmatter → chapter schema 见 §5，卷/章层级与序号为结构字段。
2. 更新状态机（草稿→存稿→定时→已发布→修订）→ 章节列表按状态分组，发布流与平台无关地本地化流转。
3. 单章字数按平台口径检测 → 校验规则：低于平台下限（如 VIP ≥3000 字）warn，超上限（如 2 万字）warn；生成"章节字数分布图"辅助节奏诊断。
4. 章末钩子标注 → 章节元数据增加 `hook_type` 枚举，章末 200 字可 AI 辅助识别钩子类型，未识别出钩子的章节进入"钩子缺失"清单。
5. 存稿池与续航天数 → 存稿章数 ÷ 日更章数 = 可支撑天数；低于阈值（如 3 天/7 天）触发断更预警，与 I08 统计模块共用日历。
6. 更新计划表 → 项目级"更新模板"（每周更新日 × 时段 × 章数），实际发布记录与计划偏差可视化。
7. 定时发布 → 章节可设定发布时刻，应用离线时由本地任务队列在启动后补发提示（不代替平台发布）。
8. 卷章结构校验 → 序号连续性、卷归属完整性、重排后引用（伏笔埋设/回收章节号）的联动更新——与 F08 伏笔台账联动。

## 5. 对御书设计的启示

**数据结构建议：章节实体 schema（frontmatter 草案）**

```yaml
# chapters/vol1/ch-012.md 的 frontmatter
id: ch-012
title: 第12章 夜探藏经阁
index: 12                  # 全书连续序号（重排时引擎维护）
volume: vol1
status: scheduled          # draft | stock | scheduled | published | revised
word_count: 3120           # 按平台有效字数口径计算
publish_at: 2026-10-02T20:00:00+08:00
published_channels: []     # 平台侧发布记录（外置，不强制）
pov: {character: char-linyuan}
outline_ref: outline/ch-012        # 章纲双向链接（I02）
hook:
  type: action_cutoff      # action_cutoff | reversal | crisis | identity | dilemma | cost
  note: 断在推门瞬间
foreshadow_refs: [fs-003]  # 埋设/回收伏笔（F08 台账联动）
summary: ""                # 章摘要（记忆系统分层，见 J03）
```

**更新状态机**

```text
draft ──> stock ──> scheduled ──> published ──> revised
  ↑          │            │            │
  └──────────┴────────────┴────────────┘   (均可回退，回退记录留痕)
```

**功能建议**

- 章节列表按状态分组（草稿箱/存稿池/待发布/已发布），存稿池显示"可支撑 N 天"续航指标。
- 更新日历：计划模板（每周更新日 × 时段 × 章数）叠加上实际发布记录，偏差用颜色标注；与 I08 码字统计共用同一日历组件。
- 章末钩子助手：对选中章节的末段做钩子类型建议（AI 候选 + 用户确认），未标注章节进入"钩子缺失"看板。
- 章节字数分布图：全书逐章字数折线 + 平台口径参考线（3000/4000/6000），识别"注水章/超短章"（与 I04 注水检测联动）。
- 定时发布为本地提醒队列，不代替平台发布流程（对应 docs/01 §5 非目标）。

**校验规则建议**

- `chapter-word-floor`：VIP 章节字数 < 平台下限 → warn（规则参数来自平台规则包，见 I07）。
- `chapter-hook-missing`：连续 ≥3 章 `hook` 为空 → info 提示，不强制。
- `chapter-index-gap`：卷内序号不连续 → error；重排后自动修复引用。
- `chapter-foreshadow-ref`：章节引用的伏笔 ID 在 F08 台账中不存在 → error。

**AI 提示词建议**

- 「断章改写」：输入章末 300 字 + 钩子类型目标，输出 2~3 个断章位置候选（说明切断点与读者预期）。
- 「章节命名」：依据章纲与正文生成候选标题（对齐全书命名风格，与 C09 命名体系联动）。
- 「章摘要」：生成 ≤150 字章摘要回写 frontmatter，供记忆系统分层使用。
