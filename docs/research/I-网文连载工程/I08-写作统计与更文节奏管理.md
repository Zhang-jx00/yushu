# I08-写作统计与更文节奏管理

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究「写作行为本身」的量化与节奏管理：把每一次敲键盘的产出，转化为日/周/月字数、速度曲线、目标打卡、断更预警、专注习惯与防丢稿联动的可管理数据。边界划分：I01 管章节实体与发布状态机，本领域只消费其「存稿池」数据做续航预警；F02/I03 研究连载叙事与情绪曲线，I04 关注「写得注不注水」，本领域只回答「写了多少、能否持续」；J 类（合规证据链）回答「谁写的」，本领域回答「写了多久、有没有断」。核心工程问题：字数的「平台有效口径」如何建模、目标与打卡如何计算达标、断更风险如何提前预警、多项目并行时统计如何隔离。本领域直接对应 docs/01 §4.6 作者刚需套件中的「码字统计与更文管理」「防丢稿」「专注模式」三项。

## 2. 核心知识框架

1. **字数口径与「当日有效更新字数」**。番茄全勤以后台「打卡日历」显示字数为准，口径为「作者维度单日有效更新字数」；未过审章节不计入打卡字数，重审通过后只回填到初次发表当天。番茄分两档：普通全勤「每日有效更新字数 4,000 字及以上」、进阶全勤「6,000 字及以上」；官方同时标注 4,000 为打卡门槛、6,000 为爆更。起点侧无更新频率硬性要求，但每章内容不能为空、单章不超过 20,000 字、建议 2,000~6,000 字。飞卢口径更严：非 VIP 全勤「每日 3,000 字以上且月更 9 万」或「每日 6,000 字以上且月更 18 万」，且「字数统计以 Word 统计为准」。
2. **速度曲线与产出节律**。统计不止总字数，还含码字速度（字/分钟、字/小时）、净字数与会话时长。番茄作家助手在「码字日历」中打卡每天写作字数，第三方工具（小黑屋、闭关写作）则实时显示「字数、码字速度、码字时速」。速度曲线把「产能」拆成可诊断的日节律：识别高效时段、估算完稿工期、区分「打字数」与「净增字数」（删改回退）。
3. **全勤制度与达标计算**。番茄全勤需同时满足：签约且有效过审满 10 万字的次月起、当月听读分成收益≥500 元、当月每日有效更新达档位；每本书每月可请假 1 天（须在后台打卡日历点「请假申请」）；同一自然月每位作家仅一部作品享受全勤。断更代价：连续断更超 15 天作品被标记「断更」，失去全部平台福利。飞卢「自然月内断更不超过 1 天」才可申请全勤。达标计算 = 逐日达标天数 × 是否使用请假额度 × 收益门槛。
4. **目标管理与打卡习惯**。番茄上线的「码字团战」等组队打卡活动证明：连续打卡、累计打卡（断一天仍可续）、日更冲刺阶梯是强驱动的养成机制。番茄工作法（25 分钟专注 + 5 分钟短休，4 个番茄后长休 15~30 分钟）给出可配置的专注单元模型：番茄时间不可分割、被打断即作废、记录每日番茄数并复盘。
5. **断更预警与存稿续航**。预警本质是「缺口预测」：今日进度 vs 档位下限、存稿章数 ÷ 日更章数 = 可支撑天数；临近月度结算的达标风险最高，官方明确提醒「请勿在月底 23:00 之后极限打卡/补打卡」，且补打卡只能在当月内通过修改章节字数完成，无更新当天则完全无法补。
6. **专注、防丢稿与统计联动**。小黑屋以「锁定」（设定时长或字数，未完成不可退出）为强制专注核心，并强调「不丢稿」是写作软件的底线；它每一次回车即保存、每十分钟生成独立文档、可设邮箱存稿。统计与存储的联动点是：字数计数依赖自动保存的落盘事件，崩溃恢复后需能续算当日字数。
7. **多项目并行统计隔离**。番茄「同一自然月每位作家仅一部作品享受全勤」这一平台约束，倒逼工具必须按项目（书）维度隔离统计，避免「一本冲榜何不并两本冲」的误差；作者身份下的笔名/多本书需共享「日产」但不共享「达标」。

## 3. 可转化为产品规则的关键实践

1. 日/周/月三级字数视图 + 速度曲线 → statistics schema（见 §5），按项目聚合，支持导出 CSV。
2. 「当日有效更新字数」按平台规则包计算 → 规则包（见 I07）声明档位（4,000/6,000）、有效字数换算（去空白/格式符）、打卡归属日（以发布时间为准）。
3. 全勤目标管理与达标计算 → goal schema 声明日/周/月目标与档位，逐日累计达标天数、请假额度、收益门槛三项合成「全勤达成度」进度环。
4. 断更预警（消费 I01 存稿池）→ 存稿可支撑天数低于阈值（3/7 天）触发预警，叠加以「今日缺口 + 距月末天数」的风险投影。
5. 写作日历与习惯养成 → 日历视图输出打卡热力图（连续/累计两种口径）、番茄钟会话记录、专注时段统计。
6. 专注模式（番茄钟 / 沉浸 / 可选小黑屋式强制锁定）→ 会话计时器独立于统计，会话结束时写入 `sessions`，不达标者可选择「作废本次番茄」。
7. 防丢稿与统计联动 → 自动保存（WAL + debounce，见 S8）落盘即累加计数；崩溃恢复后从快照重算当日净字数，避免丢稿导致统计跳变。
8. 多项目并行统计隔离 → 统计按 `project` 分区存储，跨项目查询需显式聚合；同账号笔名仅共享「日产」展示，不共享达标计数。

## 5. 对御书设计的启示

**数据结构建议：写作统计日报 schema**

```yaml
# stats/daily/2026-10-02.yaml
date: 2026-10-02
project: proj-demo            # 多项目隔离：统计按 project 分区
channel: fanqie               # 平台口径包（见 I07）
counted:
  raw_chars: 5230             # 正文原始字符数
  effective_chars: 5120       # 平台「有效更新字数」口径
  tier: advanced              # none | basic(4000) | advanced(6000)
sessions:
  - {start: "09:10", end: "10:05", chars: 1200, mode: pomodoro}
  - {start: "21:00", end: "22:30", chars: 3900, mode: focused}
speed: {net_cpm: 62, active_minutes: 145}
goals: {daily: 6000, met: false}
streak: {consecutive_days: 12, leave_used: 0}   # 番茄每月可请假 1 天
stock: {chapters: 4, sustain_days: 2.0}          # 消费 I01 存稿池
saved_at: 2026-10-02T22:31:05+08:00
snapshot_ref: snap-20261002-2230                  # 防丢稿快照联动（K10）
```

**目标与打卡配置 schema**

```yaml
# stats/goals.yaml
goals: {daily_chars: 6000, weekly_chars: 40000, monthly_chars: 180000}
checkin:
  policy: platform_tier       # platform_tier | custom
  leave_quota_per_month: 1    # 番茄：每本书每月 1 天
  arc: cumulative             # consecutive | cumulative（团战累计打卡口径）
limits:
  late_night_cutoff: "23:00"  # 之后不鼓励极限打卡
```

**功能建议**

- 产能仪表盘：日/周/月字数折线 + 速度曲线 + 打卡热力图（连续/累计双口径），叠加平台档位参考线 4000/6000。
- 全勤达成度进度环：三项合成（逐日达标天数、已用请假额度、收益门槛），一眼看出「差几天/差多少字」。
- 断更预警看板：今日缺口、推移后的月度达标风险、存稿可支撑天数（与 I01 存稿池共用日历组件）。
- 专注中心：番茄钟（可配置 25/5/15-30）、沉浸模式、可选小黑屋式「锁定到目标字数/时长」；作废/记录番茄的显式操作。
- 统计与防丢稿联动：自动保存落盘即累加；崩溃恢复后按快照重算当日净字数，不产生统计跳变。
- 多项目统计切换器：默认按项目视图，跨项目对比需显式开启，避免误把两本书字数算作单书达标。

**校验规则建议**

- `stats-effective-floor`：当日有效更新字数 < 平台档位下限（默认 4,000）→ warn，并标注「不计入打卡」。
- `stats-streak-risk`：超过 `late_night_cutoff`（默认 23:00）仍未达档位 → 高优先提醒（对齐番茄「勿极限打卡」）。
- `stats-goal-miss`：周/月目标完成率 < 80% → info，输出缺口与所需日均。
- `stats-stock-days-low`：存稿可支撑天数 < 3（可配置 7）→ 断更预警（与 I01 联动）。
- `stats-project-bleed`：跨项目同日写作量归属冲突或统计串项 → error（多项目隔离）。
- `stats-autosave-gap`：统计入库时间与最后自动保存时间差 > 阈值 → info，提示补建快照（K10）。

**AI 提示词建议**

- 「节奏诊断」：输入近 30 天统计 + 平台档位，输出未达标日的归因（时段/速度/存稿）与下周排产建议。
- 「目标拆解」：依据月更目标与作者习惯时段，生成每日字数与更新时段安排（含请假额度使用建议）。
- 「卡文干预」：结合当日缺口与 I01 章纲，给出「先写哪一段最容易达标」的最小任务清单。
