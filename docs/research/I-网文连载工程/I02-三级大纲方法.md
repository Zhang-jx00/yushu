# I02-三级大纲方法

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究连载小说"三级大纲"的结构化工程：总纲（全书）→卷纲（一卷）→章纲/细纲（单章）三级数据结构的字段、粒度与依赖关系，以及围绕大纲展开的工作流——细纲作为防卡文核心、从结局倒推的反向大纲（雪花法）、章纲与正文的双向映射与写作偏差对比、大纲卡片的拖拽重排与引用维护。边界划分：F01 研究三幕/英雄之旅/救猫咪 15 节拍/七点结构等叙事理论，F02 研究"卷-篇章-章"的网文层级切分与黄金三章；本领域不重复叙事理论本身，只把大纲当作可编辑、可校验、可扩写、可重排的数据结构来落地。I01 管章节实体与更新节奏，本领域管"写什么"的计划层。核心工程问题：三级大纲如何建模为一棵可被 AI 分层扩写、被规则校验、被重排后自动修链的结构。

## 2. 核心知识框架

1. **三级层级与粒度**。业内通行工作流是"大纲→章纲/细纲→正文"：总纲=题材卖点+梗概主线+人设+金手指+结局；卷纲=一卷一条相对独立主线+卷末大高潮；章纲/细纲=单章剧情。番茄官方口径为"粗纲定方向、细纲定节奏"，单章细纲用 2~5 句话概括核心剧情并标注冲突、转折、情绪、钩子。
2. **细纲是防卡文核心**。番茄官方课程直言"细纲对治疗卡文有奇效——如果你知道下一章要发生什么，就不会不知道今天要写什么"；细纲不必一次写完全书，只需覆盖正文之后约 2~3 万字（不足 1 万字即须补写），是"防卡文核心"（docs/01 §4.4）。
3. **细纲的展开粒度**。单章细纲需回答"谁/在哪/目标/阻碍/转折/结果/钩子"七要素，对齐单章 3000 字正文容量；一个完整"冲突+博弈+结果收获"的小剧情对应几千到上万字。
4. **反向大纲与雪花法**。七点结构主张"从结局倒推设计"（F01）；雪花法 10 步递归扩写并强调"迭代回溯"——后步发现问题必须回改前步；中文实操称"逆推顺写法"：先把人物前世今生与事件来龙去脉推清，再顺着写。
5. **目标树大纲法（OKR）**。番茄官方"OKR 大纲法"把主线当作目标 O，逐层拆成关键结果 KR，KR 可再降为目标 O 继续细化——本质与"总纲→卷纲→章纲"的目标树同构，章纲即目标树的叶子。
6. **章纲-正文双向映射与偏差对比**。晋江作者法强调"时刻紧跟大纲，但又不依附大纲""随时观测正文走到大纲哪一步"；章纲可随正文微调，但调整后须及时回写章纲，形成计划（plan）与实际（actual）的偏差记录——大纲是诊断工具而非契约。
7. **卡片拖拽重排与依赖**。章纲以卡片承载，重排会改变序号与引用关系（伏笔埋设/回收章节号 F08、节拍打点 F01、读者承诺 I03），因此重排必须触发引用自动修链；卡片之间存在前置依赖（因果/埋设/兑现）。

## 3. 可转化为产品规则的关键实践

1. 三级大纲建模 → 总纲/卷纲/章纲三层实体（schema 见 §5），每级字段固定且必填项可配。
2. 细纲覆盖窗口检测 → 规则 `outline-coverage-gap`：正文之后已写细纲不足 N 章（默认 10）→ 提示"细纲告急"，防卡文。
3. 细纲粒度校验 → 单章细纲缺 goal/obstacle/turn/result/hook 任一 → warn，并给出补全示例。
4. 章纲-正文双向链接 → 章纲 `chapter_ref` 与章节 frontmatter `outline_ref`（I01）互链，任一侧缺失提示。
5. 偏差对比视图 → 每章记录 planned/actual/delta，规则 `outline-deviation`：已发布章节的偏差未确认即入"待回写"清单。
6. 反向大纲向导 → 按 F01 的 `design_order`（结局→钩子→中点→其余）依次填空，驱动雪花法式倒推。
7. 卡片拖拽重排 → 重排后自动更新序号、卷归属与所有引用（伏笔 F08 / 节拍 F01 / 承诺 I03 / 依赖）。
8. 依赖图与循环检测 → `dependencies` 字段维护前置关系，出现环或悬空引用报错。
9. 结构模板包 → 三幕/救猫咪 15 节拍/七点/起承转合编译为模板骨架（复用 F01 模板包），模板只给节拍骨架，不生成具体剧情。
10. 一键扩写 → 细纲→草稿的 AI 分层生成（对接 docs/01 §4.4 与 F02 的分层控制），每层人工确认后再进下一层。

## 5. 对御书设计的启示

**数据结构建议：三级大纲 schema（frontmatter/YAML 草案）**

```yaml
# outline/outline.yaml（大纲系统唯一事实源）
story_outline:                      # 总纲（全书）
  logline: 一句话故事线             # 15~25 字，不含人名
  promise: 对读者的总承诺           # 引 F12 承诺清算
  ending_type: 封闭
  structure_template: save_the_cat_15   # 引 F01 模板包 id
  beats_pinned: [catalyst@c12, midpoint@c60, all_is_lost@c180]
volume_outline:                     # 卷纲
  id: vol1
  logline: 本卷一句话主线（必填）    # 写不清=结构问题预警（引 F02）
  state_shift: 卷初状态 → 卷末状态
  climax: 卷末大高潮
  chapter_range: [1, 60]
  word_target: 200000
  arc_refs: [a1, a2]                # 卷内篇章（引 F02）
chapter_outline:                    # 章纲/细纲（一等公民）
  id: co-012
  chapter_ref: ch-012               # 双向链接（I01 frontmatter outline_ref）
  goal: 主动提出退婚并夺回遗物      # 谁 + 在哪 + 目标
  obstacle: 未婚夫脚踏两船、表妹觊觎嫁妆
  turn: 当众拿出证据
  result: 婚退、遗物到手、男方理亏
  hook_close: reveal                # 章末钩子类型（引 I01 hook.type）
  word_target: 3000
  promise_ids: [promise-003]        # 引 I03 读者承诺清单
  foreshadow_refs: [fs-003]         # 引 F08 伏笔台账
  beat_refs: [midpoint]             # 引 F01 节拍打点
  status: outlined                  # outlined | drafting | drafted | deviated
deviation:                          # 写作偏差（计划 vs 实际）
  chapter_ref: ch-012
  planned: {goal: 退婚, result: 夺回遗物}
  actual:  {summary: 退婚暂缓，改为先夺遗物}
  delta: 结果延后，须同步更新 promise-003.due_ch
  approved: false                   # 用户确认后回写章纲
dependencies:                       # 卡片依赖
  - {before: co-011, after: co-012, type: causal}   # causal | setup | payoff
```

**校验规则建议（含规则 id）**

- `outline-coverage-gap`：正文之后已写细纲 < N 章（默认 10）→ warn "细纲告急，防卡文"。
- `outline-field-missing`：章纲缺 goal/obstacle/turn/result/hook 任一 → warn。
- `outline-deviation`：`deviation.approved=false` 且章节已发布 → info "偏差待回写章纲"。
- `outline-link-broken`：`chapter_ref`/`foreshadow_refs`/`promise_ids` 指向不存在实体 → error。
- `outline-dependency-cycle`：`dependencies` 出现环或前置悬空 → error。
- `outline-beat-unpinned`：正文已进入某节拍窗口但该节拍未绑定章纲 → warn（联 F01）。
- `outline-order`：卡片重排后卷内序号/index 非单调不减 → error，并自动修链。

**功能建议**

- 三级大纲编辑器：总纲/卷纲/章纲三个视图联动，章纲以卡片承载，支持拖拽重排与批量移动。
- 细纲热力条：以"正文之后已有细纲的章数"为指标显示"续航"，低于阈值变红（与 I01 存稿池同页）。
- 偏差对比面板：章纲（计划）与正文摘要（实际）并排 diff，一键"回写章纲"或"标注为有意偏离"。
- 反向大纲向导：按结局→钩子→中点顺序逐步提问，落点自动写入 beats_pinned。
- 依赖视图：卡片间因果/埋设/兑现依赖以有向图呈现，重排时实时提示受影响的下游引用。

**AI 提示词建议**

- 「三层扩写」：输入一句话灵感 → 生成总纲候选 → 人工确认 → 生成卷纲（含 logline/state_shift/climax）→ 确认 → 生成章纲五要素（引 F02 分层控制，对接 docs/01 §4.4）。
- 「反向大纲」：先要求模型只输出结局与终场画面，再倒推中点与触发事件，缺口冷冻不生成后续，避免顺写式脑补。
- 「细纲生成」：注入当前卷纲 + 前情摘要 + 在册伏笔（F08）+ 未兑现承诺（I03），要求每章显式回答"目标/阻碍/转折/结果/钩子"并标注所属节拍（F01）。
- 「偏差对比」：输入章纲与实际正文，输出偏差清单（结果/钩子/承诺兑现三栏），并给出"回写章纲"或"保留偏离并联动下游"的建议。
