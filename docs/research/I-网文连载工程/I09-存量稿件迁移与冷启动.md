# I09-存量稿件迁移与冷启动

> 类别：I-网文连载工程 ｜ 世界构建金字塔层级：工程层 · 连载工程
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

研究作者既有稿件的「一次性迁移」与随之而来的「设定库冷启动」：把散落在 TXT/DOCX（乃至平台导出的乱码 txt）中的旧稿，经编码还原、正文清洗、自动分章、字数对账，转成御书的结构化章节，再由 AI 抽取人物/地点/势力/物品/设定，沉淀为可确认入库的设定卡，最后产出可核验的迁移校验报告。边界划分：I01 管新章节实体与发布，本领域只管「历史正文如何变成章节 + 设定卡」；J03/J06 提供记忆分层与结构化抽取能力（本领域是其下游消费方）；K13 管大文档性能与 Worker 委托。核心工程问题：迁移的**数据保真**（可对账、可回滚、可中断恢复）与「迁移即建库」（导入即完成设定库冷启动）。

## 2. 核心知识框架

1. **编码探测**。TXT 无内建编码信息，解码前必须先「猜」编码。可靠顺序：BOM 优先（UTF-8 `EF BB BF`、UTF-16 `FF FE`/`FE FF`）→ 试 UTF-8（用替换字符 `U+FFFD` 计数判断是否失败）→ 回退 GB18030（GBK/GB2312 的超集）→ 再试 Big5/Shift_JIS/EUC-JP 等 → 统计探测（chardet，返回 `encoding`/`confidence`/`language`）。官方与社区共识：中文小说站导出的 TXT 多为 GBK 或 UTF-8 无 BOM，GB18030 是 GB 系「最安全的兜底」；短样本上统计探测会误判，需给出置信度并要求人工预览确认。
2. **正文清洗**。旧稿常混入平台广告行、站点水印声明、作者感言、重复章节标题头、「返回目录」等噪声，需以可配置正则行级剔除，并保留清洗报告（删了多少行、剩多少字），避免「静默丢内容」。
3. **自动分章**。主流做法是正则识别标题行：插件 `txt-novel-reading` 用 `/(?<=\r\n)(\s*)([第序]{1}.*?[章幕卷篇]{1}.*?)(?=\r\n)/g`；阅读器 Reader Copilot 内置 `(第)([―－\-─—壹贰叁肆伍陆柒捌玖一二两三四五六七八九十○零百千O0-9]{1,12})([章节節回集卷部篇])`。更稳的是「两段式」：先按内置规则海选标题行，再用 AI 二次筛选，减少误切。
4. **误切检测与人工校正**。误切形态：把正文中的「第一章」引用当标题、序号回退/重复、标题过长或过短、章节字数突变（如某章 300 字或 3 万字）。校正界面需支持合并/拆分/重排/重命名，并实时预览前后章节。
5. **字数对账**。迁移前后必须可核对：导入前正文总字数（扣除清洗噪声）应等于分章后各章字数之和（含/不含标题行需给出明确口径）；差值为 0 或不超阈值才通过，否则进入人工复核。
6. **实体抽取建库**。以章节窗口为输入，用结构化输出（JSON Schema 强制）抽取人物/地点/势力/物品/设定，每条带出处（章号 + 引文）与置信度；抽取结果先进「候选池」，由用户确认后写入设定卡，形成设定库冷启动。此路径与 J06 的结构化抽取、J05 的设定注入同构。
7. **大文件性能与可中断恢复**。百万~三百万字级导入必须分块 + 增量 + 断点续跑：DOCX 解析下放 Worker；任务状态持久化（章节进度、最后成功章号），中断后可续跑；对老作者「多本书 / 多笔名 / 多平台历史」需支持批量任务与独立报告。

## 3. 可转化为产品规则的关键实践

1. 导入任务状态机（pending→running→needs_review→done/failed）→ import-job schema（见 §5），进度与断点可持久化、可中断续跑。
2. 编码探测 → 先 BOM、再 UTF-8、再 GB18030 兜底、失败转统计探测；置信度低或预览乱码则强制人工确认。
3. 正文清洗 → 可配置 strip 正则（广告/水印/作者话/目录残留）+ 清洗报告（removed_lines / kept_chars）。
4. 自动分章 → 章节正则冷却包 + 两段式「规则海选 → AI 筛选」，正则匹配率低时回退 AI。
5. 误切检测 → 章号连续性、标题长度、章节字数分布三类校验，异常进入人工校正清单（合并/拆分/重排）。
6. 字数对账 → 迁移前后总字数比对与差值报告，超阈值拦截为「需复核」。
7. 实体抽取 → 结构化输出为候选，`status: candidate`，用户确认后写入设定卡（引用 J06）。
8. 设定库冷启动流水线 → 候选按类型分组（人物/地点/势力/物品/设定）、去重合并别名、冲突高亮，一键「确认入库」。
9. 迁移校验报告 → 汇总编码/清洗/分章/对账/抽取五段结果，输出「可核验报告」供老作者签字式确认。

## 5. 对御书设计的启示

**数据结构建议：导入任务 schema**

```yaml
# imports/job-imp-0007.yaml
id: imp-0007
source: {path: "D:/旧稿/demo.txt", size_bytes: 5123456,
         detected_encoding: GB18030, encoding_confidence: 0.74, bom: false}
normalize: {target_encoding: UTF-8, strip_patterns: [], 
            clean_report: {removed_lines: 132, kept_chars: 3012345}}
split: {regex: "(第)([一二三…0-9]{1,12})(章|节|回|卷|篇|集)",
        matched: 812, fallback_ai_used: false}
reconcile: {source_chars: 3012345, chapter_chars_sum: 3011990, delta: -355}
status: needs_review    # pending | running | needs_review | done | failed
checkpoint: {last_chapter: 512, resumable: true}
```

**实体抽取候选 schema（对齐 J06 结构化输出）**

```yaml
# imports/extract/imp-0007-candidates.yaml
type: character        # character | location | faction | item | setting
name: 林渊
aliases: [小渊]
evidence: [{chapter: 12, quote: "林渊推开殿门…"}]
confidence: 0.86
source_job: imp-0007
status: candidate      # candidate | confirmed | rejected
```

**章节正则配置**

```yaml
# imports/rules/chapter-regex.yaml
patterns:
  cn_num: "(第)([一二三四五六七八九十百千零两〇0-9]{1,12})(章|节|回|卷|篇|集)"
  en: "Chapter\\s+\\d+"
min_title_len: 2
max_title_len: 40
```

**功能建议**

- 导入向导分五步：选文件 → 编码预览（可手动切换 GB18030/GBK/Big5）→ 清洗预览 → 分章预览与人工校正 → 对账报告。
- 分章校正界面：左侧小说树 + 右侧正文，支持合并/拆分/重排/重命名、批量按正则重切、实时显示「本章字数」与异常标记。
- 设定库冷启动面板：抽取候选按类型分栏，别名自动合并、冲突高亮，勾选即「确认入库」写入设定卡。
- 迁移进度与断点：分块进度条 + 可中断续跑；百万字级把 DOCX 解析与正则分章下放 Worker（K13）。
- 迁移校验报告：编码/清洗/分章/对账/抽取五段结论 + 差值明细，可导出 Markdown/PDF 供作者存档。
- 老作者场景：支持多书批量任务、笔名/平台历史元数据（作者名、首发平台、原书字数），每本独立报告。

**校验规则建议**

- `import-encoding-ambiguous`：编码置信度 < 阈值（默认 0.6）或预览检出乱码 → 需人工确认，不允许静默通过。
- `import-wordcount-mismatch`：迁移前总字数与分章后各章字数之和偏差 > 阈值（默认 0.5%）→ error（对账失败）。
- `import-chapter-regex-fallback`：标题匹配率 < 阈值（默认 90%）→ 提示调整正则或启用 AI 海选。
- `import-chapter-title-dup`：章号重复/回退/标题长度越界 → warn，进入人工校正清单。
- `import-adline-residue`：清洗后仍检出广告/水印特征行 → warn。
- `import-entity-conflict`：抽取实体与既有设定卡重名或别名冲突 → error（引用 J06/J05 一致性层）。
- `import-job-interrupted`：任务中断且未生成校验报告 → error，提示断点续跑。

**AI 提示词建议**

- 「标题海选」：输入疑似标题行（含上下文各 1 行），输出是否为章节标题 + 归一化标题（供两段式分章的第二段）。
- 「实体抽取」：按章节窗口抽取人物/地点/势力/物品/设定，强制 JSON Schema 输出，每条带章号与引文（引用 J06）。
- 「噪声识别」：识别广告行、站点声明、作者感言、目录残留，输出建议剔除的正则行模式（写入 `strip_patterns`）。
- 「迁移复核摘要」：依据五段校验结果生成人类可读的迁移报告开头，标注需人工确认的异常项。
