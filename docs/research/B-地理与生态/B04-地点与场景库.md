# B04-地点与场景库

> 类别：[B-地理与生态] ｜ 世界构建金字塔层级：[L1 地理层]
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

地点与场景库研究"一个个具体地点"如何成为可检索、可复用、可被叙事引用的资产：从大陆级地标、一座城、一条街，到一间酒馆。它关心地点条目的字段结构（最小必填集与扩展字段）、层级组织（世界→区域→场所→房间）、与地图 pin 的双向链接，以及地点在写作端的消费方式——场景规划时按氛围/功能/出场历史检索候选地点。边界上：城市"如何作为系统生长"归 B05，地图绘制工艺归 B01；本领域管的是地点作为"设定库中的实体"与"叙事中的布景"双身份。

## 2. 核心知识框架

1. **三种工具范式与地点条目的两种哲学**（种子库对比评测结论）：World Anvil 是强类型模板（25+ 模板把地点切成字段表单），LegendKeeper 是弱类型自由页面+嵌套地图 pin（地点即一篇 wiki 页，pin 是入口），Campfire 是模块拼装（Locations 独立模块）。结构化利于校验与 AI 消费，自由页利于写作手感——御书应取"最小结构+自由扩展"的混合态。
2. **地图 pin 链接页面**：LegendKeeper 的核心交互是 pin 即页面——空间实体与文档统一，点图即达条目。这使"地点库"天然有空间索引，而非平铺列表。
3. **问卷式字段蓝本**：Wrede 问卷中地点相关条目（外观、防御、物产、居民对外人的态度、此地最重要的矛盾）与 Reedsy 模板的地点卡（感官细节、氛围、冲突潜力）共同构成地点字段集的公共蓝本。
4. **开源社区方案**：Obsidian TTRPG 生态用 Leaflet 地图插件+自由 wiki 页把 vault 变成地点库——证明"地图为索引、页面为实体、双链为关系"的轻量方案可行且受欢迎（Obsidian TTRPG Tutorials 提供分步实践）。
5. **冰山原则与出场追踪**：GRRM"冰山九分之十在水下"（Rolling Stone 访谈）映射到地点库：大多数地点不进正文，但必须存在。因此地点条目需要"出场状态"元数据（已出场/备选/水下），并自动统计 `recorded_in_scenes[]`。
6. **地点要有故事钩子**：社区方法论共识——好地点不是布景而是潜在的冲突发生器。地点条目应有一等公民的 hooks 字段（此地藏着什么/谁想毁掉它/谁在等谁）。
7. **场景消费视角**：Storyflow 等工具评测显示写作工具的薄弱点是"设定→正文"的最后一公里；地点库的价值要在场景规划与写作视图里兑现，而不是只在设定库里自嗨。

## 3. 可转化为产品规则的关键实践

1. 地点层级树 → `Location` 支持父子嵌套（世界→大陆→地区→城市→街区→房间），全库一棵树，任意深度可检索。
2. 最小必填+渐进披露 → 仅"名称+父级"必填，其余字段（感官/钩子/居民）按需展开——WA 与 LK 对比的最大教训是不逼用户填巨型表单。
3. 地图 pin 双向绑定 → 每个地点可选挂 pin；有 pin 的地点在地图上直达，无 pin 的地点列表中标记"未定位"。
4. 五感速写卡 → 气味/声音/光线/触感/味觉五个短字段，专供写作时快速取用而非档案完整性。
5. 出场追踪 → 自动统计该地点出现的章节/场景，未出场的地点进入"冰山清单"面板。
6. 钩子字段一等公民 → 每个地点可挂 `hooks[]`（潜在冲突/秘密/传闻），场景规划板可按钩子检索地点。
7. 氛围标签检索 → 写作时按"雨夜+港口+市集"式标签组合筛选候选地点。
8. 空缺检测 → 正文/大纲中出现未建档地名时提示"此处地点未入库，是否建档"。

## 5. 对御书设计的启示

**数据结构建议**
- `Location`：`parent_id`、`map_pin{map_id,x,y}`、`senses{smell,sound,light,touch,taste}`、`hooks[]`、`tags[]`（氛围/功能/时段）、`reveal_state`（水下/备选/已揭示）、`scene_refs[]`、`residents[]`、`linked_factions[]`。
- 地点引用协议：场景、章节、人物履历、事件全部通过 `location_ref` 指向同一地点实体，避免同一酒馆出现三个版本。

**功能建议**
- 写作侧悬浮速查卡：光标停在地名上即显示五感卡+钩子+上一次出场的章节。
- 场景规划板：按章节列出将出场地点，空缺处推荐按标签匹配的备选地点。
- 设定侧"冰山面板"：按出场状态分组浏览全部地点，支持把水下地点一键提升为正文素材。

**校验规则建议**
- 孤儿地点：声称位于某城内但无父级/无 pin → 提示补层级。
- 场景引用了不存在的地点 → 建档提示。
- 场景描写与地点属性冲突（沙漠城场景出现"湿滑石板路"、冬季场景无季节说明）→ 与 B02 联动提示。

**AI 提示词建议**
- 生成场景描写时注入：该地点 senses、hooks、当前季节与天气，要求至少调用两条感官细节。
- 生成新地点时先让 AI 产出"故事钩子"再产出外观——防止地点沦为无效布景。
