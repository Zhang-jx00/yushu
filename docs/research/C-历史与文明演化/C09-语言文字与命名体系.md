# C09-语言文字与命名体系

> 类别：C-历史与文明演化 ｜ 世界构建金字塔层级：L4 文明层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

语言文字与命名体系研究虚构世界的语言规划（conlang）与命名方法论：从音位库到构词的"命名语言"技术、各文化命名规则的差异、文字系统、语言随历史的分化与接触，以及支撑这一切的命名生成器设计。边界：不做完整语法（那是 conlang 深水区），做"够命名全书"的规则化生成。命名是御书消费频次最高的设定——每个角色、地点、宗门、招式都需要名字，且必须与文化身份一致；C07 的民族条目、C10 的礼俗（避讳、表字）都直接引用本领域。

## 2. 核心知识框架

1. **构语五步**：Zompist《语言构造套件》的经典路径——音位库（辅音/元音清单）→ 音位配列（音节模板、合法音簇、禁止组合）→ 构词法（词根+词缀）→ 语法 → 语族分化。并警示反模式："先写一堆酷炫文本再倒推语法"、随机音节拼接产生杂烩感。
2. **命名语言（naming language）**：rassaku 与 Larkwood 的共识——小说不需要完整语言，只要"音系+构词规则一致"，生成的名字就自然同族；一个下午可建成。这是文学场景的性价比最优解（现实中《冰与火之歌》的瓦雷利亚语最初也是命名语言）。
3. **音色锚定**：LoreTeller 主张先定"声音调色板"（如塞音多→蛮荒感、流音多→柔美）并锚定现实语族参照；Mythcreants 提醒两大坑：所有文化共用一套欧美音、直接音译现成词导致穿帮。
4. **命名的社会语义**：姓氏来源（父名/母名/地名/职业/赐姓）、排行、避讳、成年命名、出家法号、封号谥号——名字是身份的档案，命名规则的差异就是文化差异的可感知载体。
5. **文字系统与权力**：表意/表音/字母/元音附标各有学习成本与美学；识字率决定谁掌握经典与法律（联动 C11），征服者改写文字即文化清洗（联动 C04）。
6. **语言演化与接触**：语族树（祖语→方言→互不相通）、借词（贸易品名最易借入）、征服语言替换、通用语（lingua franca）；Azgaar 用 culture sets 给每个文化直接配命名集，示范"文化-语言-命名"三合一建模。
7. **东方范式**：单字名+姓氏+表字/号、避国讳、谥法、年号——中文命名自带一整套"名讳礼制"规则库，可直接作为一套命名语言的文化绑定模板；宗门/道号/官职称谓是网文命名的高频痛点。

## 3. 命名生成器的规则化设计

**NamingLanguage schema（每文化一份，随 Ethnicity 自动实例化）**

```yaml
NamingLanguage:
  id: nl-xia
  绑定文化: ethnicity-xia       # C07 引用
  语族引用: lang-tree-node-7
  时代变体: { 古体: 开启, 今体: 默认 }
  音位库:
    辅音: [b, p, m, f, d, t, n, l, g, k, h, j, q, x, zh, ch, sh, r, z, c, s, w, y]
    元音: [a, o, e, i, u, ü]
    声调: 平仄      # enum: 无 | 平仄 | 四声 | 高低重音
  音位配列:
    音节模板: ["CV(n)", "CV(n)g"]        # n 为鼻音韵尾
    合法音簇: []
    禁止组合: [l-元音i, j-元音u]
    词首偏好: [塞音, 零声母]
    音节数: { 人名: [2,3], 地名: [1,3] }
  构词规则:
    人名: { 姓氏规则: 父系单姓, 名: 1-2 字, 前/后缀概率表: {} }
    地名: { 式: 专名+通名, 通名池: [山, 川, 泽, 堡, 坊, 关, 洲] }
    宗门命名式: [意象字+宗/阁/门/派, 地望+宗/观]
    年号/谥号规则: 内置谥字表
  语义词根表(可选): { "光明": 明, "石": 磐, "剑": 锋 }   # 启用后生成"含义卡"
  黑名单: [现实人名表, 全书已用名, 出戏词表]
  随机种子: 20260928          # 存档可复现
```

**生成流程**：选实体类型 → 载入其文化绑定的 NamingLanguage → 按构词模板采样音节 → 黑名单与重名过滤 → 可选生成"含义卡"（词根拆解）→ 人工采纳并锁定（`name_locked=true`，此后 AI 改写不得触碰锁定名，改动必须走"改名事件"）。

**取名助手功能清单**：批量生成（一次 20 个候选，按贵族/平民/僧侣/外族分列）；一致性 lint（跨章新名字与其文化命名语言不符即警告）；易读度 lint（超过 4 音节或连续 3 个同辅音提示"读者卡壳"）；重名与近音检测（全书已用名+谐音）；名字含义卡（显示词根拆解与拟义）；改名事件（赐名/避讳改名/法号）绑定 C02 时间轴。

## 4. 可转化为产品规则的关键实践

1. 每文化一套命名语言 → 创建 Ethnicity 时自动实例化 NamingLanguage，默认模板可一键换风格。
2. 风格预设库 → 内置"中原雅言/塞北草原/江南水乡/西域商队/冰原部族"等东方预设与"拉丁/北欧/闪含"西式预设，预设=预填的音位库+配列+构词。
3. 音位配列校验 → 所有新角色/地点名入库时跑配列规则，违规即建议改用生成器。
4. 语义词根表可选启用 → 启用后地名可自动释义（"磐石关"），人名生成含义卡。
5. 命名来源标记 → 每实体记录 name_source（生成器/手填/历史引用），手填名必须通过一致性 lint。
6. 语族树与音变 → 祖语分化子语言时应用音变规则（如词首 p→f），同源词自动标注并显示。
7. 通用语对照 → 同一地点允许存多个文化的不同称呼，称呼差异即历史恩怨的细节。
8. 黑名单与复现种子 → 生成结果以种子存档可复现；黑名单防止生成现实人名或与其他文化撞名。

## 6. 对御书设计的启示

**数据结构建议**
- `NamingLanguage`（见第 3 节 schema）；`LanguageNode {母语引用, 分化年代, 音变规则[], 使用民族[]}`；`NameRecord {实体引用, 名, 类型: 人名|地名|组织|器物, 含义卡, name_source, locked, 所属语言}`。

**功能建议**
- 取名助手面板（第 3 节功能清单）：御书高频入口，建议放在全局工具栏而非某实体页内。
- 语族树视图：可视化祖语-子语分化年代，节点可点开看音变规则与同源词。
- 地名释义地图层：开启语义词根表后，地图上的地名悬停显示含义。
- 通用语对照表：同一实体多文化称呼并列，差异处标注历史原因。

**校验规则建议**
- 无文化绑定 lint：新角色名无所属文化/语言 → 警告"无根之名"。
- 跨文化混用 lint：名字的音系归属与其身份文化不符 → 提示（可豁免：外族配偶、赐名剧情）。
- 锁定名保护：`name_locked` 实体在 AI 批量改写中被更名 → 报错并回滚。

**AI 提示词建议**
- "只允许使用文化 X 的 NamingLanguage 生成新名字，输出附词根拆解，并排除黑名单。"
- "为同一条山脉生成两个文化的称呼，并解释称呼差异反映的领土主张。"
- "按谥法规则为本朝前四位皇帝拟谥号，附盖棺定论的一句理由。"
