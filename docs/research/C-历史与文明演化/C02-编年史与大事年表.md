# C02-编年史与大事年表

> 类别：C-历史与文明演化 ｜ 世界构建金字塔层级：L3 历史层
> 质量要求：信息来源 ≥6 条、覆盖 ≥3 种来源类型；URL 必须来自真实检索结果。

## 1. 领域定义

编年史与大事年表研究"世界历史如何组织为可查询、可维护、可引用的事件序列"：事件实体的属性与精度、纪元与历法的骨架、多视角的不可靠记载、事件之间的因果链。它是 L3 历史层的数据底盘——C01 定下纪元框架后，所有战争、王朝、文明事件都要落到年表上，C06 的"历史→现状"映射也以事件为源头。与 C01 的区分：C01 管历史的"形状"，本领域管历史的"账本"；与 C04/C05 的区分：王朝与战争是年表上的特定内容类型，本领域研究承载它们的通用结构。

## 2. 核心知识框架

1. **体裁学基础**：中国史学提供两种原型——编年体（逐年条目，《春秋》《资治通鉴》式，时间轴绝对优先）与纪事本末体（事件为中心，完整叙述来龙去脉）。虚构世界需要两者并存：一条时间轴 + 每个事件可展开的"本末"详情页。
2. **伪史书方法**：GRRM 把《血与火》当"伪史书"写：用世界内史官的口吻、互相矛盾的记载、伪造或佚失的一手文献（伪引文、伪奏章、伪回忆录）来呈现历史。Fake History 实践指南的核心技巧正是"给叙事塞入历史行动者的证据"——伪引文、伪文件、伪证词让编年史获得质感。r/literature 与 Writing.SE 的讨论补充了文体要点：学术腔的克制、史料引用格式、视角偏离真相的"度"。
3. **事件实体的最小属性集**：真实时点（可挂多历法换算）、时点精度（日/月/年/约某某年）、地点、参与者（人物/势力/文明）、事件类型、起因与后果、可信度、来源文献。World Anvil 的事件类型学（event types）把事件分为普通事件与"重大灾变类"事件，并强调重大事件（如城市毁灭）会产生"回响至今的深远后果"——即事件天然携带后果指针。
4. **多视角与不可靠记载**：同一事件应有多个世界内"记载"（官方正史、敌国史书、民间传说、幸存者证言），记载之间允许且鼓励矛盾——这是伪史书方法的工程化。
5. **历法与纪元系统**：LegendKeeper 的 Chronicle/Gantt/Calendar 三视图 + 自定义历法代表了工具侧的最佳实践：时间线既是列表、也是甘特（并排比较各势力纪元）也是日历（历法可视化）。自定义历法（月相、闰法、纪年起点）是历史沉浸感的重要来源。
6. **两本账分离**：世界背景史（建国、神战、灾变）与剧情年表（主角经历）应分开维护但允许引用关联——混在一张表里会导致"世界史被剧情噪声淹没"。
7. **纪元化编年范本**：Serina 种子世界按地质/演化纪元组织数百万年的编年，示范了"长时段世界如何分纪元、每纪元如何有独立主角与终结事件"。

## 3. 可转化为产品规则的关键实践

1. 事件实体 schema → `{id, 真实时点, 时点精度, 地点, 参与者[], 类型, 起因事件[], 后果事件[], canon_level, 记载[]}`，作为全工具通用的事件底座。
2. 多视角记载 → 每条事件挂 `InWorldAccount {记载者, 立场势力, 文本, 偏差类型: 美化|隐瞒|篡改|讹传}`，提供"正史/野史/敌方记载"对照视图。
3. 时点精度分级 → 允许"约三百年前""某王在位第 7 年"等模糊时间，底层存区间 [earliest, latest]，检索与排序按区间处理。
4. 两本账 → 世界史年表与剧情年表分库存放，剧情年表条目可引用世界史事件作为背景。
5. 涟漪扩散标注 → 后果分"直接后果 / 一代涟漪 / 二代涟漪"三级，自动生成事件因果图（联动 C06）。
6. 历法引擎 → 支持自定义历法（年长、月长、闰法、纪元名）与多历法换算器，事件时点在视图中按所选历法渲染。
7. 三视图时间线 → 列表（编年体）、甘特（势力并排纪元）、日历（历法沉浸）三种渲染同一数据。
8. 伪史料生成器 → 为大事事件生成配套的伪一手文献（诏书残句、史官按语、碑铭），作为小说引文素材。

## 5. 对御书设计的启示

**数据结构建议**
- 核心实体 `Event`（schema 见实践 1）+ `Calendar {纪元列表, 年月长度, 闰法}` + `Era`（引用 C01 结构）；`Account`（世界内记载）作为 Event 的子实体而非独立顶层，避免视角碎片化。
- 事件的 `后果事件[]` 用带权边实现（影响强度 + 作用对象），供 C06 的现状映射直接消费。

**功能建议**
- 时间线编辑器默认"编年体列表 + 点击展开本末详情"双栏；大势列表（王国/王朝/文明）叠加为甘特泳道。
- "空白年段"高亮：某纪元内超过设定长度（如 50 年）无任何事件时提示补史。
- 因果图可视化：以选中事件为根节点展开上下游，涟漪层级用颜色区分。

**校验规则建议**
- 时间倒置检测：起因事件的时点不得晚于后果事件（模糊时间用区间求交验证）。
- 孤儿事件检测：无任何起因、后果、参与者引用的孤立事件标记为"死条目"。
- canon 矛盾提示：同一事件的多个 Account 若在关键事实上冲突，展示矛盾而非报错——冲突是特性不是缺陷。

**AI 提示词建议**
- "为事件 E 生成三份世界内记载：胜利方正史、失败方残卷、百年后民间歌谣，各自带一处与作者真相的偏差"。
- "按编年体为纪元 X 生成 10 条大事条目，每条一句话 + 一条伪史料引文"。

## 6. 领域内子主题备忘（可选）

- 史料学引入虚构：一手/二手/三手史料的区分，可作为 Account 的可信度分级依据。
- 口述史与歌谣传统：无文字文明的"年表"形态（歌谣、史诗、纪念碑），与 E 类人文层衔接。
- 时间线合并与分支：多位面/时间线世界（A07）下年表的分支结构。
- 断代工程：参考"夏商周断代工程"的思路，为虚构世界做模糊时代的定年工作流。
