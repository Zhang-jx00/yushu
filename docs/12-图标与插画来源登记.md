# 图标与插画来源登记（docs/12）

> **本文件是图标来源的唯一登记表**（契约 §1.1「一个事实只有一个来源」）。
> 界面里**任何**矢量图形（图标、箭头、标记、插画）都必须在这里点名，
> 没登记的形状不许出现在渲染层——判据 `ui-contract.test.ts` 的「图标来源登记」一组会当场拦下。

## 0. 为什么要有这张表

图标看起来是最不需要交代的东西，但它们是**别人做的**。
一件署了别人名字的资产混进产品里，出了事追不到源头；把自绘的当上游的用，功劳算错了人。
所以这张表只回答三个问题：**谁做的、什么许可、画布多大**。

**不抄、不改**：上游的 path 逐字用（改 path 就等于换图标，那时候要改的是"选哪个"这个决定）；
自绘的**没有上游**，不许冒充"来自某图标库"。

**图标 vs 图表的区别**：图标是**资产**（画法固定、有上游或自绘）；图表是**数据驱动的呈现**
（每次渲染都不同）。两者都要进这张表——不进表就会出现"这里有个 svg 却查不到出处"的糊涂账；
但它们登记的**内容不同**：图标登记 path 的出处与许可，图表登记"画法由数据决定"这一事实。

### 1.4 自绘插画（**没有上游**，登记的是**画法口径**）

| 插画 | 用途 | 画布 / 描边 | 所在文件 |
|---|---|---|---|
| 空稿纸（还没写的稿纸） | 空状态 | 24×24 / 2px / 单色 currentColor / 不填色 | `apps/desktop/renderer/src/components/StateArt.tsx` |
| 划掉的稿纸（写坏了） | 错误态 | 同上 | 同上 |

**插画与图标不是一回事**：图标是**资产**（固定画法，有上游或自绘），登记的是它的出处与许可；
插画是**自绘**的、**没有上游**，登记的是**画法口径**（画布 / 描边 / 颜色），以及它落在哪个文件。
两者都要进这张表——不进表就会出现「这里有个图形却查不到出处」的糊涂账。

## 2. 已知的两套口径（**不是错误，是记录**）

自绘的折叠箭头是 **16×16 / 1.6px**，与 Lucide 的 **24×24 / 2px** 不是同一套。
这是**控件级图形**与**图标级图形**的差别（前者要小、要淡，不该跟标签图标抢注意力），
不是谁画错了。**本轮不统一它**——统一要改画面，而"改画面"要带截图对照（docs/10 §2）。

**将来要统一时的规矩**：改之前先在这张表里写清"从哪套换到哪套、为什么"，改完把两行并成一行。

## 3. 规矩（判据逐条钉住）

1. **渲染层里含矢量图形的文件，只许是本表点名的那些**——新增一处内联图形而没登记 ⇒ 判据红。
2. **上游的 path 不许改**：要换观感就换"选哪个图标"，不偷偷改坐标。
3. **自绘的必须写明"自绘"**：没有上游的东西不许写成"来自某图标库"。
4. **许可声明跟着文件走**：用上游的图标，那个文件头要有上游的许可原文（本项目的做法），`NOTICE` 里也要登记。

## 4. 本轮明确没做的

- **空状态与错误态插画**（第四批的另一半）：插画要么自绘、要么登记来源的免费素材，
  两者都要一段时间的取舍与逐页比对，**不在本轮**，顺延下一轮。
- **两套描边口径的统一**：见 §2。
- **界面级状态/操作图标集**（勾选、警告、运行中等）：同样是"选哪些 + 什么来源"的决定，
  没有登记就没有它。
