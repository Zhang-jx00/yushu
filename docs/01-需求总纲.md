# 御书 · 需求总纲

> **宗旨：从起源构建世界。**
> 每一部小说都不单单是一篇文字，而是要创作出另一个世界——文化完整，有历史，有生态，有人文，有地理的完整世界。世界是第一公民，故事只是这个世界的一个切面。

## 1. 产品定位

**「御书」= 从起源构建世界的全流派开源小说创作操作系统。**

- 开源：代码开源、文件格式开放、社区共建（派系包与插件生态）
- 本地优先：数据主权归用户，Markdown 开放格式，不强制云端账号
- 全流派：内置市面主流流派库，派系可组合、可修改、可自建、可分享
- 世界优先：每部小说项目 = 一个完整世界 + 世界中展开的故事

**差异化定位**（预研结论）：市面上没有任何工具同时做到「世界分层构建 + 设定影响传播 + 一致性校验 + 全流派派系包 + AI 合规证据链 + 本地数据主权」。

**目标用户**：中文网文作者优先（全国约 3269 万网文作者，主力为兼职与新人作者），兼顾传统长篇写作者与世界观爱好者（跑团/设定控）。

### 1.1 用户画像与核心场景

| 画像 | 典型场景 | 最需要的御书能力 |
|---|---|---|
| 新人网文作者 | 第一次开书，不知道怎么搭世界观和大纲 | 流派选择向导、起源工作台问卷、三级大纲模板、黄金三章自查 |
| 连载中的作者 | 日更 4000~6000 字，最怕断更和设定崩 | 记忆系统（写到第 800 章人物不穿帮）、码字统计、断更预警、防丢稿 |
| 老作者换工具 | 三百万字存量书稿要迁移 | 存量书稿导入（TXT/DOCX→自动分章→AI 抽实体建库） |
| 多本连载作者 | 同时写两本书，设定互串 | 分项目记忆隔离、派系包按项目配置 |
| 设定控/世界观爱好者 | 喜欢构建世界多过写正文 | 起源工作台全流程、世界圣经、关系图谱、编年史 |
| 恐怖/悬疑作者 | 线索与规则必须公平自洽 | 线索公平性校验、规则怪谈自洽检查（派系包规则） |

## 2. 世界优先设计原则（由宗旨推导）

1. **项目即世界**：项目 = 一个完整世界（World）+ 世界中展开的故事（Story），而非文档集合。
2. **自上而下推演**：起源→法则→地理→生态→历史→文明→社会现状→人物→故事；下游由上游推导，上游变更向下游传播。
3. **题材模板 = 世界预设**：都市文继承现实起源（低魔世界，重点在人文/商业/情感），玄幻自创起源（高魔世界，重点在历史/地理/等级战力）——同一套世界模型统一表达所有题材，不存在"某题材不需要世界观"的问题，只是世界预设不同。
4. **一致性是生命线**：战力不崩塌、历史不穿帮、称呼不漂移——靠结构化设定 + 一致性引擎 + AI 生成时强制注入世界约束共同保障。

## 3. 四维派系模型与流派引擎

### 3.1 模型

流派不是单选标签，而是四个正交维度的组合（一部作品通常是多维叠加，如"男频 + 玄幻 + 系统流 + 爽文"）：

| 维度 | 取值（可扩展） |
|---|---|
| 频道维 | 男频 / 女频 / 纯爱 / 百合 / 无CP / 全性别 |
| 世界维 | 玄幻 / 仙侠 / 武侠 / 西幻 / 科幻 / 超凡都市 / 现实都市 / 历史 / 末世 / 异世界 / 民俗志怪 / 游戏 / 娱乐圈 … |
| 手法维 | 系统流 / 穿越流 / 重生流 / 无限流 / 直播流 / 签到流 / 种田基建流 / 快穿 / 规则怪谈 / 幕后黑手流 / 诸天流 / 领主流 / 苟道流 / 马甲文 / 团宠 … |
| 基调维 | 爽文 / 甜宠 / 虐恋 / 治愈 / 黑深残 / 轻松搞笑 / 正剧 |

感情线形态（有女主/无女主/单CP/多CP/无CP）作为独立开关，不绑定频道（源自平台生态预研：番茄"无女主"归男频、"无CP"归女频）。

### 3.2 派系包（Genre Pack）

每个流派 = 一包可插拔内容：

1. **世界预设**：从起源层继承的世界模板与必填设定
2. **设定卡 schema 扩展**：玄幻有境界体系卡、恐怖有诡异档案卡/规则卡、都市有公司商业卡
3. **校验规则集**：战力防崩塌 / 推理线索公平性 / 规则怪谈逻辑自洽 / 时间线一致
4. **写作指南与节拍表**：该流派的写法要点与章节节拍
5. **爽点模式库**：该流派的期待感与情绪曲线模式
6. **AI 提示词模板**：该流派的续写/润色/大纲提示词
7. **术语表**：境界/称呼/器物命名体系
8. **雷点禁忌清单**：读者普遍反感的处理方式
9. **大纲模板**：该流派的卷纲/章纲骨架
10. **演化链与年代字段**：开山作—仿作—反套路（流派有生命周期）
11. **平台分类映射表**：起点/番茄/晋江/飞卢/七猫的对应分类与标签

### 3.3 流派工作流

- **新建项目向导**：选频道 + 世界类型 + 手法流派 + 基调（均可多选）→ 融合派系包（合并 schema、规则去重、冲突提示）→ 生成世界构建流程 / 写法指南 / 大纲骨架 / AI 配置 → **用户可修改一切**
- **用户自定义派系**：从零创建，或复制现有派系包魔改；派系包可导出/导入/分享（社区内容生态，与插件系统同构）
- **核心最小化**：内核只含世界/人物/事件/伏笔/大纲等最小通用概念，一切流派差异由派系包注入，**不搞大一统架构**

示例：「男频+玄幻+系统流」→ 境界体系卡+系统面板卡+战力校验规则+升级爆点节拍表；「女频+都市+甜宠」→ 情感线卡+CP 档案+糖点节奏表+误会和解节拍——两套完全不同的写法体系。

## 4. 功能需求总清单（MoSCoW）

### 4.1 起源工作台（Genesis Workbench）【Must】

- 引导式世界构建流程：创世起源→超凡法则→地理生态→历史纪元→文明文化→社会现状→人物→故事线
- 每步以问卷脚手架驱动（借鉴 Patricia Wrede 七板块问卷、雪花法分形扩写），产出结构化设定卡
- top-down 与 bottom-up 混合模式；渐进披露（少量必填 + 可扩展字段）
- 命名生成器：每文化一套音位/构词规则 + 随机种子，生成成族名字（角色/地名/门派/功法/书名）
- 东方题材预置山海经式 schema 参考；现实题材预置"现实起源"预设

### 4.2 世界引擎（World Engine）【Must】

- 分层数据模型：World→纪元→地域→物种→文明/势力→人物→事件→故事线→章节（借鉴 Azgaar 分层依赖管线）
- 设定变更影响传播：修改上游设定自动标记下游受影响实体清单，用户逐项确认
- 跨层一致性引擎：等级战力校验 / 时间线校验 / 人物-历史冲突校验（如"角色出身于已被历史事件灭亡的国度"报警）/ 称呼漂移检测
- 设定条目元数据：叙事可见性（冰山原则：已写未揭示）、关联剧情标记、来源章节链接
- 编年史：大事年表 + 同一事件多文化视角的"伪史书"模式
- 时间线：内部统一数字刻度，虚构纪年（锚定事件=Year 0）与多历法在渲染层映射

### 4.3 记忆系统【Must】

- 六类核心实体：角色 / 地点 / 势力 / 物品 / 功法技能 / 事件（schema 按派系包扩展）
- 关系图谱：人物关系网、势力关系、地点归属
- 伏笔全生命周期：登记→埋设章节标记→密度提示→回收标记→未回收看板（契诃夫之枪台账）
- 记忆分层：核心设定卡→卷摘要→章摘要→事实级记忆（带出处）→RAG 全文检索；摘要可被用户修正后回库
- AI 上下文组装：核心世界观常驻注入；其余设定按"别名/提及"关键词触发；Token 预算与插入优先级可调；上下文预览器（查看实际发给模型的内容）

### 4.4 大纲系统【Must】

- 三级大纲：总纲→卷纲→章纲（细纲），与正文双向映射、卡片拖拽重排、写作偏差对比
- 结构模板：三幕 / 英雄之旅 / 救猫咪 15 节拍 / 七点结构 / 24章×3幕 / 起承转合
- 雪花法反向大纲向导（从一句话到场景表）
- 细纲编辑器为一等公民：章节卡 + 拖拽排序 + 一键扩写为草稿（细纲是防卡文核心）

### 4.5 AI 副驾【Must，辅助定位，默认可关】

- 多模型接入：OpenAI 兼容主干 + Provider 能力矩阵（tools/structured_output/stream/usage/reasoning，自动降级）+ Anthropic/Gemini 原生适配 + Ollama/llama.cpp/LM Studio 本地模型
- 任务路由：大纲/命名/润色用小模型、正文用旗舰；失败重试与 fallback 链
- 功能：续写/扩写/润色/改写（按节生成、字数分档——单次生成上限约 2000 词的学术结论）、取名助手、灵感头脑风暴、大纲候选生成（批量走半价通道）、设定卡自动抽取（结构化输出）、设定变更提案、一致性审查报告
- AI 多候选：同一任务生成多候选、diff 对比、整段或局部采纳
- 成本与体验：流式输出（chunk 缓冲 + rAF 打字机、AbortController 停止）、Token 计数（本地估算 + usage 实报）、成本面板、prompt caching 稳定前缀编排（世界设定总纲+风格卡置头）
- **人类创作证据链（合规核心）**：版本历史 + 编辑轨迹留存 + AI 使用记录 + 一键生成平台申报材料；AI 输出显式标识、默认关闭、可审计
- 中文处理：中文校对（错别字/标点/重复/称呼漂移）、OpenCC 繁简转换、按 GB/T 15834 与 W3C clreq 的一键排版

### 4.6 作者刚需套件【Must】

- 码字统计与更文管理：日/周/月字数、速度曲线、写作日历、目标设定、断更预警、按平台口径的"当日有效字数"
- 防丢稿四层防线：自动保存（WAL+debounce）、本地快照、崩溃恢复、防手滑
- 存量书稿导入：TXT/DOCX → 自动分章 → AI 抽取实体建库
- 敏感词分平台自查流水线：投稿前检测 + 替换建议 + 词库外置可更新
- 专注模式：番茄钟 / 沉浸写作 / 可选小黑屋式强制码字
- 云备份（可选）：WebDAV / S3 / Syncthing，密钥本地持有，不强制账号

### 4.7 编辑器【Must】

- TipTap（ProseMirror 内核）富文本 + CodeMirror 6 源码模式双形态；结构化文档为唯一真源、Markdown 为序列化产物
- 实体内联标记（@引用角色/地点，悬停显示设定卡，点击跳转）
- 写作视图：无干扰模式 / 打字机滚动 / 双栏对照（左设定右正文）

### 4.8 出版与发布【Should】

- 世界圣经自动汇编：设定集一键导出
- 导出管线：TXT / EPUB 3.3（EPUBCheck 质检）/ DOCX / PDF / 平台章节格式
- 发布状态机：章节字数统计、定时发布、发布状态流转

### 4.9 可视化【Should】

- 关系图谱（可编辑，React Flow/G6）与世界观全量知识图谱（只读探索，Sigma.js）
- 世界时间轴（编年史 + 剧情轴统一，虚构历法显示）
- 世界地图（图片底图 + 地点标注 + 事件锚点，借鉴 Azgaar 分层思路）

### 4.10 插件与社区【Could】

- 插件 API：命令 / 视图 / 实体类型 / 规则 / AI 任务五类扩展点
- 派系包工坊：可视化创建/编辑/导出/导入派系包
- 社区运营：贡献指南、Roadmap、行为准则、派系包分享规范

## 5. 非目标（Non-Goals）

- 不做云端账号强制体系（可选云备份 ≠ 云端身份）
- v1 不做多人实时协作（远期评估 CRDT）
- 不内置模型训练；不做通用聊天助手（AI 限定创作辅助场景）
- 不替代平台发布流程（只做格式适配与自查）
- v1 不做移动端（存储格式为跨端预留）

## 6. 数据主权承诺

1. 正文与设定卡为纯文本文件（Markdown + YAML），用户可直接阅读、可被 Git 版本化、可随时迁移
2. SQLite 索引可随时从文件重建，删除索引不丢失任何数据
3. API Key 与所有配置本地加密存储，不上传
4. AI 功能默认关闭、逐项开启、输出可标识、使用可审计
5. 卸载即净卸载：用户目录外不留任何数据

## 7. 验收基线（MVP 定义）

一位从未用过的作者，在 30 分钟内完成：选择「男频+玄幻+系统流」→ 用起源工作台建立"一个世界"的核心设定（≥5 张设定卡）→ 生成三级大纲骨架 → 用 AI 续写出符合世界约束的第一章 → 导出 TXT 且通过敏感词自查。全程不联网也能完成除 AI 调用外的所有步骤。
