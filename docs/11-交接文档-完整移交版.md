## 1. 这个项目是什么

**御书（yushu）** = 面向中文网络小说作者的**本地优先**桌面创作工具。五个核心系统：
起源工作台（开书问卷）、世界引擎（设定卡 + 派系包）、记忆系统（五层上下文与注入）、
一致性引擎（体检与豁免）、导出与自查（平台格式与合规）。

**架构底座，一句话不能忘**：真源是仓库里那棵 `Markdown + YAML frontmatter` 的文件树，
SQLite 只当索引，删掉索引库结论必须不变。技术栈：Electron + React 19 + TypeScript strict +
pnpm workspace + vitest；正文编辑器 TipTap；导出走 Pandoc / EPUBCheck（外部工具，现场探测）。

产品目标与验收门槛的权威出处：`docs/01-需求总纲.md`（要做什么、验收 A#）、
`docs/04-开发计划.md`（**唯一勾选账**）、`docs/03-开发规划方案.md`（架构与红线）。

## 6. 文档账本规矩（这里最容易犯规）

1. **`docs/04` 是唯一勾选账**。改代码的**同一轮**必须落勾选或写明"为什么不勾"；
   写成"回头再对账"就会永久对不上（这条是早期实撞）。
2. 每轮要同步的地方（少一处就是对外撒谎）：`docs/04` 注记 → `docs/06` 轮次记录 →
   `docs/08` §1 数字行 + §11 台账 → `docs/09` 基线 → `README.md` → `CHANGELOG.md`。
3. **有锁盯着文档**：`governance-docs.test.ts` 拿 `docs/08` 里"M4 已勾 x/12"这句跟 `docs/04` 实况对账，
   不一致就红；还有一条"账本已动过的里程碑不许写未开始"的反漂移断言。
4. **判据必须回源**：规则注释里写的 `F02` / `D03` 这类编号，那份调研文档里必须真有那条规则。

6. 更正一处错误后，**grep 同一个符号名扫全部引用处**——半条错话最难发现。

## 11. 踩过的坑（新接手最容易重复的，按"代价"排序）

1. **门禁全绿而交付物是坏的**（R104 实撞）：`packages/@yushu/*/src` 与 `apps/desktop/src` 里
   相对导入漏 `.js` 后缀，`pnpm test` 与 `pnpm typecheck` 都看不见（vitest/tsc 按打包器规矩补后缀，
   只有真跑起来的 Node 不补），直到 e2e 起 Electron 才 `ERR_MODULE_NOT_FOUND`。
   现在有一条 `esm-relative-imports.test.ts` 盯着，且它自带"扫不到 150 个文件就红"的防空转护栏。
2. **假绿灯比红更贵**。这一类在本仓库出现过十几种形态，最狠的五种：
   ① 断言吃既有状态（点之前就已经是那个值 ⇒ 空处理器也绿）；
   ② 探针自己把条件喂饱（回滚前那次写操作白送一个脏标记 ⇒ 不修产品也绿）；
   ③ 空对空（两个空视图比"逐字不变"）；
   ④ 变异窗口没包住被测运行 ⇒ 集体误报"锁无效"；
   ⑤ 检查器自己会假绿（needle 少一层、归一化 ≠ 真实写法）。
   **新写一条判据，第一件事是拿它去量"应该红"的场景，看它真红**。
3. **Edit 类工具会吃相邻文本**：本轮及 R103 多次发生——插入时把上一条目的标题或相邻 JSX 一行吞掉，
   或在 Markdown 里留下字面 `\n`。**每次编辑后要看 diff**，CHANGELOG 尤其危险。
4. **预演夹具的时序**：换标签页会卸载视图，异步 `card:read` 会把旧 doc 覆盖回面板 ⇒
   "已保存"写到了上一张卡；React 受控 input 的 `input` 事件与点击不能同一拍发。
5. **截图证据要拍在被断言那一段**：只量不改画面的步骤会被滞后帧标"证据存疑"；
   `screenshotFailures: []` 只说明图取到了，不说明拍对了（要 `scrollIntoView`）。
6. **pnpm 严格 node_modules**：桌面端不能直接 `import "yaml"`，格式解析放引擎侧。
7. **连续两轮同样红才追根因**是默认口径，但"状态变更型步骤"重试救不回来（step17 遗留未定）。
8. **临时文件卫生**：预演/性能产物写 `D:\Temp\`，用完即清并回报残留；不要把垃圾留在 C 盘。
