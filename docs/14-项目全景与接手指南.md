## 1. 目标与产品定位

### 1.1 产品目标

让一个写网文的人**只维护一个项目目录**，就能从"这个世界是什么样"一路走到"这一卷写完了、可以导出投稿"，
中间每一份数据都是**可读、可改、可版本管理**的普通文件。

| 里程碑 | 交付的东西 | 主要落点 |
|---|---|---|
| M1 | 起源工作台（建世界）、设定卡、大纲、编辑器 | `GenesisView` / `OutlineView` / `ChapterEditorView` |
| M2 | 稿件总览、索引与检索、Git 版本管理、码字统计、恢复 | `LibraryView` / `packages/@yushu/search` / `git-ops` |
| M3 | 项目迁移包、发布通道、会话与快照恢复 | `project-ops` / `publish-ops` |
| M4 | 规则引擎与一致性引擎（规则包、钩子、批注、一致性体检、影响传播） | `packages/@yushu/genre-engine` / `consistency-ops` |
| M5 | 世界地图、设定集、导入存量稿件、发布状态机、派系包与平台包 | `packages/@yushu/world-engine` / `packs/` |

### 1.2 设计取向（贯穿全仓，违反即返工）

- **本地优先**：不依赖云；断网时除 AI 外全部可用（AI 可关，写作不受影响）。
- **真源是文件**：Markdown/YAML；SQLite（`.yushu/index.db`）只是**可重建的索引**。
- **AI 是助手不是作者**：AI 的输出一律是**候选**，作者显式采纳才写库。
- **确定性**：同输入必得同输出（排序走码点序，不用 `localeCompare`）。
- **界面学 AI 工具的主页**：入口是主角、进度常驻可见、三栏（清单 / 工作区 / 产物）。

### 4.1 世界与起源（M1）

- 「接下来做什么」第三段：告诉作者**下一步**（先建哪一层 / 接着写哪章 / 这本书多大了）⇒ R147。

### 4.2 大纲与正文（M1–M2）

- 三级大纲：卷 → 章 → 章纲（**七要素**，R104 起）⇒ `OutlineView.tsx`。

### 4.3 稿件总览与版本（M2）

## 6. 硬性要求（不可违背）

### 6.1 六条红线

1. **Markdown/YAML 是唯一真源**；SQLite 与 `.yushu/` 都是派生物，删掉可重建。
2. **AI 输出一律候选化** —— 未经作者确认不写正文、不改设定；采纳必须显式。
3. **密钥永不以明文落盘**：真源只记 `api_key_env` / `key_ref`，密文进 `.yushu/secrets.json`（不入 Git/索引/快照）。
4. **派生层不能变成第二真源**：一致性结论、影响传播提案都落派生区，不写 `reports/`。
5. **确定性优先**：排序走码点序（不用 `localeCompare`），同输入必得同输出。
6. **交付物不带密钥**：迁移包写出前剥离、落盘后再复扫一遍。

### 6.2 四道门禁（缺一项不算完成）

在**仓库根**执行，**用 `pnpm.cmd`**（不是 `pnpm` —— 后者在 PowerShell 里不设 `$LASTEXITCODE`）：

```powershell
pnpm.cmd test
pnpm.cmd typecheck
pnpm.cmd --filter @yushu/desktop e2e
pnpm.cmd --filter @yushu/desktop exec electron . "--ui-walkthrough=D:\Temp\yushu-walkthrough-vNNN"
```

细则：

- **退出码绝不能从管道尾部取**（`| Out-File` 会吞掉退出码）⇒ 写成 `cmd /c "pnpm.cmd test > log 2>&1"`，或在 PowerShell 里立刻读 `$LASTEXITCODE`。
- **预演目录编号只增不复用且单调递增**（已用到 v410；并行线各占号段，见 §0.3 / §5.5）。
- **`exec electron .` 跑的是 `dist`** ⇒ 改完主进程代码**必须先 build 再跑预演**（跑旧构建会得到"改了没生效"的假象，实撞过）。
- **GUI 自动化绝不允许打扰桌面** ⇒ 一律走**离屏渲染**（`webPreferences.offscreen:true` + `show:false`）。
- **不要与别的预演并行跑**（会互相干扰，见 §8.4）。

### 6.3 一轮的标准动作

1. **先写判据**（测试），再写实现。
2. **配一组变异**证明判据抓得到人（恒绿判据等于没锁）。
3. 跑完四道门禁，**全绿**才收口。
4. **台账七处同步**：`docs/04` / `docs/06` / `docs/08` / `docs/09` / `README` / `CHANGELOG` / `御书-交接文档.md`；另在 `docs/11` 加自己那一节。
5. **每轮独立提交并推送**（feat + docs 两个提交），提交信息写**为什么**。
6. 推送后**独立回读** `git ls-remote origin main` 确认远端 sha 与本地 HEAD 一致。

### 6.4 代码级硬规矩

- **相对导入必须带 `.js` 后缀**（NodeNext）⇒ 仓库有判据当场抓住（`esm-relative-imports`）。
- **CSS 长度字面量棘轮 ≤620**：`:root` 之外**不许新增** px/em/rem/ch ⇒ 用既有令牌
  （`--space-*` / `--radius-*` / `--border-width` / `--text-*` / `--ink` / `--muted` / `--panel` / `--accent`）或**百分比**。
  右栏宽度用**百分比**（22%）。
- **注释里不许出现 `*/` 连写**；**`String.raw` 模板里不许有反引号或 `${}`**（连注释里也不行，否则模板被提前闭合）。
- **同一个数在一页里只能有一个出处**；**新造的名字不许与页面上已有的名字撞**
  （R154：右栏的「豁免占比」不能叫「豁免率」—— 中栏已有每条规则的豁免率）。
- **同一个算法不许写两遍**：共用就提到**共享模块**或 `buildScript` 的**共享前置段**
  （R166：对比度算法从 step99 提到前置段，step99 与将来的巡检共用一份）。
- **判据要认位置 / 精确形态 / 调用 / 回执**，不能只认"文件里出现过 X"（§8.2）。
- **键盘可达性**：可点的必须键盘可达；新增可点元素要有 `role`/`tabIndex`/`onKeyDown`（`ui-contract` 有扫描器钉着）。
- **确定性**：不写 `localeCompare`。
- **不许留半成品**："采到了却不报"等于假装查过 ⇒ 要么接进判定，要么撤掉并写清口径（R166 的教训）。

### 6.5 GitHub 规矩（并行时尤其重要）

- **绝不 force push**（`--force` / `--force-with-lease`）到共享分支。
- **绝不 amend 已推送的提交**。
- 后推的人遇 **non-fast-forward** ⇒ `git pull --no-rebase --no-edit origin main`（**合并**，不 rebase ——
  rebase 会改写已推送提交的 sha，别人可能已经基于它们工作）。
- **只 add 明确列出的文件**（别用 `git add -A`）⇒ 否则会把别人的半成品一起提交。
- **不删远端分支/tag、不改 GitHub 仓库设置、不动其它 remote**（只操作 `Zhang-jx00/yushu` 这一个仓库）。

### 8.1 最贵：门禁全绿，而交付物是坏的

### 8.2 恒绿判据的几种形态（本仓吃过二十多种）

1. **认"文件里出现过 X"** ⇒ 同名子串蒙混过关（只认 `X` 不认 `X-x`）。
2. **认"定义过函数"** ⇒ 搬走了照样绿（要认**调用**）。
3. **认位置不认形态** ⇒ 前缀也能匹配。
4. **判据改了自己也绿** ⇒ 判据必须配变异。
5. **只钉源码不钉回执** ⇒ "量法删了照样绿" ⇒ 要读**报告里那一步的 detail**（R159 的做法）。
6. **同一事实两处手抄** ⇒ 必然漂移。
7. **只认"出现了"不认"用上了"** ⇒ 查表了没渲染也绿。
8. **只认数量不认对账** ⇒ 数目对、内容错照样绿。
9. **只认"文字匹配"不认"是哪一个控件"** ⇒ 产品新增一个**同名**控件后，判据点到了**另一个对象**
   （R174 的存稿池表格也写着「标记为已发布」⇒ step67 去标了**另一章**）⇒
   **判据要认容器 / 类名 / 位置**（迁移区那一组是 `button.chip`）。

### 8.3 工具与命令类

| 坑 | 处置 |
|---|---|
| `pnpm` 在 PowerShell 里不设 `$LASTEXITCODE` | 一律用 `pnpm.cmd`；`\| Out-File` 会吞退出码 |
| `exec electron .` 跑 `dist` | 改完主进程**先 build** |
| 中文路径在 PS 5.1 的 `-File` 脚本里按 ANSI 读成乱码 | 脚本里不写中文路径字面量（用 `$PSScriptRoot` 推）或存成 **UTF-8 带 BOM** |
| pnpm 要求 `node_modules` 是**真实目录** | worktree 里用 junction 会报 "workspace hoist directory is not a real directory" ⇒ `pnpm install --frozen-lockfile --offline`（本地 store，2 秒） |
| worktree 第一次跑测试可能超时 1~2 个 | 冷启动（新装依赖 + 磁盘冷）⇒ **重跑即可**，别当产品缺陷查 |
| `node -e` 多行被 PowerShell 吃掉 | 写 `.mjs` / `.py` 文件跑 |
| Python 脚本 print 中文会 GBK 报错 | 用 `ascii()` |
| PowerShell 文本管道原地改写含中文的源文件 | `Get-Content -Raw \| Set-Content` 会按系统代码页解码再编码 ⇒ 中文乱码、源码报废 ⇒ 用 `edit` 工具或 node 的 `fs.readFileSync/writeFileSync(...,'utf8')` |
| `git stash` 是**全局**的 | 并行时 stash 会互踩（实撞：一条线的在制品被另一条线 stash 走） |
| GitHub 间歇 443 不通 | 推送要重试；推完独立回读 |
| `git add -A` | 会把别人的半成品一起提交（实撞两次） |
| 相对导入漏 `.js` 后缀 | 判据当场抓住（`esm-relative-imports` / TS2835） |

### 8.4 预演（UI 自动化）

- 一律**离屏渲染**；`capturePage` 要先 `moveTop` + 等两帧，否则返回上一帧（"证据存疑"）。
- 步骤要**幂等**（重试时回到初始态）；否则第二次必红。
- **并行跑预演会互相干扰**（实撞：并行时"点『打开』跳转编辑器"假红，单独重跑就绿）。
- 步号有**空洞**（历史 step77；另有 127 → 140 的跨段）⇒ **总步数 ≠ 最大步号**（快照时点：127 步 / 最大号 140），别当成 bug。
- **往 `STEPS` 数组末尾追加一步 = 动一次"数组收尾"** ⇒ 收尾行是**单点**，撞坏了整棵树都编不过（§8.6）。
- 抖动要如实记（`flakySteps`），不许"重跑一次取好看的"。

### 8.5 判据与实现层

- **effect 里拿 DOM 元素时，依赖数组必须包含"元素在不在"的那份数据** ⇒ 否则监听永远挂不上。
- **滚轮**：React 的 `onWheel` 是被动监听 ⇒ 必须 `ref` + `addEventListener('wheel', h, {passive:false})`。
- **状态样式必须显式压过 `:hover`**（`.x-active` 会被 `.x:hover` 盖掉）。
- **常驻组件不许用条件分支卸载** ⇒ 用 `hidden` 藏而不拆（state / 订阅会丢）。
- **flex 子项默认会缩** ⇒ 三栏中栏的面板要 `flex: 0 0 auto`（R154 实撞）。
- **窄栏里塞不下的宽表要自己横向滚**（`overflow-x: auto`）⇒ 否则整页被撑宽（R159 的巡检项）。

### 8.6 并行线不跑门禁 ⇒ **全线替它付账**（2026-11-03 实撞，本仓最贵的一次）

**现象**：`main` 上桌面端**根本编译不过**（`tsc` 报 `TS1137`），
而台账里 R174 / R175 / R176 / R177 几轮写的都是"四道门禁全绿"——
**因为跑门禁的是那条线自己的树，而它提交进 `main` 的那个文件从没被门禁碰过**。

**根因（精确到行，可复现）**：预演脚本 `apps/desktop/src/main/walkthrough.ts` 的 `STEPS` 数组**收尾行是单点**：

| 提交 | 它做了什么 | 收尾行长什么样 | 合法？ |
|---|---|---|---|
| R163 `4f5f185` | 追加 step124 时把收尾写成"关掉这一步 + 关掉数组"**挤在一行** | `  },];` | ✅ 合法 |
| R174 `b53d35e` | 再追加 step127，在**那行之前**插了新步并补了 `  },`，**却没删前一轮的 `  },];`** | `  },` + `  },];` | ❌ **多一个 `}`** |

⇒ 数组尾部多出一个 `}` ⇒ `TS1137` ⇒ **桌面端 build 从 R174 起一直是红的**，
R175–R177 三轮的"绿灯"都建在一棵**编不过的树**上。

**取证手法（可复用，别靠肉眼读 JS-in-template）**：语法错用 **TS 自己的解析器**定位，它会直接给"第几行第几列 + 错误码"：

```powershell
node -e "const ts=require('typescript'),fs=require('fs');const p='apps/desktop/src/main/walkthrough.ts';const sf=ts.createSourceFile(p,fs.readFileSync(p,'utf8'),ts.ScriptTarget.ES2022,true);sf.parseDiagnostics.forEach(d=>{const l=sf.getLineAndCharacterOfPosition(d.start);console.log(l.line+1+':'+l.character+1,ts.flattenDiagnosticMessageText(d.messageText,' '))})"
```
⇒ 输出 `9327:3 TS1137 Expression or comma expected.`；
而 `tsc` 的输出会把这类错混在一堆别的错里（还可能**顺带掩盖后面真正的错**）。

**三条防线**：

1. **追加一步 = 动一次数组收尾** ⇒ 动手前先读一遍**上一轮留下的最后三行**
   （`git show HEAD:<file> | Select-Object -Last 3`），确认自己是**插在 `];` 前面**，
   而不是**插在别人那行收尾后面**。
2. **提交前必须在自己这条线的树上跑完四道门禁**，而且要**留退出码**（"我跑过"不算数）。
3. **合进 `main` 的人要再跑一遍** —— 别人的绿灯不能替你担保。
   预演脚本这种**单点大文件**，尤其只要 `tsc --noEmit` **解析一遍**就够，**不必跑整套预演**。

**连带教训**：**"四道门禁全绿"这句话本身也要核**——
核法不是"看台账写得漂不漂亮"，而是**在你要交付的那棵树上实跑一遍**。
台账是**人写的**，树是**机器编的**；两者打架时，**信树**。

### 8.7 产品加了一个**同名控件** ⇒ 判据点到了**另一个对象**（2026-11-03 实撞）

**现象**：预演 step67（发布状态机）**从 R174 起必红**，报「面板里没有「退回草稿」按钮」——
而引擎侧的回退能力一直都在（`world-engine/src/publish.ts` 的 `TRANSITIONS` 含 published → draft，`rollback: true`）。

**根因**：R174 给发布面板加了**存稿池表格**，表格里也有一个「标记为已发布」按钮；
而 step67 的取件方式是"**页面上第一个文字匹配的 button**"：

```js
const list = [...panel.querySelectorAll('button')].filter((b) => String(b.textContent).indexOf(label) >= 0);
return list[0];          // ← 存稿池那一行排在前面 ⇒ 点的是**另一章**
```

⇒ 它把**存稿池里的一章**标成了已发布，**选中的那一章仍是草稿** ⇒ 迁移区自然不给「退回草稿」入口 ⇒ 这一步必红。
**比"红"更严重的是它写错了对象**：判据在预演里对**不该动的章**做了真实写入。

**修法（已做）**：两个句柄各认各的 ——
迁移区只认 `button.chip`（面板里唯一一组 chip，是"当前选中章"的迁移入口），
定时区只认**全文相等**的普通按钮（`设定定时` / `清除定时` 不是 chip）。
**断言一条没减**：发布后盘上状态、回退后盘上状态、两次台账留痕、非法迁移禁用、定时进出，一个都没放过。

**教训**：

1. 判据的取件方式必须**认容器 / 类名 / 精确文案**，不能只认"页面上有个文字匹配的按钮"（§8.2 第 9 条）。
2. **产品新增控件时，要回头看一眼有没有判据在按文字找它** ——
   这是"产品改动 ⇒ 判据失配"的**通用形态**（换文案、加同名按钮、挪位置都会中招）。
3. **判据点错对象，比判据直接红更危险**：它会**静默地写错东西**，而且**照样有回执**。
   ⇒ 判据"点了某个按钮"之后，必须再核对**被点的那个东西是不是你以为的那个**（选中章的 id / 路径 / 盘上状态）。

## 9. 并行开发约定（五条线同时跑时的纪律）

### 9.1 为什么会互相踩

单工作树 + 单分支 ⇒ `styles.css`、`apps/desktop/test/ui-contract.test.ts`、
`apps/desktop/src/main/walkthrough.ts`、`apps/desktop/src/shared/ipc.ts`、`apps/desktop/src/main/ipc.ts`、
`apps/desktop/src/preload/preload.cjs`、台账七处 —— 这些是**单点**。

### 9.2 实操步骤（真要并行时照这个做）

```powershell
# ① 每条线一个 worktree（分支各走各的）
git worktree add D:\Temp\yushu-line-<name> -b line/<name>-r<from>-r<to>
# ② worktree 里 node_modules 必须是真实目录（junction 不行）
cd D:\Temp\yushu-line-<name>
pnpm install --frozen-lockfile --offline --ignore-scripts
# ③ 预演号段各线各占一段，段内只增不复用
# ④ 做完先推自己的分支（互不干扰）
git push origin line/<name>-r<from>-r<to>
# ⑤ 最后由一条线把分支合进 main 并推（冲突集中在共用文件，按"两条线各加一段"解）
git merge --no-ff line/<name>-r<from>-r<to>
git push origin main
```

### 9.3 已踩过的两次

1. 互相 `git stash` 走对方的在制品（`git stash` 是**全局**的）⇒ 改用**只 add 明确文件** + worktree 隔离。
2. `git add -A` 把对方正在写的文件一起提交 ⇒ 同上。

### 9.4 台账的并发

台账七处是单点 ⇒ 最好**由一条线统一写**；若多线各写，合并时以最后一次为准，并**逐字复核**数字
（`governance-docs.test.ts` 的漂移锁会当场拦）。

### 10.3 接手时最容易犯的三个错

1. **信文档里的数字，不跑门禁** ⇒ 文档可能停在上一轮（快照时点就是如此）。
2. **在别人正在改的文件上动手**（尤其 `walkthrough.ts` / `ui-contract.test.ts` / `shared/ipc.ts` / 台账七处）

## 13. 术语表

| 词 | 意思 |
|---|---|
| **真源** | Markdown/YAML 文件本身（作者手改的那份）。SQLite、`.yushu/`、派生报告都是**派生物** |

| **预演** | Electron 离屏跑脚本 + 截图取证的 UI 自动化（`--ui-walkthrough=<目录>`） |

| **变异** | 故意改坏产品代码，证明判据会红 |

## 14. 维护这份文档

- **每完成一组十轮**（或大改版后）更新：§0.2 的数字、§0.3 的线与号段、§4 的已开发内容、§5 的进度、**§5.5 的未完成清单**。

- 写**实测来的事实**（跑出来的数字、真的撞过的坑），不写印象。
  凡是"大概/应该/据说"的内容 ⇒ 要么去跑一遍，要么在文中明写"未核实"。
