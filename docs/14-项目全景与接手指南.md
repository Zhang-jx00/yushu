## 1. 目标与产品定位

### 1.1 产品目标

让一个写网文的人**只维护一个项目目录**，就能从"这个世界是什么样"一路走到"这一卷写完了、可以导出投稿"，
中间每一份数据都是**可读、可改、可版本管理**的普通文件。

具体形态（M1–M5 五个里程碑，见 `docs/03`）：

| 里程碑 | 交付的东西 | 主要落点 |
|---|---|---|
| M1 | 起源工作台（建世界）、设定卡、大纲、编辑器 | `GenesisView` / `OutlineView` / `ChapterEditorView` |
| M2 | 稿件总览、索引与检索、Git 版本管理、码字统计、恢复 | `LibraryView` / `packages/@yushu/search` / `git-ops` |
| M3 | 项目迁移包、发布通道（GitHub/自建）、会话与快照恢复 | `project-ops` / `publish-ops` |
| M4 | 规则引擎与一致性引擎（规则包、钩子、批注、一致性体检、影响传播） | `packages/@yushu/genre-engine` / `consistency-ops` |
| M5 | 世界地图、设定集、导入存量稿件、发布状态机、派系包与平台包 | `packages/@yushu/world-engine` / `packs/` |

### 1.2 设计取向（贯穿全仓，违反即返工）

- **本地优先**：不依赖云；所有能力在断网时可用（AI 可关，写作不受影响）。
- **真源是文件**：Markdown/YAML；SQLite（`.yushu/index.db`）只是**可重建的索引**。
- **AI 是助手不是作者**：AI 的输出一律是**候选**，作者显式采纳才写库。
- **确定性**：同输入必得同输出（排序走码点序，不用 `localeCompare`）。
- **界面学 AI 工具的主页**：入口是主角、进度常驻可见、三栏（清单 / 工作区 / 产物）。

## 4. 已开发内容（按域盘点）

> 这一节回答"东西到底做出来没有"。**每一条都能在代码里查到**，括号里是落点。

### 4.1 世界与起源（M1）

- 起源工作台：分层建卡（世界 → 文明 → 政体 → …），一句话开局，**入口不许替作者做决定**（只填表单不自动保存）。
- 设定卡：类型化卡（人物/地点/物品/势力/规则…），`docs/` 真源，卡有 `layer` 概念。
- 「接下来做什么」第三段：告诉作者**下一步**（先建哪一层 / 接着写哪章 / 这本书多大了）。

### 4.2 大纲与正文（M1–M2）

- 三级大纲：卷 → 章 → 章纲（**七要素**，R104 起）。
- 编辑器：tiptap + markdown-it 互转，**写作版面 44em 行长是契约**（R64 刻意定的，R165 加右栏也不许动）。
- 自动保存 / 三方自动合并 / 实体提及（`@` 提及卡）/ 快照 / 恢复。

### 4.3 稿件总览与版本（M2）

- 全库视图：**固定行高 + 虚拟滚动**（`computeVirtualWindow`）。
- Git 版本管理：isomorphic-git 实现，基线提交、暂存、整体回滚（写前强制快照）。
- 索引与检索：`.yushu/index.db`（SQLite FTS），增量索引。

### 4.4 一致性引擎与规则（M4）★ 本仓最有价值的部分

- **规则 DSL + 派系包**：`packages/@yushu/genre-engine`，规则带 id/级别/作用域/结论/出处/问题。
- **一致性体检**：结构类规则 + 已求值的包规则，结论分 error/warn/info，**带出处**（可跳到正文）。
- **豁免机制**：豁免清单要理由（`entries[].reason` 必填）、可撤销、有**豁免率**视图与阈值配置。
- **AI 采样审计**：AI 生成的结论单独标记、可弃用。
- **影响传播**：改动 ⇒ 提案 ⇒ 逐项决策（accept/reject/pending），**决策只写派生区，不写回真源**。
- **规则跑在项目数据上**（战力台账等）：没数据可比就点名"没跑"，不假装通过。

### 4.5 世界地图（M5，R120–R152）

- 引擎侧（`packages/@yushu/world-engine`）：图片底图 + `bounds` + 图层 + 标注 / 事件锚点 / **区域（外环 + 洞）** / 行程线。
- 界面侧：坐标空间画布、图层独立显隐、点标注查地点卡。
- 缩放（滚轮以指针为锚点）/ 平移（拖拽）/ 图例 + 当前倍率（从画布 viewBox **反推**）。
- **挖洞**（R151）：区域可挖洞；洞的顶点必须严格在外环内；几何规则**读与写共用一份**。

### 4.6 记忆（M5）

- 五层记忆：卷摘要 / 章摘要 / 事实 / 实体提及 / 注入门控。
- 冷启动计划（T5-9）：覆盖率、待补批次、"补上后同一次读取里计数与覆盖率同时变"（不留第二份事实）。
- 摘要**候选化**：AI 候选 → 作者采纳；人工修订过的摘要 **rev 保护**（AI 不得覆盖）。

### 4.7 导出与发布（M3/M5）

- 能力矩阵（TXT/EPUB/DOCX/PDF）按**本机实测**给结论，不按猜测。
- 导出前**显式确认**（防手滑），敏感词命中显式外显。
- 发布状态机：`draft → revised → published`，非法迁移禁用并给理由；定时发布与提醒队列。
- 平台章节格式包（番茄 / 七猫）：**每条规则带出处**，缺来源进不了包。

### 4.8 导入存量稿件（M5/T5-7）

三段式：预览（三份报告）→ 分章（正则 → AI 筛 → 人工校正）→ 入库（建卷建章 + 逐章字数对账）。
中断可续跑（有 job 记录），候选一律不自动入库。

### 4.9 界面骨架化（R146–R165，本轮快照的主线）

- R146–R153：入口是主角、进度常驻、"接下来做什么"、地图图例与倍率、区域挖洞。
- R154–R165：**三栏骨架**铺到规则 / 稿件总览 / 导出 / 档案 / AI 副驾 / 大纲六页 + 编辑器右栏。
- R159：排版巡检从"面板层"扩到"栏层"（并排 / 不重叠 / 不越栏）。

## 6. 硬性要求（不可违背）

### 6.1 六条红线（README「五条不会妥协的红线」+ 仓库既有口径）

1. **Markdown/YAML 是唯一真源**；SQLite 与 `.yushu/` 都是派生物，删掉可重建。
2. **AI 输出一律候选化** —— 未经作者确认不写正文、不改设定；采纳必须显式。
3. **密钥永不以明文落盘**：真源只记 `api_key_env` / `key_ref`，密文进 `.yushu/secrets.json`（不入 Git/索引/快照）。
4. **派生层不能变成第二真源**：一致性结论、影响传播提案都落派生区，不写 `reports/`。
5. **确定性优先**：排序走码点序（不用 `localeCompare`），同输入必得同输出。
6. **交付物不带密钥**：迁移包写出前剥离、落盘后再复扫一遍。

### 6.2 四道门禁（缺一项不算完成）

在**仓库根**执行，**用 `pnpm.cmd`**（不是 `pnpm` —— 后者在 PowerShell 里不设 `$LASTEXITCODE`）：

```powershell
pnpm.cmd test                                                    # vitest run
pnpm.cmd typecheck                                               # pnpm -r run build && pnpm -r run typecheck
pnpm.cmd --filter @yushu/desktop e2e
pnpm.cmd --filter @yushu/desktop exec electron . "--ui-walkthrough=D:\Temp\yushu-walkthrough-vNNN"
```

细则：

- **退出码绝不能从管道尾部取**（`| Out-File` 会吞掉退出码）⇒ 写成
  `cmd /c "pnpm.cmd test > log 2>&1"` 或在 PowerShell 里立刻 `$LASTEXITCODE`。
- **预演目录编号只增不复用且单调递增**（历史：v375 → v410 已用；本轮快照后各线各占号段，见 §0.3）。
- **`exec electron .` 跑的是 `dist`** ⇒ 改完主进程代码**必须先 build 再跑预演**（跑旧构建会得到"改了没生效"的假象，实撞过）。
- **GUI 自动化绝不允许打扰桌面** ⇒ 一律走**离屏渲染**（`webPreferences.offscreen:true` + `show:false`）。

### 6.3 一轮的标准动作（R121 起的固定节奏）

1. **先写判据**（测试），再写实现。
2. **配一组变异**证明判据抓得到人（恒绿判据等于没锁）。
3. 跑完四道门禁，**全绿**才收口。
4. **台账七处同步**：`docs/04` / `docs/06` / `docs/08` / `docs/09` / `README` / `CHANGELOG` / `御书-交接文档.md`；另在 `docs/11` 加自己那一节。
5. **每轮独立提交并推送**（feat + docs 两个提交），提交信息写**为什么**。
6. 推送后**独立回读** `git ls-remote origin main` 确认远端 sha 与本地 HEAD 一致。

### 6.4 代码级硬规矩

- **相对导入必须带 `.js` 后缀**（NodeNext）⇒ 仓库有判据当场抓住（`esm-relative-imports`）。
- **CSS 长度字面量棘轮 ≤620**：`:root` 之外**不许新增** px/em/rem/ch ⇒ 用既有令牌
  （`--space-*` / `--radius-*` / `--border-width` / `--text-*` / `--ink` / `--muted` / `--panel` / `--accent`）或**百分比**。
  右栏宽度用**百分比**（22%）。
- **注释里不许出现 `*/` 连写**；**`String.raw` 模板里不许有反引号或 `${}`**（连注释里也不行，否则模板被提前闭合）。
- **同一个数在一页里只能有一个出处**；**新造的名字不许与页面上已有的名字撞**
  （R154：右栏的「豁免占比」不能叫「豁免率」—— 中栏已有每条规则的豁免率）。
- **同一个算法不许写两遍**：需要共用就提到**共享模块**或 `buildScript` 的**共享前置段**
  （R166：对比度算法从 step99 提到前置段，step99 与巡检共用一份）。
- **判据要认位置 / 精确形态 / 调用 / 回执**，不能只认"文件里出现过 X"（详见 §9.2）。
- **键盘可达性**：可点的必须键盘可达；新增可点元素要有 `role`/`tabIndex`/`onKeyDown`（`ui-contract` 有扫描器钉着）。
- **确定性**：不写 `localeCompare`；时间戳要确定（`Date.now()` 仅用于会话内不落盘的值）。

## 8. 踩过的坑（按代价排序）

### 8.1 最贵：门禁全绿，而交付物是坏的

- 预演步骤**写窄了** ⇒ 看着通过，其实在验一个不存在的东西。
  实撞：R156 的 step59 从提示文案抠导出路径（路径已搬进右栏 ⇒ 判据失效）；
  R164 的章名渲染在 `<input>` 里（不在 `textContent` 里）；R165 的 step41 写坏豁免清单不带 baseHash 盲写。
- 预演步骤**查得太早** ⇒ 页面还没渲染完就查 ⇒ 假红。
  实撞：R160 的 step122（地图面板要等 IPC 读回来）、R163 的"我已核对"勾选框在预览回来前是**禁用**的。
- **容差单位写错**：R162 的地图几步容差写成"1 个用户坐标"，实际是"1 个屏幕像素"的换算结果 ⇒ 画布变小 ⇒ 偏了 2。
- **产品缺陷被误判成判据问题**（或反过来）：R162 的左右两栏被 flex 压扁 ⇒ 内容越出边界 127~201px ⇒ 是**产品缺陷**。

### 8.2 恒绿判据的几种形态（本仓吃过二十多种）

1. **认"文件里出现过 X"** ⇒ 同名子串蒙混过关（只认 `X` 不认 `X-x`）。
2. **认"定义过函数"** ⇒ 搬走了照样绿（要认**调用**）。
3. **认位置不认形态** ⇒ 前缀也能匹配。
4. **判据改了自己也绿** ⇒ 判据必须配变异。
5. **只钉源码不钉回执** ⇒ "量法删了照样绿" ⇒ 要读**报告里那一步的 detail**。
6. **同一事实两处手抄** ⇒ 必然漂移。

### 8.3 工具与命令类

- **`pnpm` 在 PowerShell 里不设 `$LASTEXITCODE`** ⇒ 一律用 `pnpm.cmd`；`| Out-File` 会吞退出码。
- **`exec electron .` 跑 `dist`** ⇒ 改完先 build。
- **中文路径在 PS 5.1 的 `-File` 脚本里被按 ANSI 读成乱码** ⇒ 脚本里不写中文路径字面量（用 `$PSScriptRoot` 推）或存成 **UTF-8 带 BOM**。
- **pnpm 要求 `node_modules` 是真实目录** ⇒ worktree 里用 junction 会报
  "workspace hoist directory is not a real directory" ⇒ 用 `pnpm install --frozen-lockfile --offline`（本地 store，2 秒）。
- **worktree 第一次跑测试可能超时 1~2 个**（冷启动：新装的依赖 + 磁盘冷）⇒ 重跑即可，**别当产品缺陷查**。
- **`node -e` 多行被 PowerShell 吃掉** ⇒ 写 `.mjs`/`.py` 文件跑。
- **Python 脚本 print 中文会 GBK 报错** ⇒ 用 `ascii()`。
- **不要用 PowerShell 的文本管道原地改写含中文的源文件**（`Get-Content -Raw | Set-Content` 会按系统代码页解码再编码 ⇒ 中文乱码、源码报废）⇒
  用 `edit` 工具，或用 node 的 `fs.readFileSync/writeFileSync(..., 'utf8')`。
- **`git stash` 是全局的** ⇒ 并行时 stash 会互踩（实撞：一条线的在制品被另一条线 stash 走）。
- **GitHub 间歇不可达** ⇒ 推送用重试循环，推完独立回读。

### 8.4 预演（UI 自动化）

- 离屏渲染；`capturePage` 要先 `moveTop` + 等两帧，否则返回上一帧（"证据存疑"）。
- 步骤要**幂等**（重试时回到初始态）；否则第二次必红。
- 步号有**空洞**（历史 step77）⇒ 总步数比最大号少 1，别当成 bug。
- 抖动要如实记（`flakySteps`），不许"重跑一次取好看的"。

### 8.5 判据与实现层

- **effect 里拿 DOM 元素时，依赖数组必须包含"元素在不在"的那份数据** ⇒ 否则监听永远挂不上。
- **滚轮**：React 的 `onWheel` 是被动监听 ⇒ 必须 `ref` + `addEventListener('wheel', h, {passive:false})`。
- **状态样式必须显式压过 `:hover`**（`.x-active` 会被 `.x:hover` 盖掉）。
- **常驻组件不许用条件分支卸载** ⇒ 用 `hidden` 藏而不拆（state/订阅会丢）。

## 9. 并行开发约定（五条线同时跑时的纪律）

### 9.1 为什么会互相踩

仓库是**单工作树 + 单分支**：`styles.css`、`apps/desktop/test/ui-contract.test.ts`、
`apps/desktop/src/main/walkthrough.ts`、`apps/desktop/src/shared/ipc.ts`、`apps/desktop/src/main/ipc.ts`、
台账七处 —— 这些是**单点**。两条线同时改 ⇒ 互相覆盖、互相 stash、预演目录撞号。

### 9.2 处置办法（按优先级）

1. **每条线一个 worktree**（已建好，依赖已装）：
   ```powershell
   git worktree add D:\Temp\yushu-line-<name> -b line/<name>-r<from>-r<to>
   # worktree 里 node_modules 必须是**真实目录**：
   pnpm install --frozen-lockfile --offline --ignore-scripts
   ```
2. **预演号段各线各占一段，段内只增不复用**（见 §0.3）；不同线不撞号。
3. **共用文件的冲突留到最后合并时解**（形态是"两条线各加一段"，不要整文件取一边）。
4. **台账七处最好由一条线统一写**；若多线各写，合并时以最后一次为准并逐字复核。

### 9.3 已知事实（快照时点）

- 对话二/三/四**没有**切到 worktree，提交直接落在 `main`（R171 / R174 / R177 都在 `main` 上）。
- 对话五自建了 `D:\Temp\yushu-qa-r180`（分支 `line/quality-r180-182-qa`）。
- `D:\Temp\yushu-line-mixed-backup\`：并行开工时共用工作树留下的半成品备份（各线重做时可取用）。
