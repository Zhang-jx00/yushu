### 调研读出来的三条结论（本轮设计的依据）

1. **设计系统的价值不在"有组件"，在"有单一来源"**。Radix / shadcn / Radix Colors / W3C Design Tokens
   反复讲的是同一件事：一个事实只在一个地方定义。御书早就是这条（`:root` 令牌）⇒ **本轮不是引入设计系统，
   是把已有令牌补齐成"能覆盖一整轮改版"的规模**。
2. **动效的主流口径是"退场比进场快、短距离比长距离快、桌面比移动更快更简"**（Material 3 / Apple HIG /
   Fluent 2 / Carbon 一致）。⇒ 御书现有的三档时长（140 / 240 / 380ms）方向是对的，
   **本轮补的是"语义别名"**（进场 / 退场 / 状态 / 揭示四族），让改版时不再随手挑一个时长。
3. **中文排版与拉丁排版不是同一套参数**（W3C clreq 与中文排版实践都指出：行高要 1.4–1.7、
   中西之间留 1/4 em、禁则与标点悬挂、窄栏不两端对齐）。御书已经吃了这条（docs/10 §3），
   **本轮补的是"读屏上的密度"**（见 §3）。

## 1. 视觉语言：不变的部分与要变的部分

**不动的**（改了就是换产品，不是重构）：

- 纸墨色系：`--bg #f7f4ee` / `--panel #fffdf8` / `--ink #2b2620` / `--accent #8c5a2b`。
- 层级靠**描边 + 极浅阴影**，浮层才用 overlay 级阴影。
- 单色图标、2px 描边、24 画布。

**要变的**（本轮只动"结构"，不动"颜色"）：

- **密度从"一种"变成"三档"**（§3）：紧凑 / 标准 / 宽松，**默认档 = 今天的取值**。
- **版心与行长**要成为一等公民（§3）：中文正文超过约 40 个汉字一行就开始难读，这是排版常识不是审美。

## 2. 排版与密度（本轮的主战场）

### 2.1 三档密度

| 档 | 表格单元格内距 | 表格字号 | 用在 |
|---|---|---|---|
| 紧凑 | 2px / 6px | 12px | 笔记本小屏、一屏要看很多条线索 |
| **标准（默认）** | **4px / 8px** | **12.5px** | **与改版前逐字一致** |
| 宽松 | 7px / 12px | 13px | 大屏、长时间读不累 |

**默认档的取值必须等于改版前的取值**——这是本轮的第一条机器判据。
理由：密度档是**给作者的选择**，不是"我们顺手把画面改了"。改版要有对照的基线，
基线就是"今天的样子"。

### 2.2 三条实施纪律

1. **档位只重定义令牌，不改任何一条规则**：组件里写 `var(--density-*)` ⇒ 切档即刻生效。
2. **档位写 `:root[data-density=...]`**：令牌就是 `:root` 级的，"值只许出现在 `:root` 里"
   （R83 棘轮）这条规矩在密度档上照样成立。
3. **本轮只做会话内**（不落盘）：写进项目真源要新增一条 IPC 与一份配置，
   而"界面偏好算不算项目内容"还没定论 ⇒ **先把三档做对、看得见，再决定要不要持久化**。

### 2.3 排版尺度（第二批落地）

**先订正一条**：本文件初稿写的"中文正文一行不超过约 40 字"**与实现对不上**——
R64 已经把**写作版面**定成 `--prose-measure: 44em`（≈616px @14px ≈ 44 字/行），
并在代码里写了理由：**"常见中文阅读器是 35–45 字，取上沿是因为这是写作的版面不是阅读的版面——
再窄就变成'看小说的宽度'了"**。那是个**刻意的决定**，本轮不推翻它。
⇒ 正确的口径是**分两种版面**：

| 版面 | 上限 | 理由 |
|---|---|---|
| **写作版面**（编辑器正文、.cm-host / .tiptap-host） | **44em（已定，R64）** | 写作时眼睛要来回扫，宽一点更省力；再窄就成了"看小说的宽度" |
| **阅读型长文块**（面板里的说明性段落） | **34em（约 34 字/行）** | 这类文字是"读"的，不是"扫"的——行太长眼睛容易串行 |

两者的差别不在审美，在**用法**：写作是扫（眼跳多、行可以宽），阅读是读（眼跳少、行要短）。
⚠️ 两者的上限都**不许手写 px**——一律走令牌（`--prose-measure` / `--prose-measure-narrow`），
理由与间距令牌同源（一个事实只有一个来源）。

**层级靠字重与留白，不靠更多字号**：一屏里超过 4 档字号就是没排好版。
现状的字号令牌有 7 档（11 / 12 / 12.5 / 13 / 14 / 16 / 18），这不违规——
**一屏用了几档**才是判据（令牌多 ≠ 一屏乱）。本轮给"一屏字号档数 ≤ 4"留了判据（见 R110 的锁）。

- **数字列一律 `tabular-nums`**（已在 docs/10 §3）+ **数字列右对齐**（R110 落地）：
  左对齐的数字列是"能看但不好比"，右对齐才能竖着比。

## 3. 动效：四族语义 + 退出更快

### 3.1 现有三档时长（保留）+ 四族语义别名（新增）

| 语义 | 取值 | 用在 |
|---|---|---|
| `--motion-exit` | 140ms | 退场（**比进场快**，M3 的桌面口径） |
| `--motion-state` | 140ms | 状态切换、hover / 按下 |
| `--motion-enter` | 240ms | 进场 |
| `--motion-reveal` | 380ms | 面板揭示（真实高度过渡） |

**语义别名指向既有三档**，不新增时长值 ⇒ 棘轮不涨。

**R111 实装口径**（第三批落地时定下的四条，判据逐条钉住）：

1. **组件只许引用语义别名**：`--motion-quick` / `--motion-base` / `--motion-slow` 是"档"，
   只在 `:root` 里出现；组件里写的是 `--motion-state` / `--motion-enter` / `--motion-reveal` / `--motion-exit`。
   好处不是好看，是**改版时不再凭手感挑一个时长**。
2. **退场比进场快**要落到可观测的事实上：浮层进场 240ms、退场 140ms；
   面板**展开走揭示 380ms、收起走退场 140ms**（CSS 的 transition 取**新状态**的计算值 ⇒ 一套规则写两行就够）。
3. **浮层只动 opacity，不动 transform**：`@` 候选菜单的 `.above` 态用 `transform: translateY(-100%)` 做
   "贴底向上弹出"的定位，动 transform 会和定位打架——**那是既有约定，不能为了动效去改定位**。
4. **退场的延时只有一个来源**：组件从 CSS 令牌 `--motion-exit` 读它，不在组件里写死毫秒；
   系统要求减少动效时**立即卸载**（不播退场，也不让人干等一个动画）。

### 3.2 三条不可退让

1. **退场比进场快**；短距离比长距离快。
2. **`prefers-reduced-motion` 必须同时关 `transition` 与 `animation`**（只关后者等于没关，R63 实测踩过）。
   本轮新增的开屏入场用 `transition: none` 关掉 ⇒ **不引入新的字面量例外**。
3. **不许新增 `@keyframes`**（契约 §5 锁在 1）：开屏那一下用**过渡**，因为它是一次性身份表达，
   不是"每个元素都在表演"。

- 密度选择器是**原生 `<select>`**（键盘可达、屏幕阅读器认得），带 `aria-label`。

## 5. 图标与品牌

### 5.1 界面图标（继续用 Lucide 原件）

11 个标签页图标是 Lucide v1.55.0 的**原件 path**（ISC，文件头保留许可、`NOTICE` 登记来源），
**不许改 path**（改了就不再是上游那份，署名也失去意义）。

### 5.2 品牌标记（**本项目自绘**，不是图标库）

**为什么必须自绘**：品牌标记**没有上游**。抄一份别人的 logo 当自己的品牌是署名事故，
和"抄图标"是两件性质不同的事。

**形状**：**一卷书 + 右下角一枚朱色落款印**。
「御」这个字自带官印的意象，写作工具最贴切的身份物就是"作者的落款"——一份写好的稿子末尾盖一枚印。
纸墨色系里补一枚朱，正好是印章的颜色，不是外来配色。

**制图口径**（与界面图标同源，所以看过去是一家人）：
24×24 画布、**2px 描边**、round join / round cap、**单色**（`currentColor`）；
**小尺寸优先**——16px 下仍要认得出是"一页稿子 + 一枚印"（朱印是**实心块**而不是小圆点：
16px 的圆点会消失，块不会）。

**机器判据**：path 只许出现在 `brand.tsx` 一个文件里（散落两份就等于有两枚不同的印）。

### 5.3 品牌字标

顶栏与欢迎屏共用同一处来源（`BrandWordmark`）：标记 + 「御书」两字。
两字标的 `letter-spacing: 0.08em` 是**全站唯一的字距例外**（docs/10 §3 已定）。

## 6. 开屏：欢迎屏就是开屏

**不做 Electron 的独立 splash 窗口**——理由写在这里，别下次又手痒：

- 御书的冷启动在 1 秒量级（perf 基线见 docs/08 §2），**独立 splash 窗口是纯开销**：
  多开一个窗口、多一次合成，还可能把冷启动指标顶穿。
- 一个真正的 splash 会把"加载"包装成"品牌表演"——**动效的职责是告诉他东西去哪了**。
- ⇒ **开屏 = 欢迎屏**（作者真正看到的第一屏）：品牌标记 + 一句定位 + 一次入场过渡。
  它的入场是**一次过渡**（不是每个元素都在动），且 `reduced-motion` 下完全关掉。

## 7.1 错峰落位（应用模式，R122）

一串元素**依次**出现时（地图标注、列表行），用 `transition-delay: calc(var(--i) * <既有别名> / N)`
把它们错开——**步长用既有别名算出来，不新增时长值**（§3 的纪律：时长只有一个来源）。

两条实施上的坑（都踩过）：

- **只动 opacity**：`transform` 留给悬停/选中这类**反馈**（feedback 要跟手），
  进场动效碰它就会和反馈抢同一个属性。
- **错峰放在只带一条过渡的外层 wrapper 上**：`transition-delay` 作用在该元素的**所有**过渡上，
  放在元素自己身上会连反馈的过渡一起拖慢。
- **系统要求减少动效时，延迟也要归零**：只归零时长的话，元素会一盏盏闪出来（那比不闪更让人不安）。

## 7.2 地图画面的层次（R123）

底图是**作者自己找的图**（深浅不保证）⇒ 画面按**五层**从上到下排：

1. **底图**（作者登记的图片，按 bounds 铺满）
2. **压暗层**（一层「地面色」：把底图拉到与界面同一档，标注与网格才读得出来；这层是 primitive ⇒ 换主题跟着换）
3. **坐标网格**（淡，只为让人看出"这是个坐标系"）
4. **标注**（形状按图层分：色盲与黑白打印都还分得开；颜色只用来做"选中"这一件事）
5. **越界标注**（虚线环 + 降透明——"它不在图里"要看得出来）

### 7.3 排版通则（R124）

- **说明不许堆成一长串**：信息多于两三项就**分行对齐**（键值成行），别用「·」串成一长串自由文本——
  在窄栏里它会断成四五行，读起来像碎片。要结构化就**让载荷带结构**（面板按行渲染），
  **别在界面里切字符串**：切出来的"项"会丢掉句子里的限定词（"读到 3 个爽点 · 3 条承诺" 切成两项后
  前一项的"读到"就管不到后一项了）⇒ 意思变了还不自知。
- **窄容器用容器查询，不拿媒体查询猜**：面板在栅格里时，它的宽度由**栅格**决定，不是视口宽度
  ⇒ 媒体查询一定会猜错（窄面板被挤成 175px 的窄柱）。让面板自己当容器（`container-type: inline-size`），
  按**自己的**宽度换布局；**宁可上下，也不要挤成一柱**。
- **动效不许过渡会让每一帧都重排的属性**（`width` / `height` / `top` / `left` / `right` / `bottom` /
  `margin` / `padding`）：那些过渡每一帧都重排 ⇒ **掉帧**。要动就用 **opacity / transform**
  （合成器就能做，不触发布局）。唯一登记的例外是展开 / 收起的 `grid-template-rows`
  （那是"内容增减"，面板小，R111 刻意选的）。
- **页面列的子项不许被压到比内容还矮**（R124）：`.panel { min-height: 0 }` 这类全局规则在 **flex 列**里
  会覆盖 flex item 默认的 `min-height: auto` ⇒ 面板被压扁 ⇒ 内容探出卡片、压住下一个。
  ⇒ 列的子项一律 `flex: none`（按自身内容撑高），**列自己滚**——宁可滚，也不要互相压。
- **页面列的容器规则只命中直接子级**（`.memory > section`，不是 `.memory section`）：
  后代选择器会把列里**嵌套的那个 section** 也当成列 ⇒ 同样的错。

### 7.4 排版要有跨页巡检（R125）

排版坏掉**不会让任何门禁变红**（静态结构合法，坏的是"哪条规则命中了谁"）⇒ 一次修一处不够，
得让**每一轮预演都巡一遍全应用**。

预演 `step88` 逐个标签页量三件事：

1. 面板**两两不相交**；
2. 面板的**直接子元素**不越出它的内容盒（**别用 scrollHeight**——面板自带滚动区天然更大，那是设计如此）；
3. 页面**不横向溢出**。

首跑 11 个页面 / 47 个面板 / 问题 0。这类巡检的价值不在"今天查出几个问题"，
而在**以后每改一处排版都会被量一遍**。

### 7.5 汇总要结构化，不许在界面里切字符串（R126）

面板的汇总**不要**写成"13 个实体 · 4 条引用行 → 1 条边；全图；…"这样的一长串：

- 窄栏里它会折成三四行，读起来像碎片；
- **切出来的"项"会丢掉句子里的限定词**——"读到 3 个爽点 · 3 条承诺"切成两项后，
  前一项的"读到"就管不到后一项了 ⇒ **意思变了还不自知**。

⇒ **结构由后端给**（载荷带 `summary: {label, value}[]`），界面用共享组件 `SummaryRows`
**逐行渲染**（标签一列、值一列）：值再长也不会把标签挤歪，多行值只在值那一列折行。

**标签列必须是"共享的一列"**：父级 `grid-template-columns: auto minmax(0, 1fr)` +
子行 `grid-template-columns: subgrid` ⇒ 列宽由**清单里最宽的标签**决定，所有行共用。
- 每行自己定一个窄宽（`3em`）⇒ **四个汉字的标签塞不下**（「悬空引用」= 50px > 37.5px）
  ⇒ 标签折成两行、整行高度翻倍；
- 每行自己按内容定宽（`auto`）⇒ **各行的值左边界参差**，看上去歪。

⇒ 判"汇总排得对不对"要量**标签的高度**（一行高）与**值列的左边界**（对齐），
**不要**量整行高度（值那一列本来就允许折行 ⇒ 整行高度不是判据）；另外要堵一条退化工况：
**值必须落在标签的右边**（上下叠成两行时，左边界反而全齐 ⇒ 前两条会误绿）。

### 7.6 判据要认"真实形状"，别认名字（R127）

判"这个面板用没用共享组件"时，**认 JSX 用法**（`<SummaryRows`），不要认组件名：
`import { SummaryRows } from "./SummaryRows";` 这一行**也含组件名** ⇒ 只认名字的话，
"面板早就不用了"时判据照样绿 ⇒ **恒绿判据等于没锁**。

同理，判"后端造了结构化行"要认**具体那一行**（`{ label: "爽点" }`），
不要认 `summary: [` ⇒ `summary: []`（空数组）也满足它 ⇒ **把行删光它照样绿**。

⇒ 这两条都是**变异跑当场抓到的**：把行删光、把面板改回自由文本，判据都该红。
（口径：判据写完必须想一遍"**这条判据在什么情况下会误绿**"，并用变异把那个情况跑出来。）

### 7.7 汇总结构化这条线到此收口（R128）

「世界观档案」页上**五个带汇总的面板**——图谱 / 爽点 / 编年史 / 伏笔 / 时间线——**全部**走共享组件 `SummaryRows`，
结构**全部**由后端给（载荷带 `summary: {label, value}[]`），界面一律不切字符串。

⇒ 判"这条线收口了没有"的方式是**运行时**的：逐个面板量
（标签一行高 / 值列左边界对齐 / 值在标签右边 / 值不越列），
而不是数一数源码里有几个 `SummaryRows`。

### 7.8 高对比要分「拉满」与「柔和」两档（R129）

系统「高对比度」在深色下最自然的实现是**纯黑底 + 纯白字**（把对比拉到两头），
但那一档夜里长时间看会晃眼 ⇒ 深色下**再给一档柔和高对比**：**按纸墨底调**——
底还是那张暗纸、字是暖白、描边明显加重 ⇒ 依然是高对比，但不刺眼。

- **只动 primitive 一层**（semantic 一个字没动），默认色板一个像素没动；
- 判据要**现算**：底色不是纯黑、字色不是纯白、正文对比度仍 ≥ 7（实测 ≈ 14.97:1）、
  描边比**默认暗色档**更明显（实测 1.49 → 2.82，**比的是相对值**，不写死数字）。

### 7.9 机器跑法不许拿别人的桌面当测试台（R130）

预演要**逐帧采样 CSS 过渡**、还要**截图取证** ⇒ 窗口必须**真的在渲染**。
但"在渲染"不等于"得让作者看见"：

- 窗口**被遮挡 / 隐藏 / 挪到屏幕外** ⇒ 浏览器**不出帧** ⇒ 过渡不插值、截图空白
  （实测：挪到屏幕外 ⇒ step74「中间态 0 帧」）⇒ 这条路不行；
- **透明窗口**也不行：页面自己画着不透明底色 ⇒ 照样实心可见；
  再叠上鼠标穿透 + 不可聚焦 ⇒ 窗口变成**点不掉、关不掉**（作者实测）。

⇒ 正确做法：**离屏渲染（`webPreferences.offscreen`）+ 永不显示**。
探针实测两条硬要求都满足：过渡**中间态 12 帧**、截图**非空**、`visibility=visible`，
而**桌面上一个窗口都没有**。

⇒ 配套纪律：**动跑法之前先问"这会不会碰到作者的桌面"**——
预演/压测/端到端这类"为了取证而开的窗口"，一律走离屏。

### 7.10 事件挂坐标：锚点与标注是**两件事**（R131，K08 §3.8）

地图上钉着两类点，作者常混：

- **标注（marker）**绑**地点实体**（K08 §3.7 标注即地点卡）⇒ 点开是那张地点卡；
- **事件锚点（event_anchor）**绑**事件**（K08 §3.8 事件挂坐标）⇒ 选事件能定位到地图上。

⇒ 二者的**键名、校验、形状都要分开**：
- 键名：锚点用 `event_ref`（K08 的样例写 `xy: [420, 610]`，本项目沿用地图自己的 `x` / `y` 分开写
  ⇒ 作者只学一套坐标写法；照 K08 抄 `xy:` 会被**点名拒绝**，不静默忽略）；
- 校验：**一个事件只能有一个锚点**（两个锚点会让"选事件定位到哪儿"变得不确定 ⇒ 拒绝加载并点名）；
- 形状：锚点画成**空心环 + 中心点**，地点标注是实心 ⇒ 形状优先于颜色，一眼分得清。

⇒ 判据要**运行时**的：锚点画出来了、名单列出来了、摘要数得对，而且**挂的是真事件**
（时间线里能看到同一个 event id ⇒ 锚一个不存在的事件不会"看起来正常"）。

### 7.11 跨面板的联动：**一个 id 贯穿两头**（R132）

时空联动是**跨面板**的（地图 ⇄ 时间线），最容易出的毛病是**两套状态**：
"选中锚点" + "选中事件" 各管一头 ⇒ 对不上时作者看到"高亮的行"和"高亮的点"根本不是同一件事，
联动看起来像坏了，而且**很难查**（两处都"亮着"）。

⇒ **一个事件 id 贯穿两头**：点锚点 ⇒ 那个事件 id 成为"当前联动的事件"；
时间线那边按同一个 id 高亮。反过来也一样。

配套三条：
- **跨面板的联动，数据只取一次**：地图把锚点清单**上报**给同一页的父组件（不要让父组件再取一遍）⇒ 两处不会对不上；
- **联动的一端永远键盘可达**：`role` / `tabIndex` / `onKeyDown` 写成**字面量**（条件表达式会让键盘债扫描器判成债）⇒ 键盘债仍是 0；
- **高亮要够显眼**：跨面板的视线要能跳 ⇒ 高亮不能只是"颜色深一点"。

**量联动之前，先把状态归零**：预演里**失败步骤会自动重试一次** ⇒ 上一轮的状态还在
（第一次尝试的最后一步已经点亮了联动）⇒ 第二次尝试会"因为残留状态"而通过
⇒ **变异的失效被盖住、判据看起来是绿的**（实测：这样跑，变异抓不到）。
⇒ 凡是"点了会改状态"的步骤，**重试路径必须从干净状态起跑**（切走再切回 ⇒ 组件重挂载 ⇒ 状态归零）。

### 7.12 联动的两端要有**可引用的关联**（R133）

R132 把"事件 ↔ 锚点"接上了（K08 §3.8 的前半句）；要接上"地点标注 ↔ 那件事"，
前提是**事件能引用地点实体**：时间线原先只有 `location`（**自由文本**、写给人看的地名）⇒
与地图标注的 `entity_ref` 对不上号 ⇒ 两边永远接不上。

⇒ 关联要分清两种东西：
- **引用**（`place_ref`）：一个**实体 id** ⇒ 能和别的真源对得上号 ⇒ 才有联动；
- **文本**（`location`）：写给人看的地名 ⇒ 好看，但**对不上号**。

⇒ 界面上点标注后的提示要**放在旁边、别把页面滚走**：点标注的**主**含义是"打开那张地点卡"
（K08 §3.7 标注即地点卡）⇒ 一上来就把页面滚到时间线，作者手里的卡就滚没了 ⇒
两头都在眼前才接得上（地图面板旁边说"这个地点在时间线上有 N 条"，旁边给一个"跳到时间线"）。

### 7.13 跨文件的引用要有**孤儿体检**（R134）

`place_ref` 这种**跨文件引用**（时间线 → 地点卡）一旦写错 id，界面只会说"地图上没这个地点"
⇒ 作者得自己猜是不是写错了 ⇒ **不静默**的要求没满足。

⇒ 要有一条**体检结论**（error 级）**点名**哪个事件、哪个 id 不存在。
但判定得**跨文件**（引擎只管时间，不认地点实体）⇒ 这条判定只能放在**桌面接线**那一层
（那里能读项目的实体表）⇒ **判定放在哪一层，取决于谁知道事实**。

⇒ 判"孤儿"时**按 id 存在与否**判，**不猜类型名**：地点卡的 type 叫 `location`、layer 叫 `geography`
（实测：把 `type === "place"` 写死 ⇒ 把**有效**的引用报成了孤儿）⇒ 与地图那边（`map-marker-orphan`）保持同一口径。

⇒ 顺带一条工装纪律：**预演里"等数据"要等 DOM，不要靠固定 sleep**——
判定一重（这里多扫一遍实体表），数据到得更慢 ⇒ 固定 sleep 就悄悄不够了（本轮实测：时间线那两步先红）。

### 7.14 改了哪个包，就重建哪个包（R134 的「假绿」教训）

本轮改了**引擎包**的源码，却只重建了桌面端（`build:main` **不重建依赖包**）
⇒ 预演跑的是**旧引擎** ⇒ 引擎的投影里没有新字段 ⇒ 界面那两步连着红。

⇒ **危险不在于它会红**（它确实红了）⇒ 而在于**旧代码是自洽的**：
只改了消费方、没改被依赖的包时，**门禁可能照样绿**（跑的是旧实现 ⇒ 判据也绿）
⇒ ⇒ 这是一种**看不见的假绿**。

⇒ 纪律：
① **改了哪个包就重建哪个包**（或直接 `pnpm -r run build`）；
② **门禁的顺序也要对**：桌面端的单测 import 的是工作区包的 **`dist`**（`@yushu/world-engine` 的
   `main` 指向 `dist/index.js`）⇒ **单测同样跑旧代码** ⇒ ⇒ **先全量重建、再跑单测/预演**；
③ **跑门禁前先确认构建是最新的**（构建产物的 mtime 早于源码 ⇒ 就是在跑旧代码）。

### 7.15 写盘路径的纪律（R135：底图登记）

地图面板从"只读"变成"能给作者一个入口"，就多了一条**写盘**路径 ⇒ 纪律照抄既有的写通道约定：

- **路径不出主进程**：原生对话框在主进程开，渲染层只拿**项目内的相对路径**与尺寸；
- **只追加，不重写**：地图文件里作者的标注、图层、注释**原样留着** ⇒ 不重写整个文件
  （重写要序列化器，会把注释与排版抹掉）；格式归**引擎**管（`appendMapBase`）；
- **不替作者做决定**：已经有底图登记 ⇒ **拒绝**并把该改的三行给作者看（换底图是作者的决定）；
- **写盘带 baseHash**：作者在别处改过 map.yaml ⇒ **报冲突**、不覆盖；
- **只动 primitive 一层**不适用于这里，但"只动一层"的思路一样：**新增能力不许顺手改别的**。

⇒ 判据分两处：**写盘链路**用 ops 级单测（断**盘上的字节**，比断界面更硬），
**界面接线**用静态锁；原生对话框在预演里用**桩**（桩是工装，断言断的仍是盘上的字节）。

### 7.16 「登记」与「换」是**同一个入口的两种模式**（R136）

R135 只做了"第一次登记"（已有登记 ⇒ 拒绝并把该改的三行给作者看）⇒ 结果是**换不了**。
这一轮让"换"也能一键完成，但**不新开一个按钮**：

- 按钮**按有没有登记过**给不同的模式（"登记底图" / "换底图"）⇒ 作者看到的就是他要做的事；
- 「换」= 把那几行**替换**（不是追加第二份 ⇒ YAML 不会出现重复键）；
- **旧的图片文件留在项目里**（换错了能改回去，工具不替作者删资产）；
- **换之前的那三行显示在面板上**（他要换回去，把它们贴回去即可）⇒
  **回退是"把旧的三行贴回去"，不需要另造一套撤销机制**（项目的快照另算）。

⇒ 通则：**同一个入口、两种模式**；换之前的东西**留着**，回退的路**摆在作者眼前**。

### 7.17 对比度要**逐页量**，量过一次就当全过了（R137）

暗色色板落地后只量过**两页**（预演 step82 / step92）⇒ docs/13 §6 明写"没做逐页"。
R137 把这条补上，补出来的是**真缺陷**，而且不在暗色、在**默认档**：

- **动态那一半**（预演 step99）：11 个页面 × 3 档主题 = 33 组，
  每组取**该页最差的一段文字**，算它与**它所在的那层不透明祖先背景**的对比度 ⇒ 每组 ≥ 4.5。
  **量法上有个容易做错的地方**：量 body 是没用的——body 每页配色一样，量它等于只验了一次；
  要量"这段字**自己**落在哪层底上"（往上找第一个不透明的祖先背景）。
- **静态那一半**（`apps/desktop/test/contrast-gate.test.ts`）：把样式表声明的所有
  「字色 × 底色」组合逐套主题算一遍（含系统高对比两档）⇒ 不再靠"量过两页"交差。
- 量出来的结论是：**默认档的次要文字在纸底上只有 3.49:1** ⇒ 默认档自己违反 docs/13 §3 的底线，
  而"没人改过它"所以一直没被发现 ⇒ 改成"当前值逐字锁 + 差异登记锁"（docs/13 §9.3）。

三条做法上的自约束（都是防假绿）：

- 判据要**点名具体那一对**（哪个字色、哪层底、哪套主题、多少比值），不能只报"有多少处不合规"；
- **不许靠删规则绕过**：钉住几对**必须存在**的组合（少一对就红）；
- **不许靠解析器坏掉变绿**：每套主题断言比对过的组合数有下限。

⇒ 通则：**"量过一次"不等于"全都过了"**；色值不许凭感觉调，先算再调，调完让判据守住。

### 7.18 「框定 bounds」是**模型翻转**：bounds 从"整张图"变成"图里的一块"（R138）

K08 §3.6 写的是「地图 = 图片底图 + bounds → 用户上传底图并**框定 bounds**」，
而 R135 只做了"上传底图"（bounds 按量出来的尺寸自动填 = 整张图）⇒ **框定那一步一直空着**。

这一轮把它补上，也把**渲染模型翻了过来**（只加一个按钮是不够的）：

- **bounds 成了"图里的一块"**（不再是整张图）⇒ 引擎的判定从「尺寸必须等于底图」改成
  「**范围必须落在底图里**」（框到图外才是写错）；标注与锚点**按新框归一**，
  框在外面的**逐条点名**（`map-marker-outside` / `map-anchor-outside`）——作者看得见自己框掉了什么。
- **画布 = 框定的那一块**，底图**按框裁切**显示（视图里把图往左挪 `-x0`）。
- **框定模式画的是整张图**（不是当前那一块）：在已裁切的画面上拖，永远框不到图外的地方；
  当前框用虚线画出来，作者看得见自己框到哪了。
- **键盘也能框**（方向键移动、`+` / `-` 改大小、回车定下来）：拖拽只是"快"的那条路，
  不是唯一的路（契约 §6：键盘债是 0）。
- **写盘只改 `bounds` 那一行**（底图登记、图层、标注、锚点、作者自己的注释**原样留着**）；
  范围落在底图外 ⇒ 拒绝并说清底图多大；写盘带 baseHash ⇒ 作者在别处改过 map.yaml 时报冲突。

⇒ 通则：**「框定」这类交互要同时给两条路**（指针快、键盘准）；
  **裁切类的功能要同时改「坐标空间」与「画布」**——只改一边就会出现"框了但没生效"。

### 7.19 「放 marker」的第一件事是**挪**（R139）

K08 §5 的地图编辑器链条是「上传底图 → 框定 bounds → **放 marker**、区域、行程线 → 绑定实体」。
R135 做了第一步、R138 做了第二步 ⇒ 这一轮接上第三步的**第一件事**：
作者手填的坐标常常差一点（差几十像素，地图上就偏了一截）⇒ 让他在图上**拖**。

三条做法上的口径：

- **写盘只改那一个标注的 x / y**（底图登记、bounds、别的标注、锚点、作者自己的注释**原样留着**）——
  与「登记底图」「框定边界」「换底图」同一条纪律：**只动该动的那几行**，
  并把**改之前那一行**给作者（他要挪回去，把那行贴回去即可）。
- **落点必须落在框定的那一块里**（落在外面 ⇒ 那个点看不见）⇒ 拒绝并说清范围。
- **键盘也能挪**（方向键微调，Shift 走大步）⇒ 拖拽不是唯一的路（契约 §6：键盘债是 0）；
  拖动与点击要**分得开**：**移动不足 3px 就算一次点击**（开地点卡），拖过就**不顺带**开卡。

⇒ 通则：**直接操作（拖）要配一条键盘路**；**拖拽与点击必须分得开**
  （判据是"移动了多少"，不是"按下过没有"）。

### 7.20 「放 marker」= 选一个地点 ⇒ 在图上点一下（R140）

K08 §5 的链条走到第三步的**另一半**：R139 做了「挪」，这一轮做「**放**」。

三条口径：

- **地点清单来自真源**（面板里的下拉列的是项目里的 **location 类实体**）——
  标注只能绑**真实存在**的地点（K08 §3.7：标注即地点卡 ⇒ 绑一个不存在的地方就是孤儿标注），
  不让作者去填一个可能不存在的 id。
- **写盘只追加那一行**（放在 `markers:` 段的**末尾** ⇒ 作者自己写的标注顺序不变）；
  **标注 id 由主进程生成**（`m-<n>`，跳过已占用的）——撞 id 的话地图文件会被严格解析拒绝，
  **整个地图都读不出来**（不是"少一个点"，是"地图没了"）。
- **键盘也能放**（十字光标 + 方向键 + 回车）⇒「点一下」不是唯一的路（契约 §6：键盘债是 0）；
  放标注与框定是**两种模式，一次只做一件事**。

⇒ 通则：**「在某处落一个东西」要有键盘路**（光标 + 方向键 + 回车）；
**id 交给工具生成**（作者手写 id 迟早撞，撞了就是整个文件读不出来）。

### 7.21 地图编辑面：一条状态行、一组按钮、一句作者语言（R141）

R138–R140 三轮都往地图面板上加了入口（框定边界 / 放标注 / 挪标注 / 挪锚点）⇒
面板长成了一堆散落的说明与提示。R141 把它收一遍，**顺带把"作者看到什么"当成一条口径**：

- **一条状态行**：框定 / 放标注 / 挪标注 / 挪锚点的**回执都在同一处**
  （面板上只留一行"刚才那一下怎么了"，不再三四处各挂一句）。
- **一组按钮**：模式相关的控件（框回整张图 / 地点下拉）**只在该模式里出现**；
  按钮按状态改字（"框定边界" ⇄ "退出框定"）⇒ 模式是看得见的。
- **一句作者语言**：提示只说**作者要做什么**，**不露实现细节**
  （"只改 map.yaml 里那一个标注的 x / y"这种话是给实现者看的，不是给作者看的）。
- **汇总用共享的 SummaryRows**：与地点卡、爽点看板同一套结构化行，
  不再是几行各自为政的 div（标签与值挤一行、值一长就折行 ⇒ 读起来像碎片）。

⇒ 通则：**面板上的每一条字都要有归属**——状态、提示、汇总各归各的；
  **给作者看的文字里不许出现文件名与字段名**。

### 7.22 事件锚点也交给作者放（R142）

K08 §3.8 说的是「**事件可挂坐标** ⇒ 选事件能定位到地图上」。
R131 之后锚点只能**手写**在 `world/map.yaml` 里 ⇒ 对不会写 YAML 的作者等于"这张功能没有"。

这一轮把它交给作者动手：**选一个事件 ⇒ 在图上点一下 ⇒ 落一个锚点**。

- **事件清单来自真源**（`world/timeline.yaml`）⇒ 锚点**只能挂真实的事件**
  （挂一个不存在的事件 = 悬空引用，选事件时定位不到）。
- **写盘只追加那一行**（放在 `event_anchors:` 段的**末尾** ⇒ 作者自己写的锚点顺序不变），
  **锚点 id 由主进程生成**（`a-<n>`，跳过已占用的）——撞 id 的话地图文件会被严格解析拒绝，
  **整个地图都读不出来**。
- **落点必须落在框定的那一块里** ⇒ 拒绝并说清范围（落在外面 ⇒ 那个点看不见）。
- 地图面板的放置入口分成**放标注 / 放锚点**两个 ⇒ **一个入口一件事**，
  下拉按模式换清单（地点清单来自实体表，事件清单来自时间线）。

⇒ 通则：**"挂到某个东西上"要有东西的清单**（清单来自真源 ⇒ 挂不上假的）；
  **两种"放"不要塞进一个入口**（标注与锚点的清单、校验、结果都不同）。

### 7.23 区域与行程线：**点用底图像素**，一行一个形状（R143）

K08 §5 的地图编辑器链条：「上传底图 → 框定 bounds → 放 marker、**区域、行程线** → 绑定实体」。
R135/R138/R140/R142 依次补上了前三样 ⇒ 这一轮补上**最后两样**。

**K08 给了图层类型（`type: region` / `type: polyline`）但没给几何 ⇒ 这一段的几何由本项目定**：

```yaml
regions:
  - {id: r-1, layer: political, name: 北境, points: [[100, 100], [300, 100], [300, 300]]}
routes:
  - {id: rt-1, layer: route, points: [[100, 100], [250, 250]]}
```

- **点用底图像素**（与标注、锚点同一套坐标空间）——K08 §3.6 明写「坐标以图片像素 / 归一化坐标记录（不用真实经纬度）」。
- **区域是闭合多边形**（至少 3 个点），**行程线是折线**（至少 2 个点）——少一个点**拒绝加载并点名**（严格解析）。
- **写盘只追加那一行**，排在 `regions:` / `routes:` 段的**末尾** ⇒ 作者自己写的顺序不变；
  形状 id 由**主进程**生成（`r-<n>` / `rt-<n>`，跳过已占用的）——撞 id 的话地图文件会被严格解析拒绝，
  **整个地图都读不出来**。
- **顶点必须落在框定的那一块里**（落在外面 ⇒ 那个形状看不见）⇒ 拒绝并说清范围。
- **画形状也要有键盘路**：方向键挪十字光标、**回车加一个顶点**、**退格删掉最后一个**，
  「画完了」按钮定下来 ⇒ 拖/点不是唯一的路（契约 §6：键盘债是 0）。
- 画到一半的那串点**要看得见**（虚线 + 小点）⇒ 否则作者是在盲画。

⇒ 通则：**"画一条线 / 一个面"要有键盘路**（光标 + 加点键 + 撤销键 + 一个"定下来"的按钮）；
**顶点用哪套坐标要写死**（这一段用底图像素，与标注/锚点同源）。

### 7.24 入口多了以后，**收成"一个分组 + 几个档位"**，别收成"一个入口 + 一个下拉"（R144）

地图面板连着几轮加了入口：框定边界、放标注、放锚点、放区域、放行程线 ⇒ 五枚按钮平铺着，
作者看到的是"五件不相干的事"，而不是"编辑地图"。

⇒ 收成**一个分段控件**（`map-mode-group`）：一个分组 + 五个档位 + **当前档位高亮**
（`is-on` + `aria-pressed`）⇒ 看起来是同一件事的五种做法，做起来各管各的。

**为什么不是"一个入口 + 一个下拉"**：这五件事的**清单、校验、结果都不同**
（地点清单 / 事件清单 / 顶点数下限 / 落点范围）⇒ 塞进一个下拉，作者反而看不出
"现在能放的是哪一种"；而**分段的五档**既保住了各自的语义，又让面板不再是一堵按钮墙。

配套三条：
- **模式相关的控件只在该模式里出现**（框回整张图 / 画完了 / 对象下拉）⇒ 平时那排只留五个档位。
- **模式态要看得见**（高亮 + `aria-pressed`），不能只靠按钮文案改字。
  **"看得见"要有数**：选中态底色 vs 常态底色 ≥ **3:1**（WCAG 1.4.11 的非文本对比度）。
  R144 实测踩过这个坑 —— 当时选中态底色用的是 `--accent-soft`（#f0e2ce）、
  常态是 `--panel`（#fffdf8），两者只有 **1.25:1**（浅色档）；暗色 1.16、柔和高对比 1.10、
  系统高对比浅 1.27、系统高对比暗 1.54 ⇒ **五套主题全部低于 3:1**，
  证据图里五个胶囊按钮长得一模一样，"当前在哪一档"在屏幕上分不出来。
  改成**实心强调底 + 反色字**（`--accent` / `--ink-on-accent`）后，
  底色差 5.72~15.68:1、字色对比 5.81~13.64:1，五套主题全过。
  判据：`apps/desktop/test/selected-state-contrast.test.ts`（逐套主题卡 3:1 与 4.5；
  把那条 CSS 删掉也会红 ⇒ 不许靠删规则绕过）。
  **色板一个色值都没动** —— 问题是"选哪两个既有令牌"，不是"调哪个值"。
  这条判据分两半：**静态**那一半量样式表声明的令牌组合，
  **动态**那一半（预演 **step106**：停在「放标注」模式里不放点，量 `getComputedStyle` 的真实渲染值）
  也卡 3:1 与 4.5 —— 只量静态那一半，等于没量屏幕上真正画出来的那层。
- **图层显隐要管到面与线**（K08 §3.9「图层独立显隐」）：关掉"路线"层 ⇒ 那条线也得跟着没，
  图层的计数也要把区域/行程线算进去。

⇒ 通则：**入口变多时先分组、再分档**（同一件事的几种做法放一组、当前档位高亮），
**不要把不同语义的东西塞进一个下拉**；**"关掉某层"要真的关干净**（点、线、计数都算上）。

### 7.25 底图再大也看不清局部：**缩放与平移是"看"的状态**，不进真源（R145）

底图可能是一张几千像素的图，画布只有一屏大 ⇒ 不放大就永远看不清局部。
但作者放大只是为了看清楚——**那不是作品的一部分**。

四条口径：
- **缩放/平移不写盘**（`map.yaml` 一个字节都不动）：放大是"看"的动作，
  作品里不该有一行"作者当时放大到了 1.5 倍"。
- **看得见的范围永远在作者框定的那一块里**（bounds 之内）⇒ 越界的平移要钳回去：
  框外那部分作者没框过，不该出现在作品视图里。
- **缩放有上下限**：1 倍 = 整块框（默认），最多 4 倍（再大只见一块）。
- **放大之后落点仍然准**：画面坐标 → 底图像素的换算走 SVG 的 `getScreenCTM()` 逆变换，
  缩放只改 viewBox ⇒ 那个矩阵自动跟着变 ⇒ 落点不会偏。

**键盘路**（键盘债必须是 0）：`+` / `-` 改大小、`方向键` 挪画面、`0` 复位；
画布要**恒可聚焦**（R138 时只在框定模式里可聚焦，那时缩放平移还没有键盘路）；
界面上另有三个控件（放大 / 缩小 / 复位）⇒ 作者不用记快捷键。

**两条让位规则**（别抢作者正在做的事）：
- 框定 / 放置 / 画形状时，方向键与 `+` / `-` 归那些模式（作者正在精确落点）；
- 焦点落在某个标注/锚点上时，方向键归它（那是"挪这个点"）。

**怎么落地的**：边界（缩放上下限、越界钳制、步长）都是**能算的** ⇒ 提成纯函数
`renderer/src/components/map-view.ts`，判据在 `apps/desktop/test/map-view.test.ts`，
界面那侧只做接线。预演 **step107** 验三件事：放大/平移看得见、**盘上一个字节没动**、
**放大之后落点仍然准**（用同一个用户坐标反算屏幕坐标再点，落点仍应是那个坐标）。

⇒ 通则：**"看清楚"是视图的事，别把它写进作品**；**放大之后落点不许偏**
（这一条比缩放本身更要紧——落点偏了，作者放的东西就落在了别处）。

### 7.26 主界面学 codex / trae SOLO / zcode：**入口是主角**，不是一堆表单（R146）

**参考站实地看到的**（R146 调研，不凭印象）：
- **TRAE SOLO 主界面是三栏式**：左「任务管理面板」/ 中「AI 对话面板」/ 右「工具面板（编辑器、终端、浏览器预览、文档）」。
  它自己的一句话是"原来你是中心，现在 AI 是中心，你在边上看它干活" ⇒ **主界面把"正在进行的任务"放在最左边**。
- **TRAE 官网的设计特征**（据其社区整理）：深色画布、亮蓝强调色、**编号式功能导航**、AI 渐变光晕。
- 这类工具的主页共性：**入口是一个输入框**（对话/命令），**状态常驻可见**（上下文用量条、任务进度），**空态有引导**（`/spec`、`/plan` 这类命令入口）。

**御书的第一屏（起源工作台）原先长什么样**：右栏一张表单卡（三个空框），下面 60% 屏幕是空白；
左边九层清单 + 一行小字"目标：≥5 张设定卡"。
⇒ 作者看到的是"一张要填的表"，而不是"从哪开始"。

**这一轮改了三处**（结构变了，不是换皮）：
- **入口是主角**：首屏加**「这本书从哪里开始？」**——一个输入框 + 一个「用这句话开局」+ 四个快捷起点
  （起一个事件 / 起一个人物 / 起一场冲突 / 起一座城）。**快捷起点只给样板文字，不直接提交**。
- **进度看得见**：左栏加**真进度条**（`role="progressbar"` + `aria-valuenow`），"设定卡 N / 5"不再只是一行小字。
- **不替作者做决定**：那句话**只填进当前步的必填字段**，**不自动保存** ⇒ 盘上的卡数一个字都不多
  （与本项目"候选要作者显式采纳才写库"的口径一致）。

**顺带记一条门禁抓到的**：进度条最初写了 `transition: width` ⇒ 被 R124 那条
"动效不许过渡会让每一帧都重排的属性"当场拦下 ⇒ 进度条是低频变化，**不过渡**。

⇒ 通则：**AI 工具的主页不是给你看功能的，是让你马上开始做一件事** ⇒
**首屏要有一个"一句话就能开始"的入口**；**进度/状态要常驻**；**入口不许替作者做决定**。

### 7.27 首屏的下半屏：**「接下来做什么」**要现算，不能写死（R147）

R146 给了首屏一个"一句话开局"的入口，但下半屏还是空的 ⇒ 作者填完第一步，
下面还是一大片空白。AI 工具的主页在这块从不空着：**入口之外还会告诉你下一步与最近的产物**
（TRAE SOLO 左栏就是"正在进行的任务"）。

⇒ 起源工作台第三段：**「接下来做什么」**，三条：
- **先建这一层**：按**卡片的 layer** 现算（第一张还没建卡的层）；
- **接着写**：按稿件总览里**已建草稿**的章现算；
- **这本书**：章数 / 已建草稿 / 总字数。

**一条硬口径**：**写死的文案没有用**——那不是作者的书 ⇒ 三条都要现算，
判据也要认"计算的那几处"而不是"文案在不在"（判据里点名 `GENESIS_STEPS.find(...)`、
`draftedChapters`、`library.totals.chapters`）⇒ 改回写死文案时门禁会红。

⇒ 通则：**空着的下半屏是"作者不知道该干嘛"** ⇒ 首屏要告诉他**下一步**，
而且**要说真话**（从他自己的项目里现算，不是从模板里抄）。

### 7.28 滚轮缩放：**以指针为锚点**，且必须是**非被动**监听器（R148）

R145 给了缩放/平移的按钮与键盘路，R148 补上最自然的那一下：**滚轮**。

三条口径：
- **手感**：滚轮该"**指针下那一点不动**"⇒ 以指针为锚点缩放（`zoomAtPoint`）。
  若一律以画布中心缩放，作者想看的是指针指着的那一块 ⇒ 越放大越跑偏。
- **实现**：**React 17+ 的 `onWheel` 是被动监听器** ⇒ `preventDefault()` **不生效**
  ⇒ 滚轮会连带把整页滚起来 ⇒ 必须 `ref` + `addEventListener("wheel", h, { passive: false })`。
- **依赖里必须有 `map`**：地图没加载时组件走 early return（先渲染「正在读地图…」）
  ⇒ **画布根本不在 DOM 里** ⇒ 那时 effect 拿到的 ref 是 null ⇒ 监听没挂上；
  而 `width` / `height` 在加载前后**恰好相同**（bounds 正好 1000×700）⇒ 依赖没变
  ⇒ effect 不重跑 ⇒ **监听永远挂不上**。⇒ 依赖里要有 `map`（它才是「画布出现与否」的那个状态）。

**边界优先**：锚点贴在可见范围边缘、或缩到 1 倍（可见范围 = 整块 ⇒ 没有平移余地）时，
"锚点不动"与"看得见的范围不许出框"**不能同时满足** ⇒ 以**边界优先**，锚点允许移动。

让位规则与键盘同一套：框定 / 放置 / 画形状时，滚轮也归那些模式。

⇒ 通则：**滚轮放大要锚在指针上**；**要能阻止默认行为**（否则整页跟着滚）；
**边界与手感冲突时，边界优先**；**在 effect 里拿 DOM 元素，依赖里要有"元素出现与否"的那个状态**。

### 7.29 主界面学 TRAE SOLO：**三栏**（左=进行中的任务 / 中=主工作区 / 右=产物与工具）（R149）

TRAE SOLO 的主界面是三栏：左「任务管理面板」/ 中「AI 对话面板」/ 右「工具面板（编辑器、终端、浏览器预览、文档）」，
它自己的一句话是"原来你是中心，现在 AI 是中心，你在边上看它干活"。

⇒ 御书进项目后的第一屏（起源工作台）也改成三栏：
- **左 = 正在进行的任务**：世界构建层级九步 + 设定卡进度（`role=progressbar`）；
- **中 = 主工作区**：一句话开局 → 创世事件表单 → 「接下来做什么」；
- **右 = 产物与工具**：**刚建好的卡**、**已写的章**、**去哪儿**（跳到稿件总览 / 规则体检 / 世界观档案）。

两条硬口径：
- **右栏只放真产物**（作者刚建好的卡、已经写出来的章），**全部从真源现算** —— 不摆装饰性的卡片；
- **「去哪儿」要真能跳**（产物栏不是好看的）⇒ 判据认 `onNavigate("library")` 这类**调用**，而不是认"有个按钮"。

版式约束：第三栏宽度用**百分比**（22%）而不是 px ⇒ 不给"长度字面量棘轮"（只许降不升）添新账。

### 7.30 拖拽平移：**指针是稀缺资源**，先定让位规则再动手（R150）

放大之后要看别处，键盘方向键能挪，但按住鼠标拖更顺手。问题在于：**同一块画布上还有别的指针语义**
——挪标注（R139）、框定边界（R138）、放东西（R140/R143）都要用指针。

⇒ 口径：
- **只在无模式、且点在空白处时**才平移（框定 / 放置 / 画形状一律**让位**）；
- **点在标注 / 锚点上不开始平移**（那是"挪这个点"，不是"挪画面"）——
  标注的 pointerdown **会冒泡到画布**（没有 stopPropagation）⇒ 所以必须**自己判**
  （closest 判 .map-marker-in / .map-anchor 等），不能指望事件不冒泡；
- 平移**要钳住**（看得见的范围永远不许被推出作者框定的那一块）；
- 平移只是"看" ⇒ **不写盘**。

⇒ 通则：**同一个指针能做的事不止一件 ⇒ 先写清让位规则，再动手**；
判据钉的是**让位**与**不抢**这两条（不是"有没有拖拽"）。

### 8. 明确还没做的（不许被读成已做）

- **暗色色板的具体取值与 `data-theme` 开关**：R116 只把令牌分成两层（primitive / semantic），**默认色板一个像素没动**；暗色值本身还没定 ⇒ R121。
- **世界地图的 UI 渲染**：R114 只做了引擎侧（图片底图 + bounds 的投影与体检）⇒ 界面顺延 R120。
- **插画的深色版、插画在更多空态上的铺开**（R118 明写没做）。
- **密度档同步到多台设备**——那是产品决定，不是技术决定（R117 明写没做）。
- **两套描边口径的统一**（见 `docs/12` §2）。
